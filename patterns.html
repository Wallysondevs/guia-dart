Dart Patterns e Desestruturação Dart 3.0

Na aula de Records, você juntou vários valores num pacotinho: ('Ana', 30). Agora vem o caminho de volta: desmontar o pacote e pôr cada valor na sua variável, numa linha só. Isso se chama desestruturação, e o que descreve o "formato" do pacote se chama pattern (em inglês, "padrão" ou "molde"). Os patterns chegaram no Dart 3.0, junto com os records, e funcionam também com listas e mapas.

Você vai aprender
  • Como desmontar um record: final (nome, idade) = aluna;
  • Como pegar campos pelo nome: final (:nome, :preco) = produto;
  • Como desmontar uma lista: final [ouro, prata, bronze] = podio;, e o ...resto.
  • O curinga _ ("não quero esse") e a troca de duas variáveis numa linha.
  • Patterns no for-in, em mapas, no if-case e no switch.
  • Os erros reais: o formato não combina (erro de compilação) e o Pattern matching error (ao rodar).

Todos os programas desta aula rodaram no Dart 3.13.5 da máquina da Ana (usuária ana, computador notebook), com dart run arquivo.dart.

A ideia: a fôrma de gelo

Pense numa fôrma de gelo com três buracos. Você despeja água e cada buraco recebe a sua parte. O formato da fôrma decide onde cada parte vai parar.

Um pattern é a fôrma. Você escreve, do lado esquerdo do =, o formato do valor, com nomes de variáveis nos "buracos": (nome, idade). O Dart encaixa o valor da direita nesse formato e cada variável recebe a sua parte. Se o valor não couber na fôrma (três buracos, mas só dois valores), dá erro.

1. Desmontando um record

void main() {
  final aluna = ('Ana', 30);
  final (nome, idade) = aluna;
  print(nome);
  print(idade);
}
final aluna = ('Ana', 30);
Um record com dois campos (veja Records).
final (nome, idade) = aluna;
A desestruturação. O lado esquerdo, (nome, idade), é o pattern: "um record com dois campos". Ele cria duas variáveis de uma vez: nome recebe o 1º campo e idade recebe o 2º. O final vale para as duas.
print(nome); print(idade);
Agora são variáveis comuns. O Dart sabe até os tipos: nome é String e idade é int.
$ dart run desmontar.dart
Ana
30

Sem pattern, seriam duas linhas: final nome = aluna.$1; e final idade = aluna.$2;. O pattern faz o mesmo, mais curto e com nomes melhores que $1 e $2.

Campos com nome

Num record com campos nomeados, o pattern diz qual campo vai para qual variável:

void main() {
  final produto = (nome: 'café', preco: 18.9);

  final (nome: n, preco: p) = produto;
  print('$n custa $p');

  final (:nome, :preco) = produto;
  print('$nome custa $preco');
}

$ dart run nomeados.dart
café custa 18.9
café custa 18.9
(nome: n, preco: p)
"O campo nome vai para a variável n; o campo preco, para p."
(:nome, :preco)
Atalho para quando a variável tem o mesmo nome do campo: :nome quer dizer nome: nome. É a forma mais usada.

O curinga _

Quando um valor não interessa, ponha _ (sublinhado) no lugar dele. O _ encaixa qualquer coisa e não cria variável nenhuma:

(int, int) menorEMaior(List<int> notas) {
  var menor = notas.first;
  var maior = notas.first;
  for (final n in notas) {
    if (n < menor) menor = n;
    if (n > maior) maior = n;
  }
  return (menor, maior);
}

void main() {
  final (_, maior) = menorEMaior([7, 9, 4, 10, 6]);
  print('Maior nota: $maior');
}

$ dart run curinga.dart
Maior nota: 10

Missão: em vez de usar aluna.$1 e aluna.$2, desmonte o record em duas variáveis, nome e idade, com final (…) = aluna;, e use-as no print.

void main() {
  final aluna = ('Bia', 25);
  print('${aluna.$1} tem ${aluna.$2} anos');
}

void main() {
  final aluna = ('Bia', 25);
  final (nome, idade) = aluna;
  print('$nome tem $idade anos');
}

2. Desmontando uma lista

Com colchetes, o pattern descreve uma lista. O pódio da corrida da escola:

void main() {
  final podio = ['Bia', 'Caio', 'Ana'];
  final [ouro, prata, bronze] = podio;
  print('1º lugar: $ouro');
  print('2º lugar: $prata');
  print('3º lugar: $bronze');
}

$ dart run lista.dart
1º lugar: Bia
2º lugar: Caio
3º lugar: Ana

O pattern [ouro, prata, bronze] quer dizer "uma lista com exatamente três itens". Se a lista tiver outro tamanho, o programa para com erro ao rodar (veja Quando dá errado).

O resto: ...

Quando o tamanho pode variar, use ... para "o resto" (os mesmos três pontos do spread, agora do lado de quem recebe):

void main() {
  final fila = ['Ana', 'Bia', 'Caio', 'Davi'];
  final [primeira, ...outros] = fila;
  print('Atendendo: $primeira');
  print('Esperando: $outros');

  final [..., ultimo] = fila;
  print('Último da fila: $ultimo');
}

$ dart run resto.dart
Atendendo: Ana
Esperando: [Bia, Caio, Davi]
Último da fila: Davi
[primeira, ...outros]
"O primeiro item vai para primeira; todos os outros, numa lista, vão para outros."
[..., ultimo]
"Ignore o começo, quantos itens forem, e me dê o último." O ... sem nome descarta o resto.

3. Trocar duas variáveis numa linha

O pattern também funciona numa atribuição, sem final nem var, com variáveis que já existem. O truque clássico é trocar dois valores:

void main() {
  var a = 'café';
  var b = 'chá';
  (a, b) = (b, a);
  print('a = $a, b = $b');
}

$ dart run trocar.dart
a = chá, b = café

O lado direito, (b, a), monta um record com os valores de antes; o lado esquerdo desmonta esse record em a e b. Sem pattern, a troca precisaria de uma terceira variável (final temp = a; a = b; b = temp;).

4. Patterns no for-in e em mapas

Uma lista de records (nome e nota de cada aluno) fica fácil de percorrer: o pattern vai direto no for-in.

void main() {
  final turma = [('Ana', 9.0), ('Bia', 6.5), ('Caio', 8.0)];
  for (final (nome, nota) in turma) {
    print('$nome tirou $nota');
  }

  final precos = {'pão': 1.0, 'leite': 5.5};
  for (final MapEntry(:key, :value) in precos.entries) {
    print('$key: R\$ $value');
  }
}

$ dart run forin.dart
Ana tirou 9.0
Bia tirou 6.5
Caio tirou 8.0
pão: R$ 1.0
leite: R$ 5.5
for (final (nome, nota) in turma)
A cada volta, o record da vez é desmontado em nome e nota.
precos.entries
Os pares do mapa, cada um como um MapEntry ("entrada do mapa"), com os campos key (chave) e value (valor). Veja Percorrendo Mapas.
MapEntry(:key, :value)
Um pattern de objeto: o nome do tipo e, entre parênteses, os campos que você quer. Funciona com qualquer classe, não só com MapEntry.

Um mapa também pode ser desmontado pelas chaves, com chaves { } no pattern:

void main() {
  final pedido = {'cliente': 'Ana', 'mesa': 4};
  final {'cliente': cliente, 'mesa': mesa} = pedido;
  print('$cliente está na mesa $mesa');
}

$ dart run mapa.dart
Ana está na mesa 4
Cuidado com a chave que falta

Se o mapa não tiver uma das chaves do pattern, o programa compila, mas para ao rodar com Bad state: Pattern matching error (veja Quando dá errado). Para mapas que vêm de fora (um arquivo, a internet), prefira o if-case da próxima seção, que testa antes.

5. Patterns que testam: if-case e switch

Até aqui, o pattern tinha de encaixar. Mas ele também pode ser uma pergunta: "esse valor tem esse formato? Se tiver, desmonte". É o if (valor case pattern):

void main() {
  final List<Object> dados = [('Ana', 30), 'oi', ('Bia', '25'), 42];
  for (final d in dados) {
    if (d case (String nome, int idade)) {
      print('$nome tem $idade anos');
    } else {
      print('Não é (String, int): $d');
    }
  }
}

$ dart run ifcase.dart
Ana tem 30 anos
Não é (String, int): oi
Não é (String, int): (Bia, 25)
Não é (String, int): 42
if (d case (String nome, int idade))
"Se d for um record com um String e um int, desmonte em nome e idade e entre no bloco." Os tipos dentro do pattern são testes.
('Bia', '25')
Caiu no else: a idade estava entre aspas, era um String, e o pattern pedia int. Nenhum erro: o if-case só respondeu "não encaixa".

O switch leva essa ideia mais longe: vários patterns, um embaixo do outro, e vale o primeiro que encaixar. A expressão switch e o when ("quando", uma condição extra) têm aula própria em switch e Expressões switch; aqui, um exemplo com listas:

String descrever(List<int> fila) {
  return switch (fila) {
    [] => 'fila vazia',
    [final so] => 'só uma senha: $so',
    [final primeira, ...] when primeira > 100 => 'senha alta na frente: $primeira',
    [final primeira, ...final resto] => 'próxima: $primeira, depois mais ${resto.length}',
  };
}

void main() {
  print(descrever([]));
  print(descrever([7]));
  print(descrever([150, 3]));
  print(descrever([12, 13, 14]));
}

$ dart run switch.dart
fila vazia
só uma senha: 7
senha alta na frente: 150
próxima: 12, depois mais 2

Dentro de um switch ou de um if-case, a variável nova leva final (ou var) na frente: [final so]. Sem ele, o Dart entenderia so como uma constante para comparar, e não como uma variável nova.

O pattern (nome, preco) pede dois campos sem nome; o record tem dois campos com nome. Para o Dart, são formatos diferentes, mesmo que as variáveis tenham os mesmos nomes dos campos. Como consertar: ponha os dois-pontos: final (:nome, :preco) = produto;.

Testou tipos numa desestruturação comum

Os tipos dentro do pattern são testes. Numa desestruturação comum (fora do if-case e do switch), o Dart exige ter certeza de que eles passam:

  final (String nome, int idade) = dado;

Missão final: o boletim

Missão: percorra a turma com um for que desmonta cada record em nome e nota (for (final (nome, nota) in turma)). Mostre Ana: 9.0 (aprovada) para nota a partir de 7 e Bia: 5.5 (recuperação) para as outras.

void main() {
  final turma = [('Ana', 9.0), ('Bia', 5.5), ('Caio', 7.0)];
  for (final aluno in turma) {
    print(aluno);
  }
}

void main() {
  final turma = [('Ana', 9.0), ('Bia', 5.5), ('Caio', 7.0)];
  for (final (nome, nota) in turma) {
    final situacao = nota >= 7 ? 'aprovada' : 'recuperação';
    print('$nome: $nota ($situacao)');
  }
}

Resumo

  • Um pattern descreve o formato de um valor; do lado esquerdo do =, ele desmonta o valor em variáveis. Existe desde o Dart 3.0.
  • Records: (a, b), (:nome, :preco). Listas: [a, b], [a, ...resto]. Mapas: {'chave': v}. Objetos: MapEntry(:key, :value).
  • _ ignora um valor; (a, b) = (b, a) troca duas variáveis.
  • Se o formato pode não encaixar, use if (x case …) ou switch: eles testam em vez de dar erro.
  • Record de outro formato: erro de compilação. Lista de outro tamanho ou mapa sem a chave: Bad state: Pattern matching error ao rodar.
  • Próxima parte do curso: Classes, os "moldes" para criar os seus próprios tipos de objeto.
