Dart Mixins (with)

A Ana abriu a lojinha para pedidos pelo celular, e os clientes dão estrelas: para o bolo que compraram e para o entregador que levou. O código de avaliar é o mesmo nos dois casos (guardar as notas, calcular a média). Mas produto e entregador não têm parentesco: herança não serve. Interface também não resolve, porque ela só promete os métodos, e a Ana teria de escrever o código duas vezes. Para emprestar o mesmo código pronto a classes diferentes, o Dart tem o mixin, usado com a palavra with ("com").

Você vai aprender
  • O que é um mixin e como se escreve: mixin Avaliavel { … } e class Produto with Avaliavel.
  • Como uma classe usa vários mixins, e como juntar extends e with.
  • Como limitar um mixin a uma família de classes com on.
  • O que é mixin class (Dart 3) e o que acontece quando dois mixins têm o mesmo método.
  • Os erros reais: classe comum usada como mixin, tentar criar um objeto do mixin, on não cumprido e o LateInitializationError.

Todos os programas desta aula rodaram no Dart 3.13.5 da máquina da Ana (usuária ana, computador notebook), com dart run arquivo.dart.

A ideia: o carimbo

Na lojinha há um carimbo "AVALIE-NOS ★★★★★". A Ana carimba a caixa do bolo, o saquinho do pão, o recibo do entregador. O carimbo não transforma o pão em recibo, nem o recibo em pão: ele só acrescenta o mesmo desenho em coisas diferentes.

O mixin é o carimbo: um pedaço de código (campos e métodos) que se "mistura" a uma classe com with. O nome vem do inglês mix in, "misturar dentro", como as coberturas que se misturam no sorvete.

1. O primeiro mixin

mixin Avaliavel {
  final List<int> notas = [];

  void avaliar(int estrelas) {
    notas.add(estrelas);
  }

  double get media => notas.isEmpty ? 0 : notas.reduce((a, b) => a + b) / notas.length;
}

class Produto with Avaliavel {
  final String nome;

  Produto(this.nome);
}

class Entregador with Avaliavel {
  final String nome;

  Entregador(this.nome);
}

void main() {
  final bolo = Produto('Bolo de cenoura');
  bolo.avaliar(5);
  bolo.avaliar(4);

  final caio = Entregador('Caio');
  caio.avaliar(3);

  print('${bolo.nome}: ${bolo.media} estrelas (${bolo.notas.length} notas)');
  print('${caio.nome}: ${caio.media} estrelas (${caio.notas.length} nota)');
  print(bolo is Avaliavel);
}
mixin Avaliavel { … }
Declara o mixin. Por dentro parece uma classe: tem um campo (notas), um método (avaliar) e um getter (media). Mas não tem construtor: um mixin não vira objeto sozinho.
final List<int> notas = [];
Cada objeto que usa o mixin ganha a sua própria lista de notas: as do bolo não se misturam com as do Caio.
notas.reduce((a, b) => a + b) / notas.length
Soma as notas e divide pela quantidade: a média (o reduce está em map, where, reduce e Outros). Com a lista vazia, devolve 0.
class Produto with Avaliavel
"Produto, com Avaliavel". O produto ganha notas, avaliar() e media como se tivessem sido escritos dentro dele.
class Entregador with Avaliavel
Outra classe, sem parentesco, ganhando o mesmo código.
$ dart run avaliavel.dart
Bolo de cenoura: 4.5 estrelas (2 notas)
Caio: 3.0 estrelas (1 nota)
true

O código das estrelas foi escrito uma vez e funcionou nas duas classes. E o is Avaliavel deu true: o mixin também vale como tipo, então uma List<Avaliavel> aceitaria bolos e entregadores juntos.

2. Vários mixins, e junto com extends

Depois do with cabem vários mixins, separados por vírgula. E dá para combinar com herança: primeiro o extends (a mãe, uma só), depois o with (os carimbos):

mixin Avaliavel {
  final List<int> notas = [];

  void avaliar(int estrelas) => notas.add(estrelas);

  double get media => notas.isEmpty ? 0 : notas.reduce((a, b) => a + b) / notas.length;
}

mixin Registravel {
  void registrar(String mensagem) {
    print('[registro] $mensagem');
  }
}

class Produto {
  final String nome;
  final double preco;

  Produto(this.nome, this.preco);
}

class Bebida extends Produto with Avaliavel, Registravel {
  final int volumeMl;

  Bebida(super.nome, super.preco, this.volumeMl);
}

void main() {
  final suco = Bebida('Suco de laranja', 6.5, 300);
  suco.avaliar(5);
  suco.registrar('${suco.nome} recebeu nota 5');
  print('Média: ${suco.media}');
  print(suco is Produto);
  print(suco is Registravel);
}

$ dart run dois_mixins.dart
[registro] Suco de laranja recebeu nota 5
Média: 5.0
true
true

A Bebida é um Produto (herança) e, além disso, é avaliável e registrável (mixins). A ordem na declaração é sempre class X extends Mae with M1, M2 implements I1, quando houver as três.

3. Mixin só para uma família: on

Às vezes o mixin precisa usar algo da classe em que vai ser misturado. Um mixin de estoque quer saber o nome e o preco do produto. Com on Produto ("sobre Produto"), ele avisa: "só posso ser usado em classes que são Produto", e em troca pode usar tudo o que o produto tem:

class Produto {
  final String nome;
  final double preco;

  Produto(this.nome, this.preco);
}

mixin ComEstoque on Produto {
  int quantidade = 0;

  void repor(int qtd) {
    quantidade += qtd;
    print('$nome: +$qtd (estoque: $quantidade)');
  }

  double get valorEmEstoque => preco * quantidade;
}

class Doce extends Produto with ComEstoque {
  Doce(super.nome, super.preco);
}

void main() {
  final brigadeiro = Doce('Brigadeiro', 3.0);
  brigadeiro.repor(20);
  brigadeiro.repor(10);
  print('Valor em estoque: R\$ ${brigadeiro.valorEmEstoque.toStringAsFixed(2)}');
}

$ dart run on.dart
Brigadeiro: +20 (estoque: 20)
Brigadeiro: +10 (estoque: 30)
Valor em estoque: R$ 90.00

Dentro do mixin, $nome e preco funcionaram porque o on Produto garante que eles existem. Sem o on, o Dart reclama (testado no lab): Error: The getter 'nome' isn't defined for the type 'ComEstoque'., e o mesmo para preco. Usar esse mixin numa classe que não é produto dá erro (veja Quando dá errado).

4. Dois mixins com o mesmo método: vale o último

mixin Educado {
  String saudar() => 'Bom dia!';
}

mixin Animado {
  String saudar() => 'Ôpa, bom dia!!!';
}

class AtendenteA with Educado, Animado {}

class AtendenteB with Animado, Educado {}

void main() {
  print(AtendenteA().saudar());
  print(AtendenteB().saudar());
}

$ dart run ordem.dart
Ôpa, bom dia!!!
Bom dia!

Os mixins são aplicados em camadas, da esquerda para a direita, e cada camada fica por cima da anterior. No AtendenteA, o Animado veio por último e venceu; no AtendenteB, o Educado. Não há erro, então convém evitar nomes repetidos entre mixins, ou ficar atento à ordem.

5. mixin class: classe e mixin ao mesmo tempo Dart 3.0

Desde o Dart 3.0, uma class comum não pode ser usada depois do with (antes podia). Se você quer algo que funcione das duas formas, declare mixin class:

mixin class Registrador {
  void registrar(String mensagem) => print('[registro] $mensagem');
}

class Caixa with Registrador {}

void main() {
  final r = Registrador();
  r.registrar('usado como classe');
  Caixa().registrar('usado como mixin');
}

$ dart run mixin_class.dart
[registro] usado como classe
[registro] usado como mixin

Como classe, deu para criar Registrador(); como mixin, entrou no with da Caixa. Uma mixin class não pode ter extends nem on. A aula sealed, final, base e interface mostra os outros modificadores que o Dart 3 trouxe.

Quando dá errado

Usou uma classe comum depois do with 
class Registrador {
  void registrar(String mensagem) => print('[registro] $mensagem');
}

class Caixa with Registrador {}

void main() {
  Caixa().registrar('abriu o caixa');
}

$ dart run erro_classe.dart
erro_classe.dart:5:18: Error: The class 'Registrador' can't be used as a mixin because it isn't a mixin class nor a mixin.
class Caixa with Registrador {}
                 ^

Linha por linha: erro de compilação (Error:, código 254) na linha 5, coluna 18, onde está o nome depois do with. "A classe Registrador não pode ser usada como mixin porque não é nem uma mixin class nem um mixin." É a regra do Dart 3 (seção 5); muitos exemplos antigos da internet, de antes do Dart 3, fazem isso e hoje não compilam. Como consertar: troque class Registrador por mixin Registrador (se ninguém cria objetos dele) ou por mixin class Registrador.

Tentou criar um objeto do mixin 
mixin Avaliavel {
  final List<int> notas = [];
}

void main() {
  final a = Avaliavel();
  print(a.notas);
}

$ dart run erro_instanciar.dart
erro_instanciar.dart:6:13: Error: Couldn't find constructor 'Avaliavel'.
  final a = Avaliavel();
            ^^^^^^^^^

"Não encontrei o construtor Avaliavel." Um mixin não tem construtor: ele é o carimbo, não a coisa carimbada. Como consertar: crie uma classe com o mixin (class Produto with Avaliavel) e crie um objeto dela.

Usou um mixin on Produto numa classe que não é produto

Dois erros para a mesma linha 12. O primeiro parece estranho ("faltou Produto.preco"): como o mixin exige um Produto, o Dart passou a cobrar do Cliente tudo o que um produto tem, e o nome ele já tinha. Como consertar: o cliente não é produto, então não use esse mixin nele.

Um campo late do mixin que ninguém preencheu (exceção durante a execução) 
mixin Registravel {
  late String origem;

  void registrar(String mensagem) {
    print('[$origem] $mensagem');
  }
}

class Caixa with Registravel {
  Caixa() {
    origem = 'caixa';
  }
}

class Estoque with Registravel {}

void main() {
  Caixa().registrar('abriu às 7h');
  Estoque().registrar('chegaram 20 brigadeiros');
}

#0      Registravel.origem (file:///home/ana/erro_late.dart)
#1      Registravel.registrar (file:///home/ana/erro_late.dart:5:14)

Como o mixin não tem construtor, é comum ele declarar um campo late ("tardio": "prometo preencher antes de usar"; veja late e o Operador !) e deixar a classe preencher. A Caixa preencheu no construtor e funcionou. O Estoque esqueceu:

  • LateInitializationError: Field 'origem' has not been initialized.: "o campo origem não foi inicializado". A promessa do late foi quebrada. Código de saída 255.
  • #0 Registravel.origem, sem número de linha: é a leitura do campo, feita por um código que o próprio Dart gera.
  • #1 Registravel.registrar, linha 5: onde o campo foi lido (o print). #2 main, linha 19: quem chamou, o Estoque().registrar(…).

Como consertar: preencha o campo em toda classe que usa o mixin, ou troque o campo por um getter abstrato (String get origem;): aí esquecer vira erro de compilação, como em Classes Abstratas, que é muito melhor do que descobrir rodando.

Missão final: o caderno de registro

Missão: a Caixa e o Estoque já usam with Registravel, mas o mixin não existe. Escreva o mixin Registravel com um método registrar(String mensagem) que mostra [registro] seguido da mensagem.

// escreva o mixin Registravel aqui

class Caixa with Registravel {
  void abrir() => registrar('Caixa aberto');
}

class Estoque with Registravel {
  void receber(int qtd, String item) => registrar('Chegaram $qtd $item');
}

void main() {
  Caixa().abrir();
  Estoque().receber(20, 'brigadeiros');
}

  void registrar(String mensagem) {
    print('[registro] $mensagem');
  }
}

  void abrir() => registrar('Caixa aberto');
}

Resumo

  • Um mixin é um pedaço de código pronto (campos, métodos, getters) que se mistura em classes com with; ele não tem construtor nem vira objeto.
  • Uma classe pode usar vários mixins (with A, B) e combinar com herança: extends Mae with A, B. Se dois mixins têm o mesmo método, vale o último da lista.
  • mixin M on Produto limita o mixin a produtos e deixa usar os membros deles.
  • No Dart 3, só mixin e mixin class podem ir depois do with; uma class comum dá erro de compilação.
  • Campo late num mixin é uma promessa que a classe tem de cumprir; se esquecer, LateInitializationError durante a execução. Um getter abstrato transforma esse esquecimento em erro de compilação.
