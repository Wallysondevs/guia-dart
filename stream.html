Dart Stream

Um Future entrega um valor, uma vez, no futuro. Mas muita coisa chega aos poucos: as linhas de um arquivo grande, as mensagens de um chat, os cliques num botão, as leituras de um sensor a cada segundo. Para isso o Dart tem o Stream (em inglês, "fluxo", "correnteza"): uma sequência de valores que vão chegando ao longo do tempo, até o fluxo acabar.

Você vai aprender
  • A diferença entre Future<T> (um valor) e Stream<T> (vários valores).
  • Como percorrer um Stream com await for, e como reagir a cada valor com listen.
  • Como criar Streams prontos: Stream.periodic e Stream.fromIterable.
  • Como filtrar e transformar: where, map, take, reduce, toList.
  • Como fabricar o seu Stream com StreamController (add, addError, close) e tratar erros.
  • Os erros reais: Stream has already been listened to, await for sem async, e o close esquecido.

Todos os programas desta aula rodaram no Dart SDK 3.13.5 da máquina da Ana (usuária ana, computador notebook), com dart run arquivo.dart.

A ideia: a esteira da padaria

Na padaria industrial do bairro, os pães saem do forno numa esteira. A funcionária da embalagem não sabe quantos pães vêm hoje; ela fica na ponta da esteira e embala cada pão quando ele chega. No fim do turno, a esteira para, e ela vai embora. Às vezes cai uma bandeja: é um problema no meio do fluxo.

  • A esteira é o Stream; cada pão é um evento (um valor).
  • Embalar cada pão que chega é o await for ou o listen ("escutar").
  • A esteira parar é o fim do Stream (o done, "pronto").
  • A bandeja caída é um erro no meio do Stream.
Um valorVários valores
Agora (síncrono)int, String…List<T>, Iterable<T>
Depois (assíncrono)Future<T>Stream<T>

Um Stream é, de certa forma, uma "lista que vai chegando". Por isso muitos métodos são os mesmos das listas (where, map…).

1. O primeiro Stream: await for

Future<void> main() async {
  final fornadas = Stream.periodic(
    Duration(seconds: 1),
    (i) => 'fornada ${i + 1}',
  ).take(3);

  print('Esperando as fornadas...');
  await for (final f in fornadas) {
    print('Saiu a $f');
  }
  print('Forno desligado');
}
Stream.periodic(Duration(seconds: 1), (i) => …)
"Periódico": um Stream que solta um valor a cada 1 segundo, para sempre. A função recebe a contagem i (0, 1, 2…) e devolve o valor do evento.
.take(3)
"Pegue 3": um novo Stream que termina depois dos 3 primeiros valores. Sem ele, as fornadas não parariam nunca.
await for (final f in fornadas)
Um for-in com await na frente: espera cada valor chegar, roda o bloco com ele, e espera o próximo. Só sai do laço quando o Stream termina. Como todo await, exige uma função async.
print('Forno desligado')
Roda só depois que o Stream acabou.

O Stream.fromIterable([…]) transforma uma lista num Stream: cada item vira um evento. É ótimo para testar. No lab, a solução mostrou Total do dia: 57.

2. listen: reagir a cada valor

O outro jeito de usar um Stream é registrar uma função que o Dart chama a cada valor, sem pausar a função atual. É o listen ("escutar"), primo do then dos Futures:

void main() {
  final pedidos = Stream.fromIterable(['pão', 'bolo', 'broa']);
  pedidos.listen(
    (p) => print('Pedido: $p'),
    onDone: () => print('Sem mais pedidos'),
  );
  print('listen registrado');
}

A função é chamada uma vez para cada valor do Stream.

Um parâmetro nomeado opcional: roda quando o Stream termina.

Mesmo com a lista pronta, os eventos de um Stream só chegam depois que o código normal termina, como os Futures (veja a ordem em Future). O main nem é async: o listen não espera nada.

3. Filtrar e transformar

Os métodos de Stream criam novos Streams, como os de lista criam novos iteráveis (veja map, where, reduce). Os que juntam tudo num valor só devolvem um Future:

Future<void> main() async {
  final precos = Stream.fromIterable([4, 12, 7, 30, 2]);
  final caros = precos.where((p) => p >= 7).map((p) => 'R\$ $p');
  await for (final c in caros) {
    print(c);
  }
  final total = await Stream.fromIterable([4, 12, 7]).reduce((a, b) => a + b);
  print('Total: $total');
  final lista = await Stream.fromIterable(['a', 'b']).toList();
  print(lista);
  print(Stream.fromIterable([1, 2]));
}

4. O seu Stream: StreamController

Para fabricar um Stream e decidir quando cada valor entra, use um StreamController ("controlador do fluxo"), da biblioteca dart:async. Ele tem a entrada (add, addError, close) e a saída (.stream):

import 'dart:async';

Future<void> main() async {
  final esteira = StreamController<String>();

  esteira.add('pão');
  esteira.add('bolo');
  esteira.addError(StateError('bandeja caiu'));
  esteira.add('broa');
  esteira.close();

  try {
    await for (final item in esteira.stream) {
      print('Embalando $item');
    }
  } on StateError catch (e) {
    print('Parou: ${e.message}');
  }
  print('Fim');
}

Uma esteira de textos.

Desliga a esteira: avisa que não vem mais nada. É o que faz o await for terminar (veja Quando dá errado).
await for … dentro de try
Quando o erro chega, o await for o lança, e o laço acaba ali. A broa, que vinha depois do erro, nunca foi embalada.

Com o listen, o erro vai para o onError, e o Stream continua:

import 'dart:async';

void main() {
  final esteira = StreamController<String>();
  esteira.stream.listen(
    (item) => print('Embalando $item'),
    onError: (e) => print('Problema: $e'),
    onDone: () => print('Esteira parada'),
  );
  esteira.add('pão');
  esteira.addError(StateError('bandeja caiu'));
  esteira.add('broa');
  esteira.close();
}

$ dart run s5.dart
Embalando pão
Problema: Bad state: bandeja caiu
Embalando broa
Esteira parada

Aqui a broa foi embalada: o onError tratou a bandeja caída e a esteira seguiu até o close (Esteira parada).

Missão final: só as aprovadas

Missão: as notas da turma chegam num Stream, e o programa mostra todas como "aprovadas". Crie um Stream só com as notas maiores ou iguais a 7, com where: final aprovadas = notas.where((n) => n >= 7);, e percorra o aprovadas no lugar do notas.

Future<void> main() async {
  final notas = Stream.fromIterable([8, 4, 10, 6, 9]);
  await for (final n in notas) {
    print('Aprovada: $n');
  }
  print('Fim');
}

Future<void> main() async {
  final notas = Stream.fromIterable([8, 4, 10, 6, 9]);
  final aprovadas = notas.where((n) => n >= 7);
  await for (final n in aprovadas) {
    print('Aprovada: $n');
  }
  print('Fim');
}

No lab, a solução mostrou Aprovada: 8, Aprovada: 10, Aprovada: 9 e Fim.

Resumo

  • Um Stream<T> é uma esteira: vários valores chegando ao longo do tempo, até o fim (ou um erro no meio).
  • await for percorre o Stream esperando cada valor (precisa de async); listen reage a cada valor sem pausar nada, com onError e onDone.
  • where, map e take criam novos Streams; toList e reduce devolvem um Future.
  • StreamController fabrica um Stream: add, addError e, sempre, close. Sem o close, o await for nunca termina, e o resto da função não roda.
  • O Stream de um StreamController comum aceita um ouvinte só; para vários, .broadcast().
