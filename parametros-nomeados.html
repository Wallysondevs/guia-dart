Dart Parâmetros Nomeados e required

Na aula Parâmetros Posicionais, a Ana trocou sem querer a ordem de comDesconto(10, 200) e o preço ficou negativo, sem erro nenhum. Os parâmetros nomeados resolvem isso: na chamada, cada valor vai junto com o nome do parâmetro, comDesconto(preco: 200, porcentagem: 10). Fica impossível confundir, e quem lê o código entende cada número sem abrir a declaração. É o estilo que você vai ver o tempo todo no Flutter.

Você vai aprender
  • Declarar parâmetros nomeados com chaves { } e chamar com nome: valor.
  • Que a ordem dos argumentos nomeados não importa.
  • O required ("obrigatório"), e por que o Dart exige que você escolha entre required, um tipo anulável ou um valor padrão.
  • Nomeados que podem faltar (String? observacao).
  • Misturar posicionais e nomeados na mesma função.
  • Os erros reais: falta do required, parâmetro obrigatório esquecido, nome errado, chamada sem os nomes, = no lugar de :.

Todos os programas desta aula rodaram no Dart 3.13.5 da máquina da Ana (ana@notebook), com dart run arquivo.dart.

A ideia: o formulário com rótulos

Um formulário só com linhas em branco ("____, ____, ____") obriga você a lembrar o que vai em cada linha. Um formulário com rótulos ("Preço: ____ · Desconto: ____") deixa claro onde escrever cada coisa, e tanto faz se você preenche o desconto antes do preço. Os parâmetros nomeados são o formulário com rótulos.

1. A primeira função com parâmetros nomeados

double comDesconto({required double preco, required double porcentagem}) {
  return preco - preco * porcentagem / 100;
}

void main() {
  print(comDesconto(preco: 200, porcentagem: 10));
  print(comDesconto(porcentagem: 10, preco: 200));
}
{ … }
As chaves dentro dos parênteses dizem: "estes parâmetros são nomeados". Tudo o que está entre elas é chamado pelo nome.
required
"Obrigatório": quem chamar tem de passar este valor. Sem o required, um parâmetro nomeado é opcional (seção 3).
double preco
O tipo e o nome, como num parâmetro posicional.
preco: 200
Na chamada: o nome do parâmetro, dois-pontos e o valor. Lê-se "preço: 200".
comDesconto(porcentagem: 10, preco: 200)
A mesma chamada com a ordem invertida. Como cada valor diz a que parâmetro pertence, o resultado é o mesmo.
$ dart run desconto.dart
180.0
180.0

As duas linhas deram 180.0: a troca de ordem que antes dava -10.0 agora não faz diferença nenhuma.

2. Muitos parâmetros, uma por linha

Os nomeados brilham quando a função recebe muita coisa. O pedido da padaria:

void registrarPedido({
  required String cliente,
  required String produto,
  required int quantidade,
  String? observacao,
}) {
  print('$cliente: $quantidade x $produto');
  if (observacao != null) {
    print('  Obs.: $observacao');
  }
}

void main() {
  registrarPedido(cliente: 'Ana', produto: 'pão francês', quantidade: 10);
  registrarPedido(
    cliente: 'seu Zé',
    produto: 'bolo de fubá',
    quantidade: 1,
    observacao: 'sem cobertura',
  );
}

$ dart run pedido.dart
Ana: 10 x pão francês
seu Zé: 1 x bolo de fubá
  Obs.: sem cobertura
  • Um parâmetro por linha, na declaração e na chamada longa: fica fácil de ler e de acrescentar mais um.
  • A vírgula depois do último (observacao, e 'sem cobertura',) é permitida e recomendada: o dart format (veja Análise e Formatação) entende essa vírgula como "quero um por linha" e mantém o formato.
  • String? observacao não tem required: é opcional. O primeiro pedido não passou observação, e ela ficou null.

Compare com a versão posicional: registrarPedido('Ana', 'pão francês', 10, null). Qual é o cliente, qual é o produto? Só abrindo a função para saber.

3. required, anulável ou valor padrão: o Dart quer que você escolha

Um parâmetro nomeado pode ficar de fora da chamada. Mas, se ficar de fora, que valor ele tem? Sem mais informação, seria null, e um double comum não pode ser null. Veja o que o Dart diz quando a Ana esquece o required:

double comDesconto({double preco, double porcentagem}) {
  return preco - preco * porcentagem / 100;
}

void main() {
  print(comDesconto(preco: 200, porcentagem: 10));
}

double comDesconto({double preco, double porcentagem}) {

The parameter 'preco' can't have a value of 'null' because of its type 'double'…
"O parâmetro preco não pode valer null, por causa do tipo double…"

"…mas o valor padrão implícito é null": se ninguém passar o preço, ele valeria null. Contradição.

4. Misturando posicionais e nomeados

Uma função pode ter os dois: primeiro os posicionais, depois as chaves com os nomeados. É comum deixar o valor "principal" como posicional e os detalhes como nomeados:

void etiqueta(String produto, {required double preco, int? estoque}) {
  final textoEstoque = estoque == null ? 'sem controle' : '$estoque no estoque';
  print('$produto | R\$ ${preco.toStringAsFixed(2)} | $textoEstoque');
}

void main() {
  etiqueta('Leite', preco: 5.49, estoque: 30);
  etiqueta('Pão de queijo', preco: 1.20);
  etiqueta(preco: 4.0, 'Café');
}

$ dart run misto.dart
Leite | R$ 5.49 | 30 no estoque
Pão de queijo | R$ 1.20 | sem controle
Café | R$ 4.00 | sem controle
String produto
Posicional, fora das chaves: sempre o primeiro argumento sem nome.
{required double preco, int? estoque}
Nomeados: o preço é obrigatório; o estoque pode faltar (fica null).
estoque == null ? … : …
O operador ternário escolhe o texto (veja O Operador Ternário).
etiqueta(preco: 4.0, 'Café')
Na chamada, os nomeados podem vir até antes do posicional. Dart 2.17 O posicional continua sendo reconhecido pela posição entre os sem nome.
Você vai ver muito isso no Flutter

No Flutter, quase tudo se monta com parâmetros nomeados, um por linha, com a vírgula no fim. O trecho abaixo é ilustrativo (não há Flutter no lab; veja Dart e Flutter), só para você reconhecer o formato: Text('Olá', style: TextStyle(fontSize: 20, color: Colors.blue)). O texto é posicional; style, fontSize e color são nomeados.

Quem vem do Python escreve preco=200. No Dart, preco = 200 é uma atribuição ("guarde 200 na variável preco"), e não existe variável preco no main: daí o Setter not found ("não achei onde guardar preco"). Resumo

  • Parâmetros entre chaves, f({…}), são nomeados: a chamada diz o nome de cada valor, f(preco: 200), em qualquer ordem.
  • Um nomeado é opcional, a não ser que tenha required. Por isso o Dart exige uma escolha: required, tipo anulável (int?) ou valor padrão (= 0).
  • Nomeados evitam a troca silenciosa de argumentos do mesmo tipo e deixam a chamada legível.
  • Dá para misturar: posicionais primeiro, nomeados nas chaves depois.
  • Na chamada, nome e valor se separam com :, nunca com =.
