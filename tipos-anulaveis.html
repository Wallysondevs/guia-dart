Dart Tipos Anuláveis

Na aula Null Safety, você viu a regra: um tipo sem ? nunca é null; um tipo com ? pode ser. Esta aula é sobre os tipos com ?, os anuláveis (nullable): como criar, como passar de um lado para o outro, como usar sem o Dart reclamar, e o que cada mensagem de erro está dizendo.

Você vai aprender
  • Como declarar String?, int?, double?, bool?, e quanto eles valem quando nascem sem valor.
  • Por que um String cabe num String?, mas o contrário não.
  • A promoção de tipo: != null, is e o "sai cedo" com == null e return.
  • Funções que devolvem String? e parâmetros que aceitam null.
  • A diferença entre List<String?> e List<String>?.
  • Os erros reais: método e operador num anulável, argumento anulável e a promoção que se perde.

Todos os programas desta aula rodaram no Dart 3.13.5 da máquina da Ana (usuária ana, computador notebook), com dart run arquivo.dart.

A ideia: o campo "opcional" da ficha

Na ficha de cadastro da lojinha, alguns campos têm asterisco (obrigatórios: nome, CPF) e outros dizem "opcional" (apelido, telefone fixo). Quem lê a ficha sabe: o nome sempre vai estar lá; o apelido, talvez. Antes de chamar a cliente pelo apelido, você olha se o campo foi preenchido.

No Dart, o ? no fim do tipo é o "opcional" da ficha. String nome é o campo obrigatório. String? apelido é o opcional: o Dart vai exigir que você olhe antes de usar.

1. Declarando tipos anuláveis

void main() {
  String? apelido;
  int? mesa;
  double? gorjeta;
  bool? confirmado;
  print(apelido);
  print(mesa);
  print(gorjeta);
  print(confirmado);
  mesa = 7;
  print(mesa);
}

$ dart run declarar.dart
null
null
null
null
7
String? apelido;
Qualquer tipo ganha a versão anulável com um ? colado no fim. Sem valor inicial, uma variável anulável começa valendo null, sem erro nenhum.
int? mesa; double? gorjeta; bool? confirmado;
O mesmo para números e bool. Um bool? tem três respostas possíveis: true, false e null ("ainda não respondeu").
mesa = 7;
Depois, a gaveta pode receber um valor de verdade.

Compare com a aula anterior: String nome; (sem ?) usada sem valor era erro de compilação (Non-nullable variable 'nome' must be assigned before it can be used.). Com ?, o "nada" é um valor permitido, e o Dart o usa como valor inicial.

2. String cabe em String?; o contrário, não

void main() {
  String nome = 'Ana';
  String? apelido = nome;
  print(apelido);
  String? recado;
  String texto = recado;
  print(texto);
}

$ dart run atribuir.dart
atribuir.dart:6:18: Error: A value of type 'String?' can't be assigned to a variable of type 'String'.
  String texto = recado;
                 ^

A linha 3 passou sem problema: um texto que com certeza existe pode ir para uma gaveta "texto ou nada". A linha 6, não: "um valor do tipo String? não pode ser atribuído a uma variável do tipo String". O recado talvez esteja vazio, e a gaveta texto não aceita vazio.

3. Usando um anulável: a promoção de tipo

Num String?, o Dart não deixa chamar length, toUpperCase() nem nada de texto (a seção Quando dá errado mostra as mensagens). O jeito é conferir primeiro. Depois da conferência, o Dart trata a variável como String: é a promoção de tipo.

Com != null ou is

void main() {
  String? apelido = 'Aninha';
  if (apelido != null) {
    print('${apelido.toUpperCase()} tem ${apelido.length} letras');
  }
  if (apelido is String) {
    print('Também funciona com is');
  }
}

$ dart run promover.dart
ANINHA tem 6 letras
Também funciona com is

Dentro de cada if, apelido é um String comum. O != null é o jeito mais usado; o is String faz o mesmo trabalho (veja is, is! e as).

"Sai cedo": == null e return

Muitas vezes é mais limpo tratar o caso do null primeiro e sair da função. Daí para baixo, o Dart sabe que a variável tem valor:

void mostrarMesa(int? mesa) {
  if (mesa == null) {
    print('Pedido para viagem');
    return;
  }
  print('Mesa $mesa (a do lado é a ${mesa + 1})');
}

void main() {
  mostrarMesa(7);
  mostrarMesa(null);
}

$ dart run cedo.dart
Mesa 7 (a do lado é a 8)
Pedido para viagem
void mostrarMesa(int? mesa)
Uma função (um bloco de código com nome, que você chama de vários lugares; veja Funções) cujo parâmetro é int?: ela aceita um número ou null.
if (mesa == null) { …; return; }
Se não tem mesa, avisa e sai da função com return ("retornar").
mesa + 1
Depois do if, o único jeito de chegar aqui é mesa não ser null. O Dart percebe isso sozinho e libera a conta.

Missão: o int.tryParse devolve int?, e o Dart não deixa fazer conta com ele. Ponha o print dentro de um if (quantidade != null) para mostrar Total: 6 pães.

void main() {
  int? quantidade = int.tryParse('3');
  print('Total: ${quantidade * 2} pães');
}

void main() {
  int? quantidade = int.tryParse('3');
  if (quantidade != null) {
    print('Total: ${quantidade * 2} pães');
  }
}

4. Funções que podem não ter resposta

Uma função também pode devolver um tipo anulável. É o jeito honesto de dizer "talvez eu não ache":

String? buscarApelido(String nome) {
  if (nome == 'Ana') {
    return 'Aninha';
  }
  return null;
}

void main() {
  String? a = buscarApelido('Ana');
  String? b = buscarApelido('Bia');
  print(a);
  print(b);
}

$ dart run funcao.dart
Aninha
null

O String? antes do nome da função é o tipo do resultado: quem chama já sabe, só de olhar, que precisa tratar o null. É exatamente o que int.tryParse faz. Se a função dissesse só String, o return null; seria erro de compilação.

5. Listas: onde fica o ?

Com listas, a posição do ? muda tudo:

void main() {
  List<String?> apelidos = ['Aninha', null, 'Bia'];
  List<String>? pedidos;
  print(apelidos);
  print(apelidos.length);
  print(pedidos);
  pedidos = ['pão', 'café'];
  print(pedidos);
}

$ dart run listas.dart
[Aninha, null, Bia]
3
null
[pão, café]
TipoLê-seExemplo
List<String>Uma lista (que existe) de textos (que existem)['pão', 'café']
List<String?>Uma lista que existe; cada item pode ser null['Aninha', null, 'Bia']: 3 itens, um vazio
List<String>?A lista inteira pode não existir; se existir, os itens são textosnull, ou ['pão', 'café']

Para usar os itens de uma List<String?>, confira cada um:

void main() {
  List<String?> apelidos = ['Aninha', null, 'Bia'];
  for (var a in apelidos) {
    if (a != null) {
      print(a.toUpperCase());
    } else {
      print('(sem apelido)');
    }
  }
}

$ dart run lista_ok.dart
ANINHA
(sem apelido)
BIA

Formas diferentes de usar um anulável

O mesmo trabalho (mostrar o apelido em maiúsculas, ou um aviso) de quatro jeitos. Os dois últimos são das próximas aulas:

if (apelido != null) {                       // 1. conferir
  print(apelido.toUpperCase());
} else {
  print('sem apelido');
}

if (apelido == null) return;                  // 2. sair cedo (dentro de uma função)
print(apelido.toUpperCase());

print(apelido?.toUpperCase() ?? 'sem apelido');   // 3. ?. e ??

print(apelido!.toUpperCase());                // 4. ! (quebra se for null)
SituaçãoQual usar
Fazer várias coisas quando o valor existeif (x != null) { … }
Numa função, o null é o caso "estranho"if (x == null) return; no começo
Uma expressão curta, com valor padrãox?.metodo() ?? padrao (aula ?. , ?? e ??=)
Você tem certeza de que não é null e o Dart não percebex! (aula late e o Operador !)
O valor nunca faltaNem use ?: tipo comum

Quando dá errado

Chamou um método num String? 
void main() {
  List<String?> apelidos = ['Aninha', null, 'Bia'];
  for (var a in apelidos) {
    print(a.toUpperCase());
  }
}

because it is potentially null.
"…porque ele é potencialmente null" (pode ser). O item do meio da lista é mesmo null, mas o Dart reclamaria mesmo se nenhum fosse: ele olha o tipo.

"Tente chamar com ?.." Funciona, mas mostraria null no item vazio.

Como consertar: confira cada item com if (a != null), como na seção 5. Com uma propriedade, a mensagem troca Method … cannot be called por Property 'length' cannot be accessed.

Fez conta com um int? 
void main() {
  int? quantidade = int.tryParse('3');
  print(quantidade + 1);
}

$ dart run err_conta.dart
err_conta.dart:3:20: Error: Operator '+' cannot be called on 'int?' because it is potentially null.
  print(quantidade + 1);
                   ^

"O operador + não pode ser usado num int?, porque ele pode ser null." Quanto é "nada + 1"? Não existe resposta. Como consertar: if (quantidade != null), ou um valor padrão: (quantidade ?? 0) + 1.

Mandou um String? para uma função que pede String 
void saudar(String nome) {
  print('Olá, $nome!');
}

void main() {
  String? recado;
  saudar(recado);
}

$ dart run err_param.dart
err_param.dart:7:10: Error: The argument type 'String?' can't be assigned to the parameter type 'String'.
  saudar(recado);
         ^

"O tipo do argumento, String?, não pode ser atribuído ao tipo do parâmetro, String." É a regra da seção 2 de novo: "talvez texto" não entra onde se exige texto. Como consertar: confira antes de chamar (if (recado != null) saudar(recado);), mande um padrão (saudar(recado ?? 'cliente')), ou, se a função sabe lidar com o "nada", mude o parâmetro para String? nome.

A promoção se perdeu depois de uma nova atribuição 
String? lerApelido() => null;

void main() {
  String? apelido = 'Aninha';
  if (apelido != null) {
    apelido = lerApelido();
    print(apelido.length);
  }
}

$ dart run err_perde.dart
err_perde.dart:7:19: Error: Property 'length' cannot be accessed on 'String?' because it is potentially null.
Try accessing using ?. instead.
    print(apelido.length);
                  ^^^^^^
err_perde.dart:6:5: Context: Variable 'apelido' could not be promoted due to an assignment.
Try null checking the variable after the assignment.  See http://dart.dev/go/non-promo-write
    apelido = lerApelido();
    ^

Este é traiçoeiro: o if (apelido != null) está lá! Mas, na linha 6, a variável recebeu um valor novo, que pode ser null, e a conferência deixou de valer. A segunda mensagem, Context: ("contexto"), explica: "a variável apelido não pôde ser promovida por causa de uma atribuição. Tente conferir o null depois da atribuição". (O => null da linha 1 é uma função de uma linha que devolve null: veja Funções de Uma Linha.) Como consertar: confira depois de atribuir: apelido = lerApelido(); if (apelido != null) { … }.

Guardou um anulável num tipo comum

Seção 2: A value of type 'String?' can't be assigned to a variable of type 'String'. Como consertar: declare a variável como String?, confira antes, ou use ?? padrao.

Missão: buscarTelefone devolve String? (a Bia não tem telefone), e o programa não compila. Na função mostrar, trate o null primeiro: se telefone == null, mostre NOME: sem telefone e saia com return. A saída deve ser Ana: 10 caracteres e Bia: sem telefone.

String? buscarTelefone(String nome) {
  if (nome == 'Ana') {
    return '99999-1234';
  }
  return null;
}

void mostrar(String nome) {
  String? telefone = buscarTelefone(nome);
  print('$nome: ${telefone.length} caracteres');
}

void main() {
  mostrar('Ana');
  mostrar('Bia');
}

String? buscarTelefone(String nome) {
  if (nome == 'Ana') {
    return '99999-1234';
  }
  return null;
}

void mostrar(String nome) {
  String? telefone = buscarTelefone(nome);
  if (telefone == null) {
    print('$nome: sem telefone');
    return;
  }
  print('$nome: ${telefone.length} caracteres');
}

void main() {
  mostrar('Ana');
  mostrar('Bia');
}

Resumo

  • Um ? no fim do tipo o torna anulável: String?, int?, bool?, List<String>?. Sem valor inicial, ele vale null.
  • Um valor comum cabe numa variável anulável; um anulável não cabe numa comum sem conferência.
  • Métodos, propriedades e operadores não funcionam direto num anulável: o Dart diz because it is potentially null.
  • Confira com != null, is ou == null + return: depois disso, a variável é promovida ao tipo comum. Uma nova atribuição desfaz a promoção.
  • Funções podem devolver e receber anuláveis; em listas, o lugar do ? decide se é o item ou a lista que pode faltar.
