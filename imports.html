Dart import, export e Bibliotecas

Você já escreveu import 'dart:io'; e import 'package:intl/intl.dart'; várias vezes. Nesta aula, o import ("importar", trazer de fora) ganha explicação completa: de onde ele traz as coisas, como trazer só uma parte, como resolver dois arquivos com o mesmo nome de função, o que fica escondido com _, e como o export junta vários arquivos num só.

Você vai aprender
  • Que cada arquivo .dart é uma biblioteca.
  • Os três tipos de import: dart:, package: e o caminho de um arquivo.
  • Como dar um apelido com as e como trazer só algumas coisas com show ou deixar algumas de fora com hide.
  • Por que um nome que começa com _ não sai do arquivo.
  • Como o export junta vários arquivos numa porta de entrada só.
  • Os erros reais: nome importado de dois lugares, o show que esconde, o _ privado, o arquivo que não existe e o import fora do lugar.

Todos os programas desta aula rodaram no Dart 3.13.5 da máquina da Ana (usuária ana, computador notebook), numa pasta loja com vários arquivos .dart lado a lado, com dart run arquivo.dart.

A ideia: as gavetas da loja

A lojinha da Ana tem um armário com gavetas etiquetadas: "preços", "estoque", "dinheiro". Quando ela precisa calcular um troco, abre a gaveta "dinheiro" e pega a calculadora. Ela não despeja todas as gavetas no balcão.

  • Cada arquivo .dart é uma gaveta. No Dart, o nome técnico é biblioteca (library).
  • import é abrir uma gaveta e pôr o conteúdo dela ao seu alcance.
  • Algumas coisas ficam no fundo da gaveta, só para uso interno: são os nomes com _.
  • export é a etiqueta "kit": uma gaveta que, ao ser aberta, entrega o conteúdo de outras.

1. Importando um arquivo seu

O arquivo precos.dart tem as contas da loja:

const taxaEntrega = 5.0;

double comEntrega(double valor) => valor + taxaEntrega;

double _arredondar(double valor) => (valor * 100).round() / 100;

double comDesconto(double valor, double porcento) =>
    _arredondar(valor * (1 - porcento / 100));

O main.dart, na mesma pasta, usa essas contas:

import 'precos.dart';

void main() {
  print('Pedido de R\$ 30 com entrega: R\$ ${comEntrega(30)}');
  print('Bolo de R\$ 58.90 com 10% de desconto: R\$ ${comDesconto(58.90, 10)}');
}

$ dart run main.dart
Pedido de R$ 30 com entrega: R$ 35.0
Bolo de R$ 58.90 com 10% de desconto: R$ 53.01
import 'precos.dart';
Um caminho relativo: "o arquivo precos.dart que está na mesma pasta que este". Para um arquivo numa subpasta: import 'contas/precos.dart';.
comEntrega(30), comDesconto(…)
As funções de precos.dart são usadas como se fossem deste arquivo. A constante taxaEntrega também veio.
_arredondar
Usada dentro de precos.dart (pelo comDesconto), mas o main.dart não pode chamá-la: o _ a deixa privada (seção 4).

Os três tipos de import

Começa comDe onde vemExemplo
dart:as bibliotecas que vêm com o Dartimport 'dart:math';
package:um pacote do pub.dev (aula Pacotes) ou a pasta lib/ do seu projeto (aula dart create)import 'package:intl/intl.dart';
nada dissoum arquivo, pelo caminho a partir desteimport 'precos.dart';

A biblioteca dart:core (com print, String, List…) é a única importada sozinha, em todo arquivo.

Ordem dos imports (Effective Dart)

Os import vêm sempre no topo do arquivo, antes de qualquer código. O estilo recomendado põe primeiro os dart:, depois os package:, depois os relativos, cada grupo em ordem alfabética e separado por uma linha em branco. As regras que o dart create liga não conferem essa ordem (no lab, um package: antes de um dart: deu No issues found! no dart analyze); para o dart analyze cobrar, ligue a regra directives_ordering no analysis_options.yaml (veja Análise e Formatação).

2. Apelido: as

Com as, tudo o que vem da biblioteca passa a ser usado com um prefixo, como um sobrenome. Fica claro, no meio do código, de onde veio cada coisa:

import 'dart:math' as math;

void main() {
  final raio = 10;
  final area = math.pi * math.pow(raio, 2);
  print('Área da pizza de raio $raio cm: ${area.toStringAsFixed(1)} cm²');
}

$ dart run com_as.dart
Área da pizza de raio 10 cm: 314.2 cm²

math.pi é o π e math.pow(raio, 2) é "raio ao quadrado". Sem o as, seria só pi e pow. O apelido segue a regra dos nomes de arquivo: minúsculas e _.

3. Só uma parte: show e hide

A dart:math tem dezenas de coisas. Com show ("mostrar"), você traz só as que vai usar; com hide ("esconder"), traz tudo, menos as citadas.

import 'dart:math';

void main() {
  print('Raiz de 2: ${sqrt(2)}');
  print('Pi: $pi');
  print('Maior: ${max(7, 12)}');
}

$ dart run matematica.dart
Raiz de 2: 1.4142135623730951
Pi: 3.141592653589793
Maior: 12

Agora com show sqrt, pi, e a mesma chamada ao max:

import 'dart:math' show sqrt, pi;

void main() {
  print(sqrt(16));
  print(pi);
  print(max(1, 2));
}

$ dart run com_show.dart
com_show.dart:6:9: Error: Method not found: 'max'.
  print(max(1, 2));
        ^^^
$ echo $?
254

"Método não encontrado: max". O show deixou entrar só o sqrt e o pi; o max ficou na gaveta. Para consertar, acrescente-o à lista: show sqrt, pi, max.

Missão: conserte o import para o max funcionar, mantendo o show.

import 'dart:math' show sqrt, pi;

void main() {
  print(sqrt(16));
  print(max(7, 12));
}

import 'dart:math' show sqrt, pi, max;

void main() {
  print(sqrt(16));
  print(max(7, 12));
}

Dois arquivos, o mesmo nome

Onde as, show e hide mais ajudam é quando duas bibliotecas têm algo com o mesmo nome. A Ana tem uma função formatar em dinheiro.dart e outra em estoque.dart:

String formatar(double valor) => 'R\$ ${valor.toStringAsFixed(2)}';

String formatar(int quantidade) => '$quantidade unidades';

Importando as duas normalmente, o Dart não sabe qual usar (veja Quando dá errado). Com as, cada uma ganha o seu sobrenome:

import 'dinheiro.dart' as dinheiro;
import 'estoque.dart' as estoque;

void main() {
  print(dinheiro.formatar(12));
  print(estoque.formatar(12));
}

$ dart run conflito_as.dart
R$ 12.00
12 unidades

Se você só precisa de uma delas, esconda a outra com hide:

import 'dinheiro.dart';
import 'estoque.dart' hide formatar;

void main() {
  print(formatar(12));
}

$ dart run conflito_hide.dart
R$ 12.00

4. O que começa com _ é privado

No Dart, não existe palavra private: um nome que começa com _ (sublinhado) só pode ser usado dentro do próprio arquivo (da própria biblioteca). Vale para funções, variáveis, classes e membros de classes (veja Privacidade (_)). O _arredondar de precos.dart é um detalhe interno; quem importa precos.dart não o vê:

import 'precos.dart';

void main() {
  print(_arredondar(3.14159));
}

$ dart run privado.dart
privado.dart:4:9: Error: Method not found: '_arredondar'.
  print(_arredondar(3.14159));
        ^^^^^^^^^^^

Para o privado.dart, é como se _arredondar não existisse. Isso é bom: quem escreveu precos.dart pode mudar ou apagar o _arredondar sem quebrar o código de ninguém.

5. export: uma porta de entrada para vários arquivos

Quando o código cresce, quem usa precisa de muitos import. Um arquivo com export ("exportar", repassar) reúne os outros:

export 'dinheiro.dart';
export 'precos.dart';

import 'tudo.dart';

void main() {
  print(formatar(comEntrega(30)));
}

$ dart run usa_tudo.dart
R$ 35.00

O usa_tudo.dart importou um arquivo só e recebeu o formatar (de dinheiro.dart) e o comEntrega (de precos.dart). É assim que os pacotes se organizam: num projeto, o arquivo lib/padaria.dart costuma ter só exports dos arquivos de lib/src/, e quem usa escreve um único import 'package:padaria/padaria.dart';. O export também aceita show e hide.

Qual usar

SituaçãoUse
usar uma biblioteca normalmenteimport 'x.dart';
deixar claro de onde vem cada coisa, ou a biblioteca tem nomes genéricosimport 'x.dart' as x;
usar só uma ou duas coisasimport 'x.dart' show a, b;
um nome atrapalha (conflito)import 'x.dart' hide a; ou as
esconder um detalhe internocomece o nome com _
oferecer vários arquivos como um sóum arquivo com export

Quando dá errado

O mesmo nome importado de dois lugares 
import 'dinheiro.dart';
import 'estoque.dart';

void main() {
  print(formatar(12));
}

$ dart run conflito.dart
conflito.dart:5:9: Error: 'formatar' is imported from both 'dinheiro.dart' and 'estoque.dart'.
  print(formatar(12));
        ^^^^^^^^

"formatar é importado tanto de dinheiro.dart quanto de estoque.dart." Repare: o erro aparece na linha que usa o nome (linha 5), não nos import. Importar os dois é permitido; ambíguo é chamar. Como consertar: as nos dois (e chame dinheiro.formatar / estoque.formatar) ou hide formatar no que você não quer.

O arquivo importado não existe 
import 'preco.dart';

void main() {
  print(comEntrega(30));
}

$ dart run naoachou.dart
naoachou.dart:1:8: Error: Error when reading 'preco.dart': No such file or directory
import 'preco.dart';
       ^
naoachou.dart:4:9: Error: Method not found: 'comEntrega'.
  print(comEntrega(30));
        ^^^^^^^^^^
  • Error when reading 'preco.dart': No such file or directory — "erro ao ler preco.dart: arquivo ou diretório inexistente". Faltou o s: o arquivo é precos.dart.
  • Method not found: 'comEntrega' — consequência do primeiro erro. Conserte o primeiro, e este some.

Como consertar: confira o nome e a pasta. O caminho é relativo ao arquivo que faz o import, não à pasta onde você está no terminal.

import depois do código 
void main() {
  print('oi');
}

import 'dart:math';

$ dart run ordem.dart
ordem.dart:5:1: Error: Directives must appear before any declarations.
Try moving the directive before any declarations.
import 'dart:math';
^^^^^^

"Diretivas precisam aparecer antes de qualquer declaração. Tente mover a diretiva para antes das declarações." Diretiva é o nome técnico de import e export; declaração é uma função, classe ou variável. Como consertar: todos os import/export no topo do arquivo.

Os outros dois erros desta aula já apareceram acima: o nome deixado de fora pelo show (Method not found: 'max') e o nome privado (Method not found: '_arredondar'). Repare que, nos três casos, a mensagem é "não encontrado": para o arquivo que importa, esses nomes simplesmente não existem.

Resumo

  • Cada arquivo .dart é uma biblioteca; import traz o que ela oferece.
  • dart: = bibliotecas do Dart; package: = pacotes e lib/ do projeto; sem prefixo = caminho relativo de um arquivo.
  • as dá um prefixo; show traz só alguns nomes; hide deixa alguns de fora. Os três resolvem conflitos de nomes.
  • Nomes com _ são privados do arquivo.
  • export repassa outras bibliotecas: um import só traz várias.
  • import e export vêm no topo do arquivo, antes de qualquer código.
