Dart Herança (extends)

Na lojinha da Ana, tudo o que se vende é um produto: tem nome e preço. Mas algumas coisas são produtos com algo a mais: uma bebida também tem volume (300 ml, 2 litros). Em vez de escrever a classe Bebida do zero, repetindo nome e preço, o Dart deixa você dizer: "uma Bebida é um Produto, mais o volume". Isso se chama herança, e a palavra-chave é extends (em inglês, "estende", "amplia").

Você vai aprender
  • O que é herança: superclasse (a classe "mãe") e subclasse (a "filha").
  • Como escrever class Bebida extends Produto e o que a subclasse ganha de graça.
  • Como o construtor da filha passa os dados para o da mãe: super.nome e : super(nome, preco).
  • Como acrescentar campos e métodos novos só na subclasse.
  • Como testar o tipo com is, e por que toda classe, no fim, herda de Object.
  • Os erros reais: construtor sem super, dois extends, campo que só a filha tem, e o as que falha durante a execução.

Todos os programas desta aula rodaram no Dart 3.13.5 da máquina da Ana (usuária ana, computador notebook), com dart run arquivo.dart (veja Rodando um Programa). Esta aula usa classes, campos e construtores: se precisar, revise Classes e Construtores.

A ideia: "é um"

Pense numa ficha de cadastro da lojinha. A ficha de produto tem dois campos: nome e preço. A ficha de bebida é a mesma ficha de produto com um campo a mais embaixo: volume. Ninguém redesenha a ficha inteira; você pega a de produto e acrescenta uma linha.

Herança é isso. A frase que ajuda a decidir quando usar é: "uma Bebida é um Produto". Se a frase faz sentido, herança costuma ser uma boa escolha. "Um Refrigerante é uma Bebida": faz sentido. "Um Carrinho é um Produto": não faz (o carrinho tem produtos), então ali não é herança.

1. A primeira subclasse

class Produto {
  String nome;
  double preco;

  Produto(this.nome, this.preco);

  String descricao() => '$nome: R\$ ${preco.toStringAsFixed(2)}';
}

class Bebida extends Produto {
  int volumeMl;

  Bebida(super.nome, super.preco, this.volumeMl);
}

void main() {
  final pao = Produto('Pão francês', 0.75);
  final suco = Bebida('Suco de laranja', 6.5, 300);

  print(pao.descricao());
  print(suco.descricao());
  print('${suco.nome} tem ${suco.volumeMl} ml');
}
class Produto { … }
Uma classe comum, como as da aula Classes: dois campos, um construtor e um método. Ela vai ser a superclasse.
class Bebida extends Produto
"A classe Bebida estende Produto". Com isso, toda Bebida já nasce com nome, preco e descricao(), sem você reescrever nada.
int volumeMl;
O campo a mais, que só a bebida tem.
Bebida(super.nome, super.preco, this.volumeMl);
O construtor da filha. this.volumeMl você já conhece: guarda o valor no campo da própria Bebida. super.nome e super.preco querem dizer: "este valor vai para o construtor da superclasse", que é quem cuida de nome e preco. (super = "de cima", "superior".)
suco.descricao()
O método foi escrito em Produto, mas funciona na Bebida: ela herdou.
$ dart run produtos.dart
Pão francês: R$ 0.75
Suco de laranja: R$ 6.50
Suco de laranja tem 300 ml

A segunda linha veio do método descricao() da mãe, aplicado ao suco. A terceira usa o nome (herdado) e o volumeMl (próprio da bebida) lado a lado: para quem usa o objeto, não há diferença entre um e outro.

A filha tem tudo da mãe; a mãe não tem nada da filha

Toda Bebida tem nome, preco e volumeMl. Um Produto comum continua só com nome e preco: o pão não tem volume. A herança só desce, nunca sobe (o erro que aparece quando se esquece disso está em Quando dá errado).

Experimente: crie mais uma bebida, Bebida('Água mineral', 2.5, 500), e mostre a descrição dela. Depois tente mostrar pao.volumeMl e leia o erro.

2. O construtor da filha chama o da mãe

Quando você cria uma Bebida, o Dart monta o objeto em duas etapas: primeiro roda o construtor do Produto (que preenche nome e preço), depois termina a parte da Bebida. Por isso a filha precisa entregar à mãe o que o construtor dela pede. Há duas formas de escrever isso.

Forma curta: super.nome Dart 2.17

É a que você viu acima: Bebida(super.nome, super.preco, this.volumeMl);. Cada super. é um parâmetro que passa direto para a mãe, na mesma ordem em que o construtor dela pede (primeiro o nome, depois o preço). Chama-se parâmetro super e existe desde o Dart 2.17.

Forma longa: : super(nome, preco)

class Produto {
  String nome;
  double preco;

  Produto(this.nome, this.preco);
}

class Bebida extends Produto {
  int volumeMl;

  Bebida(String nome, double preco, this.volumeMl) : super(nome, preco);
}

void main() {
  final suco = Bebida('Suco de uva', 7.0, 500);
  print('${suco.nome}, R\$ ${suco.preco}, ${suco.volumeMl} ml');
}
Bebida(String nome, double preco, this.volumeMl)
Parâmetros comuns: nome e preco chegam aqui como variáveis normais.
: super(nome, preco)
Depois dos dois-pontos vem a lista de inicialização (veja Construtores). super(…) chama o construtor da mãe com esses valores.
$ dart run super_longo.dart
Suco de uva, R$ 7.0, 500 ml

O resultado é o mesmo. A forma longa ainda é útil quando você quer mexer no valor antes de mandá-lo para a mãe, por exemplo : super(nome.trim(), preco). Quando é só repassar, a forma curta é a recomendada (é o que o lint use_super_parameters do Dart sugere).

3. Acrescentando um método na subclasse

A filha pode ter métodos que a mãe não tem. A bebida sabe calcular o preço por litro; o pão, não:

class Produto {
  String nome;
  double preco;

  Produto(this.nome, this.preco);

  String descricao() => '$nome: R\$ ${preco.toStringAsFixed(2)}';
}

class Bebida extends Produto {
  int volumeMl;

  Bebida(super.nome, super.preco, this.volumeMl);

  double precoPorLitro() => preco / volumeMl * 1000;
}

void main() {
  final suco = Bebida('Suco de laranja', 6.5, 300);
  print(suco.descricao());
  print('Por litro: R\$ ${suco.precoPorLitro().toStringAsFixed(2)}');
}

$ dart run metodo_novo.dart
Suco de laranja: R$ 6.50
Por litro: R$ 21.67

Dentro de precoPorLitro(), o preco é o campo herdado: a filha usa os campos da mãe como se fossem dela. (E se a bebida quiser uma descricao() diferente, com o volume junto? Isso é sobrescrever um método, o assunto da próxima aula: Sobrescrevendo (@override).)

4. Uma lista de produtos e o is

Como toda bebida é um produto, uma List<Produto> aceita bebidas. E o operador is (veja is, is! e as) pergunta "este objeto é deste tipo?":

class Produto {
  String nome;
  double preco;

  Produto(this.nome, this.preco);
}

class Bebida extends Produto {
  int volumeMl;

  Bebida(super.nome, super.preco, this.volumeMl);
}

void main() {
  final List<Produto> carrinho = [
    Produto('Pão francês', 0.75),
    Bebida('Suco de laranja', 6.5, 300),
    Produto('Manteiga', 12.9),
  ];

  for (final item in carrinho) {
    if (item is Bebida) {
      print('${item.nome} (bebida, ${item.volumeMl} ml)');
    } else {
      print(item.nome);
    }
  }

  final suco = Bebida('Suco de uva', 7.0, 500);
  print(suco is Bebida);
  print(suco is Produto);
  print(suco is Object);
  print(Produto('Bolo', 20) is Bebida);
}

$ dart run is_lista.dart
Pão francês
Suco de laranja (bebida, 300 ml)
Manteiga
true
true
true
false
  • Dentro do if (item is Bebida), o Dart já sabe que item é uma bebida e deixa usar item.volumeMl. Isso se chama promoção de tipo.
  • suco is Produto deu true: a bebida é também um produto.
  • suco is Object deu true: no Dart, toda classe herda de Object, mesmo sem escrever extends. class Produto é, por baixo, class Produto extends Object. É de lá que vêm o toString() e o == que todo objeto tem (aula toString, == e hashCode).
  • O bolo é só Produto: is Bebida deu false.

5. Herança em vários andares

Uma subclasse pode ser mãe de outra. Um refrigerante é uma bebida, que é um produto:

class Produto {
  String nome;
  double preco;

  Produto(this.nome, this.preco);
}

class Bebida extends Produto {
  int volumeMl;

  Bebida(super.nome, super.preco, this.volumeMl);
}

class Refrigerante extends Bebida {
  bool zeroAcucar;

  Refrigerante(super.nome, super.preco, super.volumeMl, {this.zeroAcucar = false});
}

void main() {
  final refri = Refrigerante('Guaraná', 5.0, 350, zeroAcucar: true);
  print('${refri.nome}, ${refri.volumeMl} ml, zero: ${refri.zeroAcucar}');
  print(refri is Bebida);
  print(refri is Produto);
}

$ dart run cadeia.dart
Guaraná, 350 ml, zero: true
true
true

O Refrigerante passa três valores para cima com super. (nome, preço e volume, que é tudo o que o construtor da Bebida pede) e guarda o seu próprio zeroAcucar, um parâmetro nomeado com valor padrão. A cadeia fica: Object → Produto → Bebida → Refrigerante.

Não exagere nos andares

Dois ou três níveis ainda se leem bem. Uma cadeia muito comprida obriga quem lê a subir classe por classe para descobrir de onde veio um campo. Se a frase "é um" começar a soar forçada, prefira outra ferramenta: implements, mixins ou simplesmente um campo (o carrinho tem uma lista de produtos).

Formas diferentes de fazer

Para uma "bebida que é um produto com volume", existem estes caminhos:

SituaçãoQual usar
A frase "X é um Y" faz sentido e X aproveita os campos e métodos de Yclass X extends Y (esta aula)
O construtor da filha só repassa os valores para a mãeBebida(super.nome, super.preco, this.volumeMl)
A filha precisa transformar um valor antes de repassarBebida(String nome, …) : super(nome.trim(), …)
X só precisa prometer os mesmos métodos que Y, sem aproveitar o códigoimplements (aula Interfaces)
Várias classes sem parentesco precisam do mesmo pedaço de códigowith (aula Mixins)
X tem um Y (o carrinho tem produtos)Um campo: final List<Produto> itens

Resumo

  • class Filha extends Mae: a filha herda todos os campos e métodos da mãe e pode acrescentar os seus.
  • Use herança quando a frase "a filha é uma mãe" faz sentido.
  • O construtor da filha tem de alimentar o da mãe: super.nome (forma curta, Dart 2.17+) ou : super(nome, preco).
  • A herança só desce: a filha tem tudo da mãe, a mãe não tem nada da filha.
  • Cada classe tem uma mãe só; todas descendem de Object.
  • is pergunta o tipo com segurança; as afirma o tipo e, se errar, dá exceção durante a execução (código 255). Erros de compilação saem com código 254.
