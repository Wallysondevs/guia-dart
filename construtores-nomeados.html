Dart Construtores Nomeados e factory

Na aula de Construtores, cada classe tinha um jeito de criar objetos: Produto('café', 18.9). Mas às vezes existem vários jeitos que fazem sentido: um produto normal ou um brinde (de graça); uma temperatura em Celsius ou em Fahrenheit; um produto escrito à mão ou lido de uma linha de texto. Uma classe só pode ter um construtor sem nome, mas pode ter quantos construtores nomeados quiser. E, quando criar o objeto exige mais que copiar valores, existe o construtor factory ("fábrica").

Você vai aprender
  • Como escrever um construtor nomeado: Produto.brinde(this.nome) : preco = 0;
  • Que você já usou vários sem saber: List.filled, List.generate, DateTime.utc.
  • Como um construtor pode repassar o trabalho para outro: : this(nome, 0).
  • O que é um construtor factory e quando usar: montar o objeto a partir de um texto, ou devolver um objeto que já existe.
  • Os erros reais que o Dart mostra.

Todos os programas desta aula rodaram no Dart 3.13.5 da máquina da Ana (usuária ana, computador notebook), com dart run arquivo.dart.

A ideia: os balcões da padaria

Na padaria, um pedido pode chegar de vários jeitos: no balcão (o cliente diz o que quer e paga), como brinde (a bala que vai de graça para a criança), ou pelo bilhete que a vizinha deixa por escrito ("2 pães; 1 leite"). No fim, é sempre um pedido; o que muda é como ele começa.

Os construtores nomeados são esses balcões: cada um tem um nome que diz de onde vem o objeto (Produto.brinde, Produto.deLinha), e todos produzem um Produto.

1. O primeiro construtor nomeado

class Produto {
  final String nome;
  final double preco;

  Produto(this.nome, this.preco);

  Produto.brinde(this.nome) : preco = 0;

  @override
  String toString() => '$nome: R\$ $preco';
}

void main() {
  final cafe = Produto('café', 18.9);
  final bala = Produto.brinde('bala');
  print(cafe);
  print(bala);
}
Produto(this.nome, this.preco);
O construtor de sempre, sem nome (veja Construtores).
Produto.brinde(…)
Um construtor nomeado: o nome da classe, um ponto e um nome seu, em lowerCamelCase. O nome conta para quem lê o que esse jeito de criar faz.
(this.nome)
Recebe só o nome, que vai direto para o campo.
: preco = 0
A lista de inicialização dá o preço: brinde é de graça.
Produto.brinde('bala')
Para usar, escreva o nome completo, com o ponto.
$ dart run nomeado.dart
café: R$ 18.9
bala: R$ 0.0

Vários nomes, um jeito para cada situação

Uma temperatura pode chegar em graus Celsius ou em Fahrenheit (os americanos usam esta). A classe guarda sempre em Celsius e oferece três construtores, todos nomeados:

class Temperatura {
  final double celsius;

  Temperatura.celsius(this.celsius);

  Temperatura.fahrenheit(double f) : celsius = (f - 32) * 5 / 9;

  Temperatura.congelando() : celsius = 0;
}

void main() {
  final hoje = Temperatura.celsius(28);
  final nyc = Temperatura.fahrenheit(50);
  final gelo = Temperatura.congelando();
  print('Hoje: ${hoje.celsius} °C');
  print('Nova York: ${nyc.celsius} °C');
  print('Gelo: ${gelo.celsius} °C');
}

$ dart run temperatura.dart
Hoje: 28.0 °C
Nova York: 10.0 °C
Gelo: 0.0 °C

Os 50 °F viraram 10 °C pela conta da lista de inicialização. Repare que esta classe não tem construtor sem nome: Temperatura(28) dá erro de compilação (no lab: Error: Couldn't find constructor 'Temperatura'., "não encontrei o construtor Temperatura"). Assim, quem cria uma temperatura é obrigado a dizer a unidade, e ninguém confunde 28 °F com 28 °C.

3. Repassar para outro construtor: : this(…)

Um construtor nomeado pode só repassar o trabalho para outro construtor da mesma classe, completando os valores que faltam. Isso evita repetir código:

class Produto {
  final String nome;
  final double preco;

  Produto(this.nome, this.preco);

  Produto.brinde(String nome) : this(nome, 0);

  Produto.cafe() : this('café', 18.9);

  @override
  String toString() => '$nome: R\$ $preco';
}

void main() {
  print(Produto.brinde('bala'));
  print(Produto.cafe());
}

$ dart run redireciona.dart
bala: R$ 0.0
café: R$ 18.9

: this(nome, 0) quer dizer "crie usando o construtor principal, com este nome e preço 0". Se o construtor principal um dia ganhar uma conferência de preço, os nomeados que repassam para ele ganham junto. Um construtor que repassa não tem corpo nem lista de inicialização própria.

4. O construtor factory

Um construtor comum sempre cria um objeto novo, e só pode preencher campos. Às vezes, criar o objeto exige trabalho antes: separar um texto, converter números, decidir algo. Um construtor marcado com factory funciona como uma função comum: roda o código que quiser e, no fim, devolve (return) o objeto.

Montar o objeto a partir de um texto

A lista de preços chegou num arquivo, uma linha por produto, no formato nome;preço:

class Produto {
  final String nome;
  final double preco;

  Produto(this.nome, this.preco);

  factory Produto.deLinha(String linha) {
    final partes = linha.split(';');
    final nome = partes[0].trim();
    final preco = double.parse(partes[1]);
    return Produto(nome, preco);
  }

  @override
  String toString() => '$nome: R\$ $preco';
}

void main() {
  final linhas = ['pão;1.0', 'leite; 5.5', 'café;18.9'];
  for (final l in linhas) {
    print(Produto.deLinha(l));
  }
}
factory Produto.deLinha(String linha)
A palavra factory antes do construtor. Ele recebe o texto inteiro.
linha.split(';')
Separa o texto no ;: 'pão;1.0' vira ['pão', '1.0'] (veja Métodos de String).
partes[0].trim()
O nome, sem espaços nas pontas.
double.parse(partes[1])
Converte o texto do preço em número (veja Conversão de Tipos). O double.parse aceita o espaço de ' 5.5'.
return Produto(nome, preco);
O factory devolve o objeto, criado com o construtor principal. Sem esse return, dá erro.
$ dart run factory.dart
pão: R$ 1.0
leite: R$ 5.5
café: R$ 18.9

Devolver um objeto que já existe

Como o factory só precisa devolver um objeto, ele pode devolver um que já foi criado antes, em vez de um novo. As moedas do programa da Ana: só existe um objeto para cada código.

class Moeda {
  final String codigo;

  Moeda._(this.codigo) {
    print('criando a moeda $codigo');
  }

  static final _criadas = <String, Moeda>{};

  factory Moeda(String codigo) {
    return _criadas.putIfAbsent(codigo, () => Moeda._(codigo));
  }
}

void main() {
  final a = Moeda('BRL');
  final b = Moeda('BRL');
  final c = Moeda('USD');
  print(identical(a, b));
  print(identical(a, c));
}

$ dart run cache.dart
criando a moeda BRL
criando a moeda USD
true
false
Moeda._(this.codigo)
O construtor que cria de verdade. O nome _ o deixa privado: só este arquivo pode usá-lo (veja Privacidade).
static final _criadas = <String, Moeda>{};
Um mapa que pertence à classe, e não a cada moeda, com as moedas já criadas (veja Membros static).
factory Moeda(String codigo)
O construtor sem nome também pode ser factory. Quem usa escreve Moeda('BRL') e nem percebe a diferença.
_criadas.putIfAbsent(codigo, …)
"Ponha se não estiver lá": se o código já estiver no mapa, devolve a moeda guardada; se não, cria uma com Moeda._, guarda e devolve.
identical(a, b)
"São o mesmo objeto?" Para a e b, sim: a mensagem criando a moeda BRL só apareceu uma vez.
Comum × factory

Um construtor comum só preenche campos (com this., a lista de inicialização e o corpo), e sempre resulta num objeto novo. Um factory roda código à vontade e devolve um objeto: novo, guardado, ou até de uma subclasse (assunto de Herança). Em troca, ele não pode usar this, porque não há um objeto "em construção".

Formas diferentes de fazer a mesma coisa

Para "criar um produto a partir de uma linha de texto", existem três caminhos: um factory (seção 4), uma função solta fora da classe (como a criar da aula de Classes), ou um método static da classe. O static tem uma vantagem: pode devolver null quando não dá para criar, coisa que um construtor (nem o factory) não pode:

class Nota {
  final double valor;
  Nota._(this.valor);

  static Nota? tentar(String texto) {
    final v = double.tryParse(texto);
    if (v == null || v < 0 || v > 10) return null;
    return Nota._(v);
  }
}

void main() {
  print(Nota.tentar('8.5')?.valor);
  print(Nota.tentar('11')?.valor);
  print(Nota.tentar('oito')?.valor);
}

"Parâmetros do tipo this.campo só podem ser usados num construtor." Para o Dart, um factory não é um construtor "de verdade": não existe objeto sendo montado, então não há campo para preencher. Como consertar: receba um parâmetro comum (String nome) e passe-o ao construtor que você chamar no return. (Ou, aqui, nem use factory: Produto.brinde(String nome) : this(nome, 0);.)

Esqueceu o return no factory

    Produto(partes[0], double.parse(partes[1]));

Resumo

  • Uma classe tem no máximo um construtor sem nome, mas quantos nomeados quiser: Classe.nome(…). Não existe sobrecarga: cada construtor tem um nome diferente.
  • Construtores nomeados usam this., lista de inicialização e corpo, como os outros, ou repassam para outro com : this(…).
  • O factory roda código à vontade e devolve um objeto com return: novo, ou um que já existia. Ele não pode usar this.
  • Os nomes contam o que cada jeito de criar faz: Produto.brinde, Temperatura.fahrenheit, List.filled.
  • Próxima aula: get e set, campos "calculados" e campos que conferem o valor antes de aceitar.
