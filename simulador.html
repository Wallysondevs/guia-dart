Dart O Editor do Guia

Em toda aula deste guia aparecem caixas Experimente. Você escreve um programa em Dart, clica em Rodar e vê, logo embaixo, o que o programa escreveu. Não precisa instalar nada: o editor roda o programa dentro do seu navegador. Nesta página você conhece cada parte do editor e aprende a responder quando o programa pergunta alguma coisa. Também vê como parar um programa que não termina, como o editor mostra os erros e o que muda quando você roda o mesmo programa no terminal.

Você vai aprender
  • As partes de uma caixa Experimente: o código, Rodar, o terminal da caixa, Restaurar e Ver solução, e os atalhos do teclado.
  • Por que cada Rodar começa do zero.
  • Como responder ao stdin.readLineSync(): digitando no terminal da caixa ou pelo campo Entrada.
  • Como funcionam as abas (vários arquivos) e o campo Argumentos.
  • Como aparecem os erros de compilação e as exceções, e como parar um programa que não termina.
  • O que o editor não faz, como funcionam as missões, e as diferenças para o dart run do terminal.

A ideia: uma bancada de treino dentro da página

Pense numa escola de culinária. O professor explica a receita no quadro, mas a aula só vale a pena quando cada aluno vai para a sua bancada e faz o bolo com as próprias mãos. Se o bolo desanda, tudo bem: a bancada é de treino, e no dia seguinte ela está limpa de novo.

O editor do guia é essa bancada. A receita é o seu programa. Cada vez que você clica em Rodar, o editor:

  1. prepara uma pasta nova, a /home/ana (a pasta pessoal da Ana, a usuária das aulas), só com os arquivos da caixa;
  2. grava o seu código num arquivo, o main.dart;
  3. confere o programa e roda, como quem digita dart run main.dart no terminal;
  4. mostra tudo o que o programa escreveu e, no fim, o código de saída (0 quer dizer "terminou bem").

Por dentro, o editor é um tradutor de Dart para JavaScript, a linguagem que os navegadores sabem executar, feito para este guia. Ele imita o Dart SDK 3.13.5 (a versão das aulas) com as mesmas mensagens de erro, as mesmas saídas do print e os mesmos códigos de saída. Tudo acontece no seu computador, dentro do navegador: o seu código não é enviado para lugar nenhum. E o programa roda separado da página, então, mesmo que ele trave, a página continua funcionando.

O editor não é o Dart oficial

Os programas que aparecem nos quadros pretos das aulas (os que começam com $ dart run) foram rodados com o Dart SDK oficial, na máquina da Ana. O editor imita esse Dart muito de perto, mas não em tudo: as diferenças estão no fim desta página. Quando o editor e o terminal discordarem, quem vale é o terminal.

As partes da caixa

Esta é uma caixa livre, sem missão. Clique em ▶ Rodar:

void main() {
  final nome = 'Ana';
  print('Olá, $nome!');
  print('Bem-vinda ao Dart.');
}

Na primeira vez, o editor avisa "Carregando o Dart do editor (…, só na primeira vez)…": o navegador está baixando o editor, uns 180 KB (menos que uma foto). Isso leva um instante e só acontece uma vez. Depois, cada Rodar leva uma fração de segundo. Em seguida aparece o terminal da caixa, com a resposta. Repare nas partes:

Cada Rodar começa do zero

O programa abaixo olha se o arquivo diario.txt existe. Se existe, avisa; senão, diz que o diário é novo. Depois, acrescenta uma linha ao diário e mostra tudo o que tem nele. Rode duas ou três vezes:

import 'dart:io';

void main() {
  final diario = File('diario.txt');
  if (diario.existsSync()) {
    print('O diário já existia!');
  } else {
    print('Diário novo.');
  }
  diario.writeAsStringSync('Hoje estudei Dart.\n', mode: FileMode.append);
  for (final linha in diario.readAsLinesSync()) {
    print('No diário: $linha');
  }
}

Todas as vezes ele responde Diário novo. e uma linha só no diário. No computador da Ana, a segunda vez é diferente, porque o arquivo fica gravado no disco (o mesmo programa, salvo como diario.dart):

$ dart run diario.dart
Diário novo.
No diário: Hoje estudei Dart.
$ dart run diario.dart
O diário já existia!                               « o arquivo ficou no disco
No diário: Hoje estudei Dart.
No diário: Hoje estudei Dart.

No editor, cada Rodar é um dart run main.dart novinho: memória nova, variáveis zeradas e a pasta só com os arquivos das abas da caixa. O que o programa cria existe até o fim daquele Rodar e some no próximo. Não se preocupe com o File agora; ele tem aula própria: Arquivos.

Por que isso é bom

Você pode criar, mudar e apagar arquivos à vontade: nada "estraga" os exemplos das outras aulas, e o resultado é sempre o que o texto da aula descreve. A contrapartida é que nada fica guardado entre um Rodar e outro: o programa que grava e o que lê precisam estar no mesmo Rodar.

Quando o programa pergunta: o stdin.readLineSync()

O stdin.readLineSync() ("ler uma linha da entrada") faz o programa parar e esperar você digitar uma resposta (aula Lendo o Teclado). Rode a caixa abaixo: o terminal mostra a pergunta e, do lado, um campo para você digitar. Escreva o seu nome e tecle Enter:

import 'dart:io';

void main() {
  stdout.write('Qual é o seu nome? ');
  final nome = stdin.readLineSync();
  print('Olá, $nome!');
}

O que você digitou aparece no terminal, como num terminal de verdade, e o programa continua. Se, em vez de responder, você teclar Ctrl+D ("fim da entrada"), o readLineSync() devolve null, e o programa mostra Olá, null!. O Ctrl+C no campo para o programa, como o ■ Parar.

Por dentro

O editor não consegue "pausar" o programa no meio. Então, a cada linha que você digita, ele roda o programa de novo desde o começo, já com as respostas que você deu, e mostra só o que ainda não estava na tela. Para você, parece um programa só. A diferença só aparece num programa que sorteia números com Random() ou usa a hora antes de perguntar: os sorteios do editor ficam iguais entre as repetições, mas a hora anda.

Caixas com o campo Entrada

Algumas caixas já trazem as respostas prontas num campo Entrada, embaixo do código: cada linha do campo é uma resposta, como se alguém tivesse digitado e teclado Enter. O terminal mostra o que foi lido, e você pode mudar o campo antes de rodar:

import 'dart:io';

void main() {
  stdout.write('Nome: ');
  final nome = stdin.readLineSync()!;
  stdout.write('Idade: ');
  final idade = int.parse(stdin.readLineSync()!);
  print('$nome faz ${idade + 1} anos no ano que vem.');
}

Troque 30 por trinta no campo Entrada e rode: o int.parse não entende o texto, e o programa para com uma exceção (aula Conversão de Tipos).

Vários arquivos: as abas

Algumas caixas têm mais de uma aba. A primeira é sempre a que roda (main.dart); as outras ficam na mesma pasta. Um programa Dart pode usar funções de outro arquivo com import (aula Imports), e ler arquivos de dados, como um .txt:

import 'dart:io';
import 'contas.dart';

void main() {
  final precos = File('precos.txt').readAsLinesSync().map(double.parse).toList();
  print('Itens: $precos');
  print('Total: R\$ ${somar(precos).toStringAsFixed(2)}');
}

double somar(List<double> valores) {
  var total = 0.0;
  for (final v in valores) {
    total += v;
  }
  return total;
}

9.50
4.25

Clique nas abas para ver cada arquivo. Mude um preço em precos.txt e rode de novo. Se você apagar a linha do import 'contas.dart';, o Dart não acha a função: Method not found: 'somar'.

O campo Argumentos

Um programa pode receber palavras na linha de comando, os argumentos (aula Argumentos da Linha de Comando). Nas caixas com o campo Argumentos, o que você escreve ali chega na lista args do main, e aparece também no comando da primeira linha do terminal. Palavras entre aspas viram um argumento só:

void main(List<String> args) {
  print('Recebi ${args.length} argumento(s): $args');
}

No terminal da Ana, o mesmo programa (salvo como args.dart) responde igual:

$ dart run args.dart pão leite 'queijo minas'
Recebi 3 argumento(s): [pão, leite, queijo minas]

Quando dá errado

Errar faz parte, e as mensagens de erro são as do Dart, em inglês. O editor mostra em vermelho e explica com o código de saída. São dois tipos de erro.

Erro de compilação (código 254)

Antes de rodar, o Dart confere o programa inteiro. Se achar um erro, ele nem começa: mostra onde está o problema e termina com o código 254.

void main() {
  Print('Olá!');
}

No terminal da Ana, o mesmo erro (o programa salvo como erro.dart):

$ dart run erro.dart
erro.dart:2:3: Error: Method not found: 'Print'.
  Print('Olá!');
  ^^^^^
$ echo $?
254
erro.dart:2:3
O arquivo, a linha 2 e a coluna 3 (a 3ª letra da linha), onde o Dart achou o problema.
Error: Method not found: 'Print'.
"Método não encontrado: 'Print'". O Dart diferencia maiúsculas de minúsculas: a função se chama print, com p minúsculo.
A linha do código e o ^^^^^
A linha com o erro e, embaixo, setinhas apontando o trecho exato.
254
O código de saída de "o Dart recusou o programa".

Às vezes o programa está escrito certo, mas algo dá errado enquanto ele roda: o programa para no meio com uma exceção e termina com o código 255.

void main() {

Um programa que não termina

Um laço que nunca acaba deixa o programa rodando para sempre. No editor, o botão vira ■ Parar: clique nele. Se você não clicar, o editor para o programa sozinho depois de 10 segundos e avisa. Rode e pare:

void main() {
  var voltas = 0;
  while (true) {
    voltas++;
  }
}

No terminal, o equivalente ao ■ Parar é o Ctrl+C.

As missões

Muitas caixas têm uma Missão: uma tarefa escrita em cima do código. Embaixo da caixa fica uma linha de status que confere a sua resposta a cada Rodar:

  • Missão em andamento… enquanto ainda não está certo, com uma pista entre parênteses (por exemplo, "a saída ainda não é a esperada" ou "o programa ainda termina com erro");
  • ✔ Missão cumprida!, quando você acerta. Depois de cumprida, ela fica cumprida.

O guia não compara o seu código letra por letra com a resposta: ele roda o seu programa e confere o que ele escreveu. Por isso, quase sempre existe mais de um jeito certo. Às vezes a missão também pede um recurso (como "use um for"), ou um arquivo criado pelo programa, ou até um erro de propósito, para você aprender a reconhecê-lo. Faça a primeira:

Missão: a Ana comprou 3 pães de R$ 1,50 e 2 litros de leite de R$ 9,50. O programa tem um erro: rode, leia a mensagem (a linha, a coluna e o nome entre aspas) e conserte. A saída deve ser Total: R$ 23.50.

void main() {
  final paes = 3 * 1.50;
  final leite = 2 * 9.50;
  final total = paes + leites;
  print('Total: R\$ ${total.toStringAsFixed(2)}');
}

void main() {
  final paes = 3 * 1.50;
  final leite = 2 * 9.50;
  final total = paes + leite;
  print('Total: R\$ ${total.toStringAsFixed(2)}');
}

Rodou antes de consertar? Então viu main.dart:4:24: Error: Undefined name 'leites'.: a variável se chama leite, sem o "s", e ninguém criou uma leites. (O toStringAsFixed(2) mostra o número com duas casas decimais, e o \$ escreve o cifrão: aula Interpolação.) As missões são feitas para você errar, ler a mensagem e consertar. Se travar de vez, use Ver solução; mas tente antes, e depois de ver a solução, digite-a você mesmo.

O mesmo programa no terminal

O editor é ótimo para aprender, mas no dia a dia o Dart roda no seu computador, com o comando dart no terminal. A aula Instalar o Dart mostra como instalá-lo, e Rodando um Programa ensina o caminho completo. O mesmo programa dá as mesmas mensagens nos dois lugares. O que muda:

O que mudaNo editorNo terminal
ArquivosSomem no próximo RodarFicam gravados no disco
A hora (DateTime.now())A do seu computadorA do computador onde o programa roda
Sorteios com Random() sem sementeMudam a cada RodarMudam a cada execução (com semente, Random(42), os números são os mesmos nos dois)
Detalhes internosNomes internos do Dart e as linhas dart:core-patch do stack trace podem sair um pouco diferentesOs nomes e linhas reais do SDK
VelocidadeMais lento em contas muito pesadasO Dart compilado, bem mais rápido
Pacotes, Flutter, outros programasNão temTem (dart pub, flutter)

Resumo

  • As caixas Experimente rodam o programa dentro do seu navegador, com um editor que imita o Dart 3.13.5 (baixado uma vez, uns 180 KB). O seu código não sai do seu computador. As saídas das aulas vêm do Dart oficial, no terminal.
  • Cada Rodar é um dart run main.dart novo, numa pasta /home/ana nova, só com os arquivos das abas. O terminal da caixa mostra o comando, a saída, os erros em vermelho e o código de saída: 0 (tudo certo), 254 (erro de compilação), 255 (exceção).
  • Restaurar volta ao código original; Ver solução (nas missões) pergunta antes de trocar o seu código. Ctrl+Enter roda; o Enter recua 2 espaços depois de {.
  • O stdin.readLineSync() espera você digitar no terminal da caixa (Ctrl+D = fim da entrada, e ele devolve null), ou lê do campo Entrada. O campo Argumentos vira a lista args do main.
  • Um laço sem fim para com ■ Parar ou sozinho, em 10 segundos.
  • O editor não tem pacotes, Flutter, internet nem outros programas; isso fica para o terminal.
  • As missões rodam o seu programa e conferem a saída: ✔ Missão cumprida! quando dá certo.
