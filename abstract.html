Dart Classes Abstratas

No caixa da lojinha, a Ana aceita Pix, cartão e boleto. Toda forma de pagamento tem um valor e uma taxa, e o total é sempre "valor + taxa". Só que cada uma calcula a taxa de um jeito, e não existe um "pagamento genérico" que alguém faça no balcão: ou é Pix, ou é cartão, ou é boleto. Para descrever esse "modelo que não existe sozinho", o Dart tem a classe abstrata: abstract class (em inglês, abstract = "abstrato", uma ideia, não uma coisa concreta).

Você vai aprender
  • O que é uma classe abstrata e por que ela não vira objeto.
  • O que é um método abstrato (só a assinatura, sem corpo) e um getter abstrato.
  • Como uma classe abstrata pode ter campos, construtor e métodos prontos que usam os abstratos.
  • Como as subclasses completam o que falta, com extends e @override.
  • Os erros reais: tentar criar o objeto abstrato, esquecer um método, esquecer o abstract e o UnimplementedError durante a execução.

Todos os programas desta aula rodaram no Dart 3.13.5 da máquina da Ana (usuária ana, computador notebook), com dart run arquivo.dart. Antes, convém ter feito Herança e Sobrescrevendo (@override).

A ideia: o formulário com campos em branco

Pense num formulário impresso de "Forma de pagamento". Ele já traz pronto o cabeçalho, a linha "Valor: ____" e a conta "Total = valor + taxa". Mas a linha "Como calcular a taxa: ____" está em branco: quem preenche é o setor do Pix, o do cartão, o do boleto. Ninguém entrega ao cliente o formulário em branco; entrega uma das versões preenchidas.

  • O formulário com a linha em branco é a classe abstrata.
  • A linha em branco é o método abstrato: tem nome, mas não tem conteúdo.
  • Cada versão preenchida é uma subclasse concreta (concreta = que dá para criar objeto).

1. A primeira classe abstrata

abstract class Pagamento {
  double valor;

  Pagamento(this.valor);

  double taxa();

  double total() => valor + taxa();
}

class Pix extends Pagamento {
  Pix(super.valor);

  @override
  double taxa() => 0;
}

class Cartao extends Pagamento {
  Cartao(super.valor);

  @override
  double taxa() => valor * 0.03;
}

void main() {
  final compras = <Pagamento>[Pix(50), Cartao(50)];
  for (final p in compras) {
    print('Total: R\$ ${p.total().toStringAsFixed(2)}');
  }
}
abstract class Pagamento
A palavra abstract antes de class diz: "esta classe é um molde; ninguém cria um Pagamento puro".
double valor; e Pagamento(this.valor);
Uma classe abstrata pode ter campos e construtor, como qualquer classe. O construtor existe para as filhas chamarem (com super.valor).
double taxa();
Um método abstrato: tem tipo de retorno, nome e parênteses, e termina em ;, sem corpo (sem { } nem =>). É a linha em branco do formulário. Repare que não se escreve abstract antes do método: o ponto e vírgula já diz tudo.
double total() => valor + taxa();
Um método pronto, que usa o abstrato. A mãe não sabe calcular a taxa, mas sabe que, seja qual for, o total é valor + taxa().
class Pix extends Pagamento … @override double taxa() => 0;
A subclasse preenche a linha em branco. O @override é o mesmo da aula Sobrescrevendo: aqui a filha "sobrescreve" um método que, na mãe, não tinha corpo.
<Pagamento>[Pix(50), Cartao(50)]
Uma lista do tipo Pagamento (o tipo abstrato pode ser usado em variáveis e listas), com objetos concretos dentro.
$ dart run pagamentos.dart
Total: R$ 50.00
Total: R$ 51.50

O método total() foi escrito uma vez só, na mãe. Quando ele chamou taxa(), o Dart usou a versão do objeto de verdade: 0 para o Pix, 3% de 50 (R$ 1,50) para o cartão.

2. Getters abstratos e um método que usa tudo

Além de métodos, a classe abstrata pode exigir getters (veja get e set): cada forma de pagamento tem de dizer o seu nome. E a mãe pode trazer um método maior, que monta o recibo inteiro:

abstract class Pagamento {
  double valor;

  Pagamento(this.valor);

  String get nome;
  double taxa();

  double total() => valor + taxa();

  void recibo() {
    print('$nome: R\$ ${valor.toStringAsFixed(2)} + taxa '
        'R\$ ${taxa().toStringAsFixed(2)} = R\$ ${total().toStringAsFixed(2)}');
  }
}

class Pix extends Pagamento {
  Pix(super.valor);

  @override
  String get nome => 'Pix';

  @override
  double taxa() => 0;
}

class Cartao extends Pagamento {
  Cartao(super.valor);

  @override
  String get nome => 'Cartão';

  @override
  double taxa() => valor * 0.03;
}

class Boleto extends Pagamento {
  Boleto(super.valor);

  @override
  String get nome => 'Boleto';

  @override
  double taxa() => 2.5;
}

void main() {
  final compras = <Pagamento>[Pix(50), Cartao(50), Boleto(50)];
  for (final p in compras) {
    p.recibo();
  }
}

$ dart run recibo.dart
Pix: R$ 50.00 + taxa R$ 0.00 = R$ 50.00
Cartão: R$ 50.00 + taxa R$ 1.50 = R$ 51.50
Boleto: R$ 50.00 + taxa R$ 2.50 = R$ 52.50
String get nome;
Um getter abstrato: "toda forma de pagamento tem um nome, cada uma diz o seu". Também termina em ;.
void recibo() { … }
O formato do recibo está num lugar só. As filhas só informam o que muda (nome e taxa), e todas imprimem no mesmo padrão.
print('…' '…')
Dois textos lado a lado, sem nada no meio, viram um texto só. É um jeito de quebrar uma linha comprida (veja Strings).
Quem chama não precisa saber qual é a forma de pagamento

O main só conhece Pagamento: chama p.recibo() e pronto. Para aceitar vale-refeição amanhã, a Ana cria uma classe nova com nome e taxa(), e o resto do programa continua igual. É o que você vai fazer na missão final.

3. O tipo abstrato na variável

Você não pode criar um Pagamento, mas pode guardar um objeto concreto numa variável do tipo Pagamento:

// (Pagamento e Pix como na seção 1)
void main() {
  Pagamento p = Pix(30);
  print(p.taxa());
  print(p is Pagamento);
  print(p.runtimeType);
}

$ dart run lista_tipo.dart
0.0
true
Pix

A variável diz "aqui cabe qualquer pagamento"; o objeto dentro dela é um Pix, como mostra o runtimeType ("tipo durante a execução"). E a taxa saiu 0.0, não 0: o método promete devolver double, então o 0 do Pix virou número com casa decimal.

Formas diferentes de fazer

Uma alternativa seria uma classe comum com uma taxa "de mentira" (double taxa() => 0;) e subclasses sobrescrevendo. Funciona, mas o Dart não reclama se alguém esquecer de sobrescrever, e o programa calcula taxa errada sem avisar. Com o método abstrato, esquecer vira erro de compilação (veja abaixo). Outra alternativa é uma interface, que exige os métodos mas não traz nada pronto.

SituaçãoQual usar
Um modelo com partes prontas (campos, total(), recibo()) e partes que cada filha tem de preencherabstract class com métodos abstratos (esta aula)
A mãe tem um comportamento padrão razoável e só algumas filhas mudamClasse comum + @override (aula Sobrescrevendo)
Só uma lista de métodos que a classe promete ter, sem nada prontoimplements (aula Interfaces)
Um conjunto fechado de filhas, para o switch conferir se cobriu todassealed class (aula sealed, final, base e interface)

O método "provisório" que lança UnimplementedError (exceção durante a execução)

Os editores de código (VS Code, Android Studio) têm um atalho que escreve sozinho os métodos que faltam. Eles saem assim, com um corpo provisório:

abstract class Pagamento {
  double valor;

  Pagamento(this.valor);

  double taxa();

  double total() => valor + taxa();
}

class Pix extends Pagamento {
  Pix(super.valor);

  @override
  double taxa() => 0;
}

class Cheque extends Pagamento {
  Cheque(super.valor);

  @override
  double taxa() {
    // TODO: implement taxa
    throw UnimplementedError();
  }
}

void main() {
  final compras = <Pagamento>[Pix(50), Cheque(80)];
  for (final p in compras) {
    print('Total: R\$ ${p.total().toStringAsFixed(2)}');
  }
}

Resumo

  • abstract class é um molde: não vira objeto, mas pode ter campos, construtor e métodos prontos.
  • Método abstrato (double taxa();) e getter abstrato (String get nome;) não têm corpo: cada subclasse concreta é obrigada a implementá-los, com @override.
  • Os métodos prontos da mãe podem chamar os abstratos: o Dart usa a versão do objeto de verdade.
  • O tipo abstrato serve para variáveis e listas: <Pagamento>[Pix(50), Cartao(50)].
  • Erros de compilação (254): instanciar a classe abstrata; esquecer um membro; método sem corpo numa classe que não é abstract.
  • throw UnimplementedError() engana o compilador e estoura durante a execução (255): troque todo corpo provisório antes de entregar.
