Dart Exceções

Um programa pode estar escrito certinho, compilar sem nenhuma reclamação e, mesmo assim, tropeçar enquanto roda: alguém digita doze onde se esperava 12, uma lista não tem a posição pedida, uma conta divide por zero. Quando isso acontece, o Dart lança uma exceção (em inglês, exception, "algo fora do normal"). Se ninguém cuidar dela, o programa para na hora. Nesta aula você aprende a pegar a exceção com try e catch e a decidir o que fazer em vez de parar.

Você vai aprender
  • O que é uma exceção e o que o Dart mostra quando ninguém a trata (Unhandled exception: e o código de saída 255).
  • Como usar try ("tente") e catch ("pegue") para o programa continuar.
  • Como pegar só um tipo de exceção com on FormatException, e vários tipos com vários on.
  • Como ver o tipo da exceção e o caminho até ela: catch (e, s).
  • Como garantir que uma parte rode sempre, dando certo ou errado: finally ("finalmente").
  • Quando é melhor não usar exceção nenhuma: int.tryParse.

Todos os programas desta aula rodaram no Dart SDK 3.13.5 da máquina da Ana (usuária ana, computador notebook), salvos na pasta pessoal dela e executados com dart run arquivo.dart (veja Rodando um Programa).

A ideia: o plano B do caixa da padaria

A Ana trabalha no caixa da padaria. O normal é a cliente dizer quanto vai pagar, a Ana digitar o valor e calcular o troco. Mas às vezes acontece algo fora do normal: a máquina de cartão cai, a nota é falsa, a cliente fala "doze" e a Ana digita as letras em vez do número. A padaria tem um plano B para essas situações: "se a máquina cair, aceite Pix; se não der, anote no caderno". O atendimento não para por causa de um problema.

No Dart é igual:

  • O plano A é o código normal. Você o coloca dentro de um try { }: "tente fazer isto".
  • Se algo fora do normal acontecer lá dentro, o Dart lança uma exceção: um objeto que diz o que deu errado.
  • O plano B fica no catch { }: "se der problema, pegue a exceção e faça isto".
  • Sem plano B, a exceção "sobe" até o main, ninguém a pega, e o programa termina ali mesmo.
Exceção não é erro de compilação

Na aula Lendo uma Mensagem de Erro você viu os dois tipos de problema. O erro de compilação (main.dart:3:9: Error: …) aparece antes de o programa rodar: nada roda. A exceção aparece durante a execução: o que veio antes já rodou. O try/catch só serve para exceções; erro de compilação você conserta no código.

2. try e catch: o plano B

Agora o mesmo programa, com a parte arriscada dentro de um try:

void main() {
  print('Calculando o troco...');
  try {
    final pago = int.parse('doze');
    print('A cliente pagou $pago reais.');
  } catch (e) {
    print('Não deu para ler o valor: $e');
  }
  print('Fim do programa.');
}
try { … }
"Tente". O bloco com o plano A. O Dart roda as linhas dele em ordem, como sempre.
final pago = int.parse('doze');
Aqui a exceção é lançada. O Dart abandona o resto do try na mesma hora (o print('A cliente pagou…') não roda) e pula para o catch.
catch (e) { … }
"Pegue". O plano B. Só roda se alguma exceção foi lançada dentro do try. Os parênteses são obrigatórios.
e
Uma variável com a exceção que foi pega (o nome e é tradição; pode ser erro). Colocar $e num texto mostra a mensagem dela.
print('Fim do programa.');
Depois do catch, a vida segue: o programa continua normalmente.

3. on: pegar só o tipo que você espera

O catch (e) sozinho pega qualquer exceção, até as que você não imaginou (e talvez quisesse ver). Na maioria das vezes é melhor dizer qual problema você sabe tratar. Para isso existe o on ("em caso de"), seguido do tipo da exceção:

void main() {
  final textos = ['10', 'dez', '7'];
  for (final texto in textos) {
    try {
      final n = int.parse(texto);
      print('$texto virou o número $n');
    } on FormatException catch (e) {
      print('"$texto" não é número: ${e.message}');
    }
  }
}

$ dart run on.dart
10 virou o número 10
"dez" não é número: Invalid radix-10 number
7 virou o número 7
on FormatException
"Em caso de FormatException". Este plano B só vale para esse tipo de exceção.
catch (e)
Opcional depois do on: dá um nome à exceção, para você usar. Como o Dart já sabe que e é uma FormatException, dá para usar o que ela tem, como o e.message (só a mensagem, sem o nome do tipo).
o laço continua
O try está dentro do for: cada volta tem o seu plano B. O 'dez' deu problema, mas o '7' foi lido normalmente na volta seguinte.

Vários on, um para cada problema

Um mesmo try pode ter vários planos B. A Ana tem um estoque de caixas por posição na prateleira e quer saber quantos itens vão em cada pacote de 120. Três coisas podem dar errado: o pedido não ser número, a posição não existir, e a conta dividir por zero:

void main() {
  final estoque = [12, 0, 5];
  for (final pedido in ['1', '9', 'x', '0']) {
    try {
      final i = int.parse(pedido);
      final qtd = estoque[i];
      print('Posição $i: $qtd itens, ${120 ~/ qtd} por caixa');
    } on FormatException {
      print('"$pedido": isso não é uma posição.');
    } on RangeError catch (e) {
      print('"$pedido": posição fora da lista ($e)');
    } on UnsupportedError catch (e) {
      print('"$pedido": conta impossível ($e)');
    }
  }
}

$ dart run varios.dart
"1": conta impossível (IntegerDivisionByZeroException)
"9": posição fora da lista (RangeError (length): Invalid value: Not in inclusive range 0..2: 9)
"x": isso não é uma posição.
Posição 0: 12 itens, 10 por caixa
  • '1': a posição 1 tem 0 itens, e 120 ~/ 0 (divisão inteira por zero) lança IntegerDivisionByZeroException, que é um tipo de UnsupportedError ("operação não suportada").
  • '9': a lista só tem as posições 0, 1 e 2; pedir a 9 lança RangeError ("erro de intervalo"): "valor inválido, fora do intervalo 0..2: 9".
  • 'x': o int.parse lança FormatException. Aqui o on veio sem catch, porque a mensagem não era necessária.
  • '0': tudo deu certo, nenhum on rodou.

O Dart testa os on de cima para baixo e usa o primeiro cujo tipo combina. Os outros são pulados.

Exception e Error

Repare que alguns nomes terminam em Exception e outros em Error. No Dart, uma Exception é um problema esperado, que vem de fora (texto digitado errado, arquivo que não existe): faz sentido tratar. Um Error (RangeError, UnsupportedError…) quase sempre é um engano no código: o melhor conserto é corrigir o programa (conferir o tamanho da lista antes, não dividir por zero) e não esconder o problema com um catch. Os dois podem ser pegos; aqui os Error foram pegos só para você ver os nomes.

4. catch (e, s): o tipo e o caminho até o problema

O catch aceita uma segunda variável: o stack trace, o mesmo rastro que aparece no Unhandled exception. E toda exceção tem o runtimeType, o nome do tipo dela:

void main() {
  try {
    final lista = [1, 2, 3];
    print(lista[3]);
  } catch (e, s) {
    print('Erro: $e');
    print('Tipo: ${e.runtimeType}');
    print('Onde:');
    print(s);
  }
}

$ dart run pilha.dart
Erro: RangeError (length): Invalid value: Not in inclusive range 0..2: 3
Tipo: RangeError
Onde:

O s (de stack) é do tipo StackTrace. Ele é útil para anotar num arquivo de registro (um log) onde o problema aconteceu: aqui, pilha.dart, linha 4. Quando você só precisa de um aviso para a pessoa, o e basta. O runtimeType é bom para descobrir o tipo de uma exceção e depois escrever o on certo.

5. finally: o que roda sempre

Às vezes uma parte do código precisa rodar de qualquer jeito, dando certo ou errado: fechar o caixa no fim do atendimento, fechar um arquivo, mostrar "pronto". Para isso existe o finally ("finalmente"), que vem depois dos on/catch:

void main() {
  for (final valor in ['50', 'cinquenta']) {
    print('--- caixa aberto ---');
    try {
      final v = int.parse(valor);
      print('Recebido: R\$ $v');
    } on FormatException {
      print('Valor inválido: $valor');
    } finally {
      print('--- caixa fechado ---');
    }
  }
}

$ dart run finally.dart
--- caixa aberto ---
Recebido: R$ 50
--- caixa fechado ---
--- caixa aberto ---
Valor inválido: cinquenta
--- caixa fechado ---

Com '50', rodou o try inteiro e depois o finally. Com 'cinquenta', rodou o começo do try, o on e depois o finally. (O \$ em R\$ é para o Dart mostrar o cifrão em vez de achar que vem uma variável; veja Interpolação.)

O finally roda até quando ninguém pega a exceção. Um try pode ter só o finally, sem catch:

void main() {
  try {
    print('Abrindo o caixa');
    final v = int.parse('vinte');
    print('Recebido: $v');
  } finally {
    print('Fechando o caixa (sempre)');
  }
  print('Esta linha não roda');
}

Formas diferentes de fazer a mesma coisa

Para transformar texto em número, existe um jeito que não lança exceção: o int.tryParse ("tente converter"). Em vez de lançar FormatException, ele devolve null quando o texto não é número (veja Tipos Anuláveis):

void main() {
  for (final texto in ['12', 'doze']) {
    final n = int.tryParse(texto);
    if (n == null) {
      print('"$texto" não é número');
    } else {
      print('Número: $n');
    }
  }
  print(int.tryParse('doze') ?? 0);
}

$ dart run tp.dart
Número: 12
"doze" não é número
0

A última linha usa o ?? ("se for nulo, use este outro"; veja ?. , ?? e ??=) para ficar com 0 quando o texto não é número.

Resumo

  • Uma exceção é um problema que acontece enquanto o programa roda. Sem tratamento, o Dart mostra Unhandled exception:, o tipo, a mensagem e o stack trace, e termina com código 255.
  • No stack trace, procure a primeira linha com o seu arquivo: main (file:///home/ana/…dart:linha:coluna).
  • try { } é o plano A; catch (e) { } é o plano B. Quando a exceção é lançada, o resto do try é pulado e o programa continua depois do catch.
  • on Tipo pega só aquele tipo; com vários on, vale o primeiro que combina. Os outros tipos passam direto.
  • catch (e, s) dá também o stack trace; e.runtimeType mostra o tipo.
  • finally { } roda sempre, dando certo ou errado, mesmo quando ninguém pega a exceção.
  • Para converter texto, prefira int.tryParse; para enganos do código (RangeError, divisão por zero), conserte o código em vez de esconder com catch.
  • Na próxima aula, Lançando Exceções (throw), é você quem lança a exceção.
