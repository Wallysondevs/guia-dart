Dart na Web

O navegador (Chrome, Firefox, Safari…) não entende Dart: ele só roda JavaScript e WebAssembly. Mesmo assim, dá para fazer sites e apps web inteiros em Dart. O truque é compilar: o Dart traduz o seu programa para uma dessas duas línguas que o navegador conhece. Esta aula é uma visão geral do caminho, com o modelo de projeto web criado de verdade no lab da Ana. A parte que aparece na janela do navegador é ilustrativa (o lab não tem navegador); confira os detalhes em dart.dev/web.

Você vai aprender
  • Como o Dart chega ao navegador: compilado para JavaScript ou WebAssembly.
  • O que vem no modelo dart create -t web: index.html, main.dart e styles.css.
  • O que é o package:web, e por que ele substituiu o antigo dart:html.
  • Como ver o site no navegador (webdev serve) e como gerar o JavaScript à mão.
  • O que acontece quando se roda código de navegador com dart run.

Os comandos desta aula rodaram no Dart SDK 3.13.5 da máquina da Ana (usuária ana, computador notebook). Os programas do editor do guia rodam como programas de terminal: eles não mexem na página.

A ideia: o intérprete na reunião

A Ana só fala português, e o cliente da padaria só fala inglês. Ela contrata um tradutor, que prepara o texto em inglês antes da reunião. O cliente nunca ouve uma palavra em português, mas recebe exatamente o que a Ana quis dizer.

O navegador é o cliente; o compilador é o tradutor. Você escreve em Dart; o compilador entrega JavaScript (dart2js) ou WebAssembly (dart2wasm), e é isso que o navegador recebe junto com a página HTML.

A linha mais importante: carrega o JavaScript gerado a partir do main.dart. Repare: main.dart.js, não main.dart. Esse arquivo ainda não existe; ele é criado na compilação. O defer ("adiar") manda rodar só depois que a página carregou.

Uma caixa vazia com o nome (id) output ("saída"). O programa Dart vai escrever dentro dela.

O programa: web/main.dart

$ cat web/main.dart
import 'package:web/web.dart' as web;

void main() {
  final now = DateTime.now();
  final element = web.document.querySelector('#output') as web.HTMLDivElement;
  element.textContent =
      'The time is ${now.hour}:${now.minute} '
      'and your Dart web app is running!';
}
import 'package:web/web.dart' as web;
Traz o pacote web, com tudo que existe no navegador: a página, os botões, os eventos. O as web dá um apelido: tudo dele começa com web. (veja import, export e Bibliotecas).

A página aberta no navegador.

"Procure o elemento com id output": a div vazia do HTML. O # quer dizer "pelo id".

Diz ao Dart que o que veio é uma div (veja is, is! e as).

Troca o texto dentro da div. Os dois textos seguidos se juntam sozinhos (são "strings adjacentes").

2. package:web e o antigo dart:html

Em código e tutoriais antigos, você vai ver import 'dart:html';. Era a biblioteca de navegador que vinha com o Dart. Hoje a documentação oficial diz que as bibliotecas web antigas, como dart:html e dart:svg, estão obsoletas (deprecated) e não funcionam quando se compila para Wasm, e que o package:web as substitui "a longo prazo" (dart.dev/interop/js-interop/package-web). O package:web é construído sobre o dart:js_interop, a ponte entre Dart e JavaScript, e funciona tanto em JavaScript quanto em Wasm.

BibliotecaSituaçãoUse?
package:webAtual; funciona em JS e WasmSim
dart:js_interopAtual; conversa direto com JavaScriptPara chamar bibliotecas JavaScript
dart:htmlObsoleta; não funciona em WasmNão em código novo

3. Vendo o site: webdev serve (ilustrativo)

O caminho sugerido pelo próprio dart create é:

  1. dart pub global activate webdev: instala a ferramenta webdev uma vez no computador.
  2. webdev serve, dentro da pasta do projeto: compila e abre um servidor local. A documentação usa como exemplo o endereço localhost:8080.
  3. Abra esse endereço no Chrome. Mudou o main.dart? Salve e recarregue a página: o webdev recompila sozinho.

Para publicar o site, o webdev build gera a pasta final com o JavaScript otimizado.

Ou à mão: dart compile js

Sem o webdev, dá para gerar o main.dart.js que o index.html espera com o comando que você viu em Compilando:

$ dart compile js web/main.dart -o web/main.dart.js
Compiled 13,454,337 input bytes (8,024,796 characters source) to 129,997 characters JavaScript in 1.29 seconds
$ ls web
index.html
main.dart
main.dart.js
main.dart.js.deps
main.dart.js.map
styles.css

Agora a pasta web tem tudo que um navegador precisa: o HTML, o CSS e o JavaScript. Abrindo pelo servidor, a página funciona. Para Wasm, o comando é dart compile wasm:

$ dart compile wasm web/main.dart -o web/main.wasm
Generated wasm module 'web/main.wasm', and JS init file 'web/main.mjs'.

"Gerado o módulo wasm web/main.wasm e o arquivo JS de inicialização web/main.mjs": o navegador precisa de um pedacinho de JavaScript para carregar o Wasm (na pasta também apareceram main.support.js e main.wasm.map). Nesse caso, o index.html carrega o .mjs em vez do main.dart.js; veja os detalhes em dart.dev/web/wasm.

4. O Dart do site é o mesmo Dart

A parte que mexe na página é pequena; o resto é Dart comum: listas, mapas, funções, classes. Um bom costume é separar a lógica (que você testa no terminal) da parte que mexe na página. Por exemplo, a Ana quer mostrar a vitrine da padaria no site. A função que monta o HTML de cada item é Dart puro, e roda no terminal:

// Monta o HTML da vitrine da padaria como texto.
String itemLista(String produto, double preco) =>
    '<li>$produto: R\$ ${preco.toStringAsFixed(2)}</li>';

void main() {
  final produtos = {'Pão francês': 0.75, 'Sonho': 2.5, 'Café': 4.0};
  final html = StringBuffer('<ul id="vitrine">\n');
  for (final item in produtos.entries) {
    html.writeln('  ${itemLista(item.key, item.value)}');
  }
  html.write('</ul>');
  print(html);
}

$ dart run vitrine.dart
<ul id="vitrine">
  <li>Pão francês: R$ 0.75</li>
  <li>Sonho: R$ 2.50</li>
  <li>Café: R$ 4.00</li>
</ul>

No site, em vez de print, ela poria esse texto dentro de um elemento da página (ou criaria os elementos com o package:web). O toStringAsFixed(2) deixa sempre dois dígitos depois do ponto (veja Números), e o StringBuffer junta os pedaços (veja Montando Textos).

Quando dá errado

Rodar o programa de navegador com dart run

O main.dart do modelo web usa a página (document), que só existe dentro de um navegador. A Ana tentou rodar no terminal mesmo assim:

$ dart run web/main.dart; echo "codigo: $?"
../.pub-cache/hosted/pub.dev/web-1.1.1/lib/src/helpers.dart:24:8: Error: Dart library 'dart:js_interop' is not available on this platform.
import 'dart:js_interop';
       ^
Context: The unavailable library 'dart:js_interop' is imported through these packages:

    main.dart => package:web => dart:js_interop
    ...
« … mais de 22 mil linhas: 7.496 erros, todos dentro do pacote web … »
codigo: 254

A primeira linha diz tudo: "a biblioteca dart:js_interop não está disponível nesta plataforma". A plataforma aqui é a máquina virtual do Dart, a que roda programas de terminal. Ela não tem navegador, então não tem a ponte com o JavaScript. A linha Context mostra o caminho: o seu main.dart importa o package:web, que importa o dart:js_interop. Os milhares de erros seguintes são consequência desse primeiro (de novo: leia sempre o primeiro). O código 254 é o de erro de compilação. Como consertar: código que usa package:web roda pelo webdev serve (ou compilado com dart compile js/wasm) e aberto no navegador; a lógica que não mexe na página, separe em funções Dart puras, que rodam e se testam no terminal.

A página em branco

Se você abrir o index.html antes de compilar, o navegador procura o main.dart.js, não acha, e a div fica vazia. Não aparece erro na página: só nas ferramentas do desenvolvedor do navegador (F12, aba Console), como um arquivo não encontrado. Como consertar: use o webdev serve ou rode o dart compile js antes (ilustrativo: o lab não tem navegador).

Resumo

  • O navegador só roda JavaScript e WebAssembly: o Dart chega lá compilado (dart compile js / wasm, ou pelo webdev).
  • dart create -t web cria web/index.html (que carrega o main.dart.js), web/main.dart e web/styles.css.
  • Use package:web para mexer na página; o antigo dart:html está obsoleto e não funciona em Wasm.
  • webdev serve mostra o site num servidor local; webdev build gera a versão final.
  • Código de navegador não roda com dart run (dart:js_interop não existe no terminal). Separe a lógica em Dart puro, que roda e se testa em qualquer lugar.
