Dart Lendo uma Mensagem de Erro

Todo mundo que programa vê mensagens de erro o dia inteiro, inclusive quem programa há trinta anos. A diferença entre quem está começando e quem tem prática não é errar menos: é ler a mensagem e saber, em segundos, onde olhar. As mensagens do Dart são em inglês e parecem assustadoras, mas seguem sempre os mesmos dois formatos. Nesta aula, você vai aprender a desmontar cada um, peça por peça.

Você vai aprender
  • Os dois tipos de problema: erro de compilação (antes de rodar) e exceção (durante a execução).
  • As peças do erro de compilação: arquivo:linha:coluna, Error:, a mensagem, a linha do código, o ^^^, o Try … e o Context:.
  • As peças da exceção: Unhandled exception:, o tipo, a mensagem e o stack trace (#0, #1…).
  • Os códigos de saída: 0, 254, 255 e o seu próprio exit(n).
  • O que fazer quando vêm vários erros, e como o dart analyze conta os problemas.
  • Uma galeria com os erros e exceções mais comuns, todos colhidos no Dart de verdade, com a tradução.

Todas as mensagens desta aula saíram do Dart 3.13.5 da máquina da Ana (usuária ana, computador notebook), com dart run arquivo.dart, e foram copiadas exatamente como apareceram. O echo $? que aparece em alguns terminais é um comando do próprio terminal (não do Dart) que mostra o código de saída do último programa (veja Rodando um Programa).

A ideia: o revisor e o acidente de percurso

Imagine que a Ana escreveu as instruções do caixa num papel para o funcionário novo. Duas coisas podem dar errado:

  1. Antes de o funcionário começar, a gerente lê o papel e devolve: "linha 3: 'some três ao preço'? Três o quê? Não dá para seguir isso." O funcionário nem começou. Isso é o erro de compilação: o Dart lê o programa inteiro antes de rodar (isso se chama compilar) e recusa o que não faz sentido.
  2. O papel estava certo, o funcionário começou a atender e, no quarto cliente, a instrução mandou pegar o quarto pão do cesto, que só tinha três. Ele já tinha feito três atendimentos e parou no meio. Isso é a exceção: algo que só dá para descobrir rodando, com os dados de verdade.

1. As peças de um erro de compilação

void main() {
  print('Abrindo o caixa...');
  int quantidade = 'três';
  print('Quantidade: $quantidade');
}

$ dart run compilacao.dart
compilacao.dart:3:20: Error: A value of type 'String' can't be assigned to a variable of type 'int'.
  int quantidade = 'três';
                   ^
$ echo $?
254

Primeira coisa: o Abrindo o caixa... não apareceu, mesmo estando na linha 2, antes do problema. Com erro de compilação, nada roda. Agora, peça por peça:

compilacao.dart
O arquivo onde está o problema. Em programas de vários arquivos, olhe este nome primeiro.
:3
A linha 3. Os editores de código mostram o número de cada linha na margem.
:20
A coluna 20: o 20º caractere da linha, contando os espaços do começo e a partir de 1.
Error:
"Erro": o Dart recusou o programa.
A value of type 'String' can't be assigned to a variable of type 'int'.
A mensagem: "um valor do tipo String não pode ser guardado numa variável do tipo int". O texto 'três' não é um número inteiro (veja Os Tipos Básicos).
int quantidade = 'três';
A linha do código, copiada do seu arquivo, para você não precisar procurar.
^
O acento circunflexo fica embaixo da coluna exata. Às vezes vem um só (^), às vezes vários (^^^^), sublinhando a palavra inteira.

E o echo $? mostrou 254: é o código de saída que o dart run devolve quando o programa não compila. Nenhuma linha do seu programa rodou.

As linhas extras: Try …, - 'X' is from … e Context:

Muitas mensagens trazem linhas a mais. Este programa chama um método com a letra errada (toUppercase, com "c" minúsculo):

$ dart run metodo_errado.dart
metodo_errado.dart:3:14: Error: The method 'toUppercase' isn't defined for the type 'String'.
Try correcting the name to the name of an existing method, or defining a method named 'toUppercase'.
  print(nome.toUppercase());
             ^^^^^^^^^^^

A linha que começa com Try ("tente") é uma sugestão: "corrija o nome para o de um método que existe, ou crie um método com esse nome". O nome certo é toUpperCase, com "C" maiúsculo: o Dart diferencia maiúsculas de minúsculas.

Quando o problema envolve dois lugares do código, vem também um Context: ("contexto"), que não é outro erro: é o outro lugar, para você comparar. Aqui, uma função que pede dois valores recebeu um só:

double total(double preco, int quantidade) => preco * quantidade;

void main() {
  print(total(4.0));
}

$ dart run argumentos.dart
argumentos.dart:4:14: Error: Too few positional arguments: 2 required, 1 given.
  print(total(4.0));
             ^
argumentos.dart:1:8: Context: Found this candidate, but the arguments don't match.
double total(double preco, int quantidade) => preco * quantidade;
       ^^^^^

"Poucos argumentos posicionais: 2 obrigatórios, 1 dado." O erro está na linha 4 (a chamada). O Context: aponta a linha 1 (a declaração da função): "encontrei esta candidata, mas os argumentos não combinam". Com as duas na tela, fica fácil ver que faltou a quantidade. Você também vai ver linhas como - 'Produto' is from 'loja.dart'., que só dizem em que arquivo um tipo foi declarado.

2. Vários erros de uma vez

O Dart não para no primeiro erro: ele lista todos os que encontrou, na ordem em que aparecem no arquivo.

void main() {
  final nome = 'Ana'
  print('Olá, $nmoe!');
  int idade = '30';
}

$ dart run tres_erros.dart
tres_erros.dart:2:16: Error: Expected ';' after this.
  final nome = 'Ana'
               ^^^^^
tres_erros.dart:3:16: Error: Undefined name 'nmoe'.
  print('Olá, $nmoe!');
               ^^^^
tres_erros.dart:4:15: Error: A value of type 'String' can't be assigned to a variable of type 'int'.
  int idade = '30';
              ^

Cada erro é um bloco que começa com arquivo:linha:coluna: Error:. Para contar quantos são, conte as linhas com Error:: aqui, três. O dart run não escreve o total, mas o dart analyze (o analisador; aula Análise e Formatação) escreve, num formato de uma linha por problema:

$ dart analyze tres_erros.dart

  error - tres_erros.dart:3:16 - Undefined name 'nmoe'. Try correcting the name to one that is defined, or defining the name. - undefined_identifier
  error - tres_erros.dart:4:15 - A value of type 'String' can't be assigned to a variable of type 'int'. Try changing the type of the variable, or casting the right-hand type to 'int'. - invalid_assignment
warning - tres_erros.dart:2:9 - The value of the local variable 'nome' isn't used. Try removing the variable or using it. - unused_local_variable
warning - tres_erros.dart:4:7 - The value of the local variable 'idade' isn't used. Try removing the variable or using it. - unused_local_variable

$ echo $?
3
  • Cada linha tem: a gravidade (error = erro, warning = aviso, e existe também info), arquivo:linha:coluna, a mensagem, e no fim um código (undefined_identifier) que serve para pesquisar.
  • 5 issues found.: "5 problemas encontrados" (3 erros e 2 avisos). Os avisos não impedem o programa de rodar; aqui dizem que as variáveis nome e idade nunca foram usadas.
  • O dart analyze não roda o programa, só o lê. O código de saída dele foi 3 (havia erros).
A regra dos vários erros: conserte o primeiro e rode de novo

Um erro pode causar outros "de tabela": uma aspa esquecida, por exemplo, gera três mensagens para uma linha só (veja a galeria abaixo). Por isso: leia todos, conserte o primeiro, rode de novo. Muitas vezes os outros somem junto.

Missão: este é o tres_erros.dart, com uma linha a mais que mostra a idade. Rode, leia as mensagens e conserte uma por uma (a idade é o número 30, não o texto), até aparecer Olá, Ana! e Idade: 30.

void main() {
  final nome = 'Ana'
  print('Olá, $nmoe!');
  int idade = '30';
  print('Idade: $idade');
}

void main() {
  final nome = 'Ana';
  print('Olá, $nome!');
  int idade = 30;
  print('Idade: $idade');
}

void main() {
  print('Abrindo o caixa...');

Desta vez o programa compilou e começou: as duas primeiras linhas saíram. Na linha 5 ele parou, e o Fechando o caixa. nunca apareceu. Peça por peça:

Unhandled exception:
"Exceção não tratada". Uma exceção é um aviso de "algo deu errado" que o programa lança durante a execução. "Não tratada" quer dizer que nenhuma parte do seu código cuidou dela (como se cuida, com try/catch, é a próxima aula: Exceções), então o programa inteiro parou.
RangeError
O tipo da exceção: "erro de intervalo". O tipo é a primeira palavra; ele já diz muito (veja a tabela da seção 6).
(length): Invalid value: Not in inclusive range 0..2: 3
A mensagem: "valor inválido: não está no intervalo de 0 a 2 (inclusive): 3". A lista tem 3 itens, nas posições 0, 1 e 2; a posição 3 não existe (veja Listas).
#0 List.[] (dart:core-patch/growable_array.dart)
O começo do stack trace ("rastro da pilha"): a lista de funções que estavam em andamento quando a exceção aconteceu. A #0 é onde ela nasceu: dentro do [] da lista, no código do próprio Dart (dart:core).
#1 main (file:///home/ana/excecao.dart:5:31)
Quem chamou a #0: a sua função main, no arquivo /home/ana/excecao.dart, linha 5, coluna 31, o [3]. Esta é a linha que importa.
#2 e #3 (_delayEntrypointInvocation, _RawReceivePort)
São do Dart, que chamou o seu main. Aparecem no fim de todo stack trace; pode ignorá-las.

O código de saída foi 255: o de exceção não tratada.

Como achar a sua linha no stack trace

Leia de cima para baixo e pare na primeira linha com o seu arquivo (file:///home/ana/…). As linhas com dart:core, dart:collection, dart:isolate são da biblioteca do Dart: o erro estourou lá dentro, mas quem pediu a coisa errada foi você. Repare também que o stack trace mostra o caminho completo (file:///home/ana/excecao.dart), enquanto o erro de compilação mostra só o nome (excecao.dart).

Um stack trace mais comprido

Quando uma função chama outra, que chama outra, o rastro mostra o caminho inteiro, de dentro para fora:

double lerPreco(String texto) {
  return double.parse(texto);
}

double somarCarrinho(List<String> precos) {
  var total = 0.0;
  for (final p in precos) {
    total += lerPreco(p);
  }
  return total;
}

void main() {
  print('Somando o carrinho...');
  final total = somarCarrinho(['4.00', '20.00', 'seis']);
  print('Total: $total');
}

$ dart run profundo.dart
Somando o carrinho...
Unhandled exception:
FormatException: Invalid double
seis
#0      double.parse (dart:core-patch/double_patch.dart:111:7)
#1      lerPreco (file:///home/ana/profundo.dart:2:17)
#2      somarCarrinho (file:///home/ana/profundo.dart:8:14)
#3      main (file:///home/ana/profundo.dart:15:17)
#4      _delayEntrypointInvocation.<anonymous closure> (dart:isolate-patch/isolate_patch.dart:313:19)
#5      _RawReceivePort._handleMessage (dart:isolate-patch/isolate_patch.dart:192:12)

A mensagem tem duas linhas: FormatException: Invalid double ("exceção de formato: double inválido") e, embaixo, o texto que causou o problema: seis. O rastro se lê como uma história, de baixo para cima: o main (linha 15) chamou somarCarrinho, que na linha 8 chamou lerPreco, que na linha 2 chamou double.parse, que não conseguiu ler "seis". A primeira linha sua é a #1, mas o conserto pode estar mais embaixo: quem mandou o texto 'seis' foi o main, na #3. É a missão final desta aula.

4. Os códigos de saída

Todo programa, ao terminar, devolve um número ao terminal: o código de saída. Zero quer dizer "deu tudo certo"; qualquer outro número, "algo deu errado". Programas que rodam outros programas (scripts, testes automáticos) olham esse número. Os do Dart, conferidos no lab:

CódigoQuando
0O programa terminou normalmente
254Erro de compilação: nada rodou
255Exceção não tratada: parou no meio. Também sai 255 quando o arquivo nem existe (Could not find file `naoexiste.dart`)
o que você escolherexit(n), de dart:io: você mesmo encerra com o código n
import 'dart:io';

void main() {
  print('Estoque vazio, nada a fazer.');
  exit(3);
}

$ dart run saida3.dart
Estoque vazio, nada a fazer.
$ echo $?
3

Nada de mensagem de erro: o programa decidiu sair com o código 3, e só quem olha o $? fica sabendo. (No editor do guia, o código de saída aparece depois de cada Rodar; veja O Editor do Guia.)

5. Galeria: erros de compilação comuns

Todos colhidos no lab. Para cada um: a mensagem, a tradução e o conserto.

Faltou o ponto e vírgula 
$ dart run ponto_virgula.dart
ponto_virgula.dart:2:23: Error: Expected ';' after this.
  final total = 4.0 + 20.0

"Era esperado ; depois disto." Os ^^^^ marcam a última coisa antes do lugar onde falta o ;. Conserto: final total = 4.0 + 20.0; (veja Instruções, Ponto e Vírgula e Blocos).

Nome escrito errado

"Nome não definido: precoTotla." A variável se chama precoTotal; o Dart não adivinha. Também aparece quando a variável foi criada dentro de um bloco e usada fora dele.

Método que não existe nesse tipo

The method 'toUppercase' isn't defined for the type 'String'. (seção 1). Variações: The getter 'x' isn't defined for the type 'Y'. (para campos e getters). Confira a grafia, maiúsculas e minúsculas, e se o objeto é mesmo do tipo que você pensa.

"Não encontrei a } que fecha esta {." O ^ aponta a chave que abriu (a do for, linha 3). O arquivo tem uma } no fim, mas ela fechou o for, e o main ficou aberto. Conserto: acrescente a } que falta. Indentar direito (2 espaços por nível) ajuda a ver qual sobrou.

Aspas que abriram e não fecharam: três erros para uma linha 
$ dart run aspas.dart
aspas.dart:2:9: Error: String starting with ' must end with '.
  print('Bom dia, Ana!);
        ^^^^^^^^^^^^^^^^
aspas.dart:2:8: Error: Can't find ')' to match '('.
  print('Bom dia, Ana!);
       ^
aspas.dart:2:9: Error: Expected ';' after this.
  print('Bom dia, Ana!);
        ^^^^^^^^^^^^^^^^

O primeiro erro é a causa: "um texto que começa com ' tem de terminar com '". Como a aspa não fechou, o Dart achou que o ); fazia parte do texto, e daí vieram os outros dois ("não achei o )", "faltou ;"). É o exemplo perfeito da regra: conserte o primeiro, print('Bom dia, Ana!');, e os três somem.

Valor que pode ser null 
import 'dart:io';

void main() {
  final nome = stdin.readLineSync();
  print(nome.toUpperCase());
}

$ dart run nulo_compila.dart
nulo_compila.dart:5:14: Error: Method 'toUpperCase' cannot be called on 'String?' because it is potentially null.
Try calling using ?. instead.
  print(nome.toUpperCase());
             ^^^^^^^^^^^

"O método não pode ser chamado em String?, porque ele pode ser null." O ? no fim do tipo é o aviso (veja Null Safety e Lendo o Teclado). Conserto: nome?.toUpperCase(), (nome ?? '').toUpperCase() ou um if (nome != null).

Quando dá errado (ao ler o erro)

O erro aponta uma linha, mas o problema está em outra

No chave.dart, o problema era a } que faltou lá embaixo, e o Dart apontou a { da linha 3. No ponto_virgula.dart, o ^ ficou embaixo do 20.0, e o ; faltava logo depois dele. A linha e a coluna dizem onde o Dart percebeu o problema, que nem sempre é onde você errou. Olhe também a linha de cima e o par (abre/fecha) do símbolo apontado.

Consertou o lugar da #0, que não era seu

No profundo.dart, a #0 é double.parse (dart:core-patch/…). Esse arquivo é da biblioteca do Dart: não há o que consertar lá. Pule as linhas dart: e vá à primeira com file:///home/ana/….

Achou que o programa "não fez nada"

Com erro de compilação, nem o primeiro print aparece, e quem não lê a mensagem pensa que o programa "travou" ou "não funciona". Se nada da sua saída apareceu, procure um Error: na tela; se metade apareceu, procure um Unhandled exception:. E na dúvida, echo $?: 254 ou 255 dizem qual dos dois foi.

Resumo

  • Erro de compilação: aparece antes de rodar, nada do programa executa, código de saída 254. Formato: arquivo:linha:coluna: Error: mensagem, a linha do código e o ^; às vezes um Try (sugestão) e um Context: (o outro lugar).
  • Exceção: aparece rodando, o que veio antes já saiu, código de saída 255. Formato: Unhandled exception:, o tipo e a mensagem, e o stack trace (#0 é onde nasceu; desça até a primeira linha com o seu arquivo).
  • Vários erros: conserte o primeiro e rode de novo. O dart analyze lista erros e avisos e conta: N issues found.
  • A linha apontada é onde o Dart percebeu, nem sempre onde você errou: olhe a linha de cima e o par do símbolo.
  • Código de saída: 0 deu certo, 254 não compilou, 255 exceção (ou arquivo inexistente), e exit(n) para escolher o seu.
