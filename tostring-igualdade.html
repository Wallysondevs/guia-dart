Dart toString, == e hashCode

Toda classe do Dart herda três coisas de Object (veja Herança): o toString(), que diz como o objeto vira texto; o operador ==, que diz quando dois objetos são iguais; e o hashCode, um número que o Set e o Map usam para achar as coisas depressa. As versões de Object funcionam, mas quase nunca do jeito que a Ana espera: o print mostra Instance of 'Produto', e dois cafés de R$ 4,00 são "diferentes". Nesta aula, você vai sobrescrever os três.

Você vai aprender
  • Por que o print mostra Instance of 'Produto' e como trocar isso com toString().
  • A diferença entre ser o mesmo objeto (identical) e ter os mesmos dados.
  • Como escrever o seu operator ==, com Object other e is.
  • Por que, ao mudar o ==, é obrigatório mudar o hashCode (com Object.hash), e o que dá errado no Set e no Map se você esquecer.
  • Que os records já fazem tudo isso sozinhos.
  • Os erros reais: parâmetro do == com o tipo errado, toString que não devolve texto, e o as dentro do ==.

Todos os programas desta aula rodaram no Dart 3.13.5 da máquina da Ana (usuária ana, computador notebook), com dart run arquivo.dart. Ajuda ter visto Sobrescrevendo (@override).

A ideia: gêmeos idênticos

Duas notas de R$ 10 são "iguais"? Para pagar o pão, sim: valem o mesmo. Mas são duas notas diferentes, cada uma com o seu número de série. Depende da pergunta:

  • "É a mesma nota?" (o mesmo objeto, no mesmo lugar da memória) → no Dart, identical(a, b).
  • "Vale o mesmo?" (os mesmos dados) → no Dart, a == b, se você ensinar à classe o que "valer o mesmo" significa.

O == que vem de Object responde à primeira pergunta: só dá true se for o mesmo objeto. Para os seus produtos, quase sempre você quer a segunda.

1. O toString() de fábrica e o seu

class Produto {
  final String nome;
  final double preco;

  Produto(this.nome, this.preco);
}

void main() {
  final cafe = Produto('Café', 4.0);
  print(cafe);
  print('No carrinho: $cafe');
  print([cafe, Produto('Bolo', 20.0)]);
}

$ dart run padrao.dart
Instance of 'Produto'
No carrinho: Instance of 'Produto'
[Instance of 'Produto', Instance of 'Produto']

"Uma instância de Produto": verdade, mas inútil. O print, a interpolação ('$cafe') e o print de uma lista chamam o toString() de cada objeto, e o de Object só sabe o nome da classe. Sobrescrevendo:

class Produto {
  final String nome;
  final double preco;

  Produto(this.nome, this.preco);

  @override
  String toString() => 'Produto($nome, R\$ ${preco.toStringAsFixed(2)})';
}

void main() {
  final cafe = Produto('Café', 4.0);
  print(cafe);
  print('No carrinho: $cafe');
  print([cafe, Produto('Bolo', 20.0)]);
  print(cafe.toString().length);
}

$ dart run com_tostring.dart

No carrinho: Produto(Café, R$ 4.00)
[Produto(Café, R$ 4.00), Produto(Bolo, R$ 20.00)]
22
@override
Estamos substituindo o toString() herdado de Object.
String toString()
Tem de ser exatamente assim: nome toString, sem parâmetros, devolvendo String.
'Produto($nome, R\$ …)'
O formato é você quem escolhe. O costume é NomeDaClasse(dados), que facilita achar erros: ao imprimir uma lista, você vê o que tem dentro.

Até a lista ficou legível, e você não chamou toString() em lugar nenhum: o Dart chama sozinho. (A última linha mostra que dá para chamar à mão também: o texto tem 22 caracteres.)

2. O == de fábrica compara se é o mesmo objeto

class Produto {
  final String nome;
  final double preco;

  Produto(this.nome, this.preco);
}

void main() {
  final a = Produto('Café', 4.0);
  final b = Produto('Café', 4.0);
  final c = a;

  print(a == b);
  print(a == c);
  print(identical(a, c));
  print('Café' == 'Café');
  print(4.0 == 4);
  print([a].contains(b));
}

$ dart run igual_padrao.dart
false
true
true
true
true
false
  • a == b deu false: são dois objetos criados separadamente (duas notas de R$ 10). Os dados são iguais, mas o == de Object não olha os dados.
  • a == c deu true: final c = a; não criou outro produto; c é outro nome para o mesmo. O identical(a, c) confirma.
  • 'Café' == 'Café' e 4.0 == 4 deram true: os tipos do Dart (String, int, double, bool…) já vêm com um == que compara valores. As suas classes, não.
  • [a].contains(b) deu false: o contains das listas usa o ==. A Ana procuraria um café no carrinho e não acharia.

3. Escrevendo o seu == e o seu hashCode

class Produto {
  final String nome;
  final double preco;

  Produto(this.nome, this.preco);

  @override
  bool operator ==(Object other) =>
      other is Produto && other.nome == nome && other.preco == preco;

  @override
  int get hashCode => Object.hash(nome, preco);

  @override
  String toString() => 'Produto($nome, $preco)';
}

void main() {
  final a = Produto('Café', 4.0);
  final b = Produto('Café', 4.0);
  final d = Produto('Café', 4.5);

  print(a == b);
  print(a == d);
  print(identical(a, b));
  print([a].contains(b));
  print(a.hashCode == b.hashCode);
  print(a == 'Café');

  final vitrine = {a, b, d};
  print(vitrine);
  print(vitrine.length);
}
bool operator ==(Object other)
Operadores também são métodos, e se sobrescrevem com a palavra operator. O parâmetro tem de ser Object, porque dá para comparar um produto com qualquer coisa (um texto, um número). O nome other ("o outro") é o costume.
other is Produto && …
Primeiro pergunta se o outro é um produto. Se não for, o && para ali e o resultado é false. Se for, o Dart passa a tratá-lo como Produto (promoção de tipo), e other.nome funciona.
other.nome == nome && other.preco == preco
A sua definição de "iguais": mesmo nome e mesmo preço.
int get hashCode => Object.hash(nome, preco);
O hashCode é um getter que devolve um número calculado a partir dos mesmos campos usados no ==. Object.hash faz a conta para você, com quantos campos quiser.

Agora a == b é true (mesmos dados), mesmo não sendo o mesmo objeto (identical continua false). O café de R$ 4,50 é diferente. Comparar com um texto dá false, sem erro. E o Set (veja Conjuntos), que não guarda repetidos, ficou com dois produtos, não três: ele percebeu que a e b são o mesmo café.

A regra de ouro

Se dois objetos são ==, eles têm de ter o mesmo hashCode. Por isso: mudou o ==, mude o hashCode, usando os mesmos campos. (O contrário não precisa: objetos diferentes podem, raramente, ter o mesmo hashCode.) E prefira campos final: se o preço mudasse depois de o produto entrar num Set, o hashCode mudaria e o Set se perderia.

Experimente: mude o == para comparar só o nome (apague o && other.preco == preco) e o hashCode para nome.hashCode. Quantos produtos ficam na vitrine agora?

class Produto {
  final String nome;
  final double preco;

  Produto(this.nome, this.preco);

  @override
  bool operator ==(Object other) =>
      other is Produto && other.nome == nome && other.preco == preco;

  @override
  int get hashCode => Object.hash(nome, preco);

  @override
  String toString() => 'Produto($nome, $preco)';
}

void main() {
  final vitrine = {
    Produto('Café', 4.0),
    Produto('Café', 4.0),
    Produto('Café', 4.5),
  };
  print(vitrine);
  print(vitrine.length);
}

4. O que acontece se esquecer o hashCode

Este é o erro mais traiçoeiro da aula, porque o Dart não reclama de nada. O == foi sobrescrito, o hashCode não:

class Produto {
  final String nome;
  final double preco;

  Produto(this.nome, this.preco);

  @override
  bool operator ==(Object other) =>
      other is Produto && other.nome == nome && other.preco == preco;

  @override
  String toString() => 'Produto($nome, $preco)';
}

void main() {
  final a = Produto('Café', 4.0);
  final b = Produto('Café', 4.0);
  print(a == b);
  final vitrine = {a, b};
  print(vitrine.length);
  final estoque = {a: 10};
  print(estoque[b]);
}

$ dart run sem_hashcode.dart
true
2
null

O == diz que a e b são iguais, mas o Set guardou os dois, e o Map (veja Mapas) não achou o estoque do café ao procurar com b: deu null. Por quê? O Set e o Map funcionam como um armário de gavetas numeradas: primeiro usam o hashCode para escolher a gaveta, e só dentro dela usam o ==. Com o hashCode de Object, cada objeto cai numa gaveta diferente, e o == nem chega a ser chamado. Com o hashCode da seção 3, o mesmo estoque[b] devolve 10 (conferido no lab).

O analisador avisa

O dart run não reclama, mas o dart analyze (aula Análise e Formatação) tem uma regra exatamente para isso. Num projeto criado com dart create (que já liga as regras recomendadas), este mesmo arquivo, posto em bin/, deu no lab:

5. Records já comparam por valor

Se você só precisa agrupar alguns dados, sem métodos, os records (Dart 3.0) já vêm com toString, == e hashCode prontos, comparando os campos:

void main() {
  final a = (nome: 'Café', preco: 4.0);
  final b = (nome: 'Café', preco: 4.0);
  print(a);
  print(a == b);
  print({a, b}.length);
}

Missão final: clientes sem repetição

Missão: a Bia foi cadastrada duas vezes, e o Set não percebeu. Faça a classe Cliente mostrar Cliente(Bia) no print e considerar iguais os clientes com o mesmo telefone (sobrescreva toString, == e hashCode). A saída deve ser {Cliente(Bia), Cliente(Caio)} e 2 clientes.

class Cliente {
  final String nome;
  final String telefone;

  Cliente(this.nome, this.telefone);
}

void main() {
  final clientes = {
    Cliente('Bia', '99999-1234'),
    Cliente('Bia', '99999-1234'),
    Cliente('Caio', '98888-0000'),
  };
  print(clientes);
  print('${clientes.length} clientes');
}

class Cliente {
  final String nome;
  final String telefone;

  Cliente(this.nome, this.telefone);

  @override
  String toString() => 'Cliente($nome)';

  @override
  bool operator ==(Object other) => other is Cliente && other.telefone == telefone;

  @override
  int get hashCode => telefone.hashCode;
}

void main() {
  final clientes = {
    Cliente('Bia', '99999-1234'),
    Cliente('Bia', '99999-1234'),
    Cliente('Caio', '98888-0000'),
  };
  print(clientes);
  print('${clientes.length} clientes');
}

No lab, o código inicial mostrou {Instance of 'Cliente', Instance of 'Cliente', Instance of 'Cliente'} e 3 clientes; a solução, {Cliente(Bia), Cliente(Caio)} e 2 clientes. Com um campo só, o hashCode pode ser o do próprio campo (telefone.hashCode).

Resumo

  • Toda classe herda toString(), == e hashCode de Object.
  • toString() de fábrica dá Instance of 'X'; sobrescreva para o print e as listas ficarem legíveis.
  • O == de fábrica só diz se é o mesmo objeto (como identical). Para comparar dados, sobrescreva bool operator ==(Object other) com other is X && …, nunca com as.
  • Mudou o ==, mude o hashCode com os mesmos campos (Object.hash(a, b)). Sem isso, nada reclama, mas Set e Map erram calados.
  • Records já comparam por valor e se mostram bem no print.
