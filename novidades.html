Dart Novidades

Esta página reúne, numa vitrine, o que entrou na linguagem Dart desde o Dart 3.0 (2023) até o 3.13 (agosto de 2026), a versão do laboratório. Cada novidade tem um exemplo pequeno, rodado de verdade, e o selo da versão em que chegou. Se você encontrar código com uma dessas coisas e o seu Dart reclamar, a aula de Versões explica por quê. As aulas de cada assunto têm os detalhes; aqui é o "o que mudou".

Você vai aprender
  • O que o Dart 3.0 trouxe: records, patterns, expressões switch, if-case e modificadores de classe.
  • As novidades seguintes, uma por versão: extension types, separador de dígitos, variáveis curinga, ? dentro de coleções e atalhos com ponto.
  • As duas mais novas: parâmetros nomeados privados (3.12) e construtores primários (3.13).
  • O que aparece quando o código usa uma novidade numa versão antiga.

Todos os exemplos rodaram no Dart SDK 3.13.5 da máquina da Ana (usuária ana, computador notebook), em arquivos soltos numa pasta novidades (arquivos soltos usam a versão de linguagem do próprio SDK). A lista de novidades vem da página Language evolution e do CHANGELOG do SDK.

A ideia: o celular que atualiza

De tempos em tempos o celular da Ana recebe uma atualização. Quase sempre é invisível (correções); às vezes vem um botão novo que deixa algo mais rápido. O Dart é parecido: a maioria das versões não muda a linguagem, e as que mudam quase sempre trazem um atalho para algo que já dava para fazer de um jeito mais comprido. Você nunca é obrigado a usar a novidade; mas vai encontrá-la no código dos outros.

1. Dart 3.0 A grande reforma

O Dart 3.0 tornou o null safety obrigatório e trouxe, de uma vez, cinco recursos que mudaram o jeito de escrever Dart. Este programa usa quase todos, mais o atalho do 3.10 e o separador do 3.6:

enum Tamanho { pequeno, medio, grande }

(String, double) maisCaro(Map<String, double> precos) {
  var nome = '';
  var maior = 0.0;
  for (final MapEntry(:key, :value) in precos.entries) {
    if (value > maior) {
      (nome, maior) = (key, value);
    }
  }
  return (nome, maior);
}

void main() {
  final (nome, preco) = maisCaro({'Pão': 0.75, 'Bolo': 12.0, 'Sonho': 2.5});
  print('Mais caro: $nome, R\$ $preco');

  Tamanho cafe = .grande;
  final ml = switch (cafe) {
    .pequeno => 50,
    .medio => 100,
    .grande => 200,
  };
  print('Café $cafe: $ml ml');
  final populacao = 1_000_000;
  print(populacao);
}

$ dart run dart3.dart; echo "codigo: $?"
Mais caro: Bolo, R$ 12.0
Café Tamanho.grande: 200 ml
1000000
codigo: 0
(String, double)
Um record: a função devolve dois valores juntos, sem precisar criar uma classe. Veja Records.
final (nome, preco) = …
Um pattern de desestruturação: abre o record e guarda cada parte numa variável. Também em (nome, maior) = (key, value) e no MapEntry(:key, :value) do for. Veja Patterns.
switch (cafe) { … => … }
A expressão switch: escolhe um valor (e não só executa comandos). O Dart confere se todos os casos do enum foram cobertos. Veja switch.

Os outros dois recursos do 3.0: o if-case (if (valor case int n when n > 0), um if que testa um pattern) e os modificadores de classe (sealed, final, base, interface, veja sealed, final, base e interface).

2. Dart 3.3 Extension types

Um extension type dá um nome e métodos novos a um tipo que já existe, sem criar um objeto extra na memória. A Ana guarda preços em centavos (int), mas quer mostrá-los em reais:

extension type Centavos(int valor) {
  String get emReais => 'R\$ ${(valor / 100).toStringAsFixed(2)}';
}

void main() {
  final preco = Centavos(275);
  print(preco.emReais);
  print(preco.valor);
}

$ dart run extensao.dart; echo "codigo: $?"
R$ 2.75
275
codigo: 0

Por dentro, preco é só o int 275; por fora, ele tem o tipo Centavos e o getter emReais. É usado sobretudo na ponte com JavaScript (o package:web de Dart na Web é feito disso) e em bibliotecas. Parece com as Extensões, mas cria um tipo novo.

3. Dart 3.6 Separador de dígitos

Números grandes podem ter _ entre os dígitos, só para facilitar a leitura: 1_000_000 é exatamente 1000000 (veja a saída do programa da seção 1). Vale para int e double: no lab, print(1_250.50) mostrou 1250.5.

4. Dart 3.7 Variáveis curinga (_)

Um parâmetro ou variável local chamado _ agora quer dizer "não vou usar isto". Ele não cria variável nenhuma, então pode aparecer várias vezes:

void main() {
  final precos = [0.75, 2.5, 4.0];
  precos.forEach((_) => print('item'));
  final (_, segundo, _) = (10, 20, 30);
  print(segundo);
  var _ = 1;
  var _ = 2;
  print('ok');
}

$ dart run curinga.dart; echo "codigo: $?"
item
item
item
20
ok
codigo: 0

Antes do 3.7, _ era um nome comum, e repeti-lo dava erro. Com // @dart=3.6 na primeira linha do mesmo arquivo:

$ dart run curinga_36.dart; echo "codigo: $?"
curinga_36.dart:8:7: Error: '_' is already declared in this scope.
  var _ = 2;
      ^
curinga_36.dart:7:7: Context: Previous declaration of '_'.
  var _ = 1;
      ^
codigo: 254

"_ já foi declarado neste escopo", e o Context aponta a declaração anterior, na linha 7.

5. Dart 3.8 Elementos que aceitam nulo (?item)

Dentro de uma lista, um conjunto ou um mapa, um ? antes do elemento quer dizer "ponha só se não for nulo":

void main() {
  String? sobremesa;
  String? bebida = 'café';
  final pedido = ['pão', ?sobremesa, ?bebida];
  print(pedido);
}

$ dart run nulos.dart; echo "codigo: $?"
[pão, café]
codigo: 0

A sobremesa é null e ficou de fora. Antes, escrevia-se if (sobremesa != null) sobremesa (veja if e for Dentro de Coleções).

Missão: troque o if (manteiga != null) manteiga pelo atalho do Dart 3.8. A saída não muda.

void main() {
  String? manteiga = 'manteiga';
  String? geleia;
  final compras = ['pão', 'leite', if (manteiga != null) manteiga, ?geleia];
  print(compras);
}

void main() {
  String? manteiga = 'manteiga';
  String? geleia;
  final compras = ['pão', 'leite', ?manteiga, ?geleia];
  print(compras);
}

6. Dart 3.10 Atalhos com ponto

Quando o Dart já sabe qual tipo espera, você pode omitir o nome do tipo e começar com o ponto: Tamanho cafe = .grande; em vez de Tamanho.grande, e os casos .pequeno => 50 do switch da seção 1. No Flutter, isso encurta muito o código: crossAxisAlignment: .start. A aula de Versões mostra o erro que aparece num projeto com sdk: ^3.9.0.

7. Dart 3.12 Parâmetros nomeados privados

Campos privados começam com _ (veja Privacidade). Até o 3.11, um parâmetro nomeado não podia começar com _, e era preciso uma "lista de inicialização" para copiar o valor. Agora, this._titular num parâmetro nomeado funciona, e quem chama usa o nome sem o _:

class Conta {
  final String _titular;
  double _saldo;

  Conta({required this._titular, this._saldo = 0});

  String get resumo => '$_titular: R\$ $_saldo';
}

void main() {
  final conta = Conta(titular: 'Ana', saldo: 150);
  print(conta.resumo);
}

$ dart run privado.dart; echo "codigo: $?"
Ana: R$ 150.0
codigo: 0

8. Dart 3.13 Construtores primários

A novidade da versão do lab. Até agora, uma classe simples precisava repetir cada campo três vezes: na declaração, no construtor e no this.. Com um construtor primário, os parâmetros vão direto no cabeçalho da classe, e cada um com final ou var vira um campo:

class Produto(final String nome, final double preco);

class Ponto(var int x, var int y) {
  new origem() : this(0, 0);
}

void main() {
  final pao = Produto('Pão francês', 0.75);
  print('${pao.nome}: R\$ ${pao.preco}');
  final p = Ponto.origem();
  p.x = 3;
  print('(${p.x}, ${p.y})');
}

$ dart run primario.dart; echo "codigo: $?"
Pão francês: R$ 0.75
(3, 0)
codigo: 0
class Produto(final String nome, final double preco);
Uma classe inteira numa linha: dois campos final e o construtor Produto(nome, preco). O ; no fim quer dizer "sem corpo".
class Ponto(var int x, var int y) { … }
Com var, os campos podem mudar (p.x = 3). Aqui a classe tem corpo.
new origem() : this(0, 0);
Um construtor nomeado declarado com new, sem repetir o nome da classe (antes seria Ponto.origem()). Ele chama o construtor primário com 0 e 0.

Compare com o jeito de antes, que continua valendo (veja Construtores):

class Produto {
  final String nome;
  final double preco;

  Produto(this.nome, this.preco);
}

A mudança que quebra código antigo

Para abrir espaço para os construtores primários, o Dart 3.13 passou a reservar final e var nos parâmetros. Um final num parâmetro de função comum, que antes era permitido, agora é erro:

void dobrar(final int x) {
  print(x * 2);
}

void main() {
  dobrar(21);
}

$ dart run final_param.dart; echo "codigo: $?"
final_param.dart:1:13: Error: Can't have modifier 'final' here.
Try removing 'final'.
void dobrar(final int x) {
            ^^^^^
codigo: 254

"Não pode haver o modificador final aqui. Tente removê-lo." Como consertar: void dobrar(int x). (O CHANGELOG do 3.13 lista isso como breaking change, "mudança que quebra".)

Quando dá errado

Usar uma novidade numa versão de linguagem antiga

O mesmo primario.dart, com // @dart=3.12 na primeira linha (como se o projeto fosse Dart 3.12):

$ dart run primario_312.dart; echo "codigo: $?"
primario_312.dart:2:14: Error: The 'primary-constructors' language feature is disabled for this library.
Try removing the `@dart=` annotation or setting the language version to 3.13 or higher.
class Produto(final String nome, final double preco);
             ^
primario_312.dart:1:1: Context: This is the annotation that opts out this library from the 'primary-constructors' language feature.
// @dart=3.12
^^^^^^^^^^^^^
« … o mesmo erro mais 5 vezes, em cada ponto do código que usa o recurso … »
codigo: 254

Linha por linha: "o recurso de linguagem primary-constructors está desligado nesta biblioteca"; "tente remover a anotação @dart= ou usar a versão de linguagem 3.13 ou maior"; e o Context aponta o culpado: "esta é a anotação que tira esta biblioteca do recurso", a linha 1. Quando a versão vem do pubspec.yaml, a mensagem é parecida, e o conserto é subir o sdk: e rodar dart pub get (veja Versões).

Copiar um exemplo novo num Dart velho

Se o Dart instalado for anterior ao recurso (por exemplo, um SDK 3.9 lendo .grande), não há o que ligar: o SDK simplesmente não conhece a sintaxe e recusa o código. Confira a sua versão com dart --version e compare com o selo da novidade.

Resumo

  • 3.0: null safety obrigatório, records, patterns, expressões switch, if-case e modificadores de classe.
  • 3.3 extension types · 3.6 1_000_000 · 3.7 curinga _ · 3.8 ?item em coleções · 3.10 .grande · 3.12 this._campo em parâmetro nomeado.
  • 3.13: construtores primários, class Produto(final String nome, final double preco);, e new nome() no corpo; final/var em parâmetro comum virou erro.
  • Novidade numa versão de linguagem antiga dá erro (…language feature is disabled… ou This requires the experimental '…' language feature): suba a versão no pubspec.yaml ou tire o // @dart=.
