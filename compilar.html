Dart compile

Até aqui, você rodou tudo com dart run main.dart. Isso funciona, mas exige que o computador tenha o Dart SDK instalado. E se a Ana quiser mandar o programa da padaria para o dono, que não sabe o que é Dart? Ela compila o programa: transforma o .dart num executável, um arquivo que roda sozinho, como qualquer outro programa do computador. O comando é o dart compile ("compilar").

Você vai aprender
  • O que é compilar e qual a diferença entre dart run e um executável.
  • Como gerar um executável com dart compile exe e escolher o nome com -o.
  • Que o executável roda num computador sem Dart, e por que ele é grande.
  • Os outros formatos: js (para o navegador), kernel, aot-snapshot e wasm.
  • O que acontece quando o código tem erro na hora de compilar.

Todos os comandos desta aula rodaram no Dart SDK 3.13.5 da máquina da Ana (usuária ana, computador notebook, Linux), numa pasta compilar. O editor do guia roda programas, mas não gera executáveis: compilar é coisa do terminal.

A ideia: a receita e o bolo pronto

O arquivo .dart é uma receita. Para comer o bolo, alguém precisa de cozinha, forno e saber cozinhar: é o Dart SDK, que lê a receita e executa na hora (o dart run). Compilar é assar o bolo e entregar pronto numa caixa: quem recebe só abre e come, sem cozinha nenhuma.

  • Vantagem: o executável roda em qualquer computador com o mesmo sistema (Linux, Windows ou macOS) e começa mais rápido, porque o trabalho de tradução já foi feito.
  • Desvantagem: o bolo pronto não se muda. Mexeu no código? Compile de novo. E um executável do Linux não roda no Windows: cada sistema precisa do seu.

1. O programa de exemplo

Um programa que cumprimenta quem for passado na linha de comando (os argumentos, que chegam na lista args):

void main(List<String> args) {
  final nome = args.isEmpty ? 'mundo' : args.first;
  print('Olá, $nome!');
}

$ dart run ola.dart Ana
Olá, Ana!

Com dart run, o Dart lê o ola.dart, traduz e roda, tudo de uma vez, toda vez.

O comando de compilar.

O formato: "executável" (executable), um programa que roda sozinho.
ola.dart
O arquivo com o main, o ponto de partida.
Generated: /home/ana/compilar/ola.exe
"Gerado": o caminho do executável criado. Por padrão, ele tem o mesmo nome do .dart com .exe no fim, até no Linux.

No ls -l, o x quer dizer "pode ser executado", e o tamanho é 6.503.384 bytes (uns 6 MB). O ola.dart tem só 110 bytes.
./ola.exe Ana
Roda o executável. O ./ diz "o arquivo desta pasta". O Ana chega no args, como no dart run.

Escolhendo o nome com -o

No Linux e no macOS, programas não costumam ter .exe no nome. A opção -o (de output, "saída") escolhe o nome do arquivo:

$ dart compile exe ola.dart -o ola
Generated: /home/ana/compilar/ola
$ ./ola Bia
Olá, Bia!
$ ls -lh ola
-rwxrwxr-x 1 ana ana 6,3M Oct 19 16:58 ola
$ file ola
ola: ELF 64-bit LSB pie executable, x86-64, version 1 (SYSV), dynamically linked, interpreter /lib64/ld-linux-x86-64.so.2, for GNU/Linux 2.6.32, BuildID[sha1]=6c7bdb85e417b100de2b2c268a0409f55b61d0a1, stripped

O comando file conta o que o arquivo é: ELF 64-bit … executable, x86-64 … for GNU/Linux, um executável de verdade do Linux para processadores x86-64 (os da Intel e da AMD). É o mesmo tipo de arquivo do ls e do bash. Não sobrou nada de Dart visível nele.

Por que 6 MB para um "Olá"?

O executável leva junto um pedaço do Dart: o runtime (o que cuida da memória, das exceções, do print…). Por isso ele roda sozinho. Esse pedaço tem tamanho fixo: um programa dez vezes maior não gera um executável dez vezes maior.

O time mede quanto o comando demorou (a linha real é o tempo de relógio). 4. Os outros formatos

Digitando dart compile sozinho, o Dart lista todos:

$ dart compile
Missing subcommand for "dart compile".

Usage: dart compile <subcommand> [arguments]
-h, --help    Print this usage information.

Available subcommands:
  js             Compile Dart to JavaScript.
  jit-snapshot   Compile Dart to a JIT snapshot.
  kernel         Compile Dart to a kernel snapshot.
  exe            Compile Dart to a self-contained executable.
  aot-snapshot   Compile Dart to an AOT snapshot.
  wasm           Compile Dart to a WebAssembly/WasmGC module.

Run "dart help" to see global options.

"Falta o subcomando". Cada um gera um tipo de "bolo":

FormatoGeraPara quê
exeExecutável que roda sozinhoEntregar um programa de terminal. O mais usado.
jsArquivo .js (JavaScript)Rodar no navegador (veja Dart na Web).
wasmMódulo WebAssemblyTambém para o navegador, num formato mais rápido.
aot-snapshotArquivo .aotO programa já traduzido, mas sem o runtime: precisa do dartaotruntime para rodar. Menor que o exe.
kernelArquivo .dillUm formato intermediário, que o dart run lê mais rápido que o .dart.
jit-snapshotArquivo .jitUm retrato do programa depois de rodar uma vez (o comando roda o programa para "aquecer"); uso avançado.

AOT e JIT são dois jeitos de traduzir: ahead-of-time ("antes da hora": traduz tudo antes de rodar, como no exe) e just-in-time ("na hora certa": traduz enquanto roda, como no dart run, o que permite o hot reload do Flutter).

Para JavaScript

$ dart compile js ola.dart -o ola.js

$ head -c 300 ola.js; echo
// Generated by dart2js (, csp, intern-composite-values), the Dart to JavaScript compiler version: 3.13.5.

O compilador (o dart2js) leu cerca de 10 MB (o seu programa e as bibliotecas do Dart) e gerou 97.468 caracteres de JavaScript: só o que o programa usa. A primeira linha do arquivo confirma: "gerado pelo dart2js, o compilador de Dart para JavaScript, versão 3.13.5". Junto vieram o ola.js.map (para depurar no navegador) e o ola.js.deps (a lista de arquivos usados).

Quando dá errado

Código com erro não vira executável 
void main() {
  print('oi')
}

$ dart compile exe erro.dart; echo "codigo: $?"
erro.dart:2:13: Error: Expected ';' after this.
  print('oi')
            ^
Error: AOT compilation failed
Bad state: Generating AOT kernel dill failed!
codigo: 254

Linha por linha:

  • erro.dart:2:13: Error: Expected ';' after this.: o mesmo erro que o dart run mostraria. "Era esperado ; depois disto", linha 2, coluna 13; embaixo, a linha do código e o ^ no ponto.
  • Error: AOT compilation failed: "a compilação AOT falhou".
  • Bad state: Generating AOT kernel dill failed!: um detalhe interno, "a geração do arquivo intermediário falhou". Pode ignorar: o que importa é a primeira linha.
  • codigo: 254: o mesmo código de saída de um erro de compilação no dart run.

E nenhum erro.exe foi criado. Como consertar: ponha o ; e compile de novo.

Mudou o código e o executável continua velho

O executável é um retrato do código no momento em que foi compilado. Se a Ana mudar o print no ola.dart e rodar ./ola, vai ver a mensagem antiga. Não há aviso nenhum: o ./ola não sabe que o .dart existe. Como consertar: rode o dart compile exe de novo depois de cada mudança.

Missão final: o caixa da padaria

Missão: a Ana quer compilar um caixa que recebe a quantidade e o preço na linha de comando: ./caixa 3 7.5. O editor roda com esses dois argumentos. Converta o primeiro com int.parse e o segundo com double.parse, multiplique e mostre Total: R$ 22.5.

void main(List<String> args) {
  final quantidade = int.parse(args[0]);
  // converta args[1] para double e calcule o total

  print('Quantidade: $quantidade');
}

void main(List<String> args) {
  final quantidade = int.parse(args[0]);
  final preco = double.parse(args[1]);
  final total = quantidade * preco;
  print('Total: R\$ $total');
}

Depois de funcionar, no terminal seria só dart compile exe main.dart -o caixa e ./caixa 3 7.5. (O \$ mostra o cifrão de verdade. Sem a barra, 'Total: R$ $total' nem compila: no lab, deu Error: A '$' has special meaning inside a string, and must be followed by an identifier or an expression in curly braces ({})., "o $ tem significado especial dentro de um texto", com a sugestão Try adding a backslash (\) to escape the '$'., "tente pôr uma barra invertida antes".)

Resumo

  • Compilar transforma o .dart num arquivo pronto. O dart run traduz toda vez; o executável já vem traduzido.
  • dart compile exe main.dart -o nome gera um executável que roda sem Dart, no mesmo sistema (Linux, Windows ou macOS) em que foi gerado. Ele tem uns 6 MB porque leva o runtime.
  • Rode com ./nome argumentos; recompile sempre que mudar o código.
  • Outros formatos: js e wasm (navegador), aot-snapshot (precisa do dartaotruntime), kernel e jit-snapshot.
  • Código com erro não compila: a explicação está nas primeiras linhas (arquivo:linha:coluna: Error: …), e o código de saída é 254.
