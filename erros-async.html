Dart Erros em Código Assíncrono

Tarefas demoradas falham: a internet cai, o servidor responde "não encontrado", o arquivo não existe. Quando a tarefa é um Future, o erro acontece no futuro, e isso muda as regras que você aprendeu em Exceções. A boa notícia: com await, o velho try/catch volta a funcionar do jeito de sempre. A má: sem o await, ele não pega nada, e o Dart não avisa.

Você vai aprender
  • Como usar try/catch/finally com await.
  • Por que um try sem await deixa o erro escapar.
  • Como ler o stack trace assíncrono, com as linhas <asynchronous suspension>.
  • O que acontece com Future.wait quando uma das tarefas falha.
  • Como desistir de uma tarefa que demora demais: timeout e TimeoutException.
  • A pegadinha do catchError, com o erro real.

Esta aula usa async e await. Todos os programas rodaram no Dart SDK 3.13.5 da máquina da Ana (usuária ana, computador notebook), com dart run arquivo.dart. As tarefas demoradas são simuladas com Future.delayed.

A ideia: a encomenda que não chegou

A Ana encomenda farinha ao fornecedor por telefone. Há dois jeitos de lidar com o risco de a encomenda dar errado:

  • Ela espera na linha a resposta ("aguarde um momento…"). Se o fornecedor disser "acabou a farinha", ela ouve na hora e já pensa no plano B. É o try com await.
  • Ela desliga logo depois de pedir e vai cuidar do caixa. Se o fornecedor ligar de volta com uma má notícia, ninguém está perto do telefone para atender. É o try sem await: quando o erro chega, o try já acabou faz tempo.

1. try/catch com await

Future<int> lerEstoque(String produto) async {
  await Future.delayed(Duration(seconds: 1));
  if (produto == 'pizza') {
    throw StateError('não vendemos $produto');
  }
  return 30;
}

Future<void> main() async {
  for (final p in ['pão', 'pizza', 'bolo']) {
    try {
      final n = await lerEstoque(p);
      print('$p: $n');
    } on StateError catch (e) {
      print('$p: ${e.message}');
    } finally {
      print('  (consulta de $p encerrada)');
    }
  }
}

$ dart run r1.dart
pão: 30
  (consulta de pão encerrada)
pizza: não vendemos pizza
  (consulta de pizza encerrada)
bolo: 30
  (consulta de bolo encerrada)
throw StateError(…) numa função async
Numa função async, o throw não estoura na hora: ele faz o Future devolvido terminar com erro.
await lerEstoque(p) dentro do try
O await espera o Future. Se ele terminar com erro, o await lança esse erro ali mesmo, na linha do await, dentro do try. Daí em diante é tudo igual ao que você já sabe.
on StateError catch (e)
Pega o erro do Future como pegaria um erro comum.
finally
Roda no fim de cada consulta, com ou sem erro, também com await.

Repare que a pizza falhou e o laço seguiu para o bolo: o erro foi tratado dentro da volta.

2. O try sem await não pega nada

Agora o mesmo tipo de erro, mas a Ana esqueceu o await:

}

Future<void> main() async {
  try {

3. O erro sobe pelos await

Quando uma função async chama outra com await, e ninguém trata o erro, ele vai subindo de função em função, como numa exceção comum:

Future<int> lerEstoque(String produto) async {
  await Future.delayed(Duration(seconds: 1));
  if (produto == 'pizza') {
    throw StateError('não vendemos $produto');
  }
  return 30;
}

Future<void> verificar(String produto) async {
  final n = await lerEstoque(produto);
  print('$produto: $n');
}

Future<void> main() async {
  await verificar('pão');
  await verificar('pizza');
  print('Fim');
}

$ dart run r3.dart
pão: 30
Unhandled exception:
Bad state: não vendemos pizza
#0      lerEstoque (file:///home/ana/r3.dart:4:5)
<asynchronous suspension>
#1      verificar (file:///home/ana/r3.dart:10:13)
<asynchronous suspension>
#2      main (file:///home/ana/r3.dart:16:3)
<asynchronous suspension>
$ echo $?
255

Agora o stack trace mostra o caminho inteiro, porque cada função estava aguardando a de baixo: o erro nasceu em lerEstoque (linha 4), passou pelo await da verificar (linha 10) e pelo await do main (linha 16). Cada <asynchronous suspension> marca uma espera. Você pode tratar o erro em qualquer um desses andares; a missão final faz isso na verificar.

4. Future.wait quando uma tarefa falha

Future<int> lerEstoque(String produto, int segundos) async {
  await Future.delayed(Duration(seconds: segundos));
  if (produto == 'pizza') {
    throw StateError('não vendemos $produto');
  }
  print('  $produto respondeu');
  return 30;
}

Future<void> main() async {
  try {
    final todos = await Future.wait([
      lerEstoque('pão', 1),
      lerEstoque('pizza', 2),
      lerEstoque('bolo', 3),
    ]);
    print('Todos: $todos');
  } catch (e) {
    print('Falhou: $e');
  }
}

$ dart run r4.dart
  pão respondeu
  bolo respondeu
Falhou: Bad state: não vendemos pizza

Repare na ordem: a pizza falhou aos 2 segundos, mas o Falhou só apareceu depois de bolo respondeu (aos 3). O Future.wait esperou todas as tarefas terminarem e só então lançou o erro da pizza. E a lista todos nunca existiu: o resultado do pão e do bolo se perdeu, mesmo eles tendo respondido. Se você precisa dos resultados que deram certo, trate o erro dentro de cada tarefa (com try na função, devolvendo, por exemplo, 0 ou null quando falhar).

5. Demorou demais: timeout

Às vezes o problema não é um erro, é a demora: o fornecedor não responde nunca. O método timeout ("tempo esgotado") dá um prazo ao Future. Se o prazo acabar antes, ele lança uma TimeoutException, que mora na biblioteca dart:async (por isso o import; veja import):

import 'dart:async';

Future<String> consultarFornecedor() async {
  await Future.delayed(Duration(seconds: 3));
  return 'farinha chega amanhã';
}

Future<void> main() async {
  try {
    final resposta =
        await consultarFornecedor().timeout(Duration(seconds: 1));
    print(resposta);
  } on TimeoutException catch (e) {
    print('Demorou demais: $e');
  }
}

$ dart run r5.dart
Demorou demais: TimeoutException after 0:00:01.000000: Future not completed

"Tempo esgotado depois de 1 segundo: o Future não terminou". O fornecedor levaria 3 segundos; o prazo era 1.

Formas diferentes de fazer a mesma coisa

Com then, o erro se trata com catchError (aula Future). Há uma pegadinha: o catchError de um Future<int> tem de devolver um int, o valor que vai ficar no lugar do que falhou:

Future<int> lerEstoque(String produto) async {
  await Future.delayed(Duration(seconds: 1));
  throw StateError('não vendemos $produto');
}

Future<void> main() async {
  final n = await lerEstoque('pizza').catchError((e) {
    print('Erro: $e');
    return 0;
  });
  print('n = $n');
}

$ dart run r7.dart
Erro: Bad state: não vendemos pizza
n = 0

Sem o return 0;, dá erro (veja Quando dá errado).

Como consertar: devolva um valor (return 0;), como em Formas diferentes, ou troque por try/catch com await.

O try sem await

Já visto na seção 2: o programa mostra tudo o que vem depois do try e, mais tarde, morre com Unhandled exception, sem o seu main no stack trace. Como consertar: await na chamada dentro do try.

Referência rápida

  await verificar('pão');

  print('Fim');

Resumo

  • Numa função async, o throw faz o Future terminar com erro.
  • O await transforma esse erro numa exceção comum, na linha do await: o try/catch/finally funciona como sempre.
  • Sem await, o try termina antes do erro chegar e não pega nada; o programa morre depois com Unhandled exception.
  • <asynchronous suspension> no stack trace marca cada await pelo caminho.
  • Future.wait falha inteiro se uma tarefa falhar; timeout lança TimeoutException.
  • O catchError tem de devolver um valor do tipo do Future; com await, prefira try/catch.
