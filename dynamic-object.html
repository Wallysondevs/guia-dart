Dart dynamic e Object

Até aqui, toda variável tinha um tipo só: uma String guarda texto, um int guarda inteiro, e o Dart não deixa misturar. Mas às vezes você precisa de uma variável que aceite qualquer coisa: uma sacola com pão, um número e um true dentro, ou dados que chegam de fora e você ainda não sabe o que são. Para isso o Dart tem dois tipos: Object e dynamic. Eles parecem iguais, mas têm uma diferença enorme, e esta aula é sobre ela.

Você vai aprender
  • Por que uma variável criada com var não pode trocar de tipo.
  • O tipo Object: aceita qualquer valor, mas só deixa usar o que todo valor tem.
  • Como o is libera o resto: if (caixa is String).
  • O tipo dynamic: aceita qualquer valor e desliga a conferência do Dart.
  • A armadilha do var sem valor inicial, e o Object? para aceitar também o null.
  • Os erros reais: o erro de compilação do Object e o NoSuchMethodError do dynamic.

Todos os programas desta aula rodaram no Dart 3.13.5 da máquina da Ana (usuária ana, computador notebook), com dart run arquivo.dart.

A ideia: a caixa fechada e a caixa sem etiqueta

Na lojinha da Ana chegam caixas. Ela tem dois jeitos de recebê-las:

  • Object: a caixa fechada com o aviso "conteúdo variado". Cabe qualquer coisa. Mas, enquanto a caixa está fechada, a Ana só faz o que dá para fazer com qualquer caixa: olhar a etiqueta, pesar. Para usar o conteúdo, ela primeiro abre e confere: "é um pacote de café? Então posso passar o café".
  • dynamic: o funcionário apressado que não confere nada. Ele pega a caixa e já sai fazendo: "vou ligar esta TV!". Se for uma TV, ótimo. Se for um pacote de café, o problema só aparece na hora, na frente do cliente.

O Dart normalmente confere tudo antes de rodar o programa (é por isso que erros como "A value of type 'int' can't be assigned…" aparecem sem nada rodar). O Object mantém essa conferência; o dynamic desliga.

1. Lembrete: var escolhe um tipo e fica com ele

void main() {
  var etiqueta = 'Pão';
  etiqueta = 30;
  print(etiqueta);
}

$ dart run err_var.dart
err_var.dart:3:14: Error: A value of type 'int' can't be assigned to a variable of type 'String'.
  etiqueta = 30;
             ^

O var não quer dizer "qualquer tipo". Ele quer dizer "Dart, descubra o tipo pelo valor inicial". Com 'Pão', o Dart decidiu: etiqueta é String, para sempre. Depois disso, um 30 não entra (veja Variáveis). Para uma variável que aceite tipos diferentes, é preciso dizer isso com todas as letras.

2. Object: aceita tudo, confere tudo

Todo valor do Dart (texto, número, bool, lista) é um Object (em inglês, "objeto"). Por isso, uma variável Object aceita qualquer um deles:

void main() {
  Object caixa = 'Pão';
  print(caixa);
  caixa = 30;
  print(caixa);
  caixa = 4.5;
  print(caixa);
  caixa = true;
  print(caixa);
  print(caixa.runtimeType);
  print(caixa.toString());
}

$ dart run objeto.dart
Pão
30
4.5
true
bool
true

Texto, inteiro, double, bool: tudo coube. E dá para fazer com ela o que todo objeto sabe fazer: print, toString(), runtimeType, comparar com ==. Mas experimente pedir algo que só um texto tem:

void main() {
  Object caixa = 'Pão';
  print(caixa.length);
}

$ dart run err_object.dart
err_object.dart:3:15: Error: The getter 'length' isn't defined for the type 'Object'.
 - 'Object' is from 'dart:core'.
Try correcting the name to the name of an existing getter, or defining a getter or field named 'length'.
  print(caixa.length);
              ^^^^^^
err_object.dart:3:15: Error:
Linha 3, coluna 15, erro de compilação: nada rodou.
The getter 'length' isn't defined for the type 'Object'.
"A propriedade length não está definida para o tipo Object." Hoje a caixa tem um texto, mas a variável é Object; amanhã pode ter um número, que não tem length. O Dart olha o tipo da variável, não o que está dentro agora.
- 'Object' is from 'dart:core'.
Uma informação extra: "Object vem da biblioteca dart:core", a biblioteca básica que todo programa já tem.
Try correcting the name…
A sugestão de sempre ("tente corrigir o nome…"). Aqui o nome está certo; o problema é o tipo.

O is abre a caixa

Para usar o conteúdo, confira o tipo com is ("é"). Dentro do if, o Dart já sabe que é um texto e libera tudo o que o texto tem:

void main() {
  Object caixa = 'Pão de queijo';
  if (caixa is String) {
    print(caixa.length);
    print(caixa.toUpperCase());
  }
  caixa = 7;
  if (caixa is int) {
    print(caixa + 1);
  }
}

$ dart run promocao.dart
13
PÃO DE QUEIJO
8

Isso se chama promoção de tipo (type promotion): depois do caixa is String dar true, a variável é tratada como String dentro do bloco. O is tem aula própria: is, is! e as.

Missão: este programa não compila: Object não tem length. Ponha o print dentro de um if (caixa is String) { … } para ele mostrar 13.

void main() {
  Object caixa = 'Pão de queijo';
  print(caixa.length);
}

void main() {
  Object caixa = 'Pão de queijo';
  if (caixa is String) {
    print(caixa.length);
  }
}

3. dynamic: aceita tudo, não confere nada

Com dynamic (em inglês, "dinâmico": o tipo só é visto durante a execução), o Dart deixa você usar qualquer propriedade e qualquer método, sem conferir:

void main() {
  dynamic coisa = 'Pão';
  print(coisa.length);
  coisa = 30;
  print(coisa + 1);
  coisa = [1, 2, 3];
  print(coisa.length);
  print(coisa.runtimeType);
}

$ dart run dinamico.dart
3
31
3
List<int>

Parece mais prático que o Object: nada de is. O preço aparece quando você erra. Troque o texto por um número e peça o length:

void main() {
  dynamic coisa = 30;
  print(coisa.length);
}

4. O dynamic escondido: var sem valor

Um var sem valor inicial não tem de onde descobrir o tipo. Aí ele vira dynamic, sem avisar:

void main() {
  var coisa;
  coisa = 'Pão';
  coisa = 30;
  print(coisa);
  print(coisa.length);
}

$ dart run var_sem.dart
30
Unhandled exception:
NoSuchMethodError: Class 'int' has no instance getter 'length'.
Receiver: 30
Tried calling: length
#0      Object.noSuchMethod (dart:core-patch/object_patch.dart:38:5)
#1      main (file:///home/ana/var_sem.dart:6:15)
#2      _delayEntrypointInvocation.<anonymous closure> (dart:isolate-patch/isolate_patch.dart:313:19)

A variável aceitou texto e depois número (o 30 apareceu), e o coisa.length passou pela compilação: sinal de dynamic. Boa prática: dê sempre um valor inicial ao var, ou escreva o tipo: String coisa;.

5. E o null?

Object aceita qualquer valor, menos o null (o "nada"). Para aceitar o null também, ponha um ?: Object?. O dynamic aceita null sem pedir nada:

void main() {
  Object caixa = null;
  dynamic coisa = null;
  print(caixa);
}

$ dart run err_null.dart
err_null.dart:2:18: Error: A value of type 'Null' can't be assigned to a variable of type 'Object'.
 - 'Object' is from 'dart:core'.
  Object caixa = null;
                 ^

"Um valor do tipo Null não pode ser atribuído a uma variável do tipo Object." Repare que só a linha 2 deu erro; a do dynamic passou. Com o ?:

void main() {
  Object? caixa = null;
  dynamic coisa = null;
  print(caixa);
  print(coisa);
  print(coisa.length);
}

$ dart run objnull.dart
null

Receiver: null
Tried calling: length

#1      main (file:///home/ana/objnull.dart:6:15)

"A propriedade length foi chamada em null": o erro mais famoso da programação, que o Dart só deixou acontecer porque a variável era dynamic. Por que o ? e o null importam tanto é o assunto da próxima aula, Null Safety.

6. Uma lista de coisas variadas

Um uso real do Object: uma lista com valores de tipos diferentes.

void main() {
  List<Object> sacola = ['Pão', 3, 4.5, true];
  for (var item in sacola) {
    print('$item é ${item.runtimeType}');
  }
}

$ dart run lista.dart
Pão é String
3 é int
4.5 é double
true é bool

List<Object> quer dizer "lista de Object" (veja Listas), e o for passa por cada item (veja for-in). Você vai ver o dynamic de novo em JSON: dados que chegam de fora, cujo formato o Dart não conhece de antemão.

Quando dá errado

Pediu ao Object algo que só um tipo tem

Você viu na seção 2: The getter 'length' isn't defined for the type 'Object'. Com um método, a mensagem diz The method '…' isn't defined for the type 'Object'.. Como consertar: confira com if (caixa is String) antes de usar, ou, se a variável só vai guardar texto, declare-a como String.

Nome do método digitado errado

Com o tipo certo, o Dart pega o erro de digitação antes de rodar:

void main() {
  String nome = 'ana';
  print(nome.toUppercase());
}

$ dart run err_digito2.dart
err_digito2.dart:3:14: Error: The method 'toUppercase' isn't defined for the type 'String'.
Try correcting the name to the name of an existing method, or defining a method named 'toUppercase'.
  print(nome.toUppercase());
             ^^^^^^^^^^^

Com dynamic, o mesmo erro de digitação passa na compilação e só estoura ao rodar:

void main() {
  dynamic nome = 'ana';
  print(nome.toUppercase());
}

$ dart run err_digito.dart

"A classe String não tem o método toUppercase." O nome certo é toUpperCase, com C maiúsculo. Como consertar: o nome certo, e um tipo de verdade no lugar do dynamic, para o Dart voltar a conferir.

null num Object

Seção 5: A value of type 'Null' can't be assigned to a variable of type 'Object'. Como consertar: Object?, se o "nada" for um valor válido ali.

var sem valor virou dynamic

Seção 4: o programa compilou e parou com NoSuchMethodError. Como consertar: var coisa = 'Pão'; (com valor) ou String coisa; (com tipo).

Missão final: só os textos da sacola

Missão: a sacola tem textos e números misturados. O programa não compila, porque Object não tem toUpperCase(). Ponha um if (item is String) em volta do print, para mostrar só os textos, em maiúsculas: PÃO e LEITE.

void main() {
  List<Object> sacola = ['pão', 3, 'leite', 4.5];
  for (var item in sacola) {
    print(item.toUpperCase());
  }
}

void main() {
  List<Object> sacola = ['pão', 3, 'leite', 4.5];
  for (var item in sacola) {
    if (item is String) {
      print(item.toUpperCase());
    }
  }
}

No lab, a solução mostrou:

$ dart run sacola.dart
PÃO
LEITE

Resumo

  • var com valor inicial fixa o tipo; ele não quer dizer "qualquer tipo".
  • Object aceita qualquer valor (menos null; para ele, Object?), mas só deixa usar o que todo valor tem. Para o resto, confira com is: dentro do if, o tipo é promovido.
  • dynamic aceita tudo e desliga a conferência: o erro de tipo vira NoSuchMethodError no meio da execução.
  • var x; sem valor inicial é dynamic: dê um valor ou escreva o tipo.
  • Prefira o tipo certo; depois Object/Object?; e dynamic só quando precisar mesmo.
