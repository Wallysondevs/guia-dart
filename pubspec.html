Dart pubspec.yaml

Todo projeto criado com dart create tem, na raiz, um arquivo chamado pubspec.yaml. Ele é a ficha de identidade do projeto: o nome, a versão, com qual Dart ele funciona e de quais pacotes ele precisa. É ele que o dart pub get lê para baixar os pacotes, e é por causa dele que o dart run sabe que está dentro de um projeto.

Você vai aprender
  • O formato YAML: chave: valor, indentação com espaços e comentários.
  • Para que serve cada campo: name, description, version, environment, dependencies, dev_dependencies.
  • Como ler uma restrição de versão como ^1.9.0.
  • O que é o pubspec.lock e quando rodar dart pub get.
  • Como ver os pacotes do projeto com dart pub deps e dart pub outdated.
  • Os erros reais: tab na indentação, nome com traço, SDK incompatível, versão que não existe e a indentação esquecida (que não dá erro, mas estraga).

Tudo nesta aula rodou no Dart 3.13.5 da máquina da Ana (usuária ana, computador notebook), num projeto criado com dart create confeitaria, com internet. As versões de pacotes mostradas (path 1.9.1, lints 6.0.0…) eram as do dia em que a aula foi feita; no seu computador podem ser mais novas.

No editor do guia não há pubspec.yaml

O editor desta página roda só código Dart, sem projeto e sem baixar pacotes. Tudo o que envolve pubspec.yaml e dart pub é para o terminal do seu computador. As caixas "Experimente" praticam as ideias (versões, mapas de dependências) em código Dart.

A ideia: a ficha da receita

Na confeitaria, cada receita tem uma ficha: o nome do bolo, a versão da receita ("versão 2: menos açúcar"), o forno em que ela funciona ("forno a gás, 180 °C ou mais") e a lista de ingredientes que vêm de fora ("chocolate da marca X, qualquer lote da linha 1"). Qualquer confeiteira que pega a ficha sabe o que comprar antes de começar.

O pubspec.yaml é essa ficha. "pub" é o nome do gerenciador de pacotes do Dart; "spec" vem de specification, "especificação"; e .yaml é o formato do arquivo.

1. O arquivo que o dart create fez

$ cat pubspec.yaml
name: confeitaria
description: A sample command-line application.
version: 1.0.0
# repository: https://github.com/my_org/my_repo

environment:
  sdk: ^3.13.5

# Add regular dependencies here.
dependencies:
  path: ^1.9.0

dev_dependencies:
  lints: ^6.0.0
  test: ^1.25.6

O formato YAML em 3 regras

  1. chave: valor, com um espaço depois dos dois-pontos. name: confeitaria quer dizer "o nome é confeitaria".
  2. Indentação com espaços (nunca tab) diz o que está dentro de quê. sdk tem 2 espaços na frente: ele pertence ao environment. É parecido com um mapa dentro de outro: {'environment': {'sdk': '^3.13.5'}}.
  3. # começa um comentário, como o // do Dart. A linha # repository: … está "desligada".

Campo por campo

name: confeitaria
O nome do pacote. É o nome usado no import 'package:confeitaria/…'. Só letras minúsculas, números e _, começando com letra. Obrigatório.
description: …
Uma frase sobre o projeto. O modelo traz A sample command-line application. ("um exemplo de aplicativo de linha de comando"); troque pela sua.
version: 1.0.0
A versão do seu projeto, no formato MAIOR.MENOR.CORREÇÃO (veja a seção 2).
environment: / sdk: ^3.13.5
"Ambiente": com quais versões do Dart o projeto funciona. O dart create põe a versão instalada (aqui, 3.13.5). Obrigatório.
dependencies:
"Dependências": os pacotes que o programa usa para funcionar. O modelo traz o path (para trabalhar com caminhos de arquivos).
dev_dependencies:
"Dependências de desenvolvimento": pacotes que só quem escreve o programa usa: lints (regras de estilo, para o dart analyze) e test (para os testes). Quem só usa o programa não precisa deles.

Para mudar a descrição e a versão, a Ana edita o arquivo (num editor de texto, como o nano) e roda dart pub get para o Dart conferir:

name: confeitaria
description: Calcula os pedidos da confeitaria da Ana.
version: 0.1.0
…

$ dart pub get
Resolving dependencies...
Downloading packages...
Got dependencies!
$ echo $?
0

Got dependencies! = "dependências obtidas": o arquivo está certo e os pacotes estão no lugar.

2. Lendo as versões: o ^

Versões de pacotes seguem o versionamento semântico (semver): três números, MAIOR.MENOR.CORREÇÃO.

Muda o…QuandoExemplo
CORREÇÃO (3º)conserto de defeito; nada muda para quem usa1.9.0 → 1.9.1
MENOR (2º)coisa nova, mas o que já existia continua funcionando1.9.1 → 1.10.0
MAIOR (1º)mudança que pode quebrar o código de quem usa1.10.0 → 2.0.0

O ^ ("circunflexo", em inglês caret) quer dizer: "esta versão ou qualquer mais nova que não quebre". Ou seja, pode subir o MENOR e a CORREÇÃO, mas não o MAIOR:

No pubspecQuer dizerAceitaNão aceita
path: ^1.9.0>=1.9.0 <2.0.01.9.0, 1.9.1, 1.12.31.8.3, 2.0.0
sdk: ^3.13.5>=3.13.5 <4.0.03.13.5, 3.14.03.12.0, 4.0.0
intl: ^0.20.3>=0.20.3 <0.21.00.20.3, 0.20.90.21.0
path: '>=1.8.0 <3.0.0'o intervalo escrito por extenso (entre aspas)1.8.0 até 2.x3.0.0
path: anyqualquer versão (evite)todas—

Repare na linha do intl: quando o MAIOR é 0, o pacote ainda é "jovem", e o ^ só deixa subir a CORREÇÃO.

Missão: a função aceita deveria seguir a regra de ^1.9.0 (MAIOR igual a 1 e MENOR pelo menos 9), mas está aceitando o 2.0.0. Conserte a condição do return.

bool aceita(String versao) {
  final partes = versao.split('.').map(int.parse).toList();
  final maior = partes[0];
  final menor = partes[1];
  return maior >= 1 && menor >= 0;
}

void main() {
  for (final v in ['1.9.1', '1.12.0', '2.0.0', '1.8.3']) {
    print('$v: ${aceita(v) ? 'aceita' : 'não aceita'}');
  }
}

bool aceita(String versao) {
  final partes = versao.split('.').map(int.parse).toList();
  final maior = partes[0];
  final menor = partes[1];
  return maior == 1 && menor >= 9;
}

void main() {
  for (final v in ['1.9.1', '1.12.0', '2.0.0', '1.8.3']) {
    print('$v: ${aceita(v) ? 'aceita' : 'não aceita'}');
  }
}

3. O pubspec.lock: as versões exatas

O pubspec.yaml diz o que é aceitável (^1.9.0). Na hora de baixar, o dart pub get escolhe uma versão exata para cada pacote, e anota no pubspec.lock ("trava"):

$ grep -c 'name:' pubspec.lock
50
  • # Generated by pub — "gerado pelo pub": não edite à mão.
  • dependency: transitive — dependência transitiva: ninguém pediu esse pacote no pubspec.yaml; ele veio porque um pacote que você pediu (o test, o lints) precisa dele. As que você pediu aparecem como "direct main" (o path) ou "direct dev" (o lints e o test).
  • sha256 — uma "impressão digital" do pacote, para conferir que ninguém o alterou.
  • version: "2.7.0" — a versão exata escolhida.
  • O grep -c contou 50 pacotes: os mesmos 50 do Changed 50 dependencies! do dart create. Quase todos são transitivos.

Para que serve? Para que o projeto funcione igual em qualquer computador: quem copiar a pasta com o .lock e rodar dart pub get recebe exatamente as mesmas versões, mesmo que já existam mais novas.

Vendo os pacotes

$ dart pub deps --no-dev
Dart SDK 3.13.5
confeitaria 1.0.0
└── path 1.9.1
$ dart pub outdated
Showing outdated packages.
[*] indicates versions that are not the latest available.

Found no outdated packages

dart pub deps desenha a árvore de dependências (--no-dev esconde as de desenvolvimento): o projeto usa o path, e a versão escolhida foi a 1.9.1, que cabe no ^1.9.0. dart pub outdated ("desatualizados") lista os pacotes que têm versão mais nova; naquele dia, nenhum.

Quando rodar dart pub get

  • depois de editar o pubspec.yaml à mão;
  • depois de copiar ou baixar um projeto de outra pessoa;
  • não precisa depois do dart pub add (ele já roda o get, veja Pacotes), e o próprio dart run roda o get sozinho quando percebe que falta.

Duas formas de mudar as dependências

JeitoExemploQuando
comandodart pub add intl / dart pub remove intlo jeito recomendado: escolhe a versão, edita o arquivo e baixa (aula Pacotes)
à mãoescrever intl: ^0.20.3 em dependencies: e rodar dart pub getpara ajustar uma restrição, ou quando o tutorial do pacote manda copiar a linha

Missão: o mapa abaixo imita a parte dependencies de um pubspec. Acrescente o pacote 'intl' com a restrição '^0.20.3' e rode: devem aparecer 2 dependências.

void main() {
  final dependencias = {
    'path': '^1.9.0',
  };
  print('Dependências: ${dependencias.length}');
  dependencias.forEach((pacote, versao) {
    print('  $pacote: $versao');
  });
}

void main() {
  final dependencias = {
    'path': '^1.9.0',
    'intl': '^0.20.3',
  };
  print('Dependências: ${dependencias.length}');
  dependencias.forEach((pacote, versao) {
    print('  $pacote: $versao');
  });
}

Quando dá errado

Tab na indentação

A Ana apertou Tab em vez de dois espaços antes do sdk:

$ dart pub get
Error on line 4, column 1 of pubspec.yaml: Tab characters are not allowed as indentation.
  ╷
4 │     sdk: ^3.13.5
  │ ^^^^
  ╵
$ echo $?
65

"Erro na linha 4, coluna 1 do pubspec.yaml: caracteres de tabulação não são permitidos como indentação". O desenho com │ mostra a linha 4, e os ^^^^ marcam o tab (que a tela mostra como 4 espaços). O código de saída 65 quer dizer "dados de entrada inválidos". Como consertar: apague o tab e digite 2 espaços. Muitos editores têm a opção "inserir espaços ao apertar Tab".

Nome com traço 
name: confeitaria-ana
…

$ dart pub get
Resolving dependencies...
Error on line 1, column 7 of pubspec.yaml: "name" field must be a valid Dart identifier.
  ╷
1 │ name: confeitaria-ana
  │       ^^^^^^^^^^^^^^^
  ╵
$ echo $?
65

"O campo name precisa ser um identificador Dart válido": as mesmas regras de nome de variável (veja Nomes de Variáveis). O traço não pode: o Dart leria confeitaria - ana como uma subtração. Como consertar: name: confeitaria_ana.

O projeto pede um Dart que você não tem 
environment:
  sdk: ^4.0.0

$ dart pub get
Resolving dependencies...
The current Dart SDK version is 3.13.5.

Because confeitaria requires SDK version ^4.0.0, version solving failed.
$ echo $?
1

"A versão atual do SDK do Dart é 3.13.5. Como confeitaria exige a versão ^4.0.0 do SDK, a resolução de versões falhou." Isso acontece de verdade quando você baixa um projeto feito com um Dart mais novo que o seu. Como consertar: atualize o Dart (veja Instalar e Versões) ou, se o projeto é seu e não usa nada novo, baixe a restrição.

Uma versão de pacote que não existe 
dependencies:
  path: ^99.0.0

$ dart pub get
Resolving dependencies...
Because confeitaria depends on path ^99.0.0 which doesn't match any versions, version solving failed.


You can try the following suggestion to make the pubspec resolve:
* Consider downgrading your constraint on path: dart pub add path:^1.9.1
$ echo $?
1

"Como confeitaria depende de path ^99.0.0, que não corresponde a nenhuma versão, a resolução falhou." E o pub ainda sugere a correção: "considere baixar a sua restrição do path: dart pub add path:^1.9.1". Como consertar: rode a sugestão, ou volte para ^1.9.0.

Esqueceu a indentação (não dá erro, e esse é o problema) 
dependencies:
path: ^1.9.0

$ dart pub get
Resolving dependencies...
Downloading packages...
  path 1.9.1 (from direct dependency to transitive dependency)
Changed 1 dependency!
$ echo $?
0

Sem os 2 espaços, path deixou de estar dentro de dependencies: virou um campo solto, que o pub ignora. A única pista é a linha from direct dependency to transitive dependency ("de dependência direta para transitiva"): o path só continua baixado porque outro pacote precisa dele. Um arquivo do projeto que use o path (aqui, lib/caminho.dart, com import 'package:path/path.dart' as p;) ainda roda, mas o dart analyze reclama:

$ dart analyze
Analyzing confeitaria...

   info - lib/caminho.dart:1:8 - The imported package 'path' isn't a dependency of the importing package. Try adding a dependency for 'path' in the 'pubspec.yaml' file. - depend_on_referenced_packages

1 issue found.

"O pacote importado path não é uma dependência do pacote que o importa. Tente acrescentar uma dependência de path no pubspec.yaml." E se o outro pacote deixar de precisar do path, o programa quebra. Como consertar: devolva os 2 espaços. Ao rodar dart pub get de novo, aparece (from transitive dependency to direct dependency): voltou a ser direta.

Resumo

  • O pubspec.yaml é a ficha do projeto, em YAML: chave: valor, indentação com espaços, # para comentários.
  • name e environment: sdk: são obrigatórios; dependencies são os pacotes do programa; dev_dependencies, os de desenvolvimento.
  • ^1.9.0 aceita de 1.9.0 até antes de 2.0.0 (com MAIOR 0, só a CORREÇÃO sobe).
  • O pubspec.lock guarda as versões exatas; quem tem o .lock recebe as mesmas versões.
  • Editou à mão? dart pub get. Os erros do pub mostram a linha e a coluna do pubspec.yaml, e às vezes sugerem a correção.
