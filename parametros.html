Dart Parâmetros Posicionais

Na aula Funções você criou funções como dobro(int numero), que recebem um valor para trabalhar. Esses valores de entrada são os parâmetros. Nesta aula você aprende a usar quantos quiser, por que a ordem importa (daí o nome "posicionais": cada valor vale pela posição em que é passado), como os tipos são conferidos e o que o Dart responde quando a chamada não bate com a declaração.

Você vai aprender
  • A diferença entre parâmetro (na declaração) e argumento (na chamada).
  • Funções com vários parâmetros, e por que a ordem dos argumentos importa.
  • Como o Dart confere os tipos: um int serve onde se pede double, mas não o contrário.
  • Expressões e chamadas de função como argumentos.
  • Que a função recebe uma cópia do valor: mudar o parâmetro não muda a variável de quem chamou.
  • Parâmetros que aceitam null (String?).
  • Os erros reais: argumentos a mais, a menos, de tipo errado.

Todos os programas desta aula rodaram no Dart 3.13.5 da máquina da Ana (ana@notebook), com dart run arquivo.dart.

A ideia: o formulário com espaços em branco

Pense numa etiqueta de preço impressa com espaços em branco: "Produto: ____ · Preço: ____ · Estoque: ____". A etiqueta (a função) é sempre a mesma; o que muda é o que você escreve em cada espaço. Os espaços em branco, com nome e tipo, são os parâmetros. O que você escreve neles, numa etiqueta de verdade, são os argumentos.

NomeOnde apareceExemplo
ParâmetroNa declaração da função: o nome e o tipo do "espaço em branco"void saudar(String nome)
ArgumentoNa chamada: o valor que preenche o espaçosaudar('Ana')

1. Um parâmetro

void saudar(String nome) {
  print('Bom dia, $nome!');
}

void main() {
  saudar('Ana');
  saudar('Bia');
  final cliente = 'seu Zé';
  saudar(cliente);
}
(String nome)
O parâmetro: o tipo (String) e o nome (nome). Dentro da função, nome funciona como uma variável que já chega com valor.
saudar('Ana')
O argumento 'Ana' vai para o parâmetro nome. Nesta chamada, é como se a função começasse com nome = 'Ana'.
saudar(cliente)
O argumento pode ser uma variável. O nome dela (cliente) não precisa ser igual ao do parâmetro (nome): o que passa é o valor, 'seu Zé'.
$ dart run saudar.dart
Bom dia, Ana!
Bom dia, Bia!
Bom dia, seu Zé!

2. Vários parâmetros: a ordem manda

Os parâmetros se separam por vírgula. Na chamada, os argumentos vão na mesma ordem: o primeiro argumento preenche o primeiro parâmetro, o segundo preenche o segundo, e assim por diante.

void etiqueta(String produto, double preco, int estoque) {
  print('$produto | R\$ ${preco.toStringAsFixed(2)} | $estoque no estoque');
}

void main() {
  etiqueta('Pão francês', 0.75, 120);
  etiqueta('Leite', 5.49, 30);
}

$ dart run etiqueta.dart
Pão francês | R$ 0.75 | 120 no estoque
Leite | R$ 5.49 | 30 no estoque
PosiçãoParâmetroArgumento (1ª chamada)
1ªString produto'Pão francês'
2ªdouble preco0.75
3ªint estoque120

Se a ordem dos argumentos for trocada, o Dart percebe, porque os tipos não batem:

void etiqueta(String produto, double preco, int estoque) {
  print('$produto | R\$ ${preco.toStringAsFixed(2)} | $estoque no estoque');
}

void main() {
  etiqueta(0.75, 'Pão francês', 120);
}

$ dart run troca.dart
troca.dart:6:12: Error: The argument type 'double' can't be assigned to the parameter type 'String'.
  etiqueta(0.75, 'Pão francês', 120);
           ^
troca.dart:6:18: Error: The argument type 'String' can't be assigned to the parameter type 'double'.
  etiqueta(0.75, 'Pão francês', 120);
                 ^

"O argumento do tipo double não pode ser atribuído ao parâmetro do tipo String", e o contrário para o segundo. Os tipos protegeram a Ana. Mas quando dois parâmetros têm o mesmo tipo, o Dart não tem como perceber a troca:

double comDesconto(double preco, double porcentagem) {
  return preco - preco * porcentagem / 100;
}

void main() {
  print(comDesconto(200, 10));
  print(comDesconto(10, 200));
}

$ dart run troca2.dart
180.0
-10.0

A primeira chamada é "R$ 200 com 10% de desconto": 180. A segunda trocou a ordem: "R$ 10 com 200% de desconto", e o preço ficou negativo. Compilou, rodou, e está errado. É por isso que, quando uma função tem vários parâmetros do mesmo tipo, vale usar parâmetros nomeados, em que a chamada diz o nome de cada valor: comDesconto(preco: 200, porcentagem: 10). É o assunto da próxima aula, Parâmetros Nomeados e required.

Missão: a chamada do café está com os argumentos fora de ordem e não compila. Arrume a ordem para aparecer Café | R$ 4.00 | 15 no estoque.

3. Os tipos dos argumentos

Cada argumento tem de "caber" no tipo do parâmetro. Um caso que ajuda: onde se pede double, um número inteiro escrito direto serve (o Dart o lê como double). O contrário não:

double area(double largura, double altura) {
  return largura * altura;
}

void main() {
  print(area(3, 4));
  print(area(2.5, 4));
}

$ dart run area.dart
12.0
10.0

O 3 e o 4 viraram 3.0 e 4.0, e o resultado saiu como double (12.0). Já passar 7.0 para uma função que pede int:

$ dart run intdouble.dart
intdouble.dart:11:16: Error: The argument type 'double' can't be assigned to the parameter type 'int'.
  print(metade(7.0));
               ^

Um double pode ter casas decimais, e um int não tem onde guardá-las; o Dart não arredonda escondido. Como consertar: passe um inteiro (metade(7)), ou converta de propósito: metade(7.9.toInt()) ou .round() (veja Conversão de Tipos).

E se eu não escrever o tipo do parâmetro?

void saudar(nome) compila: sem tipo, o parâmetro vira dynamic, "qualquer coisa" (veja dynamic e Object). Só que aí o Dart deixa de conferir, e o erro aparece só rodando. No lab, saudar(42) com ${nome.length} lá dentro deu:

4. Qualquer expressão serve de argumento

O argumento não precisa ser um valor pronto: pode ser uma conta, uma variável, ou até o resultado de outra chamada. O Dart calcula o argumento primeiro e passa o resultado:

int maior(int a, int b) {
  if (a > b) return a;
  return b;
}

void main() {
  final x = 7;
  print(maior(3, 9));
  print(maior(x * 2, 10));
  print(maior(maior(4, 8), 6));
}

$ dart run expressao.dart
9
14
8

Na terceira linha, o Dart resolve de dentro para fora: maior(4, 8) dá 8, e então maior(8, 6) dá 8.

5. A função recebe uma cópia

O que acontece se a função mudar o valor do parâmetro?

void aumentar(int valor) {
  valor = valor + 10;
  print('Dentro da função: $valor');
}

void main() {
  var saldo = 50;
  aumentar(saldo);
  print('Fora da função: $saldo');
}

$ dart run copia.dart
Dentro da função: 60
Fora da função: 50

O saldo do main continuou 50. A função recebeu o valor 50 e guardou no parâmetro valor, que é uma variável dela. Mudar valor não mexe em saldo. Para mudar o saldo, a função deve devolver o novo valor, e quem chamou guarda:

int aumentar(int valor) {
  return valor + 10;
}

void main() {
  var saldo = 50;
  saldo = aumentar(saldo);
  print('Saldo: $saldo');
}

$ dart run devolve.dart
Saldo: 60
Boa prática: não reatribua parâmetros

Escrever valor = … dentro da função confunde quem lê ("é o valor que chegou ou outro?"). Prefira uma variável nova (final novo = valor + 10;) ou um return direto. (Com listas e objetos a história tem um detalhe a mais, que aparece em Listas.)

6. Parâmetro que aceita null

Um parâmetro String? aceita um texto ou null (veja Tipos Anuláveis). Dentro da função, teste antes de usar:

void saudar(String nome, String? apelido) {
  if (apelido == null) {
    print('Olá, $nome!');
  } else {
    print('Olá, $nome ($apelido)!');
  }
}

void main() {
  saudar('Ana', 'Aninha');
  saudar('Bia', null);
}

$ dart run anulavel.dart
Olá, Ana (Aninha)!
Olá, Bia!

Repare: mesmo podendo ser null, o argumento tem de ser passado. saudar('Bia'), sem o segundo, dá Too few positional arguments: 2 required, 1 given. Um parâmetro posicional é sempre obrigatório. Para deixar um parâmetro de fora, ele tem de ser opcional: veja Parâmetros Opcionais e Valores Padrão.

Missão: a segunda chamada não compila, porque falta um argumento. A Bia não tem apelido: passe null no lugar dele.

void saudar(String nome, String? apelido) {
  if (apelido == null) {
    print('Olá, $nome!');
  } else {
    print('Olá, $nome ($apelido)!');
  }
}

void main() {
  saudar('Ana', 'Aninha');
  saudar('Bia');
}

void saudar(String nome, String? apelido) {
  if (apelido == null) {
    print('Olá, $nome!');
  } else {
    print('Olá, $nome ($apelido)!');
  }
}

void main() {

  saudar('Bia', null);

Tipo do argumento errado

A seção 2 mostrou: The argument type 'double' can't be assigned to the parameter type 'String'. Lê-se "o argumento do tipo X não pode ser atribuído ao parâmetro do tipo Y". Quase sempre é ordem trocada, ou um número que chegou como texto (o que vem do teclado é String: converta com int.tryParse, veja Lendo o Teclado).

Passou um String? onde se pede String 
void saudar(String nome) {
  print('Olá, $nome!');
}

void main() {
  String? digitado;
  saudar(digitado);
}

$ dart run nulo.dart
nulo.dart:7:10: Error: The argument type 'String?' can't be assigned to the parameter type 'String'.
  saudar(digitado);
         ^

A variável pode ser null, e o parâmetro não aceita null. Acontece muito com o que vem do stdin.readLineSync(). Como consertar: dê um valor de reserva na chamada: saudar(digitado ?? 'visitante'), ou teste if (digitado != null) antes de chamar.

Ordem trocada com tipos iguais

O caso mais perigoso, porque não há mensagem nenhuma: comDesconto(10, 200) no lugar de comDesconto(200, 10) deu -10.0 (seção 2). Como evitar: confira a declaração antes de chamar; para funções com vários parâmetros do mesmo tipo, use parâmetros nomeados.

Resumo

  • Parâmetro é o espaço em branco da declaração (String nome); argumento é o valor da chamada ('Ana').
  • Parâmetros posicionais são preenchidos pela ordem, e todos são obrigatórios: nem a mais, nem a menos.
  • O Dart confere os tipos de cada argumento. Um inteiro escrito direto serve para double; um double não serve para int; um String? não serve para String.
  • Qualquer expressão serve de argumento; ela é calculada antes da chamada.
  • A função recebe uma cópia do valor: mudar o parâmetro não muda a variável de quem chamou. Para devolver algo, use return.
  • Com vários parâmetros do mesmo tipo, a troca de ordem passa sem erro: use parâmetros nomeados.
