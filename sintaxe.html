Dart Instruções, ; e Blocos

Toda língua tem gramática. Em português, a frase termina com ponto e o parágrafo agrupa frases sobre o mesmo assunto. O Dart também tem a sua gramática, que os programadores chamam de sintaxe: as regras de como o código tem de ser escrito. Esta aula mostra as três peças básicas, que aparecem em todo programa: a instrução, o ponto e vírgula que a termina e o bloco de chaves que agrupa instruções.

Você vai aprender
  • O que é uma instrução e em que ordem o Dart executa as instruções.
  • Por que o ; é obrigatório no fim de cada instrução, e onde ele não vai.
  • O que é um bloco { } e por que o recuo ajuda a enxergá-lo.
  • Que espaços e quebras de linha (quase) não importam para o Dart, mas importam muito para quem lê.
  • A arrumar o código automaticamente com dart format.
  • A ler os erros reais Expected ';' after this. e Expected a declaration.

Os programas desta aula foram rodados com o Dart SDK 3.13.5 na máquina fictícia da Ana (usuária ana, computador notebook), dentro da pasta sx, com dart run arquivo.dart.

A ideia: frases e parágrafos

Num bilhete para a padaria, a Ana escreve: "Quero dez pães. Separe um bolo de fubá. Pago na sexta." São três frases, cada uma com o seu ponto final, e o bilhete inteiro trata de um assunto só. No Dart é igual:

No bilheteNo Dart
Uma frase: um pedido completoUma instrução: uma ordem completa, como print('Bom dia!')
O ponto finalO ponto e vírgula ;
O bilhete, que junta as frases de um assuntoO bloco { … }, que junta instruções
Ler de cima para baixoO Dart executa as instruções de cima para baixo

1. Instruções, uma depois da outra

Uma instrução (em inglês, statement) é uma ordem completa para o computador. Até aqui, você conhece uma: chamar o print. O Dart executa as instruções do main uma por vez, na ordem em que estão escritas:

void main() {
  print('Lista de compras');
  print('- pão');
  print('- leite');
}

$ dart run instrucoes.dart
Lista de compras
- pão
- leite
print('Lista de compras');
A primeira instrução. Só quando ela termina o Dart passa para a próxima.
;
O fim da instrução. É o ;, e não a quebra de linha, que diz ao Dart "esta ordem acabou".

2. O ponto e vírgula: obrigatório

Algumas linguagens (como Python ou JavaScript) deixam o fim da linha fazer o papel do ponto final. O Dart, não: ele ignora as quebras de linha e só sabe onde uma instrução termina porque você pôs o ;. Por isso, duas instruções podem até ficar na mesma linha:

void main() {
  print('Bom dia!'); print('Padaria aberta.');
}

$ dart run mesma_linha.dart
Bom dia!
Padaria aberta.

E uma instrução só pode se espalhar por várias linhas. O Dart continua lendo até achar o ;:

void main() {
  print(
    'Pão francês saindo às 7h',
  );
  print(2 +
      3);
}

$ dart run quebrada.dart
Pão francês saindo às 7h
5

São duas instruções, em cinco linhas. Repare na vírgula depois do texto, no primeiro print: o Dart aceita essa vírgula final (em inglês, trailing comma) dentro dos parênteses, e ela vai ser útil quando houver vários valores (aula Listas). Não confunda: a vírgula fica dentro dos parênteses; o fim da instrução continua sendo o ;.

Onde o ; não vai

Depois de uma chave que fecha um bloco não vai ;: o bloco já tem fim marcado (a }). E também não vai entre o main() e a {: ali ainda não terminou nada, o corpo da função está começando. O cenário "Ponto e vírgula depois de main()", mais abaixo, mostra o que acontece.

3. Blocos: as chaves { }

Um bloco é um grupo de instruções entre chaves. O corpo do main é um bloco: a { abre, a } fecha, e tudo o que está entre elas pertence ao main. Mais adiante, os blocos vão aparecer em todo lugar: no if ("se isto, faça este bloco"), nos laços ("repita este bloco"), nas funções e nas classes.

Um bloco pode até ficar solto dentro de outro. Não é comum, mas mostra que as chaves só agrupam; as instruções continuam rodando na ordem:

void main() {
  print('Antes do bloco');
  {
    print('Dentro do bloco');
  }
  print('Depois do bloco');
}

$ dart run bloco.dart
Antes do bloco
Dentro do bloco
Depois do bloco
{ (linha 1)
Abre o bloco do main.
{ (linha 3)
Abre um bloco dentro do primeiro. Ele tem mais dois espaços de recuo, para você ver de longe que está "mais para dentro".
} (linha 5)
Fecha o bloco de dentro. Toda { precisa da sua }, e a última que abriu é a primeira que fecha, como caixas dentro de caixas.
} (linha 7)
Fecha o main. Sem ; depois.

Para que serve um bloco solto? Para guardar coisas que só valem lá dentro, assunto da aula Closures (escopo). Por enquanto, o importante é: chave abriu, chave fecha.

4. Espaços, quebras de linha e recuo

Para o Dart, espaços e quebras de linha entre as peças do código não fazem diferença. Este programa está horrível, mas funciona:

void main(){print('Bom dia!');
        print('Padaria aberta.');
print(   2+3   )  ;}

$ dart run baguncado.dart
Bom dia!
Padaria aberta.
5

O Dart não se importa, mas você e quem ler o código depois, sim. Por isso todo programador Dart segue as mesmas regras de arrumação:

  • uma instrução por linha;
  • dois espaços de recuo para cada nível de bloco (nada de TAB);
  • a { no fim da linha que abre o bloco, a } sozinha na sua linha, alinhada com o começo daquela linha;
  • espaço em volta das contas: 2 + 3.

O dart format arruma para você

Você não precisa arrumar à mão. O Dart SDK traz o dart format, que reescreve o arquivo no estilo oficial. A Ana fez uma cópia do programa bagunçado e passou o formatador nela:

$ cp baguncado.dart arrumado.dart
$ dart format arrumado.dart
Formatted arrumado.dart
Formatted 1 file (1 changed) in 0.00 seconds.
$ cat arrumado.dart
void main() {
  print('Bom dia!');
  print('Padaria aberta.');
  print(2 + 3);
}
$ dart run arrumado.dart
Bom dia!
Padaria aberta.
5
Formatted arrumado.dart
"Formatei arrumado.dart": o arquivo foi reescrito.
Formatted 1 file (1 changed) in 0.00 seconds.
"Formatei 1 arquivo (1 mudou) em 0,00 segundo." Se o arquivo já estivesse arrumado, apareceria 0 changed.

O programa faz exatamente o mesmo; só ficou legível. No VS Code com a extensão Dart, o mesmo formatador roda quando você salva (se a opção "Format On Save" estiver ligada). Mais em Análise e Formatação.

O dart format só arruma código que compila

Ele não conserta erros: se faltar um ; ou uma chave, ele avisa e não mexe no arquivo. Com o falta.dart do cenário mais abaixo (copiado para f2.dart):

$ dart format f2.dart
Could not format because the source could not be parsed:

line 2, column 19 of f2.dart: Expected to find ';'.
  ╷
2 │   print('Bom dia!')
  │                   ^
  ╵
Formatted no files in 0.00 seconds.

"Não consegui formatar porque o código não pôde ser lido: linha 2, coluna 19, esperava encontrar ;. Nenhum arquivo formatado." Primeiro faça o programa rodar, depois formate.

Uma coisa que importa sempre: maiúsculas e minúsculas

Espaços quase nunca importam, mas a diferença entre maiúscula e minúscula importa sempre: print existe, Print não (você viu o erro em Seu Primeiro Programa). E espaço no meio de uma palavra também quebra o código: pr int são duas palavras para o Dart.

Formas de escrever a mesma coisa: qual usar

FormaFunciona?Use?

Uma instrução longa em várias linhasSimSim, quando ela não cabe numa linha; deixe o dart format decidir onde quebrar
Tudo grudado, sem espaçosSimNunca

Quando dá errado

Faltou o ; 
void main() {
  print('Bom dia!')
  print('Padaria aberta.');
}

falta.dart:2:19:
Linha 2, coluna 19: a coluna do ), o último caractere da instrução.

"Esperava ; depois disto". O "isto" é o que o ^ aponta: o ). O ; tem de ir logo depois dele.

Repare: o Dart aponta a linha certa, a 2, mesmo tendo percebido o problema só quando chegou ao print da linha 3. E, como todo erro de compilação, nada rodou, nem o Bom dia!. Como consertar: print('Bom dia!');.

A última instrução do bloco também precisa do ;, mesmo com a } logo embaixo:

$ dart run falta_fim.dart

Vírgula (ou dois-pontos) no lugar do ; 
void main() {
  print('Bom dia!'),
  print('Padaria aberta.');
}

$ dart run virgula.dart
virgula.dart:2:19: Error: Expected ';' after this.
  print('Bom dia!'),
                  ^
virgula.dart:2:20: Error: Expected an identifier, but got ','.
Try inserting an identifier before ','.
  print('Bom dia!'),
                   ^
virgula.dart:2:20: Error: Unexpected token ';'.
  print('Bom dia!'),
                   ^

Três mensagens para um erro só. A primeira é a que importa: "esperava ; depois disto". As outras são o Dart tentando entender a vírgula que sobrou: "esperava um nome (identifier), mas achou ," e "símbolo inesperado". Regra de ouro: conserte a primeira mensagem e rode de novo; muitas vezes as outras somem junto. Com dois-pontos (print('Bom dia!'):) saem as mesmas três mensagens, com ':' no lugar de ','. Como consertar: troque por ;.

; repetido: não dá erro 
void main() {
  print('Bom dia!');;
  print('Padaria aberta.');
}

$ dart run dois_pontos.dart
Bom dia!
Padaria aberta.

O ; sozinho é uma "instrução vazia": não faz nada, e o Dart aceita. Não estraga o programa, mas é sujeira, e nenhuma ferramenta reclama: o dart analyze (aula Análise e Formatação) não acha problema, e o dart format só deixa a sujeira mais visível, numa linha sozinha:

$ cp dois_pontos.dart dp.dart
$ dart format dp.dart
Formatted dp.dart
Formatted 1 file (1 changed) in 0.00 seconds.
$ cat dp.dart
void main() {
  print('Bom dia!');
  ;
  print('Padaria aberta.');
}
$ dart analyze dp.dart
Analyzing dp.dart...
No issues found!

Como consertar: apague o ; que sobrou.

Ponto e vírgula depois de main() 
void main(); {
  print('Bom dia!');
}

$ dart run ponto_main.dart
ponto_main.dart:1:12: Error: Expected a function body or '=>'.
Try adding {}.
void main(); {
           ^
ponto_main.dart:1:14: Error: Expected a declaration, but got '{'.
void main(); {
             ^

"Esperava o corpo da função ou =>. Tente acrescentar {}". Para o Dart, o ; encerrou o main antes de ele ter corpo. Depois, a { ficou sobrando fora de qualquer função: "esperava uma declaração, mas achou {" (uma declaração é a criação de uma função, variável ou classe: a única coisa que pode ficar fora do main). O => é outro jeito de escrever o corpo de funções curtas (aula Funções de Uma Linha). Como consertar: void main() {, sem ;.

Chave a mais 
void main() {
  print('Bom dia!');
}
}

$ dart run chave_a_mais.dart
chave_a_mais.dart:4:1: Error: Expected a declaration, but got '}'.
}
^

A } da linha 3 já fechou o main. A da linha 4 sobrou, fora de tudo, onde o Dart esperava uma declaração. A chave que falta dá outra mensagem, Can't find '}' to match '{'. (aula Seu Primeiro Programa). O recuo certo ajuda a achar os dois casos de olho: cada } fica alinhada com a linha que abriu a sua {. Como consertar: apague a chave que sobrou.

Missão final: o bilhete arrumado

Missão: o programa abaixo tem dois erros (um ; trocado e uma chave a mais) e está bagunçado. Faça-o rodar e deixe-o arrumado: uma instrução por linha, com dois espaços de recuo.

void main() {
print('Bilhete para a padaria'); print('Quero 10 pães'),
      print('Separe um bolo de fubá');
}
}

void main() {
  print('Bilhete para a padaria');
  print('Quero 10 pães');
  print('Separe um bolo de fubá');
}

Resumo

  • Uma instrução é uma ordem completa; o Dart executa as instruções de cima para baixo.
  • O ; termina cada instrução e é obrigatório, inclusive na última do bloco. Quebra de linha não termina nada.
  • Sem ; entre main() e {, nem depois da }.
  • Um bloco { } agrupa instruções; toda chave que abre tem a sua que fecha.
  • Espaços e quebras de linha não mudam o programa, mas o estilo oficial pede uma instrução por linha e 2 espaços de recuo. O dart format arruma sozinho.
  • Erros: Expected ';' after this. (faltou ;), Expected a declaration (chave ou algo sobrando fora do main). Conserte sempre a primeira mensagem.
