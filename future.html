Dart Future

Até aqui, cada linha dos seus programas terminava antes de a próxima começar. Mas algumas tarefas demoram: baixar uma página da internet, ler um arquivo grande, esperar o servidor responder. Se o programa ficasse parado esperando, tudo travaria. Em vez disso, o Dart entrega na hora um Future (em inglês, "futuro"): uma promessa de que o valor vai ficar pronto depois. Esta é a primeira aula do código assíncrono, o código que não acontece tudo de uma vez, em ordem.

Você vai aprender
  • O que é um Future<String> e por que o print dele mostra Instance of 'Future<String>'.
  • Como simular uma tarefa demorada com Future.delayed.
  • A ordem real em que as coisas acontecem (a linha de baixo roda antes do Future ficar pronto).
  • Como usar o valor quando ele chegar: then, encadeado, e whenComplete.
  • Como tratar um erro que acontece "no futuro" com catchError, e como esperar vários Futures com Future.wait.

Todos os programas desta aula rodaram no Dart SDK 3.13.5 da máquina da Ana (usuária ana, computador notebook), com dart run arquivo.dart. As tarefas "demoradas" aqui são de mentira: um Future.delayed que só espera alguns segundos. Nas aulas Arquivos e Pacotes você vê Futures de verdade (ler arquivo, acessar a internet).

A ideia: a senha da lanchonete

Na lanchonete, a Ana pede um sanduíche no caixa. A atendente não faz a Ana esperar parada no balcão enquanto o sanduíche fica pronto: ela entrega uma senha na hora. A Ana vai pegar um suco, senta, conversa. Quando o sanduíche fica pronto, chamam a senha dela, e aí ela pega o sanduíche.

  • A senha é o Future. Ela chega na hora, mas ainda não é o sanduíche: é a promessa de um sanduíche.
  • Enquanto espera, a Ana faz outras coisas: o programa continua rodando as linhas seguintes.
  • "Quando chamarem a senha, pegue o sanduíche" é o then ("então").
  • A senha pode ser chamada com uma má notícia ("acabou o pão"): o Future termina com um erro.

O tipo diz o que a senha promete: Future<String> é "um texto que vai ficar pronto depois"; Future<int>, um número (o <…> é um genérico).

1. O primeiro Future, e a ordem real

Future<String> assarPao() {
  return Future.delayed(Duration(seconds: 2), () => 'pão quentinho');
}

void main() {
  print('1. Ana pede um pão');
  final pedido = assarPao();
  print('2. Ela recebe o comprovante: $pedido');
  pedido.then((pao) {
    print('4. Ficou pronto: $pao');
  });
  print('3. Enquanto isso, ela paga o café');
}
Future<String> assarPao()
A função não devolve um String: devolve a promessa de um String.
Future.delayed(Duration(seconds: 2), () => 'pão quentinho')
"Futuro atrasado": cria um Future que espera 2 segundos (Duration = "duração") e depois roda a função () => 'pão quentinho'; o resultado dela vira o valor do Future. É o jeito de fingir uma tarefa demorada.
final pedido = assarPao();
Volta na hora, sem esperar os 2 segundos. O pedido é a senha.
pedido.then((pao) { … })
"Quando ficar pronto, então faça isto". O then recebe uma função anônima; o Dart a chama mais tarde, passando o valor pronto em pao. O then também volta na hora.
$ dart run f1.dart
1. Ana pede um pão
2. Ela recebe o comprovante: Instance of 'Future<String>'
3. Enquanto isso, ela paga o café
4. Ficou pronto: pão quentinho

Siga a ordem com calma, porque ela é o coração do assíncrono:

  1. O main roda de cima a baixo sem parar: mostra o 1, pede o pão (recebe a senha na hora), mostra o 2, registra o then e mostra o 3. Aí o main acaba.
  2. O programa não termina ainda: há um Future pendente. O Dart espera.
  3. Dois segundos depois, o pão fica pronto, e o Dart chama a função do then: aparece o 4.
  4. Nada mais pendente: agora sim o programa termina.

Repare na linha 2: Instance of 'Future<String>'. Mostrar a senha não mostra o pão; para pegar o valor, é preciso esperar por ele (com then, ou com o await da próxima aula).

Missão: rode e veja Pronto: Instance of 'Future<String>': o programa mostrou a senha, não o bolo. Use o then para mostrar o bolo quando ele ficar pronto: assarBolo().then((bolo) { print('Pronto: $bolo'); });

Future<String> assarBolo() =>
    Future.delayed(Duration(seconds: 1), () => 'bolo de cenoura');

void main() {
  final bolo = assarBolo();
  print('Pronto: $bolo');
}

Future<String> assarBolo() =>
    Future.delayed(Duration(seconds: 1), () => 'bolo de cenoura');

void main() {
  assarBolo().then((bolo) {
    print('Pronto: $bolo');
  });
}

2. Quem vai primeiro? A fila de tarefas

O Dart roda uma coisa de cada vez. O que é síncrono (as linhas normais do main) vai até o fim primeiro; só depois o Dart olha a fila de tarefas que ficaram para depois. A Ana colocou várias tarefas na fila de propósito, para ver a ordem:

void main() {
  print('A');
  Future.delayed(Duration(seconds: 1), () => print('B (1 segundo)'));
  Future.delayed(Duration.zero, () => print('C (zero segundos)'));
  Future(() => print('D (Future comum)'));
  Future.value('E').then((v) => print('$v (Future.value + then)'));
  print('F');
}

$ dart run f2.dart
A
F
E (Future.value + then)
C (zero segundos)
D (Future comum)
B (1 segundo)
  • A e F vieram primeiro: são as linhas normais do main. Nenhum Future "fura a fila" do código síncrono.
  • E: Future.value('E') é um Future que já nasce pronto. Mesmo assim, o then dele só roda depois que o main acaba, mas antes das tarefas com tempo (é uma tarefa "urgente", que o Dart chama de microtask).
  • C e D: Duration.zero ("zero segundos") e Future(…) não esperam nada, mas também vão para o fim da fila. Saíram na ordem em que foram criados.
  • B por último: esperou 1 segundo.
A regra que basta lembrar

Tudo o que está num then ou dentro de um Future roda depois do código normal que vem em seguida, mesmo com zero segundos de espera. Se uma linha precisa do valor do Future, ela tem de estar dentro do then (ou depois de um await).

3. Encadeando: then depois de then

O then também devolve um Future, com o valor que a função dele devolveu. Por isso dá para encadear vários passos:

Future<int> contarPaes() =>
    Future.delayed(Duration(seconds: 1), () => 24);

void main() {
  contarPaes()
      .then((qtd) => qtd * 2)
      .then((dobro) => 'Amanhã: $dobro pães')
      .then(print)
      .whenComplete(() => print('Contagem encerrada'));
  print('Contando...');
}

$ dart run f3.dart
Contando...
Amanhã: 48 pães
Contagem encerrada
.then((qtd) => qtd * 2)
Recebe o 24 e devolve 48: o resultado é um Future<int> com 48.
.then((dobro) => 'Amanhã: $dobro pães')
Recebe o 48 e devolve um texto: agora é um Future<String>.
.then(print)
Passa a própria função print (veja Funções como Valores): o texto pronto é mostrado.
.whenComplete(…)
"Quando completar": roda no fim, dando certo ou errado. É o finally dos Futures (veja Exceções).

4. Quando o Future dá errado: catchError

Uma tarefa demorada também pode falhar. Se a função dentro do Future.delayed lança uma exceção, o Future termina com erro, e o then não roda. Para tratar, existe o catchError ("pegue o erro"):

Future<int> lerEstoque(String produto) {
  return Future.delayed(Duration(seconds: 1), () {
    if (produto == 'pizza') {
      throw StateError('não vendemos $produto');
    }
    return 30;
  });
}

void main() {
  lerEstoque('pão').then((n) => print('pão: $n'));
  lerEstoque('pizza')
      .then((n) => print('pizza: $n'))
      .catchError((e) => print('Erro: $e'));
  print('Pedidos enviados');
}

$ dart run f4.dart
Pedidos enviados
pão: 30
Erro: Bad state: não vendemos pizza

O pão chegou normalmente. A pizza falhou: o then dela foi pulado e o catchError recebeu a exceção (o StateError mostra Bad state: …; veja throw). O try/catch normal não pegaria esse erro, porque ele acontece depois que o main já passou do try. Os detalhes ficam para a aula Erros em Código Assíncrono.

5. Esperando vários: Future.wait

O forno da padaria assa várias coisas ao mesmo tempo. Com Future.wait ("espere"), você junta vários Futures num só, que fica pronto quando todos ficarem:

Future<String> assar(String item, int segundos) =>
    Future.delayed(Duration(seconds: segundos), () => item);

void main() {
  final relogio = Stopwatch()..start();
  Future.wait([assar('pão', 2), assar('bolo', 3), assar('broa', 1)])
      .then((prontos) {
    print('Prontos: $prontos');
    print('Levou ${relogio.elapsed.inSeconds} segundos');
  });
}

$ dart run f6.dart
Prontos: [pão, bolo, broa]
Levou 3 segundos
  • O resultado é uma lista com os valores na ordem da lista de pedidos, não na ordem em que ficaram prontos (a broa ficou pronta primeiro, mas está em terceiro).
  • Levou 3 segundos, e não 2 + 3 + 1 = 6: as três esperas aconteceram ao mesmo tempo, e o total é o da mais demorada. O Stopwatch ("cronômetro") mediu o tempo; num computador mais lento o número pode mudar.

Formas diferentes de fazer a mesma coisa

Existem vários jeitos de criar um Future e de esperar por ele:

ParaUse
Simular uma tarefa que demoraFuture.delayed(Duration(seconds: n), () => valor)
Um Future que já nasce prontoFuture.value(valor)
Um Future que já nasce com erroFuture.error(StateError('…'))
Usar o valor quando chegar.then((v) { … }), ou await (próxima aula: async e await, o jeito mais usado hoje)
Tratar erro.catchError((e) { … }), ou try/catch com await
Algo que roda no fim, com ou sem erro.whenComplete(() { … })
Esperar vários ao mesmo tempoFuture.wait([f1, f2, f3])

Quando dá errado

Tratou o Future como se fosse o valor 
Future<String> assarPao() =>
    Future.delayed(Duration(seconds: 1), () => 'pão quentinho');

void main() {
  String pao = assarPao();
  print(pao);
}

$ dart run f7.dart
f7.dart:5:16: Error: A value of type 'Future<String>' can't be assigned to a variable of type 'String'.
 - 'Future' is from 'dart:async'.
  String pao = assarPao();
               ^

"Um valor do tipo Future<String> não pode ir numa variável do tipo String". A segunda linha diz de onde vem o Future: da biblioteca dart:async (você não precisa importá-la: o Dart já deixa o Future disponível). A senha não é o pão. Como consertar: use o valor dentro de um then: assarPao().then((pao) => print(pao));, ou espere com await (próxima aula).

Mostrou o Future em vez do valor

Com final ou var no lugar de String, o Dart não reclama (a variável vira um Future<String>), mas o print mostra Instance of 'Future<String>', como na seção 1 e na primeira missão. Como consertar: o mesmo do caso acima.

Referência rápida

Future<T>A promessa de um valor do tipo T, que fica pronto depois

Missão final: a pizza que não existe

Missão: este é o programa do último "Quando dá errado": a pizza falha e o programa morre com Unhandled exception. Acrescente um .catchError((e) => print('Erro: $e')) depois do then, para o erro ser tratado e o programa terminar bem.

Future<int> lerEstoque(String produto) {
  return Future.delayed(Duration(seconds: 1), () {
    if (produto == 'pizza') {
      throw StateError('não vendemos $produto');
    }
    return 30;
  });
}

void main() {
  lerEstoque('pizza').then((n) => print('pizza: $n'));
  print('Pedido enviado');
}

Future<int> lerEstoque(String produto) {
  return Future.delayed(Duration(seconds: 1), () {
    if (produto == 'pizza') {
      throw StateError('não vendemos $produto');
    }

void main() {

Resumo

  • Um Future<T> é a senha da lanchonete: chega na hora e promete um valor do tipo T para depois.
  • O código normal roda até o fim primeiro; o que está num then ou num Future roda depois, mesmo com zero segundos de espera. O programa só termina quando não há mais nada pendente.
  • then usa o valor quando ele chega e pode ser encadeado; whenComplete roda no fim; catchError trata o erro.
  • Um Future que falha sem tratamento derruba o programa com Unhandled exception (código 255), mesmo depois de o main ter acabado.
  • Future.wait espera vários ao mesmo tempo.
  • Na próxima aula, async e await, você escreve tudo isso de um jeito que parece código normal, de cima para baixo.
