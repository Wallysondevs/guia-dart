Dart Testes

Toda vez que você muda um programa, pode quebrar algo que já funcionava. Conferir tudo à mão, rodando e olhando a saída, cansa e falha. Um teste automático é um pequeno programa que confere o seu: "a média de 8, 6 e 10 tem de dar 8". Você escreve uma vez, e o comando dart test confere tudo em segundos, quantas vezes quiser. No Dart, os testes usam o pacote test, que já vem em todo projeto criado com dart create.

Você vai aprender
  • O que é um teste automático e por que ele vale a pena.
  • Onde os testes ficam (test/, arquivos terminados em _test.dart) e como escrever um com test() e expect().
  • Como rodar com dart test e ler a saída: +1, -1, All tests passed!.
  • Como organizar com group e conferir números decimais (closeTo) e exceções (throwsArgumentError).
  • Como ler um teste que falha: Expected, Actual, Which.
  • Os erros reais: exceção no código testado, import do package:test esquecido, arquivo sem _test e dart test fora do projeto.

Tudo nesta aula rodou no Dart 3.13.5 da máquina da Ana (usuária ana, computador notebook), num projeto criado com dart create notas (veja Criando um Projeto), com o pacote test que o dart create pôs em dev_dependencies (veja O pubspec.yaml). O 00:00 no começo de cada linha do dart test é o tempo passado (minutos:segundos); ele muda de computador para computador. A primeira execução num projeto novo leva alguns segundos a mais, porque o Dart compila os testes.

O editor do guia não roda dart test

O editor desta página não tem o pacote test nem o comando dart test. Os exemplos com test() e expect() são para o terminal do seu computador. As caixas "Experimente" usam um "testador caseiro", uma função de 3 linhas que faz o mesmo papel, para você praticar a ideia.

A ideia: a prova dos nove da padaria

Antes de vender um bolo de uma receita nova, a confeiteira prova um pedaço. Se a receita muda (menos açúcar, outra farinha), ela prova de novo. Um teste é a prova: uma situação com resultado conhecido ("com 8, 6 e 10, a média é 8"), conferida pelo computador.

Todo teste tem três partes:

  1. Preparar: os dados de entrada (as notas 8, 6 e 10).
  2. Executar: chamar a função testada (media([8, 6, 10])).
  3. Conferir: comparar o resultado com o esperado (tem de dar 8).

1. O código que vai ser testado

No projeto notas, a Ana escreve em lib/notas.dart as regras da turma: a média e a situação do aluno.

double media(List<double> notas) {
  if (notas.isEmpty) {
    throw ArgumentError('a lista de notas está vazia');
  }
  var soma = 0.0;
  for (final nota in notas) {
    soma += nota;
  }
  return soma / notas.length;
}

String situacao(double media) {
  if (media >= 7) return 'aprovado';
  if (media >= 5) return 'recuperação';
  return 'reprovado';
}

Testes conferem o código de lib/. Por isso vale separar as regras (em funções, em lib/) da parte que mostra na tela (em bin/).

2. O primeiro teste

Os testes ficam na pasta test/, em arquivos cujo nome termina em _test.dart. O dart create já criou um; a Ana troca o conteúdo de test/notas_test.dart por:

import 'package:notas/notas.dart';
import 'package:test/test.dart';

void main() {
  test('média de três notas', () {
    expect(media([8, 6, 10]), 8);
  });

  test('situação de quem tirou 7', () {
    expect(situacao(7), 'aprovado');
  });
}

Traz o código testado, da pasta lib/ (veja import).

Um arquivo de teste também começa pelo main: ele registra os testes.
test('média de três notas', () { … })
Um teste: um nome (que aparece na saída; escreva o que está sendo conferido) e uma função anônima com o teste em si.
expect(media([8, 6, 10]), 8)
"Espero que": o primeiro valor é o obtido (chamar a função), o segundo é o esperado. Se forem diferentes, o teste falha.

3. Mais testes: group, closeTo e exceções

A Ana amplia o arquivo: agrupa os testes de cada função com group ("grupo") e confere os casos de fronteira (exatamente 5, exatamente 7) e o erro da lista vazia.

import 'package:notas/notas.dart';
import 'package:test/test.dart';

void main() {
  group('media', () {
    test('de três notas', () {
      expect(media([8, 6, 10]), 8);
    });

    test('com decimais', () {
      expect(media([7.5, 8.25]), closeTo(7.875, 0.001));
    });

    test('de lista vazia lança ArgumentError', () {
      expect(() => media([]), throwsArgumentError);
    });
  });

  group('situacao', () {
    test('7 ou mais é aprovado', () {
      expect(situacao(7), 'aprovado');
      expect(situacao(10), 'aprovado');
    });

    test('entre 5 e 7 é recuperação', () {
      expect(situacao(5), 'recuperação');
      expect(situacao(6.9), 'recuperação');
    });

    test('menos de 5 é reprovado', () {
      expect(situacao(4.9), 'reprovado');
    });
  });
}
group('media', () { … })
Junta testes relacionados. O nome do grupo vira o começo do nome de cada teste na saída (media de três notas).
closeTo(7.875, 0.001)
Um matcher ("comparador"): "perto de 7.875, com diferença de no máximo 0.001". Use em contas com double, que podem ter pequenos erros de arredondamento (veja Números).
expect(() => media([]), throwsArgumentError)
Para conferir que algo lança uma exceção, passe uma função que faz a chamada (o () =>), e não a chamada em si. O expect roda a função e confere que saiu um ArgumentError.
dois expect no mesmo teste
Pode. O teste só passa se todos passarem.

Linha por linha:

  • +3 -1: … situacao 7 ou mais é aprovado [E] — 3 passaram, 1 falhou (o -1); o [E] marca o teste com erro.
  • Expected: 'aprovado' / Actual: 'recuperação' — "esperado" × "obtido de verdade". Com nota 7, a função agora diz recuperação.
  • Which: is different. — "que: é diferente". As linhas seguintes comparam os dois textos, e Differ at offset 0 diz que já diferem no caractere 0 (o primeiro). O ... só corta o texto longo.
  • test/notas_test.dart 21:7 main.<fn>.<fn> — o expect que falhou: linha 21, coluna 7 do arquivo de teste (o expect(situacao(7), 'aprovado')). <fn>.<fn> = "dentro de uma função anônima dentro de outra" (o group e o test).
  • Os outros testes continuam rodando: uma falha não para os demais.
  • Some tests failed. e a lista Failing tests: — "alguns testes falharam", e quais. A sugestão do --chain-stack-traces serve para código assíncrono complicado; aqui, pode ignorar.
  • Código de saída 1. Ferramentas automáticas (como as que conferem o código antes de publicar) usam esse número para saber que algo quebrou.

Repare que o teste entre 5 e 7 é recuperação passou: ele não testava o 7. Os testes de fronteira (o valor exato onde a regra muda) são os que pegam esse tipo de erro. Com o >= de volta, tudo passa de novo.

Rodando só alguns testes

$ dart test --name recuperação
00:00 +0: loading test/notas_test.dart

Missão final: escreva a função que os testes pedem

Missão: os testes já estão escritos (é assim que muita gente trabalha: primeiro o teste, depois o código). Escreva a função double comDesconto(double preco, double porcento), que devolve preco - preco * porcento / 100, até os três testes darem OK.

// escreva a função comDesconto aqui

void confere(String nome, Object obtido, Object esperado) {
  final ok = obtido == esperado;
  print('${ok ? 'OK  ' : 'FALHOU'} $nome${ok ? '' : ' (esperado: $esperado, obtido: $obtido)'}');
}

void main() {
  confere('10% de 50', comDesconto(50, 10), 45.0);
  confere('sem desconto', comDesconto(30, 0), 30.0);
  confere('25% de 80', comDesconto(80, 25), 60.0);
}

double comDesconto(double preco, double porcento) {
  return preco - preco * porcento / 100;
}

void confere(String nome, Object obtido, Object esperado) {
  final ok = obtido == esperado;
  print('${ok ? 'OK  ' : 'FALHOU'} $nome${ok ? '' : ' (esperado: $esperado, obtido: $obtido)'}');
}

void main() {
  confere('10% de 50', comDesconto(50, 10), 45.0);
  confere('sem desconto', comDesconto(30, 0), 30.0);
  confere('25% de 80', comDesconto(80, 25), 60.0);
}

Resumo

  • Um teste prepara dados, executa a função e confere o resultado. O pacote test já vem em todo projeto do dart create.
  • Testes ficam em test/*_test.dart; cada um é um test('nome', () { expect(obtido, esperado); }), organizados com group.
  • dart test roda tudo: +N passaram, -N falharam, código 0 ou 1.
  • Na falha, leia Expected (esperado), Actual (obtido) e a linha do expect.
  • Teste as fronteiras (o 7 exato, a lista vazia); use closeTo para double e () => com throws… para exceções.
