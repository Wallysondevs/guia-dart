Dart switch e Expressões switch

Quando uma variável pode ter muitos valores, e cada um pede uma resposta diferente (o dia da semana, a opção do menu, o tamanho da pizza), uma fileira de if … else if fica comprida e repetitiva. O switch ("chave", como a chave seletora de um ventilador) olha o valor uma vez e vai direto para o caso certo. O Dart tem duas formas: o switch clássico, que escolhe o que fazer, e a expressão switch Dart 3.0, que escolhe um valor.

Você vai aprender
  • O switch clássico: case, default, e por que no Dart 3 não precisa de break.
  • Vários valores levando ao mesmo caso.
  • A expressão switch: valor => resultado, com o _ para "qualquer outro".
  • Patterns (padrões) simples: >= 9, >= 12 && < 18, 'sábado' || 'domingo', int n e o when.
  • A exaustividade: o Dart exige que a expressão switch cubra todos os valores possíveis, e mostra o erro quando falta algum.
  • Os erros reais: default e case na expressão, a vírgula esquecida, o caso com variável, e os casos que compilam mas nunca são alcançados.

Todos os programas desta aula rodaram no Dart 3.13.5 da máquina da Ana (usuária ana, computador notebook) com dart run arquivo.dart. Você pode rodar cada um no editor do guia.

A ideia: o cardápio numerado

Na lanchonete, o cliente diz "número 3", e o atendente nem pensa: olha o cardápio, acha a linha 3 e prepara o X-salada. Ele não pergunta "é o 1? não. É o 2? não. É o 3? sim" (isso seria o if … else if). Ele compara o pedido com a lista e vai direto. E se o cliente pedir o número 99, que não existe, o atendente tem uma resposta padrão: "esse não temos". Isso é o switch: um valor, uma lista de casos, e um caso padrão.

1. O switch clássico

void main() {
  final dia = 3;
  switch (dia) {
    case 1:
      print('Domingo');
    case 2:
      print('Segunda');
    case 3:
      print('Terça');
    case 4:
      print('Quarta');
    default:
      print('Outro dia');
  }
  print('Fim');
}

{ … }
As chaves envolvem todos os casos.

"No caso de ser 1". Depois dos dois-pontos vêm as linhas desse caso, até o próximo case.
default:
"Padrão": roda quando nenhum case combinou. É opcional aqui.
$ dart run sw1.dart

O Dart comparou dia com 1, 2, 3, achou o 3, rodou print('Terça') e saiu do switch. Só um caso roda.

E o break?

Em C, Java e JavaScript, cada case precisa terminar com break ("quebrar", sair), senão o programa "cai" no caso de baixo. No Dart 3, não: um caso com instruções termina sozinho. O break ainda é aceito (no lab, um switch com break no fim de cada caso rodou igual), mas é desnecessário, e você vai encontrá-lo em código antigo.

Vários valores, o mesmo caso

Um case vazio (sem nenhuma instrução) passa para o de baixo. E, desde o Dart 3, dá para juntar valores com || num case só:

void main() {
  final dia = 'sábado';
  switch (dia) {
    case 'sábado':
    case 'domingo':
      print('Fim de semana: padaria abre às 7h');
    case 'segunda' || 'terça' || 'quarta' || 'quinta' || 'sexta':
      print('Dia útil: padaria abre às 6h');
    default:
      print('Dia desconhecido: $dia');
  }
}

$ dart run sw_varios.dart
Fim de semana: padaria abre às 7h

O case 'sábado': está vazio, então o sábado usa as linhas do case 'domingo':. A segunda forma, 'segunda' || 'terça' || …, é um pattern "ou": combina com qualquer um dos valores. O switch funciona com int, String, bool, enums e mais.

Sem default, pode não acontecer nada

void main() {
  final opcao = 9;
  switch (opcao) {
    case 1:
      print('Pão francês');
    case 2:
      print('Pão de queijo');
  }
  print('Fim do menu');
}

$ dart run sw_semdefault.dart
Fim do menu

A opção 9 não combinou com nenhum caso, e não havia default: o switch não fez nada. Num menu, quase sempre você quer um default avisando "opção inválida".

2. A expressão switch Dart 3.0

Muitas vezes, o switch só serve para escolher um valor: o nome do dia, o preço do tamanho. Para isso, o Dart 3 trouxe a expressão switch, que devolve o valor direto, como o ternário faz com duas opções:

void main() {
  final dia = 3;
  final nome = switch (dia) {
    1 => 'Domingo',
    2 => 'Segunda',
    3 => 'Terça',
    4 => 'Quarta',
    5 => 'Quinta',
    6 => 'Sexta',
    7 => 'Sábado',
    _ => 'Dia inválido',
  };
  print('Hoje é $nome');
}

$ dart run sw_expr.dart
Hoje é Terça
final nome = switch (dia) { … };
O switch fica do lado direito do =: ele é um valor. Repare no ; depois da chave final: é o fim da linha do final nome = ….
1 => 'Domingo',
Cada linha é um caso: o valor (o pattern), a seta => ("dá") e o resultado. Sem case, sem :, sem print. Os casos são separados por vírgula.
_ => 'Dia inválido',
O _ (sublinhado) é o curinga: combina com qualquer valor. É o default da expressão switch, e vem por último.
a vírgula no último caso
É opcional, mas é o estilo do Dart: com ela, o dart format mantém um caso por linha.

3. Patterns: casos que não são só um valor

Nos casos de um switch do Dart 3 vão patterns (padrões): moldes que o valor tem de encaixar. Um número ou um texto é o pattern mais simples ("igual a isto"). Há outros, e eles resolvem muita coisa que antes só o if fazia.

Comparações: >= 9

void main() {
  final nota = 7.8;
  final conceito = switch (nota) {
    >= 9 => 'A',
    >= 7 => 'B',
    >= 5 => 'C',
    _ => 'D',
  };
  print('Nota $nota: conceito $conceito');
}

$ dart run sw_rel.dart
Nota 7.8: conceito B

>= 9 quer dizer "o valor é maior ou igual a 9". Como no else if, os casos são testados de cima para baixo, e vale o primeiro que combinar: por isso o >= 7 não precisa dizer "e menor que 9".

"E" e "ou" dentro do caso: && e ||

void main() {
  final idade = 15;
  final fase = switch (idade) {
    < 0 => 'idade inválida',
    >= 0 && < 12 => 'criança',
    >= 12 && < 18 => 'adolescente',
    _ => 'adulto',
  };
  print('$idade anos: $fase');
}

$ dart run sw_faixa.dart
15 anos: adolescente

>= 12 && < 18 é uma faixa: "de 12 até menos de 18". Dentro de um pattern, o && junta dois moldes que o valor precisa encaixar ao mesmo tempo, e o || (como no 'sábado' || 'domingo') aceita qualquer um deles. Repare que não se repete o nome da variável: é >= 12 && < 18, e não idade >= 12 && idade < 18.

Missão: complete a expressão switch: abaixo de 15 é 'frio'; de 15 até menos de 28 é 'agradável'; o resto é 'calor'. Com 31 graus, deve aparecer Temperatura 31: calor.

void main() {
  final temperatura = 31;
  final sensacao = switch (temperatura) {
    < 15 => 'frio',
    _ => 'não sei',
  };
  print('Temperatura $temperatura: $sensacao');
}

void main() {
  final temperatura = 31;
  final sensacao = switch (temperatura) {
    < 15 => 'frio',
    >= 15 && < 28 => 'agradável',
    _ => 'calor',
  };
  print('Temperatura $temperatura: $sensacao');
}

Pelo tipo: int n, e o when

Um pattern também pode perguntar o tipo, como o is da aula is, is! e as, e já dar um nome ao valor:

String descrever(Object valor) {
  return switch (valor) {
    int n when n < 0 => 'inteiro negativo: $n',
    int n => 'inteiro: $n',
    double d => 'número com vírgula: $d',
    String s => 'texto com ${s.length} letras',
    _ => 'outra coisa',
  };
}

void main() {
  print(descrever(-4));
  print(descrever(10));
  print(descrever(2.5));
  print(descrever('pão'));
  print(descrever(true));
}

"Se o valor for um int, chame-o de n." Do lado direito da seta, n é um int de verdade (dá para fazer contas com ele).

Uma guarda (when = "quando"): uma condição extra. O caso só vale se o tipo encaixar e a condição for verdadeira. O -4 caiu aqui; o 10 não passou na guarda e caiu no caso de baixo.
String s => … s.length …
Para textos, o nome s já é uma String: o .length funciona sem if nem as.

4. Exaustividade: "e se não for nenhum desses?"

Uma expressão switch tem de devolver um valor, sempre. Então o Dart confere, antes de rodar, se os casos cobrem todos os valores possíveis. Essa conferência se chama exaustividade (de "esgotar": não pode sobrar nenhum valor). Sem o _:

void main() {
  final dia = 3;
  final nome = switch (dia) {
    1 => 'Domingo',
    2 => 'Segunda',
    3 => 'Terça',
  };
  print(nome);
}

Try adding a wildcard pattern or cases that match 'int()'.
  final nome = switch (dia) {
                       ^
err_exaust.dart:3:24:
Linha 3, coluna 24: o valor do switch, dia.
The type 'int' is not exhaustively matched by the switch cases…
"O tipo int não é coberto por completo pelos casos do switch…"
…since it doesn't match 'int()'.
"…porque eles não combinam com int()." O int() é o jeito do Dart dizer "um int qualquer": existem bilhões de inteiros, e os casos só cobrem 1, 2 e 3. E se dia fosse 4?
Try adding a wildcard pattern or cases that match 'int()'.
"Tente acrescentar um pattern curinga (o _), ou casos que cubram qualquer int."

O Dart reclama mesmo sabendo que dia é 3: ele confere todos os valores que o tipo permite. Com String, a mensagem é a mesma, trocando o tipo (The type 'String' is not exhaustively matched by the switch cases since it doesn't match 'String()'.). Como consertar: acrescente _ => … no fim.

Com bool, dá para cobrir tudo sem _

Um bool só tem dois valores. Com os dois casos, a expressão está completa:

void main() {
  final chovendo = false;
  final levar = switch (chovendo) {
    true => 'guarda-chuva',
    false => 'boné',
  };
  print('Leve o $levar');
}

$ dart run sw_bool.dart
Leve o boné

Esquecendo o false, o Dart diz exatamente qual valor falta:

$ dart run err_exaust_bool.dart

Try adding a wildcard pattern or cases that match 'false'.
  final levar = switch (chovendo) {
                        ^

Com bool, a exigência vale também para o switch clássico: um switch (chovendo) só com case true: deu The type 'bool' is not exhaustively matched by the switch cases since it doesn't match 'false'., com a dica Try adding a default case or cases that match 'false'. ("acrescente um default"). O mesmo vale para os enums, onde a exaustividade brilha: esqueceu um valor do enum, o Dart avisa. Com int e String, o switch clássico pode ficar sem default (como na seção 1).

A pegadinha das faixas de double

Estes casos parecem cobrir todos os números: maior ou igual a 9, a 7, a 5, e menor que 5. Mas:

void main() {
  final nota = 7.8;
  final conceito = switch (nota) {
    >= 9 => 'A',
    >= 7 => 'B',
    >= 5 => 'C',
    < 5 => 'D',
  };
  print(conceito);
}

$ dart run err_rel_exaust.dart
err_rel_exaust.dart:3:28: Error: The type 'double' is not exhaustively matched by the switch cases since it doesn't match 'double()'.
Try adding a wildcard pattern or cases that match 'double()'.

O Dart não faz contas para descobrir que as faixas se completam: ele só garante a cobertura com tipos, valores exatos (como true/false) e o curinga. (E existe mesmo um double que não é maior, nem menor, nem igual a nada: o NaN, de Operadores Aritméticos.) Como consertar: troque o último caso por _ => 'D'.

Formas diferentes de fazer

O mesmo "nome do dia" pode sair de uma cadeia de if … else if, de um switch clássico que guarda numa variável, ou da expressão switch. Para escolher:

SituaçãoUse
Escolher um valor conforme muitos casosexpressão switch: final x = switch (v) { … };
Fazer coisas diferentes (vários comandos) em cada casoswitch clássico, com case e default
Faixas de valores (notas, idades)expressão switch com >= 9, >= 12 && < 18, ou if … else if
Condições que envolvem variáveis diferentes (idade e temIngresso)if … else if (o switch olha um valor só, mas o when ajuda)
Só dois caminhosif … else ou o ternário
Valor de um tipo conforme o tipo (Object)expressão switch com int n, String s

E se um caso "não pode acontecer"? Em vez de inventar um valor qualquer para o _, dá para parar o programa com uma exceção: _ => throw ArgumentError('Tamanho desconhecido: $tamanho') (o throw é assunto de Lançando Exceções). No lab, com o tamanho 'M', o programa mostrou 12 normalmente: o throw só age se o curinga for alcançado.

Quando dá errado

Usou default numa expressão switch 
void main() {
  final dia = 3;
  final nome = switch (dia) {
    1 => 'Domingo',
    default => 'Outro',
  };
  print(nome);
}

$ dart run err_default_expr.dart
err_default_expr.dart:5:5: Error: A switch expression may not use the `default` keyword.
Try replacing `default` with `_`.
    default => 'Outro',
    ^^^^^^^

"Uma expressão switch não pode usar a palavra-chave default. Tente trocar default por _." Uma das mensagens mais claras do Dart: o default é do switch clássico; na expressão, o "qualquer outro" é o _. Como consertar: _ => 'Outro',.

Misturou case … : com a expressão switch 
void main() {
  final dia = 1;
  final nome = switch (dia) {
    case 1: 'Domingo',
    _ => 'Outro',
  };
  print(nome);
}

$ dart run err_case_expr.dart
err_case_expr.dart:4:5: Error: Unexpected token 'case'.
    case 1: 'Domingo',
    ^^^^
err_case_expr.dart:4:11: Error: Expected '=>' before this.
    case 1: 'Domingo',
          ^

"Palavra inesperada: case" e "era esperado => antes disto" (apontando o :). Na expressão switch não existe case nem :. Como consertar: 1 => 'Domingo',.

Esqueceu a vírgula entre os casos 
void main() {
  final dia = 1;
  final nome = switch (dia) {
    1 => 'Domingo'
    2 => 'Segunda',
    _ => 'Outro',
  };
  print(nome);
}

$ dart run err_virgula.dart
err_virgula.dart:5:5: Error: Expected ',' before this.
    2 => 'Segunda',
    ^

"Era esperado , antes disto." O erro aponta a linha 5, mas a vírgula faltou no fim da linha 4: o Dart só percebe quando encontra o caso seguinte. Como consertar: 1 => 'Domingo',.

Uma variável no case 
void main() {
  final limite = 10;
  final valor = 10;
  switch (valor) {
    case limite:
      print('No limite');
    default:
      print('Outro');
  }
}

$ dart run err_var_case.dart
err_var_case.dart:5:10: Error: Not a constant expression.
    case limite:

"Não é uma expressão constante." Os valores dos casos têm de ser conhecidos antes de o programa rodar: números e textos escritos direto, ou const (aula final e const). Uma final só ganha o valor rodando. Como consertar: const limite = 10;, ou um if (valor == limite).

Casos que compilam, mas nunca são alcançados

Três programas que o dart run aceita sem nenhuma mensagem, e que fazem a coisa errada:

void main() {
  final dia = 1;
  final nome = switch (dia) {
    _ => 'Outro',
    1 => 'Domingo',
  };
  print(nome);
}

$ dart run err_ordem.dart
Outro
  • O _ primeiro (acima): o curinga combina com tudo, e os casos de baixo nunca são testados. O 1 virou Outro.
  • Caso repetido: num switch clássico com case 1: duas vezes, a opção 2 mostrou Outro e o segundo case 1: nunca vai rodar.
  • Tipo errado no caso: switch (opcao) com opcao = 2 (um int) e case '2': (um texto) mostrou Outro: o número 2 nunca é igual ao texto '2'.

O dart run não avisa, mas o dart analyze (o "analisador", aula Análise e Formatação) encontra os três. A Ana pôs os três arquivos numa pasta an e rodou:

Resumo

  • O switch compara um valor com uma lista de casos. O clássico (case 1:, default:) escolhe instruções; no Dart 3, cada caso termina sozinho, sem break.
  • A expressão switch Dart 3.0 devolve um valor: switch (v) { 1 => 'a', _ => 'b' }, com vírgulas, sem case e com _ no lugar do default.
  • Os casos são patterns: valores, comparações (>= 9), faixas (>= 12 && < 18), alternativas ('sáb' || 'dom'), tipos (int n) e guardas (when). Vale o primeiro que combinar.
  • A expressão switch precisa ser exaustiva: cobrir todos os valores do tipo. Com int, double e String, isso quer dizer ter um _; com bool, basta true e false.
  • O _ vai sempre por último; o dart analyze acha casos que nunca são alcançados.
