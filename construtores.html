Dart Construtores

Na aula de Classes, cada produto era criado vazio e preenchido depois, linha por linha: final cafe = Produto(); cafe.nome = 'café'; cafe.preco = 18.9;. Funciona, mas é fácil esquecer um campo, e o objeto passa um tempo "pela metade". O construtor (em inglês, constructor) resolve isso: é o código que roda na hora de criar o objeto e que recebe os valores de que ele precisa. O objeto já nasce pronto: Produto('café', 18.9).

Você vai aprender
  • Como escrever um construtor e o atalho que todo mundo usa: Produto(this.nome, this.preco);
  • O que é o this ("este objeto").
  • Por que, com construtor, os campos podem ser final.
  • Construtores com parâmetros nomeados, required e valores padrão.
  • O corpo do construtor (para conferir os valores) e a lista de inicialização (: preco = …).
  • Os erros reais que o Dart mostra quando algo não bate.

Todos os programas desta aula rodaram no Dart 3.13.5 da máquina da Ana (usuária ana, computador notebook), com dart run arquivo.dart.

A ideia: o formulário da matrícula

Para entrar na escola, ninguém vira aluno "vazio" e preenche o nome depois. A secretaria entrega um formulário: nome, data de nascimento, responsável. Sem preencher os campos obrigatórios, não tem matrícula. Quando o formulário é aceito, o aluno já existe completo.

O construtor é esse formulário. Ele diz o que é preciso informar para criar o objeto e garante que, ao final, todos os campos tenham valor.

1. O primeiro construtor

Um construtor se escreve dentro da classe, com o mesmo nome da classe e sem tipo de retorno:

class Produto {
  String nome = '';
  double preco = 0;

  Produto(String n, double p) {
    nome = n;
    preco = p;
  }
}

void main() {
  final cafe = Produto('café', 18.9);
  print('${cafe.nome}: R\$ ${cafe.preco}');
}
Produto(String n, double p)
O construtor: o nome da classe e, entre parênteses, os parâmetros que ele recebe. Não tem void nem outro tipo na frente: ele sempre "devolve" o objeto novo.
{ nome = n; preco = p; }
O corpo: o código que roda na criação. Aqui, copia os parâmetros para os campos.
Produto('café', 18.9)
Criar o objeto agora é chamar o construtor, passando os valores na ordem.
$ dart run longo.dart
café: R$ 18.9

Funciona, mas tem dois defeitos: os campos ainda precisam de um valor inicial "de mentira" ('' e 0), e os nomes n e p não dizem nada. A forma a seguir resolve os dois.

2. O atalho this.campo

class Produto {
  final String nome;
  final double preco;

  Produto(this.nome, this.preco);
}

void main() {
  final cafe = Produto('café', 18.9);
  final pao = Produto('pão', 1.0);
  print('${cafe.nome}: R\$ ${cafe.preco}');
  print('${pao.nome}: R\$ ${pao.preco}');
}
final String nome;
O campo agora é final ("não muda mais") e não tem valor inicial. Pode ficar assim porque o construtor garante que ele vai receber um valor.
Produto(this.nome, this.preco);
O atalho: um parâmetro escrito como this.nome quer dizer "o valor que chegar aqui vai direto para o campo nome". O tipo vem do campo. Não tem corpo: termina com ;.
$ dart run curto.dart
café: R$ 18.9
pão: R$ 1.0

Este é o jeito recomendado pelo estilo oficial do Dart: curto, sem valores "de mentira", e com campos final, que protegem o objeto de mudanças acidentais. Com campos final, o produto não muda depois de criado (veja o erro em Quando dá errado).

O que é o this

this ("este") quer dizer "este objeto", aquele em que o código está rodando. Ele serve para desempatar quando um parâmetro tem o mesmo nome de um campo. Compare os dois métodos:

class Produto {
  String nome = '';

  void renomear(String nome) {
    nome = nome;
  }

  void renomearCerto(String nome) {
    this.nome = nome;
  }
}

void main() {
  final p = Produto();
  p.renomear('café');
  print('Depois de renomear: "${p.nome}"');
  p.renomearCerto('café');
  print('Depois de renomearCerto: "${p.nome}"');
}

$ dart run this.dart
Depois de renomear: ""
Depois de renomearCerto: "café"

Em renomear, os dois nome são o parâmetro (o nome mais "perto" vence): o método copiou o parâmetro nele mesmo, e o campo continuou vazio. Nenhum erro, só um programa errado. Em renomearCerto, this.nome é o campo do objeto, e nome é o parâmetro. Sem empate de nomes, o this não é necessário (e o estilo do Dart pede para não escrevê-lo).

3. Parâmetros nomeados, required e valor padrão

Produto('café', 18.9, 10): o que é esse 10? Com muitos parâmetros, a ordem confunde. Os parâmetros nomeados funcionam também no construtor: eles vão entre chaves, e quem cria o objeto escreve o nome de cada um.

class Produto {
  final String nome;
  final double preco;
  final int estoque;

  Produto({required this.nome, required this.preco, this.estoque = 0});

  @override
  String toString() => '$nome (R\$ $preco, estoque $estoque)';
}

void main() {
  final cafe = Produto(nome: 'café', preco: 18.9, estoque: 10);
  final pao = Produto(preco: 1.0, nome: 'pão');
  print(cafe);
  print(pao);
}
{ … }
As chaves dentro dos parênteses avisam: estes parâmetros são nomeados.
required this.nome
required = "obrigatório". Quem cria o produto tem de informar o nome. Sem o required, um parâmetro nomeado é opcional.
this.estoque = 0
Opcional, com valor padrão: se ninguém informar, vale 0 (veja Parâmetros Opcionais).
Produto(preco: 1.0, nome: 'pão')
Com nomes, a ordem não importa, e o estoque ficou de fora.
toString()
O texto que o print mostra (veja Classes).
$ dart run nomeados.dart
café (R$ 18.9, estoque 10)
pão (R$ 1.0, estoque 0)

O pão ficou com estoque 0: o valor padrão. Também dá para misturar: os primeiros parâmetros posicionais e os demais nomeados, como em Produto(this.nome, {this.estoque = 0}).

4. O corpo do construtor: conferir os valores

Com o atalho this., o construtor pode ter um corpo também. O corpo roda depois de os campos receberem os valores, e é o lugar de conferir se eles fazem sentido. A conta do banco não pode abrir com saldo negativo:

class Conta {
  final String dona;
  double saldo;

  Conta(this.dona, this.saldo) {
    print('Conta de $dona aberta com R\$ $saldo');
    if (saldo < 0) {
      throw ArgumentError('saldo inicial negativo: $saldo');
    }
  }
}

void main() {
  final ana = Conta('Ana', 100);
  print('Saldo da ${ana.dona}: ${ana.saldo}');
  final bia = Conta('Bia', -50);
  print('Saldo da ${bia.dona}: ${bia.saldo}');
}

5. A lista de inicialização: : campo = …

E se um campo final precisa de uma conta feita com os parâmetros? O corpo não pode dar valor a um campo final (ele roda tarde demais). Para isso existe a lista de inicialização: depois dos parênteses, dois-pontos e as atribuições.

class Produto {
  final String nome;
  final int precoCentavos;
  final double preco;

  Produto(this.nome, this.precoCentavos) : preco = precoCentavos / 100;
}

void main() {
  final cafe = Produto('café', 1890);
  print('${cafe.nome}: ${cafe.precoCentavos} centavos = R\$ ${cafe.preco}');
}

$ dart run lista.dart
café: 1890 centavos = R$ 18.9

O : preco = precoCentavos / 100 roda antes do corpo, junto com os this., quando o objeto ainda está sendo montado. Vários campos se separam com vírgula: : a = 1, b = 2.

Ordem do que acontece ao criar um objeto

  1. Os parâmetros this.campo preenchem os seus campos.
  2. A lista de inicialização (: …) preenche os outros.
  3. Todo campo final ou sem ? tem de ter valor neste ponto.
  4. O corpo { … } roda, com o objeto já completo.

6. E quando a classe não tem construtor?

Na aula de Classes, você escreveu Produto() sem ter escrito construtor nenhum. É que o Dart cria um sozinho, o construtor padrão: sem parâmetros e sem corpo.

class Cofrinho {
  double saldo = 0;
}

void main() {
  final c = Cofrinho();
  print(c.saldo);
}

$ dart run padrao.dart
0.0

Assim que você escreve um construtor seu, o padrão deixa de existir: com Produto(this.nome, this.preco), um Produto() vazio dá erro. Para ter mais de um jeito de criar o objeto, existem os construtores com nome, da próxima aula: Construtores Nomeados e factory.

"Construtores não podem ter tipo de retorno. Tente remover o tipo de retorno." O construtor sempre devolve o objeto novo; não se escreve tipo. Como consertar: apague o void.

Sem erro, mas o campo não mudou: faltou o this

O caso do renomear da seção 2: nome = nome; dentro de um método com um parâmetro nome copia o parâmetro nele mesmo. O Dart não reclama, e o campo fica como estava (no lab, Depois de renomear: ""). Como consertar: this.nome = nome;, ou dê ao parâmetro outro nome.

Missão final: o aluno com nota conferida

Missão: escreva o construtor de Aluno com parâmetros nomeados e obrigatórios (required this.nome, required this.nota) e um corpo que lança ArgumentError('nota fora de 0 a 10') quando a nota for menor que 0 ou maior que 10. O main cria a Bia (8.5) e depois o Caio (12): a Bia deve aparecer e o Caio deve parar o programa com o erro.

class Aluno {
  final String nome;
  final double nota;

  // escreva o construtor aqui
}

void main() {
  final bia = Aluno(nome: 'Bia', nota: 8.5);
  print('${bia.nome}: ${bia.nota}');
  final caio = Aluno(nome: 'Caio', nota: 12);
  print('${caio.nome}: ${caio.nota}');
}

class Aluno {
  final String nome;
  final double nota;

  Aluno({required this.nome, required this.nota}) {
    if (nota < 0 || nota > 10) {
      throw ArgumentError('nota fora de 0 a 10');
    }
  }
}

void main() {
  final bia = Aluno(nome: 'Bia', nota: 8.5);
  print('${bia.nome}: ${bia.nota}');
  final caio = Aluno(nome: 'Caio', nota: 12);
  print('${caio.nome}: ${caio.nota}');
}

Resumo

  • O construtor tem o nome da classe, não tem tipo de retorno e roda na criação do objeto.
  • Produto(this.nome, this.preco); copia os argumentos direto para os campos, que podem ser final.
  • this é "este objeto"; serve para desempatar campo e parâmetro de mesmo nome.
  • Nomeados: {required this.nome, this.estoque = 0}; quem cria escreve os nomes, em qualquer ordem.
  • A lista de inicialização (: campo = …) calcula campos final; o corpo { … } roda depois, para conferir valores (e throw se estiverem errados).
  • Sem construtor escrito, o Dart dá o padrão Classe(); para vários jeitos de criar, veja Construtores Nomeados e factory.
