Dart Classes e Funções Genéricas

Na aula Genéricos você usou as "caixas com etiqueta" que o Dart já traz: List<T>, Set<T>, Map<K, V>. Agora você vai fabricar as suas: uma classe ou uma função que funciona com qualquer tipo, sem perder a conferência de tipos do Dart. É assim que a própria List é escrita por dentro.

Você vai aprender
  • Como escrever uma classe genérica: class Caixa<T>, e o que é esse T.
  • Como montar uma Fila<T> que serve para clientes (String) e para senhas (int).
  • Como escrever uma função genérica: T primeiro<T>(List<T> lista).
  • Como usar dois tipos (Par<A, B>) e como limitar o tipo (T extends num).
  • Os erros reais: The operator '>' isn't defined for the type 'Object?' e companhia.

Esta aula usa classes e funções. Todos os programas rodaram no Dart SDK 3.13.5 da máquina da Ana (usuária ana, computador notebook), com dart run arquivo.dart.

A ideia: a fôrma de bolo

A padaria tem uma fôrma que serve para qualquer massa: chocolate, cenoura, fubá. A fôrma é sempre a mesma; o que muda é o que você coloca nela. E o que sai do forno é exatamente o que entrou: pôs massa de cenoura, sai bolo de cenoura.

Uma classe genérica é essa fôrma. O T (de "tipo") é um espaço reservado: "aqui vai um tipo, que eu ainda não sei qual é". Quem usa a classe preenche o espaço: Caixa<int>, Caixa<String>. A partir daí, em todo lugar onde a classe diz T, o Dart entende int ou String.

Sem genéricos, você teria duas saídas ruins: escrever uma classe para cada tipo (CaixaDeInt, CaixaDeString…), ou usar Object/dynamic e perder a conferência (o "sai exatamente o que entrou").

1. A primeira classe genérica

class Caixa<T> {
  final T conteudo;
  final String etiqueta;

  Caixa(this.conteudo, this.etiqueta);

  T abrir() {
    print('Abrindo a caixa "$etiqueta"...');
    return conteudo;
  }
}

void main() {
  final ovos = Caixa<int>(12, 'ovos');
  final bolo = Caixa('chocolate', 'bolo');
  final n = ovos.abrir();
  print('Tem $n ovos; dá para ${n ~/ 6} receitas.');
  final sabor = bolo.abrir();
  print('O bolo é de ${sabor.toUpperCase()}.');
  print(ovos.runtimeType);
  print(bolo.runtimeType);
}
class Caixa<T>
Declara a classe e o seu parâmetro de tipo, T. O nome é livre, mas por tradição é uma letra maiúscula: T (tipo), E (elemento), K e V (chave e valor).
final T conteudo;
Um campo do tipo T: numa Caixa<int>, é um int; numa Caixa<String>, é uma String.
final String etiqueta;
Nem tudo precisa ser T: este campo é sempre texto.
T abrir()
Um método que devolve um T: sai o mesmo tipo que entrou.
Caixa<int>(12, 'ovos')
Preenche o T com int, escrito.
Caixa('chocolate', 'bolo')
Sem escrever: o Dart infere T = String pelo valor passado.
n ~/ 6 e sabor.toUpperCase()
A prova de que o tipo não se perdeu: o Dart sabe que n é int (dá para dividir) e que sabor é String (tem toUpperCase).

Abrindo a caixa "ovos"...
Tem 12 ovos; dá para 2 receitas.
Abrindo a caixa "bolo"...
O bolo é de CHOCOLATE.
Caixa<int>
Caixa<String>

Missão: o Pote só aceita int, e o pote de orégano não compila. Torne a classe genérica: class Pote<T> e o campo final T conteudo;.

class Pote {

  print('Tempero: ${tempero.conteudo}');
}

void main() {

2. Uma classe útil: Fila<T>

Na padaria há duas filas: a de clientes (nomes) e a de senhas (números). A regra é a mesma nas duas: quem entra primeiro é atendido primeiro. Uma classe genérica serve para as duas:

class Fila<T> {
  final _itens = <T>[];

  void entrar(T item) => _itens.add(item);

  T atender() => _itens.removeAt(0);

  bool get vazia => _itens.isEmpty;
  int get tamanho => _itens.length;
}

void main() {
  final clientes = Fila<String>();
  clientes.entrar('Ana');
  clientes.entrar('Bia');
  clientes.entrar('Caio');
  print('Na fila: ${clientes.tamanho}');
  while (!clientes.vazia) {
    print('Atendendo ${clientes.atender()}');
  }

  final senhas = Fila<int>();
  senhas.entrar(101);
  senhas.entrar(102);
  print('Próxima senha: ${senhas.atender() + 0}');
}

$ dart run fila.dart
Na fila: 3
Atendendo Ana
Atendendo Bia
Atendendo Caio
Próxima senha: 101
final _itens = <T>[];
Por dentro, a fila guarda uma List<T>. O T da classe passa para a lista. O _ deixa a lista privada: de fora, só se usa entrar e atender.
void entrar(T item)
Numa Fila<String>, só entra String; o Dart barra um número na fila de clientes.
T atender()
Tira e devolve o primeiro da fila (removeAt(0)). O + 0 na senha está ali só para provar que o resultado é um int de verdade.

3. Funções genéricas

Uma função também pode ter o seu <T>. Ele vem logo depois do nome da função:

T primeiro<T>(List<T> lista) {
  return lista[0];
}

(T, T) pontas<T>(List<T> lista) => (lista.first, lista.last);

void main() {
  final nome = primeiro(['Ana', 'Bia']);
  final nota = primeiro<int>([9, 7]);
  print('$nome ${nome.length}');
  print('$nota ${nota + 1}');
  final (menor, maior) = pontas([3, 5, 8]);
  print('de $menor a $maior');
}

$ dart run func.dart
Ana 3
9 10
de 3 a 8
T primeiro<T>(List<T> lista)
Leia da direita para a esquerda: a função recebe uma "lista de T" e devolve "um T". O <T> depois de primeiro declara o espaço reservado; o T do começo é o tipo de retorno.
primeiro(['Ana', 'Bia'])
O Dart infere T = String, então nome é String e tem .length.
primeiro<int>([9, 7])
Também dá para escrever o tipo na chamada.
(T, T) pontas<T>(…)
Devolve um record com dois T, desmontado em menor e maior.

Muitos métodos que você já usou são genéricos assim: o map<R> das listas, o fold<T>, o List<E>.generate (veja map, where, reduce).

4. Dois tipos: Par<A, B>

Como o Map<K, V>, uma classe pode ter vários parâmetros de tipo, separados por vírgula:

class Par<A, B> {
  final A primeiro;
  final B segundo;
  Par(this.primeiro, this.segundo);

  @override
  String toString() => '($primeiro, $segundo)';
}

void main() {
  final item = Par<String, double>('pão', 0.75);
  print(item);
}

$ dart run par.dart
(pão, 0.75)

Para pares simples assim, hoje o Dart tem um jeito mais curto: o record ('pão', 0.75), do tipo (String, double).

5. Limitando o tipo: T extends …

Dentro de uma função genérica, o Dart não sabe nada sobre T: pode ser número, texto, uma Caixa… Por isso ele só deixa usar o que todo objeto tem. Para calcular uma média, você precisa somar; então diz ao Dart: "T pode ser qualquer tipo, desde que seja um número". É o extends ("estende"), o limite do tipo:

double media<T extends num>(List<T> valores) {
  var soma = 0.0;
  for (final v in valores) {
    soma += v;
  }
  return soma / valores.length;
}

void main() {
  print(media([7, 8, 10]));
  print(media([4.5, 9.0]));
  print(media(<num>[7, 8.5]));
}

$ dart run limite.dart
8.333333333333334
6.75
7.75

A mesma função serviu para List<int>, List<double> e List<num>. Dentro dela, o Dart sabe que v é pelo menos um num, então o soma += v é permitido. (O 8.333333333333334 é o jeito do double mostrar 25 ÷ 3; veja int e double.)

Outro limite muito usado é Comparable ("comparável"): tipos que sabem dizer qual vem antes, como números e textos, pelo método compareTo:

T maior<T extends Comparable<T>>(T a, T b) {
  return a.compareTo(b) >= 0 ? a : b;
}

void main() {
  print(maior(3, 7));
  print(maior('Ana', 'Bia'));
  print(maior(2.5, 1.0));
}

$ dart run maior.dart
7
Bia
2.5

O compareTo devolve um número positivo se a vem depois de b, zero se são iguais, e negativo se vem antes. Para textos, "depois" é na ordem do dicionário: Bia vem depois de Ana.

Quando dá errado

Usou em T uma operação que nem todo tipo tem 
T maior<T>(T a, T b) {
  return a > b ? a : b;
}

void main() {
  print(maior(3, 7));
}

$ dart run e2.dart
e2.dart:2:12: Error: The operator '>' isn't defined for the type 'Object?'.
 - 'Object' is from 'dart:core'.
Try correcting the operator to an existing operator, or defining a '>' operator.
  return a > b ? a : b;
           ^

Linha por linha:

The operator '>' isn't defined for the type 'Object?'.
"O operador > não existe para o tipo Object?". Sem limite, o T pode ser qualquer coisa, até null; para o Dart, dentro da função, ele é só um Object?. E nem todo objeto sabe fazer > (uma Caixa não sabe).
- 'Object' is from 'dart:core'.
Só informa de onde vem o Object: da biblioteca básica do Dart.
Try correcting …
"Tente corrigir para um operador que exista, ou definir um operador >".

Não importa que, na chamada, foram passados números: a função tem de funcionar para todo T possível. Como consertar: ponha um limite, como na seção 5: T extends Comparable<T> e a.compareTo(b) >= 0.

O tipo não respeita o limite 
double media<T extends num>(List<T> valores) {
  var soma = 0.0;
  for (final v in valores) {
    soma += v;
  }
  return soma / valores.length;
}

void main() {
  print(media(['sete', 'oito']));
}

$ dart run e1.dart
e1.dart:10:15: Error: The argument type 'List<String>' can't be assigned to the parameter type 'List<num>'.
 - 'List' is from 'dart:core'.
  print(media(['sete', 'oito']));
              ^

"Uma List<String> não pode ir onde se espera List<num>". O limite T extends num barrou os textos antes de rodar. Como consertar: passe números: media([7, 8]).

O valor não combina com o tipo escrito 
class Caixa<T> {
  final T conteudo;
  Caixa(this.conteudo);
}

void main() {
  final ovos = Caixa<int>('doze');
  print(ovos.conteudo);
}

$ dart run e3.dart
e3.dart:7:27: Error: The argument type 'String' can't be assigned to the parameter type 'int'.
  final ovos = Caixa<int>('doze');
                          ^

Com Caixa<int>, o construtor espera um int. É a conferência funcionando. Como consertar: Caixa<int>(12).

Número errado de tipos 
$ dart run e4.dart
e4.dart:13:13: Error: Expected 2 type arguments.
  final p = Par<String>('x', 1);
            ^
e4.dart:4:3: Context: Found this candidate, but the arguments don't match.
  Par(this.primeiro, this.segundo);
  ^^^

O arquivo e4.dart é o par.dart da seção 4 com uma linha a mais no main: final p = Par<String>('x', 1);. "Eram esperados 2 argumentos de tipo": o Par tem A e B. A linha Context: ("contexto") mostra o construtor que o Dart tentou usar. Como consertar: Par<String, int>('x', 1), ou deixe o Dart inferir: Par('x', 1).

Missão final: o último da lista

Missão: a função ultimo devolve Object?, e por isso o Dart não deixa usar .toUpperCase() nem somar + 1 no resultado (o programa não compila). Reescreva a função como genérica: T ultimo<T>(List<T> lista).

Object? ultimo(List lista) {
  return lista.last;
}

void main() {
  final compras = ['pão', 'leite', 'café'];
  print('Último item: ${ultimo(compras).toUpperCase()}');
  print('Último número + 1: ${ultimo([3, 5, 8]) + 1}');
}

T ultimo<T>(List<T> lista) {
  return lista.last;
}

void main() {
  final compras = ['pão', 'leite', 'café'];
  print('Último item: ${ultimo(compras).toUpperCase()}');
  print('Último número + 1: ${ultimo([3, 5, 8]) + 1}');
}

No lab, a solução mostrou Último item: CAFÉ e Último número + 1: 9.

Resumo

  • Uma classe genérica declara um espaço reservado para um tipo: class Caixa<T>. Quem usa preenche: Caixa<int>, ou deixa o Dart inferir.
  • Dentro da classe, T vale para campos, parâmetros, retornos e até listas internas (<T>[]).
  • Uma função genérica tem o <T> depois do nome: T primeiro<T>(List<T> lista).
  • Vários tipos se separam por vírgula: Par<A, B>.
  • Sem limite, T é tratado como Object?: nada de >, + ou .length. Com T extends num ou T extends Comparable<T>, você ganha essas operações e o Dart barra os tipos que não servem.
