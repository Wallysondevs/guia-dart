Dart Estilo de Código

Dois programas podem fazer exatamente a mesma coisa e um ser muito mais fácil de ler que o outro. A equipe do Dart escreveu um guia de boas maneiras chamado Effective Dart ("Dart eficaz", em dart.dev/effective-dart), e quase todo código Dart do mundo segue as mesmas regras. Seguindo também, o seu código fica com "cara de Dart", e qualquer pessoa entende de primeira. Nesta aula você vai ver as regras principais, o porquê de cada uma, e como o analisador avisa quando você esquece.

Você vai aprender
  • Como dar nomes: UpperCamelCase, lowerCamelCase e snake_case, e onde usar cada um.
  • Por que as constantes do Dart não são escritas em MAIÚSCULAS.
  • As escolhas do dia a dia: aspas simples, final, interpolação, isEmpty, [] e {}, e nada de new.
  • Como escrever comentários de documentação com ///.
  • Como o dart analyze aponta cada deslize, com a regra pelo nome.

Os programas desta aula rodaram no Dart SDK 3.13.5 da máquina da Ana (usuária ana, computador notebook), dentro do projeto padaria criado com dart create, que já liga as regras recomendadas (veja Análise e Formatação).

A ideia: a letra de forma da escola

Na escola, todo mundo aprende a escrever a data no mesmo canto da folha e o nome no cabeçalho. Não é porque o outro jeito esteja "errado": é porque a professora corrige 40 provas e acha tudo no mesmo lugar. Estilo de código é isso. O computador não liga para nomes nem aspas, mas pessoas leem o código muito mais vezes do que ele é escrito, inclusive você daqui a três meses.

O Effective Dart separa as regras em quatro palavras: FAÇA (DO), NÃO FAÇA (DON'T), PREFIRA (PREFER) e EVITE (AVOID). As duas primeiras quase não têm exceção; as duas últimas são conselhos fortes.

1. Um programa que funciona, mas "não tem cara de Dart"

A Ana escreveu a lista de compras assim, num arquivo bin/Lista_Compras.dart:

class lista_compras {
  var Itens = new List<String>.empty(growable: true);
}

const PRECO_PAO = 0.75;

void main() {
  var l = lista_compras();
  l.Itens.add("pão");
  l.Itens.add('leite');
  if (l.Itens.length == 0) {
    print('vazia');
  }
  var total = PRECO_PAO * 10;
  print('Total: ' + total.toString());
  var m = Map<String, int>();
  m['pão'] = 10;
  print(m);
}

2. Nomes: três jeitos de juntar palavras

Nomes não podem ter espaço. Para juntar "lista" e "compras", existem três estilos, e o Dart usa cada um num lugar:

EstiloComo éOnde usarExemplo
UpperCamelCaseCada palavra começa com maiúscula ("corcova de camelo")Classes, enum, typedef, extensõesListaCompras, ContaBancaria
lowerCamelCaseIgual, mas a primeira letra minúsculaVariáveis, funções, parâmetros, constantesprecoTotal, calcularTroco, precoPao
snake_case (lower_case_with_underscores)Tudo minúsculo, com _ entre as palavras ("cobra")Nomes de arquivos, pastas e pacoteslista_compras.dart

Por isso o analisador reclamou de quatro nomes:

  • file_names: o arquivo Lista_Compras.dart deveria ser lista_compras.dart (alguns sistemas não diferenciam maiúsculas em nomes de arquivo, e o import quebraria).
  • camel_case_types: a classe lista_compras deveria ser ListaCompras.
  • non_constant_identifier_names: o campo Itens deveria ser itens. Com maiúscula, parece uma classe.
  • constant_identifier_names: a constante PRECO_PAO deveria ser precoPao.
Por que não PRECO_PAO?

Em C, Java e Python, constantes costumam ir em MAIÚSCULAS. No Dart, não: o Effective Dart diz para usar lowerCamelCase também nas constantes. O motivo: no Dart, trocar uma variável final por const (ou o contrário) é comum, e não faz sentido ter de renomear em todo o programa por causa disso. Você vai ver pi, e e maxFinite nas bibliotecas do próprio Dart, nunca PI.

Nomes que dizem o que guardam

Além do formato, o nome tem de contar o que é. l e m não dizem nada; lista e estoque dizem. Use nomes inteiros (quantidade, não qtd), e sem acento: o Dart não aceita ç nem á em nomes (veja Quando dá errado).

Missão: renomeie a classe para ListaCompras e a constante para precoPao (nos dois lugares em que cada uma aparece). O programa deve continuar mostrando Total: 7.5.

class lista_compras {
  final itens = <String>[];
}

const PRECO_PAO = 0.75;

void main() {
  final lista = lista_compras();
  lista.itens.add('pão');
  print('Total: ${PRECO_PAO * 10}');
}

3. As escolhas do dia a dia

Sem new

No Dart antigo, criava-se um objeto com new List(). Desde o Dart 2, a palavra new é opcional, e o estilo é não escrever (unnecessary_new): ListaCompras(), não new ListaCompras(). Menos ruído para ler.

Literais de coleção: [] e {}

Em vez de Map<String, int>() ou List<String>.empty(growable: true), escreva a coleção vazia direto (prefer_collection_literals):

final itens = <String>[];          // lista vazia de textos
final estoque = <String, int>{};   // mapa vazio
final cores = <String>{};          // conjunto (Set) vazio

isEmpty em vez de length == 0

if (lista.itens.isEmpty) ("está vazia?") se lê como português; length == 0 obriga a fazer a conta de cabeça (prefer_is_empty). O contrário é isNotEmpty.

Interpolação em vez de +

'Total: ' + total.toString() funciona, mas 'Total: $total' é mais curto e converte sozinho (prefer_interpolation_to_compose_strings). Para uma conta ou um campo, use chaves: 'Total: ${preco * 10}', 'Itens: ${lista.itens.length}'.

Aspas simples

Os dois tipos de aspas funcionam igual. O estilo da comunidade (e de todo este guia) é usar simples, 'pão', e deixar as duplas para quando o texto tem apóstrofo: "Pão d'água". A regra se chama prefer_single_quotes.

final por padrão

Se uma variável não vai mudar, declare com final. Quem lê sabe na hora que aquele valor é fixo, e o Dart impede que você o mude por engano. Use var só para o que muda (um contador, um total que vai somando). A regra prefer_final_locals avisa.

4. O programa passado a limpo

A Ana renomeou o arquivo para bin/lista_compras.dart, ligou as regras prefer_single_quotes e prefer_final_locals no analysis_options.yaml, e reescreveu:

/// A lista de compras da Ana.
class ListaCompras {
  final itens = <String>[];
}

/// Preço de um pão francês, em reais.
const precoPao = 0.75;

void main() {
  final lista = ListaCompras();
  lista.itens.add('pão');
  lista.itens.add('leite');
  if (lista.itens.isEmpty) {
    print('vazia');
  }
  final total = precoPao * 10;
  print('Total: $total');
  final estoque = <String, int>{};
  estoque['pão'] = 10;
  print(estoque);
}

A mesma saída, e nenhum aviso. Antes de consertar, com as duas regras extras ligadas, a versão antiga tinha 12 info (as 8 de antes mais 3 prefer_final_locals e 1 prefer_single_quotes, no "pão" da linha 9).

5. Comentários de documentação: ///

Viu o /// em cima da classe e da constante? Comentário com três barras é um comentário de documentação: o editor de código mostra esse texto quando você passa o mouse sobre o nome, e a ferramenta dart doc o transforma em páginas de ajuda. O Effective Dart pede:

  • Use /// (e não //) para documentar classes, funções e campos.
  • Comece com uma frase curta que diz o que é ou o que faz: /// Calcula o troco da compra.
  • Cite nomes do código entre colchetes: /// Soma [preco] vezes [quantidade].
  • Para explicar um trecho por dentro de uma função, use o comentário comum, //.
/// Calcula o troco de uma compra.
///
/// Devolve quanto sobra de [pago] depois de pagar [total].
double calcularTroco(double total, double pago) {
  // arredonda para evitar 0.30000000000000004
  return ((pago - total) * 100).round() / 100;
}

Quando dá errado

Quebrar uma regra de estilo nunca dá erro: dá um info. Mas dois deslizes de "escrita" dão erro de compilação de verdade.

Acento no nome da variável 
void main() {
  final preço = 2.5;
  print(preço);
}

$ dart run acento.dart
acento.dart:2:12: Error: The non-ASCII character 'ç' (U+00E7) can't be used in identifiers, only in strings and comments.
Try using an US-ASCII letter, a digit, '_' (an underscore), or '$' (a dollar sign).
  final preço = 2.5;
           ^
acento.dart:3:12: Error: The non-ASCII character 'ç' (U+00E7) can't be used in identifiers, only in strings and comments.
Try using an US-ASCII letter, a digit, '_' (an underscore), or '$' (a dollar sign).
  print(preço);
           ^

"O caractere não ASCII ç (U+00E7, o código dele na tabela Unicode) não pode ser usado em identificadores, só em textos e comentários. Tente usar uma letra do inglês (US-ASCII), um dígito, _ ou $." Identificador é qualquer nome que você inventa: variável, função, classe. O ^ aponta a coluna 12, exatamente o ç. Dentro das aspas ('pão') o acento é livre. Como consertar: preco.

Apóstrofo dentro de aspas simples 
void main() {
  print('Pão d'água: R$ 1,20');
}

$ dart run aspas.dart
aspas.dart:2:16: Error: The non-ASCII character 'á' (U+00E1) can't be used in identifiers, only in strings and comments.
Try using an US-ASCII letter, a digit, '_' (an underscore), or '$' (a dollar sign).
  print('Pão d'água: R$ 1,20');
               ^
aspas.dart:2:29: Error: String starting with ' must end with '.
  print('Pão d'água: R$ 1,20');
                            ^^^
« … e mais 7 erros, todos causados pelo mesmo apóstrofo »

O apóstrofo de d'água fechou o texto: para o Dart, o texto é só 'Pão d', e o água virou um "nome" solto (daí o erro do á em identificador). Depois sobrou um '); que abre um texto novo e nunca fecha: "texto começando com ' tem de terminar com '". Um caractere fora do lugar gerou 9 erros em cascata; leia sempre o primeiro. Como consertar: é a exceção da regra das aspas simples. Use aspas duplas, "Pão d'água: R\$ 1,20", ou escape o apóstrofo com barra, 'Pão d\'água: R\$ 1,20'. (O R$ também precisa da barra, como você viu em Compilando.)

Resumo

  • O Effective Dart é o guia oficial de estilo; o código fica com "cara de Dart" e qualquer um lê.
  • Classes em UpperCamelCase; variáveis, funções e constantes em lowerCamelCase; arquivos em snake_case.dart; nomes sem acento e que digam o que guardam.
  • Aspas simples (duplas só com apóstrofo), final por padrão, interpolação, isEmpty, []/{} e nada de new.
  • Documente com ///, começando por uma frase curta; cite nomes entre [colchetes].
  • O dart analyze (com package:lints) aponta cada deslize como info, com o nome da regra; o dart format cuida dos espaços.
