Dart Extensões

Em todo programa da lojinha, a Ana escreve 'R\$ ${preco.toStringAsFixed(2)}' para mostrar um preço, e o resultado ainda sai com ponto (R$ 12.90), não com vírgula, como se escreve no Brasil. Seria ótimo se todo double tivesse um .reais: preco.reais → R$ 12,90. Mas o double é do Dart, não dela; ela não pode abrir a classe e acrescentar nada. Para isso existem as extensões: extension … on double ("extensão sobre double") acrescenta métodos e getters a um tipo que já existe, sem mexer nele.

Você vai aprender
  • Como escrever uma extensão: extension Reais on double { … }.
  • Getters e métodos (com parâmetros) em String, int, List<double> e nas suas próprias classes.
  • O que é this dentro de uma extensão.
  • Por que on num serve para int e double, e como lidar com double?.
  • Os erros reais: duas extensões com o mesmo nome, o tipo que não tem a extensão, e o NoSuchMethodError com dynamic.

Todos os programas desta aula rodaram no Dart 3.13.5 da máquina da Ana (usuária ana, computador notebook), com dart run arquivo.dart. As extensões existem desde o Dart 2.7.

A ideia: a capinha do celular

A Ana não pode abrir o celular e soldar um suporte novo. Mas pode pôr uma capinha com um anel atrás: o celular continua o mesmo, e agora "tem" um anel. Tirou a capinha (ou não trouxe o arquivo da extensão), o anel some.

A extensão é a capinha: ela não muda a classe double. Ela só ensina ao compilador que, quando ele vir preco.reais e preco for um double, deve chamar o código da extensão. Guarde esse detalhe ("o compilador"), porque ele explica o erro mais curioso da aula.

1. A primeira extensão: preço em reais

extension Reais on double {
  String get reais => 'R\$ ${toStringAsFixed(2).replaceAll('.', ',')}';
}

void main() {
  final preco = 12.9;
  print(preco.reais);
  print(0.75.reais);
  print((3 * 4.5).reais);
}
extension
A palavra-chave: "vou acrescentar coisas a um tipo".
Reais
O nome da extensão, em UpperCamelCase, como uma classe. Ele é opcional, mas é útil para resolver conflitos (seção 5) e para as mensagens de erro.
on double
Sobre qual tipo: todo valor double ganha o que estiver dentro das chaves.
String get reais => …
Um getter novo (veja get e set). Dentro dele, toStringAsFixed(2) é chamado no próprio número: é como escrever this.toStringAsFixed(2), onde this é o double que está antes do ponto.
.replaceAll('.', ',')
Troca o ponto pela vírgula (veja Métodos de String).
$ dart run reais.dart
R$ 12,90
R$ 0,75
R$ 13,50

O .reais funcionou numa variável, num número escrito direto (0.75) e no resultado de uma conta. Parece que o double sempre teve esse getter.

2. Métodos com parâmetros, e extensões em String

extension TextoDaLoja on String {
  String get capitalizado =>
      isEmpty ? this : this[0].toUpperCase() + substring(1).toLowerCase();

  bool get vazioOuEspacos => trim().isEmpty;

  String repetir(int vezes, {String separador = ' '}) =>
      List.filled(vezes, this).join(separador);
}

void main() {
  print('bRIGADEIRO'.capitalizado);
  print('pão de queijo'.capitalizado);
  print('   '.vazioOuEspacos);
  print('Ana'.vazioOuEspacos);
  print('oba'.repetir(3));
  print('-'.repetir(10, separador: ''));
}

$ dart run texto.dart
Brigadeiro
Pão de queijo
true
false
oba oba oba
----------
isEmpty ? this : …
Aqui o this aparece por extenso: é o texto inteiro. Se estiver vazio, devolve ele mesmo (não há primeira letra para aumentar).
this[0].toUpperCase() + substring(1).toLowerCase()
A primeira letra em maiúscula e o resto em minúscula.
String repetir(int vezes, {String separador = ' '})
Um método, com um parâmetro posicional e um nomeado com valor padrão. Extensões aceitam tudo o que um método de classe aceita.

Experimente: troque on double por on num e rode: agora 3.reais também funciona (no lab, deu R$ 3,00), porque num é o tipo que reúne int e double. Depois, acrescente um getter String get centavos => '${(this * 100).round()} centavos'; e teste com 0.75.centavos.

3. Extensão numa lista

O tipo depois do on pode ser bem específico. A Ana quer somar e tirar a média das vendas da semana, uma List<double>:

extension Contas on List<double> {
  double get soma => fold(0, (total, x) => total + x);
  double get media => isEmpty ? 0 : soma / length;
}

void main() {
  final vendasDaSemana = [120.0, 98.5, 143.0, 87.25, 160.0];
  print('Total: ${vendasDaSemana.soma}');
  print('Média: ${vendasDaSemana.media}');
  print(<double>[].media);
}

$ dart run lista.dart
Total: 608.75
Média: 121.75
0.0

O fold percorre a lista acumulando um total (veja map, where, reduce e Outros). Dentro da extensão, isEmpty, length e fold são da própria lista, e soma (usado pela media) é da extensão: os membros de uma extensão se enxergam. Uma List<String>, por outro lado, não ganha .soma: a extensão é só para listas de double.

4. Juntando: extensões nas suas próprias classes

Dá para estender as suas classes também, e uma extensão pode usar outra:

extension Reais on double {
  String get reais => 'R\$ ${toStringAsFixed(2).replaceAll('.', ',')}';
}

extension Contas on List<double> {
  double get soma => fold(0, (total, x) => total + x);
}

class Produto {
  final String nome;
  final double preco;

  Produto(this.nome, this.preco);
}

extension Etiqueta on Produto {
  String get etiqueta => '${nome.toUpperCase()} ... ${preco.reais}';
}

void main() {
  final carrinho = [Produto('Café', 4.0), Produto('Bolo', 20.0), Produto('Sonho', 6.5)];
  for (final p in carrinho) {
    print(p.etiqueta);
  }
  final total = carrinho.map((p) => p.preco).toList().soma;
  print('Total: ${total.reais}');
}

$ dart run juntas.dart
CAFÉ ... R$ 4,00
BOLO ... R$ 20,00
SONHO ... R$ 6,50
Total: R$ 30,50

Na sua própria classe, o normal é escrever o getter dentro dela. A extensão faz sentido quando a classe é de outra pessoa (de um pacote), ou quando a etiqueta é um assunto de outra parte do programa (a tela, a impressão) e você não quer misturá-lo com a classe. Para usar uma extensão escrita em outro arquivo, basta importar esse arquivo (veja import, export e Bibliotecas).

Formas diferentes de fazer

Sem extensões, a mesma coisa sai com uma função comum:

String emReais(double valor) => 'R\$ ${valor.toStringAsFixed(2).replaceAll('.', ',')}';

E se usa assim: print(emReais(preco));. Funciona igual. A extensão só muda a leitura: preco.reais se lê da esquerda para a direita, e encadeia melhor (carrinho.map(…).toList().soma.reais, em vez de emReais(somar(carrinho.map(…).toList()))). E o editor de código sugere o .reais quando você digita o ponto.

E o extension type?

O Dart 3.3 trouxe uma coisa de nome parecido, o extension type, que cria um tipo novo por cima de um existente. É um recurso avançado, diferente desta aula; se encontrar extension type num código, saiba que não é a "capinha" vista aqui.

Quando dá errado

Duas extensões com o mesmo nome de getter 
extension Reais on double {
  String get reais => 'R\$ ${toStringAsFixed(2)}';
}

extension ReaisBR on double {
  String get reais => 'R\$ ${toStringAsFixed(2).replaceAll('.', ',')}';
}

void main() {
  final preco = 12.9;
  print(preco.reais);
}

$ dart run erro_conflito.dart

Try using an explicit extension application of the wanted extension or hiding unwanted extensions from scope.
  print(preco.reais);
              ^^^^^
erro_conflito.dart:2:14: Context: This is one of the extension members.
  String get reais => 'R\$ ${toStringAsFixed(2)}';
             ^^^^^
erro_conflito.dart:6:14: Context: This is one of the extension members.

Linha por linha:

  • erro_conflito.dart:11:15: Error: erro de compilação (código 254), linha 11, no .reais.
  • "A propriedade reais está definida em várias extensões para double, e nenhuma é mais específica." O Dart não sabe qual capinha usar.
  • "Tente uma aplicação explícita da extensão desejada, ou esconda as extensões indesejadas."
  • Os dois Context: mostram as duas candidatas, linhas 2 e 6.

Como consertar: a "aplicação explícita" é chamar a extensão pelo nome, como se fosse uma função: ReaisBR(preco).reais. No lab, Reais(preco).reais deu R$ 12.90 e ReaisBR(preco).reais deu R$ 12,90. É para isso que serve o nome da extensão. "Esconder" se faz no import, com hide.

O valor pode ser null 
extension Reais on double {
  String get reais => 'R\$ ${toStringAsFixed(2).replaceAll('.', ',')}';
}

double? precoDe(String produto) => produto == 'café' ? 4.0 : null;

void main() {
  final preco = precoDe('café');
  print(preco.reais);
}

$ dart run erro_nulo.dart
erro_nulo.dart:9:15: Error: Property 'reais' cannot be accessed on 'double?' because it is potentially null.
Try accessing using ?. instead.
  print(preco.reais);
              ^^^^^

"A propriedade reais não pode ser acessada em double?, porque ele pode ser null. Tente ?.." A extensão é on double, e double? é outro tipo (veja Tipos Anuláveis). Como consertar: preco?.reais (dá null se não houver preço), (preco ?? 0).reais, ou confira com if (preco != null) antes (veja ?. , ?? e ??=).

Usou num int uma extensão on double 
extension Reais on double {
  String get reais => 'R\$ ${toStringAsFixed(2).replaceAll('.', ',')}';
}

void main() {
  final quantidade = 3;
  print(quantidade.reais);
}

$ dart run erro_int.dart
erro_int.dart:7:20: Error: The getter 'reais' isn't defined for the type 'int'.
Try correcting the name to the name of an existing getter, or defining a getter or field named 'reais'.
  print(quantidade.reais);

"O getter reais não está definido para o tipo int." O 3 é int, não double. É a mesma mensagem de quando o getter não existe em lugar nenhum: o Dart não diz "existe uma extensão, mas para outro tipo". Como consertar: extension Reais on num (como no Experimente), ou escreva 3.0.

A extensão "sumiu" com dynamic (exceção durante a execução)

Lembra do detalhe da capinha? Quem aplica a extensão é o compilador, olhando o tipo da variável. Se o tipo é dynamic ("qualquer coisa, decido rodando"; veja dynamic e Object), o compilador não sabe que é um double, e a extensão não é aplicada. É comum com dados que vêm de JSON:

import 'dart:convert';

extension Reais on double {
  String get reais => 'R\$ ${toStringAsFixed(2).replaceAll('.', ',')}';
}

void main() {
  final dados = jsonDecode('{"produto": "Bolo", "preco": 20.5}');
  final double precoTipado = dados['preco'];
  print(precoTipado.reais);
  final preco = dados['preco'];
  print(preco.reais);
}

$ dart run erro_dynamic.dart
R$ 20,50
Unhandled exception:
NoSuchMethodError: Class 'double' has no instance getter 'reais'.
Receiver: 20.5
Tried calling: reais
#0      Object.noSuchMethod (dart:core-patch/object_patch.dart:38:5)
#1      main (file:///home/ana/erro_dynamic.dart:12:15)
#2      _delayEntrypointInvocation.<anonymous closure> (dart:isolate-patch/isolate_patch.dart:313:19)
#3      _RawReceivePort._handleMessage (dart:isolate-patch/isolate_patch.dart:192:12)

O mesmo número, 20.5, duas vezes. Na variável com tipo (final double precoTipado), a extensão funcionou. Na variável sem tipo (o jsonDecode devolve dynamic), o programa compilou, rodou e quebrou:

  • NoSuchMethodError: "erro: não existe tal método". Class 'double' has no instance getter 'reais'.: "a classe double não tem um getter reais". E é verdade: o reais nunca entrou no double; ele vivia na capinha.
  • Receiver: 20.5: o objeto que recebeu o pedido. Tried calling: reais: o que se tentou chamar.
  • #0 Object.noSuchMethod é do Dart; #1 main, linha 12, é o seu preco.reais. Código de saída 255.

Como consertar: dê tipo à variável (final double preco = dados['preco'];) ou converta ((dados['preco'] as double).reais). Regra: extensão precisa de tipo conhecido.

Missão final: as estrelas das avaliações

Missão: o main usa nota.estrelas, mas ninguém ensinou isso ao int. Escreva uma extensão on int com um getter estrelas que devolve '★' * this seguido de '☆' * (5 - this) (em Dart, texto * n repete o texto n vezes). A nota 4 deve virar ★★★★☆.

// escreva a extensão aqui

void main() {
  final notas = [5, 4, 2];
  for (final nota in notas) {
    print('$nota: ${nota.estrelas}');
  }
}

extension Estrelas on int {
  String get estrelas => '★' * this + '☆' * (5 - this);
}

void main() {
  final notas = [5, 4, 2];
  for (final nota in notas) {
    print('$nota: ${nota.estrelas}');
  }
}

No lab, o código inicial parou com Error: The getter 'estrelas' isn't defined for the type 'int'., e a solução mostrou 5: ★★★★★, 4: ★★★★☆ e 2: ★★☆☆☆.

Resumo

  • extension Nome on Tipo { … } acrescenta getters e métodos a um tipo existente, mesmo que não seja seu (double, String, List<double>), sem mudar o tipo.
  • Dentro da extensão, this (ou só o nome do membro) é o valor antes do ponto.
  • Extensões não têm campos e não substituem métodos que o tipo já tem.
  • Quem aplica a extensão é o compilador, pelo tipo da variável: com dynamic ela não vale, e o erro só aparece rodando (NoSuchMethodError).
  • Tipos têm de bater: on double não vale para int (use on num) nem para double? (use ?.).
  • Com duas extensões em conflito, escolha pelo nome: ReaisBR(preco).reais.
