Dart Comentários

Um comentário é um recado escrito dentro do código para as pessoas que vão lê-lo: você mesmo daqui a um mês, um colega, o professor. O Dart pula os comentários sem ler, como se não estivessem lá. O Dart tem três tipos: o de linha //, o de bloco /* */ e o de documentação ///.

Você vai aprender
  • O comentário de linha //, sozinho na linha ou no fim de uma instrução.
  • O comentário de bloco /* … */, de várias linhas, e por que no Dart um pode ficar dentro do outro.
  • O comentário de documentação ///, que descreve funções e classes.
  • A "desligar" uma linha de código sem apagá-la.
  • Que // dentro de um texto entre aspas não é comentário.
  • O que faz um comentário ser bom ou ruim.
  • Os erros reais de comentário que não fecha e de recado sem as barras.

Os programas desta aula foram rodados com o Dart SDK 3.13.5 na máquina fictícia da Ana (usuária ana, computador notebook), na pasta pessoal dela, com dart run arquivo.dart.

A ideia: o lápis na margem da receita

No caderno de receitas da avó da Ana, há anotações a lápis na margem: "usar fermento fresco", "a vó punha uma pitada a mais de sal", e uma linha inteira riscada (sem apagar) com "não precisa". Quem faz o bolo lê as anotações, mas elas não são passos da receita.

Os comentários são o lápis na margem do código. O Dart (o cozinheiro) pula tudo o que é comentário; só as pessoas leem.

1. Comentário de linha: //

Duas barras // começam um comentário que vai até o fim da linha. Ele pode ocupar a linha toda ou vir depois de uma instrução:

// Programa da padaria: mostra o aviso do dia.
void main() {
  print('Padaria do Bairro'); // nome que vai na placa
  // print('Fechado para balanço');
  print('Pão saindo às 7h');
}

$ dart run linha.dart
Padaria do Bairro
Pão saindo às 7h
// Programa da padaria: …
Linha inteira de comentário, antes do main: explica o que o programa faz.
print(…); // nome que vai na placa
A instrução roda normalmente; do // em diante, o Dart ignora. Deixe um espaço antes e outro depois das barras.
// print('Fechado para balanço');
Uma instrução desligada: como está atrás do //, virou comentário e não roda. Repare que Fechado para balanço não apareceu na saída.
Desligar e religar linhas

Pôr // na frente de uma linha para ela não rodar se chama comentar a linha; tirar as barras é descomentar. É o jeito mais rápido de testar o programa sem um pedaço. No VS Code, o atalho Ctrl+/ comenta e descomenta as linhas selecionadas.

Missão: hoje a padaria está aberta. Comente a linha do aviso de fechado (sem apagá-la) e descomente a do pão.

void main() {
  print('Padaria do Bairro');
  print('Fechado para balanço');
  // print('Pão saindo às 7h');
}

void main() {
  print('Padaria do Bairro');
  // print('Fechado para balanço');
  print('Pão saindo às 7h');
}

2. Comentário de bloco: /* … */

Para um recado de várias linhas, abra com /* e feche com */. Tudo o que está entre os dois é ignorado, seja uma linha, seja um pedaço de linha, sejam dez linhas:

/*
  Lista de compras da Ana
  Escrito em outubro.
*/
void main() {
  print('- pão');
  /* print('- leite'); */
  print('- café' /* o de sempre */);
}

$ dart run bloco.dart
- pão
- café
/* … */ (linhas 1 a 4)
Um comentário de quatro linhas, no alto do arquivo.
/* print('- leite'); */
Uma instrução desligada: o leite não aparece na saída.
print('- café' /* o de sempre */);
Um comentário no meio da instrução. Funciona, mas atrapalha a leitura; prefira // no fim da linha.

No Dart, um bloco pode ficar dentro do outro

Em muitas linguagens (C, Java, JavaScript), o primeiro */ fecha o comentário, mesmo que haja outro /* dentro. No Dart, não: cada /* precisa do seu */, como as chaves. Assim dá para desligar um trecho que já tem comentário dentro:

void main() {
  /*
  print('Promoção de sonho');
  /* print('Só hoje'); */
  print('Leve 3, pague 2');
  */
  print('Padaria do Bairro');
}

$ dart run aninhado.dart
Padaria do Bairro

O */ da linha 4 fechou só o comentário de dentro; o de fora continuou até o */ da linha 6. Por isso nenhuma das três linhas da promoção rodou.

3. Comentário de documentação: ///

Três barras fazem um comentário de documentação: a descrição oficial de uma função, classe ou variável, escrita logo acima dela. Para o programa, é igual a um //: não roda.

/// Mostra a placa da padaria.
///
/// Todo dia de manhã a Ana roda este programa.
void main() {
  print('Padaria do Bairro');
}

$ dart run doc.dart
Padaria do Bairro

A diferença está nas ferramentas: no VS Code, ao passar o mouse sobre o nome da função, aparece esse texto; e o comando dart doc transforma esses comentários num site de documentação. É assim que é feita a documentação oficial do Dart em api.dart.dev. A primeira linha deve ser uma frase curta que resume; depois, uma linha /// vazia e os detalhes. Você vai usá-lo de verdade nas aulas de Funções e Classes.

4. // dentro de aspas não é comentário

Dentro de um texto entre aspas, as barras são só letras:

void main() {
  print('Site: https://padaria.exemplo // aberto');
  print('/* isto não é comentário */');
}

$ dart run no_texto.dart
Site: https://padaria.exemplo // aberto
/* isto não é comentário */

O Dart primeiro vê a aspa que abre o texto e só procura comentários de novo depois da aspa que fecha. Por isso endereços de site com // funcionam normalmente dentro de textos.

Os três tipos: qual usar

TipoVai atéUse para
// …O fim da linhaQuase tudo: explicar um trecho, desligar uma linha. É o mais usado.
/* … */O */ que fechaDesligar um trecho grande de uma vez. O guia de estilo do Dart prefere // em cada linha mesmo para várias linhas.
/// …O fim da linhaDescrever funções, classes e variáveis (documentação), logo acima delas.

O que é um bom comentário

Um bom comentário explica o porquê, não repete o que o código já diz:

// Ruim: repete o código.
print('Pão saindo às 7h'); // mostra "Pão saindo às 7h"

// Bom: explica o motivo.
// O forno só fica quente às 7h; antes disso, não anunciar pão.
print('Pão saindo às 7h');

Outro costume: // TODO: … (em inglês, "a fazer") marca algo que ainda falta. É só um comentário como outro qualquer (o dart analyze responde No issues found! para um arquivo com // TODO), mas é fácil de procurar depois, e o VS Code com a extensão Dart costuma listá-los.

Consequência: o comentário engoliu tudo até o fim do arquivo, inclusive o print e a } do main. Para o Dart, a chave nunca fechou.

Como consertar: feche o comentário com */ no fim da linha 2. No VS Code, o código "comentado" fica de outra cor: se metade do arquivo ficou dessa cor, falta um */.

Resumo

  • Comentários são recados para pessoas; o Dart os ignora.
  • // vai até o fim da linha; é o mais usado. Pôr // na frente de uma instrução a desliga.
  • /* … */ pode ter várias linhas e, no Dart, pode ter outro /* */ dentro.
  • /// documenta funções e classes; aparece no editor e no dart doc.
  • Dentro de aspas, // e /* são texto comum.
  • Bom comentário explica o porquê. Erros: /* sem */, e recado sem as barras, que vira uma chuva de mensagens na mesma linha.
