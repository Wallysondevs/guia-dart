Dart Privacidade (_)

A conta do banco tem um saldo. Ninguém deveria poder escrever conta.saldo = 1000000 e ficar rico: o saldo só deveria mudar por depósito e saque, que conferem os valores. Para esconder partes de uma classe, o Dart usa um sinal só: o sublinhado _ no começo do nome. _saldo é privado. Mas atenção, porque aqui o Dart é diferente de quase todas as outras linguagens: o _ esconde o nome do resto dos arquivos, e não do resto do arquivo. A privacidade é do arquivo, e não da classe.

Você vai aprender
  • O que o _ faz: privado da biblioteca, que no Dart é o arquivo.
  • Por que, no mesmo arquivo, o main consegue mexer no _saldo (e o que isso quer dizer).
  • Como separar a classe num arquivo próprio, com import, para a proteção valer.
  • O par mais comum: campo privado + getter público (só leitura).
  • Métodos, funções, classes e construtores privados.
  • Os erros reais que o Dart mostra quando alguém tenta usar o que é privado.

Todos os programas desta aula rodaram no Dart 3.13.5 da máquina da Ana (usuária ana, computador notebook). Os arquivos ficaram juntos na pasta pessoal dela, e cada programa foi executado com dart run arquivo.dart.

A ideia: a cozinha da padaria

A padaria tem o balcão, onde qualquer cliente pede pão, e a cozinha, onde só entra quem trabalha lá. Lá dentro, o padeiro, a confeiteira e o ajudante mexem à vontade nas coisas uns dos outros: na massa, no forno, na receita. A porta da cozinha não separa as pessoas de dentro; ela separa a cozinha de quem está fora.

No Dart, a cozinha é o arquivo. Tudo que tem nome começando com _ é "coisa da cozinha": qualquer classe ou função do mesmo arquivo pode usar; quem está em outro arquivo só vê o balcão, isto é, os nomes sem _.

NomeQuem pode usar
saldo, depositar, ContaTodo mundo: é público
_saldo, _registrar, _RascunhoSó o código do mesmo arquivo: é privado

1. No mesmo arquivo, o _ não protege nada

Comece pela surpresa. A classe Conta tem o saldo privado, e o main está no mesmo arquivo:

class Conta {
  final String dona;
  double _saldo = 0;

  Conta(this.dona);

  double get saldo => _saldo;

  void depositar(double valor) {
    _saldo += valor;
  }
}

void main() {
  final conta = Conta('Ana');
  conta.depositar(100);
  conta._saldo = 1000000;
  print('Saldo: ${conta.saldo}');
}

$ dart run mesmo.dart
Saldo: 1000000.0

Nenhum erro. O main está na mesma "cozinha" que a Conta, e para o Dart isso basta. Quem vem do Java, do C# ou do C++ espera que um campo privado só possa ser usado dentro da classe; no Dart, não existe privado "da classe". O _ só começa a proteger quando o código que tenta usar está em outro arquivo.

Por que isso importa

Para testar a privacidade, nunca confie num programa de um arquivo só: ele sempre vai deixar. Separe a classe num arquivo próprio, como na próxima seção. É assim que se organiza um programa de verdade, e é assim que funcionam os pacotes do Dart.

2. Dois arquivos: agora o _ protege

A classe vai para o arquivo conta.dart. O programa principal, em banco.dart, a traz com import (veja import, export e Bibliotecas):

class Conta {
  final String dona;
  double _saldo = 0;

  Conta(this.dona);

  double get saldo => _saldo;

  void depositar(double valor) {
    if (valor <= 0) {
      throw ArgumentError('depósito precisa ser positivo: $valor');
    }
    _saldo += valor;
    _registrar('depósito de $valor');
  }

  void sacar(double valor) {
    if (valor > _saldo) {
      throw StateError('saldo insuficiente: tem $_saldo, pediu $valor');
    }
    _saldo -= valor;
    _registrar('saque de $valor');
  }

  void _registrar(String texto) {
    print('[extrato de $dona] $texto');
  }
}

double _taxaDoMes() => 2.5;

double taxaComDesconto() => _taxaDoMes() * 0.8;

import 'conta.dart';

void main() {
  final conta = Conta('Ana');
  conta.depositar(100);
  conta.sacar(30);
  print('Saldo: ${conta.saldo}');
  print('Taxa: ${taxaComDesconto()}');
}
import 'conta.dart';
"Traga o que o arquivo conta.dart oferece." O nome é o caminho do arquivo, a partir da pasta onde está banco.dart. Só os nomes públicos chegam.
double _saldo = 0;
O saldo, privado. Só o código de conta.dart o vê.
double get saldo => _saldo;
Um getter público (veja get e set). Quem está fora pode ler o saldo, mas não há setter: não pode escrever.
depositar / sacar
Os únicos jeitos de mudar o saldo, e os dois conferem os valores.
void _registrar(…)
Um método privado: um "ajudante" interno, que os métodos públicos usam e que ninguém de fora deve chamar.
double _taxaDoMes()
Uma função privada, fora da classe: o _ vale para qualquer nome do arquivo.
double taxaComDesconto()
Uma função pública, que usa a privada por dentro.

3. Dentro do arquivo, todos se conhecem

Como a privacidade é do arquivo, duas classes do mesmo arquivo usam o que é privado uma da outra. Isso é útil. Na fila da padaria, só o balcão pode criar fichas (ninguém imprime ficha falsa):

class Ficha {
  final int numero;
  Ficha._(this.numero);
}

class Balcao {
  int _proxima = 1;

  Ficha chamar() {
    final f = Ficha._(_proxima);
    _proxima++;
    return f;
  }
}

class _Rascunho {
  final String texto = 'só aqui dentro';
}

import 'ficha.dart';

void main() {
  final balcao = Balcao();
  print('Ficha ${balcao.chamar().numero}');
  print('Ficha ${balcao.chamar().numero}');
  print('Ficha ${balcao.chamar().numero}');
}

$ dart run fila.dart
Ficha 1
Ficha 2
Ficha 3
Ficha._(this.numero);
Um construtor privado: um construtor nomeado cujo nome é só o _. Fora de ficha.dart, ninguém consegue criar uma Ficha.
Ficha._(_proxima)
O Balcao é outra classe, mas está no mesmo arquivo: pode usar o construtor privado da Ficha. Numa linguagem com privado "da classe", isso seria proibido.
int _proxima
O próximo número, privado: ninguém de fora pula a fila.
class _Rascunho
Uma classe inteira privada: só existe para quem está dentro de ficha.dart.

Formas diferentes de proteger um campo

FormaExemploDe fora do arquivo…
Campo público comumdouble saldo = 0;Lê e escreve à vontade
Campo finalfinal String dona;Só lê; e nem a própria classe muda depois de criado
Privado + getterdouble _saldo = 0; + double get saldo => _saldo;Só lê; a classe muda por dentro (depósito, saque)
Privado + getter + setter que confereset saldo(double v) { if (…) throw …; _saldo = v; }Lê e escreve, mas só valores aceitos
Totalmente privadoint _proxima = 1;Nem vê
Boa prática

Comece com tudo o que for "detalhe de funcionamento" privado (_proxima, _registrar) e deixe público só o que outras partes do programa precisam usar. É mais fácil abrir uma porta depois do que fechar uma porta que todo mundo já usa.

Quando dá errado

Todos os erros abaixo vêm de arquivos que fazem import 'conta.dart'; ou import 'ficha.dart';, os arquivos das seções 2 e 3.

Missão: no arquivo contador.dart (segunda aba), torne o campo privado: troque total por _total e crie um getter público int get total => _total;. O método visitar passa a somar em _total. O main.dart não precisa mudar e deve mostrar Visitas: 3.

import 'contador.dart';

void main() {
  final c = Contador();
  c.visitar();
  c.visitar();
  c.visitar();
  print('Visitas: ${c.total}');
}

class Contador {
  int total = 0;

  void visitar() {
    total += 1;
  }
}

import 'contador.dart';

void main() {
  final c = Contador();
  c.visitar();
  c.visitar();
  c.visitar();
  print('Visitas: ${c.total}');
}

class Contador {
  int _total = 0;

  int get total => _total;

  void visitar() {
    _total += 1;
  }
}

Depois de cumprir a missão, tente escrever c.total = 100; no main.dart: agora o Dart recusa, porque o total só tem getter.

Resumo

  • Um nome que começa com _ é privado: vale para campos, métodos, funções, classes e construtores.
  • Privado da biblioteca, que no Dart é o arquivo; não existe privado "da classe". No mesmo arquivo, tudo é visível, até entre classes diferentes.
  • Para a proteção valer, a classe fica num arquivo próprio e quem usa faz import.
  • Para quem está fora, o nome privado simplesmente não existe: isn't defined, Method not found, Member not found.
  • O par mais comum: campo privado + getter público (só leitura) + métodos públicos que conferem as mudanças.
  • Próxima aula: Membros static, coisas que pertencem à classe, e não a cada objeto.
