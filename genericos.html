Dart Genéricos

Desde as aulas de listas e mapas você vem escrevendo coisas como List<String> e Map<String, int>. Esse pedaço entre os sinais de menor e maior, <String>, tem um nome: é um tipo genérico (ou só "genérico"; em inglês, generics). Ele diz o que vai dentro da coleção. Nesta aula você entende o que ele faz, por que vale a pena escrevê-lo, e o que acontece quando ele falta.

Você vai aprender
  • O que o <T> quer dizer em List<String>, Set<int> e Map<String, double>.
  • Como o Dart descobre sozinho o tipo de dentro (inferência), e como ver o tipo com runtimeType.
  • Por que a lista vazia [] vira List<dynamic> e como isso explode só quando o programa já está rodando.
  • Como escrever o tipo numa coleção vazia: <int>[] e <String, double>{}.
  • Coleções dentro de coleções: Map<String, List<int>>.

Todos os programas desta aula rodaram no Dart SDK 3.13.5 da máquina da Ana (usuária ana, computador notebook), com dart run arquivo.dart.

A ideia: a caixa com etiqueta

No depósito da padaria há várias caixas iguais. Algumas têm etiqueta: "só ovos", "só farinha". Quem guarda as coisas não precisa pensar: farinha não entra na caixa de ovos, e quem tira um ovo da caixa de ovos sabe que vai sair um ovo. Uma caixa sem etiqueta aceita qualquer coisa, e quem enfia a mão nela nunca sabe o que vai sair.

No Dart, List é a caixa. O genérico é a etiqueta:

  • List<String> = "lista de textos". Lê-se "lista de String".
  • Set<int> = "conjunto de inteiros".
  • Map<String, double> = "mapa de texto para número com vírgula": as chaves são String e os valores são double.

A mesma List serve para qualquer tipo de coisa; é por isso que se chama genérica. A etiqueta escolhe o tipo em cada uso, e o Dart confere a etiqueta antes de rodar o programa.

1. A etiqueta em ação

void main() {
  List<String> compras = ['pão', 'leite'];
  compras.add('café');
  print(compras);
  print(compras.runtimeType);

  final notas = [7, 8.5, 10];
  final estoque = {'pão': 30, 'bolo': 2};
  final cores = {'azul', 'verde'};
  print(notas.runtimeType);
  print(estoque.runtimeType);
  print(cores.runtimeType);
}
List<String> compras
A variável compras é uma lista de textos. O que vai entre < e > é o argumento de tipo.
compras.add('café')
Como a lista é de String, o add só aceita String.
.runtimeType
O tipo de verdade do objeto, enquanto o programa roda (runtime = "hora de rodar").
final notas = [7, 8.5, 10];
Sem etiqueta escrita: o Dart olha os valores e descobre o tipo sozinho. Isso se chama inferência de tipo.
$ dart run g1.dart
[pão, leite, café]
List<String>
List<num>
_Map<String, int>
_Set<String>
  • notas tem int (7, 10) e double (8.5). O tipo que serve para os dois é num (veja int e double), e o Dart escolheu List<num>.
  • estoque virou Map<String, int>: chaves de texto, valores inteiros. O _ antes de Map e Set é o nome da versão interna do Dart: para você, é um Map<String, int> e um Set<String>.

Com a etiqueta, o Dart barra o que não combina antes de o programa rodar:

void main() {
  List<String> compras = ['pão', 'leite'];
  compras.add(3);
  print(compras);
}

$ dart run g2.dart
g2.dart:3:15: Error: The argument type 'int' can't be assigned to the parameter type 'String'.
  compras.add(3);
              ^

"O argumento do tipo int não pode ser passado onde se espera String". O add de uma List<String> só aceita String. Repare que nem o print rodou: é erro de compilação. A mesma mensagem aparece com final compras = ['pão', 'leite'];, sem etiqueta escrita: a inferência já deu a ela o tipo List<String>.

2. A caixa sem etiqueta: List<dynamic>

O problema aparece quando a lista começa vazia. Sem nenhum valor para olhar, o Dart não tem como adivinhar o tipo, e usa dynamic ("qualquer coisa"; veja dynamic e Object):

void main() {
  final notas = [];
  notas.add(7);
  notas.add(9);
  notas.add('dez');
  print(notas);
  print(notas.runtimeType);
  num soma = 0;
  for (final n in notas) {
    soma += n;
  }
  print('Soma: $soma');
}

$ dart run g3.dart
[7, 9, dez]
List<dynamic>
Unhandled exception:
type 'String' is not a subtype of type 'num'
#0      main (file:///home/ana/g3.dart:10:13)
#1      _delayEntrypointInvocation.<anonymous closure> (dart:isolate-patch/isolate_patch.dart:313:19)
#2      _RawReceivePort._handleMessage (dart:isolate-patch/isolate_patch.dart:192:12)
$ echo $?
255

Linha por linha:

[7, 9, dez] e List<dynamic>
A caixa sem etiqueta aceitou o texto 'dez' sem reclamar. O Dart não pôde conferir nada antes de rodar.
Unhandled exception: type 'String' is not a subtype of type 'num'
"O tipo String não é um subtipo de num": na terceira volta do for, o n era 'dez', e um texto não pode ser somado a um número. O problema só apareceu no meio da execução (veja Exceções).
main (file:///home/ana/g3.dart:10:13)
Linha 10, a do soma += n. Mas o engano de verdade foi lá na linha 5, quando o texto entrou na lista.

Agora com a etiqueta. Numa coleção vazia, ela vai antes dos colchetes:

void main() {
  final notas = <int>[];
  notas.add(7);
  notas.add(9);
  notas.add('dez');
  print(notas);
}

$ dart run g9.dart
g9.dart:5:13: Error: The argument type 'String' can't be assigned to the parameter type 'int'.
  notas.add('dez');
            ^

O mesmo engano, agora apontado na linha certa (a 5) e antes de o programa rodar. É essa a vantagem dos genéricos: o erro sai mais cedo e no lugar certo.

Regra prática

Coleção com valores dentro: deixe o Dart inferir (final compras = ['pão', 'leite'];). Coleção que começa vazia: sempre escreva a etiqueta (<int>[], <String>{}, <String, double>{}) ou o tipo da variável (final List<int> notas = [];). O guia de estilo do Dart (Effective Dart) recomenda o mesmo.

Missão: este programa morre no meio por causa do 'oito'. Troque o [] por <int>[] e rode: agora o Dart aponta o problema antes de rodar. Conserte a linha apontada (a nota é 8) até aparecer Soma: 24.

void main() {
  final notas = [];
  notas.add(7);
  notas.add(9);
  notas.add('oito');
  num soma = 0;
  for (final n in notas) {
    soma += n;
  }
  print('Soma: $soma');
}

void main() {
  final notas = <int>[];
  notas.add(7);
  notas.add(9);
  notas.add(8);
  num soma = 0;
  for (final n in notas) {
    soma += n;
  }
  print('Soma: $soma');
}

3. Coleções dentro de coleções

O argumento de tipo pode ser outro genérico. A professora guarda, para cada aluna, a lista das notas: um mapa de String para List<int>:

void main() {
  final notas = <int>[];
  notas.add(7);
  notas.add(9);
  final precos = <String, double>{};
  precos['pão'] = 0.75;
  precos['café'] = 18.9;
  print(notas.runtimeType);
  print(precos.runtimeType);
  print(precos);
  final turma = <String, List<int>>{
    'Ana': [8, 9],
    'Bia': [7, 10, 6],
  };
  for (final MapEntry(:key, :value) in turma.entries) {
    print('$key: $value');
  }
  turma['Ana']!.add(10);
  print(turma['Ana']);
}

$ dart run g4.dart
List<int>
_Map<String, double>
{pão: 0.75, café: 18.9}
Ana: [8, 9]
Bia: [7, 10, 6]
[8, 9, 10]
<String, double>{}
Um mapa vazio com etiqueta: chaves String, valores double. Num Map vão dois tipos, separados por vírgula.
<String, List<int>>{ … }
Chave String; valor List<int>. Leia de fora para dentro: "mapa de texto para lista de inteiros". Os >> no fim fecham os dois genéricos.
for (final MapEntry(:key, :value) in turma.entries)
Percorre o mapa desmontando cada par em key e value (veja Percorrendo Mapas).
turma['Ana']!.add(10)
turma['Ana'] é List<int>? (pode não existir a chave); o ! garante que existe (veja late e o Operador !). Como o Dart sabe que é uma List<int>, o add só aceita int.

4. Outros lugares onde o <T> aparece

void main() {
  final List<num> valores = [3, 2.5];
  valores.add(10);
  print(valores);
  final zeros = List<int>.filled(3, 0);
  print(zeros);
  final rotulos = [1, 2, 3].map<String>((n) => 'Item $n').toList();
  print(rotulos);
  print(rotulos.runtimeType);
  Object qualquer = [1, 2];
  print(qualquer is List<int>);
  print(qualquer is List<String>);
}

$ dart run g7.dart
[3, 2.5, 10]
[0, 0, 0]
[Item 1, Item 2, Item 3]
List<String>
true
false
TrechoO que o genérico faz
List<num>Aceita int e double juntos (os dois são num)
List<int>.filled(3, 0)O genérico vai também no construtor: uma lista de 3 inteiros, todos 0
.map<String>(…)Uma função genérica: você diz o tipo do resultado (veja map, where, reduce). Quase sempre o Dart infere sozinho
qualquer is List<int>O Dart guarda a etiqueta enquanto roda: dá para perguntar o tipo de dentro (veja is, is! e as)

Formas diferentes de fazer a mesma coisa

Uma lista de notas vazia, com o tipo certo, pode ser escrita de três jeitos. Os três dão List<int>:

final notas1 = <int>[];        // etiqueta na lista
final List<int> notas2 = [];   // tipo na variável
List<int> notas3 = [];         // tipo na variável, sem final (pode trocar a lista inteira)
SituaçãoQual usar
Coleção com valores dentroDeixe inferir: final compras = ['pão', 'leite'];
Coleção vazia numa variável localfinal notas = <int>[]; ou <String, double>{}
Parâmetro de função, campo de classe, retornoSempre o tipo completo: int somar(List<int> numeros)
Valores de tipos diferentes de verdadeO tipo comum: List<num>, List<Object>; evite dynamic

Quando dá errado

Um valor do tipo errado na lista 
void main() {
  List<int> notas = [8, 'nove', 10];
  print(notas);
}

$ dart run g5.dart
g5.dart:2:25: Error: A value of type 'String' can't be assigned to a variable of type 'int'.
  List<int> notas = [8, 'nove', 10];
                        ^

"Um valor do tipo String não pode ir onde se espera int". O ^ aponta exatamente o intruso, 'nove'. Como consertar: [8, 9, 10].

Faltou um tipo no Map 
void main() {
  Map<String> precos = {'pão': 0.75};
  print(precos);
}

$ dart run g6.dart
g6.dart:2:3: Error: Expected 2 type arguments.
  Map<String> precos = {'pão': 0.75};
  ^^^

"Eram esperados 2 argumentos de tipo". O Map precisa do tipo da chave e do tipo do valor. Como consertar: Map<String, double>.

Parâmetro List sem etiqueta 
int somar(List numeros) {
  var total = 0;
  for (final n in numeros) {
    total += n;
  }
  return total;
}

void main() {
  final vendas = [12, 30, 15];
  print('Total do dia: ${somar(vendas)}');
}

$ dart run m2.dart
m2.dart:4:11: Error: A value of type 'num' can't be assigned to a variable of type 'int'.
    total += n;
          ^

List sozinho é List<dynamic>: o n pode ser qualquer coisa, e o Dart não garante que total + n dê um int ("um valor do tipo num não pode ir numa variável int"). A lista vendas era de int, mas a função não sabia. Como consertar: é a missão final.

  var total = 0;
  for (final n in numeros) {

  }

  final vendas = [12, 30, 15];
  print('Total do dia: ${somar(vendas)}');

No lab, depois da troca, saiu Total do dia: 57.

Resumo

  • O <T> é a etiqueta da coleção: List<String> é "lista de textos"; Map<K, V> tem dois tipos, o da chave e o do valor.
  • Com valores dentro, o Dart infere a etiqueta ([7, 8.5, 10] vira List<num>). runtimeType mostra o tipo.
  • Coleção vazia sem etiqueta vira List<dynamic>: aceita tudo, e o erro só aparece ao rodar, longe do engano. Escreva <int>[].
  • Com a etiqueta, o Dart barra o tipo errado antes de rodar, apontando a linha.
  • Genéricos se encaixam: Map<String, List<int>>. Também aparecem em construtores (List<int>.filled) e funções (map<String>).
