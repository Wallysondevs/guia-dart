Dart create

Até aqui, cada programa era um arquivo só: dart run tabuada.dart. Programas de verdade crescem: o código se espalha por vários arquivos, ganha testes, passa a usar pacotes de outras pessoas. Para organizar tudo isso, o Dart tem o projeto: uma pasta com uma estrutura padrão. E o jeito de criar um é o comando dart create ("criar").

Você vai aprender
  • O que é um projeto Dart e por que usar um.
  • Como criar um com dart create padaria e o que cada arquivo e pasta criados faz.
  • Como rodar o projeto com dart run e onde escrever o seu código (bin/ e lib/).
  • Como ter mais de um programa no mesmo projeto.
  • Os modelos (-t console, cli, package…) e as opções --no-pub e --force.
  • Os erros reais: pasta que já existe, nome com maiúsculas e traço, dart run fora do projeto e o package: com nome errado.

Tudo nesta aula rodou no Dart 3.13.5 da máquina da Ana (usuária ana, computador notebook), no terminal, com internet (o dart create baixa pacotes do pub.dev). Comandos como cd (entrar numa pasta), cat (mostrar um arquivo) e tree (desenhar as pastas) são do terminal do Linux.

No editor do guia não há projeto

O editor desta página roda um arquivo main.dart (e as abas que estiverem junto); ele não tem terminal, não roda dart create nem baixa pacotes. Os comandos desta aula são para o seu computador, com o Dart instalado (veja Instalar o Dart). As caixas "Experimente" praticam o código que vai dentro do projeto.

A ideia: a cozinha organizada

Quem faz um bolo em casa usa a bancada que tiver. Uma padaria de verdade tem uma cozinha organizada: o forno num canto, a despensa no outro, o caderno de receitas na prateleira, a lista de fornecedores pregada na parede. Qualquer padeiro novo chega e sabe onde está cada coisa.

Um projeto Dart é essa cozinha: todo projeto tem as mesmas pastas, com o mesmo papel. Assim, as ferramentas do Dart (e qualquer programador) sabem onde procurar o programa principal, o código reaproveitável, os testes e a lista de pacotes de que ele precisa.

1. Criando o projeto

Na pasta pessoal, a Ana digita dart create seguido do nome do projeto:

  Downloading packages...

Created project padaria in padaria! In order to get started, run the following commands:

  cd padaria
  dart run

$ echo $?
0

Linha por linha:

  • Creating padaria using template console... — "criando padaria com o modelo console": o modelo padrão, um programa de terminal.
  • A lista de arquivos criados (os detalhes vêm na próxima seção).
  • Running pub get... — "rodando o pub get": o Dart baixa os pacotes de que o projeto precisa. Resolving dependencies = "resolvendo dependências" (descobrindo quais versões usar); Downloading packages = "baixando pacotes"; Changed 50 dependencies! = 50 pacotes entraram no projeto (são as ferramentas de teste e de análise e os pacotes de que elas dependem).
  • Created project padaria in padaria! — "projeto criado na pasta padaria", e a sugestão dos próximos comandos.

Na máquina da Ana, o dart create levou menos de meio segundo, porque os pacotes já estavam no cache; na primeira vez num computador novo, ele precisa baixá-los, e leva alguns segundos (depende da internet).

3. Rodando: dart run

Dentro da pasta do projeto, dart run sem nome de arquivo roda o programa principal, bin/padaria.dart (o que tem o mesmo nome do projeto). Dar o caminho dá no mesmo:

$ dart run
Hello world: 42!
$ dart run bin/padaria.dart
Hello world: 42!

Escrevendo o seu código

A Ana troca o exemplo pelo código da padaria. Em lib/padaria.dart, a regra de negócio (o cálculo):

double precoTotal(int quantidade, double precoUnitario) {
  return quantidade * precoUnitario;
}

Em bin/padaria.dart, o programa que usa essa regra (agora sem o apelido as, para chamar precoTotal direto):

import 'package:padaria/padaria.dart';

void main(List<String> arguments) {
  final total = precoTotal(12, 0.75);
  print('12 pães custam R\$ ${total.toStringAsFixed(2)}');
}

$ dart run
12 pães custam R$ 9.00

Por que separar em dois arquivos? Porque o precoTotal de lib/ pode ser usado por vários programas e pelos testes, sem copiar código.

Missão: aqui no editor, a função e o main estão no mesmo arquivo (num projeto, a função iria para lib/). Acrescente uma linha que mostre o preço de 30 pães usando precoTotal(30, 0.75).

double precoTotal(int quantidade, double precoUnitario) {
  return quantidade * precoUnitario;
}

void main(List<String> arguments) {
  final total = precoTotal(12, 0.75);
  print('12 pães custam R\$ ${total.toStringAsFixed(2)}');
}

double precoTotal(int quantidade, double precoUnitario) {
  return quantidade * precoUnitario;
}

void main(List<String> arguments) {
  final total = precoTotal(12, 0.75);
  print('12 pães custam R\$ ${total.toStringAsFixed(2)}');
  print('30 pães custam R\$ ${precoTotal(30, 0.75).toStringAsFixed(2)}');
}

Mais de um programa no mesmo projeto

Cada arquivo com main em bin/ é um programa. A Ana cria bin/fornada.dart, que usa a mesma função:

import 'package:padaria/padaria.dart';

void main() {
  print('Fornada de 50 pães: R\$ ${precoTotal(50, 0.75)}');
}

$ dart run bin/fornada.dart
Fornada de 50 pães: R$ 37.5
$ dart run :fornada
Fornada de 50 pães: R$ 37.5

dart run :fornada é um atalho: "o programa fornada de bin/ deste projeto".

Quando dá errado

A pasta já existe 
$ dart create padaria
Directory '/home/ana/padaria' already exists (use '--force' to force project generation).
$ echo $?
73

"O diretório /home/ana/padaria já existe (use --force para forçar a criação do projeto)". O dart create se recusa para não estragar nada, e sai com código 73. Como consertar: escolha outro nome. O --force recria os arquivos do modelo por cima dos que tiverem o mesmo nome: o seu bin/padaria.dart voltaria a ser o "Hello world". Só use se for isso mesmo que você quer.

Nome com maiúsculas, traço ou espaço 
$ dart create Padaria-Ana
Creating padaria__ana using template console...

  .gitignore
  analysis_options.yaml
  CHANGELOG.md
  pubspec.yaml
  README.md
  bin/padaria__ana.dart
  lib/padaria__ana.dart
  test/padaria__ana_test.dart

Running pub get...
  Resolving dependencies...
  Downloading packages...
  Changed 50 dependencies!

Created project padaria__ana in Padaria-Ana! In order to get started, run the following commands:

  cd Padaria-Ana
  dart run

Não dá erro, mas o resultado é estranho: a pasta se chama Padaria-Ana, e o pacote virou padaria__ana (com dois sublinhados). Nomes de pacote no Dart só podem ter letras minúsculas, números e _; o dart create converteu sozinho. Daí em diante, os import serão package:padaria__ana/….

Com espaço é pior: em dart create minha padaria o terminal entrega dois argumentos, e o projeto criado se chama só minha (a saída mostra Creating minha using template console...; o padaria foi ignorado). Como consertar: use nomes em snake_case, como os arquivos: dart create padaria_ana.

dart run fora da pasta do projeto 
$ dart run
Found no `pubspec.yaml` file in `/home/ana` or parent directories
$ echo $?
255

"Não encontrei nenhum arquivo pubspec.yaml em /home/ana nem nas pastas acima". Sem nome de arquivo, o dart run procura o projeto pelo pubspec.yaml, e a Ana estava na pasta pessoal, fora do projeto. Como consertar: cd padaria antes, ou dê o caminho do arquivo: dart run padaria/bin/padaria.dart.

O nome do pacote errado no import 
import 'package:padari/padaria.dart';

void main() {
  print(precoTotal(2, 0.75));
}

$ dart run bin/errado.dart
Error: Couldn't resolve the package 'padari' in 'package:padari/padaria.dart'.
bin/errado.dart:1:8: Error: Not found: 'package:padari/padaria.dart'
import 'package:padari/padaria.dart';
       ^
bin/errado.dart:4:9: Error: Method not found: 'precoTotal'.
  print(precoTotal(2, 0.75));
        ^^^^^^^^^^
$ echo $?
254
  • Couldn't resolve the package 'padari' — "não consegui encontrar o pacote padari": faltou um a. O nome depois de package: tem de ser o name: do pubspec.yaml (ou de um pacote baixado).
  • 1:8: Error: Not found — o mesmo problema, apontando a linha do import.
  • 4:9: Error: Method not found: 'precoTotal' — consequência: como o arquivo não foi importado, a função não existe. Conserte o primeiro erro e este some junto.

Como consertar: import 'package:padaria/padaria.dart';.

Missão final: dois arquivos, como no projeto

Missão: esta caixa tem duas abas, como bin/ e lib/ de um projeto. A função precoBolo está em precos.dart, mas o main.dart ainda não a importou. Acrescente na primeira linha do main.dart: import 'precos.dart';. (Num projeto, seria import 'package:padaria/precos.dart';; aqui, sem projeto, o caminho é o do arquivo.)

void main() {
  print('Bolo de 2 kg: R\$ ${precoBolo(2).toStringAsFixed(2)}');
}

double precoBolo(int quilos) {
  return quilos * 35.0;
}

import 'precos.dart';

void main() {
  print('Bolo de 2 kg: R\$ ${precoBolo(2).toStringAsFixed(2)}');
}

Resumo

  • Um projeto é uma pasta com estrutura padrão. dart create nome cria uma e já baixa os pacotes (pub get).
  • bin/ tem os programas (com main); lib/, o código reaproveitável; test/, os testes; pubspec.yaml, a ficha do projeto.
  • Dentro da pasta, dart run roda bin/NOME.dart; dart run bin/outro.dart (ou dart run :outro) roda outro.
  • Os programas de bin/ usam lib/ com import 'package:NOME/arquivo.dart';.
  • -t escolhe o modelo; --no-pub não baixa nada agora; --force sobrescreve.
  • Use nomes em snake_case; rode dart run de dentro do projeto.
