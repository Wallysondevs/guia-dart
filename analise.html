Dart analyze e format

Antes de entregar uma redação, é bom ter alguém que leia e aponte os erros, e alguém que passe a limpo com letra bonita. O Dart traz os dois de fábrica: o dart analyze ("analisar") lê o seu código sem rodar e avisa o que está errado ou suspeito; o dart format ("formatar") arruma os espaços, as quebras de linha e a indentação, sempre do mesmo jeito. Nesta aula você vai usar os dois no terminal da Ana.

Você vai aprender
  • O que o dart analyze faz e como ler cada linha que ele mostra: error, warning e info.
  • O que é o código de saída do analisador (0, 1, 2 ou 3) e para que ele serve.
  • Como ligar regras extras (os lints) no arquivo analysis_options.yaml.
  • Como o dart fix conserta sozinho parte dos avisos.
  • Como o dart format arruma o código, e como só conferir sem mudar nada.

Tudo nesta aula rodou no Dart SDK 3.13.5 da máquina da Ana (usuária ana, computador notebook), no terminal. O editor do guia roda programas (dart run), mas não tem os comandos dart analyze e dart format: as missões abaixo pedem que você faça à mão o que eles sugerem.

A ideia: o revisor e o arrumador

Pense na Ana escrevendo o cardápio da padaria do bairro:

  • A revisora lê o cardápio e marca a lápis: "aqui tem um erro de português" (grave: precisa consertar), "você escreveu o preço do sonho e não usou em lugar nenhum" (suspeito) e "prefira escrever R$ sempre do mesmo jeito" (sugestão de estilo). Ela não muda nada: só aponta. Esse é o dart analyze.
  • O diagramador não lê o conteúdo: ele alinha as colunas, põe um item por linha e deixa tudo com a mesma margem. Esse é o dart format.

Os dois trabalham sem rodar o programa. Por isso pegam problemas que só apareceriam muito depois, numa parte do código que quase nunca roda.

1. O primeiro dart analyze

A Ana criou uma pasta analise com este programa. Ele roda e mostra Olá, Ana, mas tem coisas sobrando:

import 'dart:math';

void main() {
  var nome = 'Ana';
  int idade = 30;
  final String cidade = "Recife";
  print('Olá, $nome');
}

Dentro da pasta, ela digita dart analyze (sem nome de arquivo, ele analisa a pasta inteira):

$ dart analyze
Analyzing analise...

warning - main.dart:1:8 - Unused import: 'dart:math'. Try removing the import directive. - unused_import
warning - main.dart:5:7 - The value of the local variable 'idade' isn't used. Try removing the variable or using it. - unused_local_variable
warning - main.dart:6:16 - The value of the local variable 'cidade' isn't used. Try removing the variable or using it. - unused_local_variable

3 issues found.

Cada linha é um diagnóstico (um "achado"). Veja a primeira, parte por parte:

warning
A gravidade. warning = "aviso": o programa roda, mas tem algo suspeito. As outras são error (erro: o programa nem compila) e info (sugestão de estilo).
main.dart:1:8
Arquivo, linha e coluna: o arquivo main.dart, linha 1, 8º caractere (onde começa o 'dart:math').
Unused import: 'dart:math'.
A mensagem, em inglês: "importação não usada: dart:math". O programa pediu a biblioteca de matemática e não usou nada dela.
Try removing the import directive.
A sugestão: "tente remover a diretiva de importação".
unused_import
O código do diagnóstico, um nome curto e fixo. Serve para procurar na internet (dart.dev/tools/diagnostics) e para ligar e desligar regras.

As outras duas linhas dizem: "o valor da variável local idade não é usado" e o mesmo para cidade. Variável que ninguém usa costuma ser esquecimento: você calculou algo e esqueceu de mostrar. A última linha conta: 3 issues found ("3 problemas encontrados"). Quando está tudo certo, ele diz No issues found! ("nenhum problema encontrado!").

Analisar um arquivo só

dart analyze main.dart analisa só aquele arquivo; dart analyze sozinho analisa a pasta atual e as subpastas. Num projeto criado com dart create, rode na pasta do projeto.

Missão: deixe o programa sem nenhum dos 3 avisos: apague o import que não é usado e use as variáveis, mostrando Ana tem 30 anos e mora em Recife. Aproveite e troque as aspas duplas de "Recife" por simples.

import 'dart:math';

void main() {
  var nome = 'Ana';
  int idade = 30;
  final String cidade = "Recife";
  print('Olá, $nome');
}

void main() {

  int idade = 30;

2. error: o que impede o programa de rodar

Agora um programa com dois erros de verdade: um texto guardado numa variável de número e um ponto e vírgula esquecido.

void main() {
  int idade = 'trinta';
  print(idade)
}

$ dart analyze erro.dart
Analyzing erro.dart...

  error - erro.dart:2:15 - A value of type 'String' can't be assigned to a variable of type 'int'. Try changing the type of the variable, or casting the right-hand type to 'int'. - invalid_assignment
  error - erro.dart:3:14 - Expected to find ';'. - expected_token

2 issues found.
  • erro.dart:2:15: "um valor do tipo String (texto) não pode ser atribuído a uma variável do tipo int (inteiro)". A coluna 15 é onde começa o 'trinta'.
  • erro.dart:3:14: "era esperado encontrar ;". A coluna 14 é logo depois do ), onde o ponto e vírgula deveria estar.

Compare com o que acontece se a Ana tentar rodar o mesmo arquivo:

$ dart run erro.dart
erro.dart:3:14: Error: Expected ';' after this.
  print(idade)
             ^
erro.dart:2:15: Error: A value of type 'String' can't be assigned to a variable of type 'int'.
  int idade = 'trinta';
              ^

São os mesmos dois erros, nas mesmas linhas e colunas, escritos de outro jeito: o dart run mostra a linha do código e o ^ embaixo do ponto exato. A diferença é que o dart analyze também mostra os warning e info, que o dart run deixa passar em silêncio, e nunca roda nada.

O analisador está dentro do seu editor de código

No VS Code com a extensão Dart, as mesmas mensagens aparecem enquanto você digita: um sublinhado vermelho (error), amarelo (warning) ou azul/cinza (info), e a lista completa na aba "Problemas". É o mesmo analisador do dart analyze. O terminal é útil para conferir o projeto inteiro de uma vez.

3. O código de saída: 0, 1, 2 ou 3

Todo comando, ao terminar, devolve um número para o terminal: o código de saída. O echo "codigo: $?" mostra o código do último comando. O dart analyze usa esses números:

CódigoQuando (no lab)
0Nenhum problema, ou só info.
1Tinha info e você pediu --fatal-infos ("infos fatais").
2Tinha pelo menos um warning.
3Tinha pelo menos um error.
$ dart analyze erro.dart
…
2 issues found.
$ echo "codigo: $?"
codigo: 3

Para que serve? Para automatizar. Um script (ou um servidor que testa o código de uma equipe antes de aceitar mudanças) roda dart analyze e, se o código não for 0, recusa a mudança. Duas opções mexem nessa regra:

  • --fatal-infos: até um info faz o código ser diferente de 0 (no lab, deu 1).
  • --no-fatal-warnings: os warning continuam aparecendo, mas o código fica 0.

4. Ligando regras extras: o analysis_options.yaml

Além dos erros e avisos que vêm sempre, o Dart tem centenas de regras de lint (em inglês, lint é o "fiapo" que fica na roupa: pequenas sujeirinhas de estilo). Elas ficam desligadas até você pedir. Pede-se num arquivo chamado analysis_options.yaml ("opções de análise"), na pasta do projeto:

linter:
  rules:
    - prefer_single_quotes
    - prefer_final_locals
linter:
A seção do linter, a parte do analisador que cuida dos lints.
rules:
"Regras": a lista das regras ligadas. No formato YAML, a indentação (2 espaços) mostra o que está dentro de quê.
- prefer_single_quotes
"Prefira aspas simples": avisa quando um texto usa "…" sem necessidade.
- prefer_final_locals
"Prefira variáveis locais final": avisa quando uma variável nunca muda e mesmo assim não é final.

Com o arquivo na pasta, o mesmo main.dart do começo ganha três info:

$ dart analyze main.dart
Analyzing main.dart...

warning - main.dart:1:8 - Unused import: 'dart:math'. Try removing the import directive. - unused_import
warning - main.dart:5:7 - The value of the local variable 'idade' isn't used. Try removing the variable or using it. - unused_local_variable
warning - main.dart:6:16 - The value of the local variable 'cidade' isn't used. Try removing the variable or using it. - unused_local_variable
   info - main.dart:4:3 - Local variables should be final. Try making the variable final. - prefer_final_locals
   info - main.dart:5:3 - Local variables should be final. Try making the variable final. - prefer_final_locals
   info - main.dart:6:25 - Unnecessary use of double quotes. Try using single quotes unless the string contains single quotes. - prefer_single_quotes

6 issues found.

"Variáveis locais deveriam ser final" (linhas 4 e 5) e "uso desnecessário de aspas duplas" (linha 6). Repare: o info nunca impede o programa de rodar. É conselho.

O pacote de regras recomendado

Ninguém liga regra por regra à mão. Quando você cria um projeto com dart create, ele já vem com um analysis_options.yaml que inclui um conjunto recomendado pela equipe do Dart (o pacote lints):

$ dart create -t console padaria

  README.md

  cd padaria

$ cd padaria
$ cat analysis_options.yaml | grep -v '^#' | grep -v '^ *#' | sed '/^$/d'

Tirando os comentários (as linhas com #), o arquivo tem uma linha só: include: package:lints/recommended.yaml, "inclua as regras recomendadas do pacote lints". Você pode acrescentar a sua seção linter: rules: embaixo para ligar mais regras. O Flutter usa um conjunto parecido, o flutter_lints.

5. dart fix: o revisor que conserta

Muitos diagnósticos têm conserto automático. O dart fix --dry-run ("ensaio") só mostra o que seria consertado:

$ dart fix --dry-run
Computing fixes in analise (dry run)...

1 proposed fix in 1 file.

main.dart
  unused_import - 1 fix

To fix an individual diagnostic, run one of:
  dart fix --apply --code=unused_import

To fix all diagnostics, run:
  dart fix --apply

"1 conserto proposto em 1 arquivo: no main.dart, 1 unused_import". Ele sugere dart fix --apply ("aplicar") para consertar tudo, ou --code=… para consertar um tipo só. Com as regras do analysis_options.yaml ligadas, a Ana aplicou:

$ dart fix --apply
Computing fixes in analise...
Applying fixes...

erro.dart
  prefer_final_locals - 1 fix

feio.dart
  prefer_final_locals - 1 fix

main.dart
  prefer_final_locals - 2 fixes
  prefer_single_quotes - 1 fix
  unused_import - 1 fix

6 fixes made in 3 files.
$ cat main.dart

void main() {
  final nome = 'Ana';
  final int idade = 30;
  final String cidade = 'Recife';
  print('Olá, $nome');
}

Ele apagou o import, pôs final nas variáveis e trocou as aspas. Mas atenção a duas coisas:

  • Ele mexeu em todos os arquivos da pasta (o erro.dart e o feio.dart também). Rode o --dry-run antes para ver o que vai mudar.
  • Ele não resolveu as variáveis não usadas: o dart fix não adivinha o que você queria fazer com elas. Esse conserto é seu (como na primeira missão).

6. dart format: o código passado a limpo

O Dart não liga para espaços e quebras de linha: este programa, todo espremido, roda normalmente. Mas ninguém consegue ler:

void main(){var precos=[3.5,2.0,10.25];var total=0.0;for(final p in precos){total+=p;}
print('Total: $total');}

$ dart format feio.dart
Formatted feio.dart
Formatted 1 file (1 changed) in 0.00 seconds.
$ cat feio.dart
void main() {
  var precos = [3.5, 2.0, 10.25];
  var total = 0.0;
  for (final p in precos) {
    total += p;
  }
  print('Total: $total');
}

"Formatado feio.dart; 1 arquivo formatado (1 mudou)". O dart format reescreveu o arquivo: uma instrução por linha, 2 espaços de indentação, espaço em volta do = e do +=, espaço depois da vírgula, a chave { no fim da linha. É o estilo oficial do Dart, igual para todo mundo: assim ninguém perde tempo discutindo onde vai a chave.

ComandoO que faz
dart format arquivo.dartFormata e regrava o arquivo.
dart format .Formata todos os .dart da pasta atual e das subpastas.
dart format --output=show arquivo.dartMostra o código formatado na tela e não mexe no arquivo.
dart format --output=none --set-exit-if-changed .Só confere: não mostra nem grava, mas devolve código 1 se algum arquivo precisaria mudar.

A conferência sem mexer em nada, num arquivo bagunçado:

$ dart format --output=none --set-exit-if-changed bagunca.dart; echo "codigo: $?"
Changed bagunca.dart
Formatted 1 file (1 changed) in 0.00 seconds.
codigo: 1
$ dart format --output=show bagunca.dart
void main() {
  print('oi');
}
Formatted 1 file (1 changed) in 0.00 seconds.
$ cat bagunca.dart
void main( ) { print( 'oi' ) ; }

O arquivo continua bagunçado: as duas opções só olharam. Num arquivo que já está bonito, a conferência diz Formatted 1 file (0 changed) e devolve 0.

A vírgula no fim muda o formato

Numa lista ou chamada longa, deixe uma vírgula depois do último item ('pão', 'leite',). O dart format entende que você quer um item por linha. É por isso que o guia recomenda "vírgula no fim de listas longas" (veja Estilo de Código).

Quando dá errado

"Rodou, então está certo" — e o aviso esquecido 
void main() {
  final preco = 7.5;
  final quantidade = 4;
  final total = preco * quantidade;
  print('Preço: $preco');
}

$ dart run main.dart
Preço: 7.5
$ dart analyze
Analyzing total...

warning - main.dart:4:9 - The value of the local variable 'total' isn't used. Try removing the variable or using it. - unused_local_variable

1 issue found.

A Ana queria mostrar o total e esqueceu. O dart run não reclamou de nada; o dart analyze achou: "o valor da variável local total não é usado", linha 4. Lição: rode o dart analyze antes de dar o programa por pronto; os warning costumam ser bugs disfarçados. Como consertar: print('Total: $total');.

O dart format não conserta erro

O formatador só mexe em espaços e quebras de linha. Ele não põe o ; que faltou, não troca tipos e não apaga variável. E, se o código tiver um erro de sintaxe, ele nem consegue entender o arquivo. Aqui faltou a } do fim:

void main() {
  print('oi');

$ dart format quebrado.dart; echo "codigo: $?"
Could not format because the source could not be parsed:

line 3, column 1 of quebrado.dart: Expected to find '}'.
  ╷
3 │  
  │ ^
  ╵
Formatted no files in 0.00 seconds.
codigo: 65

"Não foi possível formatar porque o código não pôde ser lido (parsed): linha 3, coluna 1: era esperado encontrar }". O desenho com │ e ^ aponta o lugar; no fim, Formatted no files ("nenhum arquivo formatado") e o código de saída 65. O arquivo ficou como estava. Como consertar: feche a chave e formate de novo. Regra geral: conserte os erros primeiro (com a ajuda do dart analyze), depois formate.

O analysis_options.yaml com a indentação errada

O YAML usa a indentação para saber o que está dentro de quê. Se a lista - prefer_single_quotes ficar na mesma coluna que rules:, ou se você usar tabulação em vez de espaços, as regras deixam de valer (ou o analisador acusa um problema no próprio analysis_options.yaml). Use sempre 2 espaços a cada nível, como no exemplo da seção 4.

Resumo

  • dart analyze lê o código sem rodar e lista os diagnósticos: error (não compila), warning (suspeito) e info (estilo), cada um com arquivo:linha:coluna, mensagem e código.
  • O código de saída é 0 (limpo ou só info), 1 (info com --fatal-infos), 2 (warning) ou 3 (error): é o que scripts usam para aprovar ou recusar código.
  • O analysis_options.yaml liga regras de lint; projetos do dart create já incluem package:lints/recommended.yaml.
  • dart fix --dry-run mostra e dart fix --apply aplica consertos automáticos (na pasta inteira).
  • dart format arruma espaços e quebras no estilo oficial; --output=show só mostra e --output=none --set-exit-if-changed só confere.
