Dart Isolates

Nas aulas de Future e async e await, o programa esperava coisas (o forno, a rede) sem travar. Mas esperar não é trabalhar. Quando o próprio programa tem uma conta pesada para fazer (somar bilhões de números, processar uma foto enorme), ele fica ocupado e não consegue fazer mais nada enquanto isso. A solução do Dart é o isolate ("isolado"): um segundo trabalhador, com a própria memória, que faz a conta enquanto o primeiro continua livre.

Você vai aprender
  • O que é um isolate e por que o nome é "isolado".
  • Como mandar uma conta para outro isolate com Isolate.run e receber o resultado com await.
  • Por que uma conta pesada trava o programa, e como o isolate resolve isso.
  • Que cada isolate tem a sua própria memória: o que um muda, o outro não vê.
  • Como rodar duas contas ao mesmo tempo e como trocar recados com Isolate.spawn, ReceivePort e SendPort.
  • Os erros reais: o import esquecido, a exceção dentro do isolate, o await esquecido e o objeto que não pode ser enviado.

Todos os programas desta aula rodaram no Dart 3.13.5 da máquina da Ana (usuária ana, computador notebook), executados com dart run arquivo.dart. Os tempos mostrados (milissegundos, quantos "tic" aparecem) dependem do computador e mudam a cada execução; os resultados das contas, não.

A ideia: a confeiteira e a ajudante

A Ana tem uma confeitaria e atende o balcão sozinha. Chega uma encomenda de 500 brigadeiros. Se ela mesma for enrolar, o balcão fica parado: ninguém é atendido até o último brigadeiro. Então ela chama uma ajudante, que vai para a cozinha dos fundos:

  • a ajudante enrola os brigadeiros enquanto a Ana continua atendendo;
  • a cozinha dos fundos tem os seus próprios ingredientes e panelas: a ajudante não mexe na bancada da Ana, e vice-versa;
  • as duas só se comunicam por recados: a Ana manda o pedido, a ajudante devolve a bandeja pronta.

Cada uma é um isolate. Todo programa Dart já começa com um: o isolate principal, onde roda o main. Ele é a Ana no balcão. Os isolates que você cria são as ajudantes. O nome "isolado" vem da cozinha separada: isolates não dividem memória, só trocam mensagens.

Esperar × trabalhar

async/await serve para esperar sem travar (o forno assa sozinho; a Ana só volta quando apita). Isolate serve para trabalhar sem travar (alguém precisa enrolar os brigadeiros). Para ler um arquivo ou baixar uma página, await basta. Para uma conta que ocupa o processador por muito tempo, use um isolate.

1. O primeiro isolate: Isolate.run

import 'dart:isolate';

int somarAte(int limite) {
  var soma = 0;
  for (var i = 1; i <= limite; i++) {
    soma += i;
  }
  return soma;
}

Future<void> main() async {
  print('Pedindo a conta para outro isolate...');
  final resultado = await Isolate.run(() => somarAte(100000000));
  print('Resultado: $resultado');
}
import 'dart:isolate';
Traz a biblioteca dos isolates. Ela vem com o Dart (não precisa instalar nada), mas precisa ser importada (veja import).
int somarAte(int limite)
Uma função comum, a "conta pesada": soma 1 + 2 + 3 + … até o limite. Nada nela sabe que vai rodar em outro isolate.
Isolate.run(…)
"Isolate, rode isto". Cria um isolate novo, roda lá a função que você passou, devolve o resultado e desliga o isolate. Tudo sozinho. Existe desde o Dart 2.19.
() => somarAte(100000000)
Uma função anônima sem parâmetros (veja Funções Anônimas): o "pedido" que vai para a ajudante. Ela leva junto o número 100000000 (cem milhões).
await
Isolate.run devolve um Future: o resultado chega depois. O await espera por ele. Por isso o main é Future<void> main() async.
$ dart run primeiro_isolate.dart

2. Por que usar: o programa travado

Para ver o travamento, este programa liga um relógio que mostra tic a cada 200 milissegundos (com Timer.periodic, da biblioteca dart:async). Depois de meio segundo, ele começa uma conta enorme (somar até 3 bilhões) no próprio isolate principal:

import 'dart:async';

int somarAte(int limite) {
  var soma = 0;
  for (var i = 1; i <= limite; i++) {
    soma += i;
  }
  return soma;
}

Future<void> main() async {
  final relogio = Timer.periodic(Duration(milliseconds: 200), (t) {
    print('tic ${t.tick}');
  });
  await Future.delayed(Duration(milliseconds: 500));
  print('Começando a conta pesada (no mesmo isolate)...');
  final resultado = somarAte(3000000000);
  print('Resultado: $resultado');
  await Future.delayed(Duration(milliseconds: 500));
  relogio.cancel();
}

Durante a conta, nenhum tic apareceu: o isolate principal estava ocupado no for e não teve tempo de atender o relógio. Num aplicativo de verdade (no Flutter, por exemplo), isso seria a tela congelada: botões que não respondem.

3. Cada isolate tem a sua própria memória

A lista pedidos abaixo é uma variável de fora do main (de "nível superior"). O isolate acrescenta dois itens nela:

import 'dart:isolate';

final pedidos = <String>['pão'];

Future<void> main() async {
  final tamanhoLa = await Isolate.run(() {
    pedidos.add('leite');
    pedidos.add('café');
    return pedidos.length;
  });
  print('No outro isolate, a lista tinha $tamanhoLa itens.');
  print('Aqui no main, a lista tem ${pedidos.length}: $pedidos');
}

$ dart run memoria.dart
No outro isolate, a lista tinha 3 itens.
Aqui no main, a lista tem 1: [pão]

O isolate trabalhou numa cópia da lista. Lá, ela chegou a 3 itens; aqui, continua com 1. O que volta para o main é só o que a função devolve (o número 3). Isso parece um defeito, mas é a grande vantagem: como ninguém mexe na memória do outro, dois isolates nunca "brigam" pela mesma variável. Se você precisa do resultado, devolva o que for preciso.

4. Duas contas ao mesmo tempo

O computador da Ana tem vários núcleos (processadores dentro do processador). Um isolate usa um núcleo de cada vez; dois isolates podem usar dois ao mesmo tempo. Este programa conta quantos números primos existem até 3 milhões, duas vezes: primeiro uma depois da outra, depois em dois isolates juntos com Future.wait (veja Future). O Stopwatch ("cronômetro") mede o tempo:

import 'dart:isolate';

int contarPrimos(int ate) {
  var total = 0;
  for (var n = 2; n <= ate; n++) {
    var primo = true;
    for (var d = 2; d * d <= n; d++) {
      if (n % d == 0) {
        primo = false;
        break;
      }
    }
    if (primo) total++;
  }
  return total;
}

Future<void> main() async {
  final cronometro = Stopwatch()..start();
  final a = contarPrimos(3000000);
  final b = contarPrimos(3000000);
  print('Um depois do outro: $a e $b em ${cronometro.elapsedMilliseconds} ms');

  cronometro.reset();
  final resultados = await Future.wait([
    Isolate.run(() => contarPrimos(3000000)),
    Isolate.run(() => contarPrimos(3000000)),
  ]);
  print('Em dois isolates: ${resultados[0]} e ${resultados[1]} em ${cronometro.elapsedMilliseconds} ms');
}

$ dart run paralelo.dart
Um depois do outro: 216816 e 216816 em 1666 ms
Em dois isolates: 216816 e 216816 em 820 ms
$ dart run paralelo.dart
Um depois do outro: 216816 e 216816 em 1658 ms
Em dois isolates: 216816 e 216816 em 834 ms

Os resultados (216816 primos) são sempre iguais; os milissegundos mudam a cada execução e de computador para computador. Mas a proporção se repete: com dois isolates, o tempo caiu mais ou menos pela metade, porque as duas contas rodaram em núcleos diferentes ao mesmo tempo.

Isolate não é de graça

Criar um isolate e copiar os dados de ida e volta leva um tempinho. Para uma conta pequena (somar 10 números), o isolate deixa o programa mais lento. Use para trabalho que leva dezenas ou centenas de milissegundos, ou mais.

5. Conversando com o isolate: Isolate.spawn

Isolate.run faz um pedido e recebe uma resposta. Quando a ajudante precisa mandar vários recados ao longo do tempo, o jeito mais antigo e mais completo é Isolate.spawn ("gerar, criar") com uma caixa de correio:

import 'dart:isolate';

void ajudante(SendPort paraOMain) {
  for (var i = 1; i <= 3; i++) {
    paraOMain.send('Recado $i do ajudante');
  }
  paraOMain.send(null);
}

Future<void> main() async {
  final caixaDeEntrada = ReceivePort();
  await Isolate.spawn(ajudante, caixaDeEntrada.sendPort);
  await for (final recado in caixaDeEntrada) {
    if (recado == null) break;
    print('main recebeu: $recado');
  }
  print('Fim.');
}
ReceivePort()
"Porta de receber": a caixa de correio do main. Ela é uma Stream de recados.
caixaDeEntrada.sendPort
"Porta de enviar": o endereço dessa caixa. É isso que a ajudante leva, para saber para onde mandar.
Isolate.spawn(ajudante, …)
Cria o isolate e roda nele a função ajudante, passando o SendPort como argumento. A função precisa receber exatamente um parâmetro.
paraOMain.send(…)
Manda um recado (uma cópia do valor) para a caixa do main.
send(null) / if (recado == null) break;
Um combinado entre os dois: null quer dizer "acabou". Sem ele, o await for esperaria recados para sempre e o programa não terminaria.
$ dart run spawn.dart
main recebeu: Recado 1 do ajudante
main recebeu: Recado 2 do ajudante
main recebeu: Recado 3 do ajudante
Fim.

Qual usar

SituaçãoUse
esperar arquivo, rede, temporizadorasync/await (sem isolate)
uma conta pesada, com um resultado no fimIsolate.run(() => conta())
várias contas pesadas ao mesmo tempoFuture.wait([Isolate.run(…), Isolate.run(…)])
um trabalhador que manda vários recados, ou que fica vivo recebendo pedidosIsolate.spawn com ReceivePort/SendPort
uma conta pequenauma função comum, direto no main

No Flutter existe ainda a função compute(funcao, valor), que faz o mesmo trabalho do Isolate.run (ela é do Flutter, não do Dart puro; aqui é só para você reconhecer o nome).

Resumo

  • Um isolate é um trabalhador com a sua própria memória. Todo programa começa com um (o do main).
  • await resolve esperas; isolate resolve trabalho pesado que travaria o programa.
  • await Isolate.run(() => conta()) é o jeito mais simples: roda a conta em outro isolate e devolve o resultado.
  • Isolates não dividem variáveis: o que vai e volta é copiado. Devolva o que precisar.
  • Vários isolates usam vários núcleos: com Future.wait, duas contas levaram mais ou menos metade do tempo (os milissegundos variam).
  • Isolate.spawn + ReceivePort/SendPort servem para trocar vários recados.
  • A exceção no isolate volta para o await: trate com try. Objetos "presos" (como ReceivePort) não podem ser enviados.
