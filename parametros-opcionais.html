Dart Parâmetros Opcionais e Valores Padrão

Na padaria, quem pede "um café" ganha um café médio, puro, com uma colher de açúcar. Ninguém precisa dizer tudo isso: existe um padrão, e o cliente só fala o que quer diferente ("um café com leite"). Funções também podem ser assim: alguns parâmetros são opcionais e, se ficarem de fora, usam um valor padrão. Nesta aula você vê os dois jeitos de fazer isso no Dart: posicionais opcionais, entre colchetes [ ], e nomeados opcionais, entre chaves { }.

Você vai aprender
  • Posicionais opcionais: [String? apelido], que podem ficar de fora da chamada.
  • Valores padrão com =: [int vezes = 2] e {double taxa = 10}.
  • Nomeados opcionais com padrão, o jeito mais usado (e o do Flutter).
  • Uma pegadinha: passar null de propósito "fura" o valor padrão.
  • As regras: opcionais vêm por último, [ ] e { } não se misturam, o padrão tem de ser constante.
  • Os erros reais de cada regra.

Todos os programas desta aula rodaram no Dart 3.13.5 da máquina da Ana (ana@notebook), com dart run arquivo.dart.

1. Posicional opcional: [ ]

Na aula Parâmetros Posicionais, a Bia não tinha apelido e a Ana teve de escrever saudar('Bia', null). Pondo o parâmetro entre colchetes, ele vira opcional e pode simplesmente ficar de fora:

void saudar(String nome, [String? apelido]) {
  if (apelido == null) {
    print('Olá, $nome!');
  } else {
    print('Olá, $nome ($apelido)!');
  }
}

void main() {
  saudar('Ana', 'Aninha');
  saudar('Bia');
}
String nome
Posicional comum: obrigatório.
[String? apelido]
Os colchetes tornam o parâmetro opcional. Se não for passado, ele vale null; por isso o tipo tem de aceitar null (String?).
saudar('Bia')
Chamada com um argumento só: apelido fica null.
$ dart run saudar.dart
Olá, Ana (Aninha)!
Olá, Bia!

2. Valor padrão: = valor

Em vez de null, o parâmetro opcional pode ter um valor "de sempre", escrito com = na declaração. Aí o tipo não precisa de ?, porque o parâmetro nunca fica vazio:

String repetir(String texto, [int vezes = 2]) {
  return texto * vezes;
}

void main() {
  print(repetir('ha'));
  print(repetir('ha', 5));
  print(repetir('-', 20));
}

3. Nomeados opcionais com padrão (o pedido de café)

Os posicionais opcionais têm um limite: para passar o 3º, você é obrigado a passar o 2º. Com nomeados (veja Parâmetros Nomeados), cada opcional é independente. Por isso eles são a escolha mais comum quando há vários opcionais:

void pedirCafe({String tamanho = 'médio', bool comLeite = false, int acucar = 1}) {
  final leite = comLeite ? 'com leite' : 'puro';
  print('Café $tamanho, $leite, $acucar colher(es) de açúcar');
}

void main() {
  pedirCafe();
  pedirCafe(comLeite: true);
  pedirCafe(tamanho: 'grande', acucar: 0);
}

$ dart run cafe.dart
Café médio, puro, 1 colher(es) de açúcar
Café médio, com leite, 1 colher(es) de açúcar
Café grande, puro, 0 colher(es) de açúcar

Cada chamada diz só o que muda. A terceira mudou o tamanho e o açúcar e deixou o leite no padrão; com posicionais opcionais, isso seria impossível sem escrever o leite também.

Também dá para ter um posicional obrigatório e nomeados opcionais, como na conta do restaurante, com taxa de serviço de 10% "de sempre":

double totalComTaxa(double valor, {double taxa = 10, bool arredondar = false}) {
  final total = valor + valor * taxa / 100;
  if (arredondar) {
    return total.roundToDouble();
  }
  return total;
}

void main() {
  print(totalComTaxa(84.50));
  print(totalComTaxa(84.50, taxa: 0));
  print(totalComTaxa(84.50, arredondar: true));
  print(totalComTaxa(84.50, arredondar: true, taxa: 15));
}

$ dart run nomeado.dart
92.95
84.5
93.0
97.0

84.50 com 10% dá 92.95; sem taxa, 84.5; arredondado, 93.0 (roundToDouble arredonda para o inteiro mais próximo, mantendo o tipo double); com 15% e arredondado, 97.0.

Dica do Effective Dart: bool opcional? Nomeado.

Compare totalComTaxa(84.50, true) com totalComTaxa(84.50, arredondar: true). No primeiro, ninguém sabe o que é o true. Um bool solto numa chamada quase sempre deveria ser um parâmetro nomeado.

4. A pegadinha: null de propósito fura o padrão

O valor padrão só é usado quando o argumento não é passado. Se o tipo aceita null e você passa null de propósito, o parâmetro vale null, não o padrão:

void saudar([String? apelido = 'amigo']) {
  print('Olá, $apelido!');
}

void main() {
  saudar();
  saudar('Aninha');
  saudar(null);
}

$ dart run nulo_padrao.dart
Olá, amigo!
Olá, Aninha!
Olá, null!

Na terceira chamada, o argumento foi passado: era null. Isso acontece quando você repassa uma variável que, por acaso, está null (algo lido do teclado, por exemplo). Como evitar: se existe um padrão, não use ? no tipo ([String apelido = 'amigo']): aí o Dart proíbe passar null, e quem chama tem de resolver antes (saudar(digitado ?? 'amigo')). Com int sem ?, por exemplo, a tentativa dá Error: The argument type 'Null' can't be assigned to the parameter type 'int'.

5. As regras do jogo

RegraCertoErrado
Os opcionais vêm depois dos obrigatórios(String nome, [String? apelido])([String? apelido], String nome)
Numa função, ou [ ] ou { }, nunca os dois(String nome, {int idade = 0})(String nome, [String? a], {int idade = 0})
Opcional sem padrão tem de aceitar null[int? vezes] ou [int vezes = 2][int vezes]
O padrão tem de ser uma constante (valor escrito, const){int acucar = 1}, {List<String> extras = const []}{DateTime quando = DateTime.now()}
required e padrão não combinam{required String tamanho} ou {String tamanho = 'médio'}{required String tamanho = 'médio'}
Padrão se escreve com ={String tamanho = 'médio'}{String tamanho: 'médio'} (forma antiga)

Formas diferentes de fazer a mesma coisa

A função repetir com 2 como padrão, de três jeitos:

// 1) posicional opcional com padrão
String repetir1(String texto, [int vezes = 2]) => texto * vezes;

// 2) nomeado opcional com padrão
String repetir2(String texto, {int vezes = 2}) => texto * vezes;

// 3) opcional anulável, e o padrão resolvido dentro da função
String repetir3(String texto, [int? vezes]) {
  return texto * (vezes ?? 2);
}

void main() {
  print(repetir1('ha', 3));
  print(repetir2('ha', vezes: 3));
  print(repetir3('ha', 3));
}

Missão final: a etiqueta com moeda

Missão: a padaria vende um chocolate importado, com preço em dólar. Acrescente à função um parâmetro nomeado opcional String moeda = 'R\$' e use-o no lugar do R\$ fixo. A segunda chamada deve passar moeda: 'US\$'. A saída deve ter Leite: R$ 5.49 e Chocolate: US$ 3.20.

void etiqueta(String produto, double preco) {
  print('$produto: R\$ ${preco.toStringAsFixed(2)}');
}

void main() {
  etiqueta('Leite', 5.49);
  etiqueta('Chocolate', 3.2);
}

void etiqueta(String produto, double preco, {String moeda = 'R\$'}) {
  print('$produto: $moeda ${preco.toStringAsFixed(2)}');
}

void main() {
  etiqueta('Leite', 5.49);
  etiqueta('Chocolate', 3.2, moeda: 'US\$');
}

Resumo

  • Parâmetros entre [ ] são posicionais opcionais; os nomeados entre { } sem required também são opcionais.
  • Um opcional precisa de um valor padrão (= 2) ou de um tipo anulável (int?, que vale null se faltar).
  • O padrão só vale quando o argumento não é passado; passar null de propósito fura o padrão.
  • Opcionais vêm por último; [ ] e { } não se misturam; o padrão tem de ser constante; required e padrão não combinam.
  • Vários opcionais, ou um bool: prefira nomeados com padrão, como no pedirCafe.
