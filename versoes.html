Dart Versões

O Dart muda: de tempos em tempos sai uma versão nova, com coisas novas na linguagem, nas bibliotecas e nas ferramentas. Saber ler o número da versão evita muita confusão: um tutorial antigo que não funciona, um recurso que "não existe" no seu computador, um projeto que pede uma versão diferente. Nesta aula você vai ver como descobrir a sua versão, o que cada parte do número quer dizer, um pouco da história do Dart e como um projeto escolhe a versão da linguagem.

Você vai aprender
  • Como ver a versão do Dart: dart --version e Platform.version.
  • O que quer dizer cada parte de 3.13.5, e os canais stable e beta.
  • A história do Dart, do 1.0 ao 3.13, com o que cada versão 3.x trouxe.
  • Como o pubspec.yaml (sdk: ^3.10.0) e o comentário // @dart= escolhem a versão da linguagem.
  • Os erros reais quando o código usa algo mais novo que a versão escolhida.

Tudo nesta aula rodou no Dart SDK 3.13.5 da máquina da Ana (usuária ana, computador notebook). As datas e os recursos de cada versão vêm do CHANGELOG do SDK e da página Language evolution do dart.dev.

A ideia: a edição do livro

A Ana comprou um livro de receitas na "3ª edição, 13ª revisão, 5ª reimpressão". A edição muda pouco, mas quando muda pode reorganizar o livro inteiro; a revisão acrescenta receitas novas sem tirar as antigas; a reimpressão só corrige erros de digitação. Se uma amiga diz "faça a receita da página 40 da 2ª edição", na edição da Ana a página pode ser outra. Com programas é igual: o número diz o tamanho da mudança, e o código precisa dizer para qual "edição" foi escrito.

2. O que quer dizer 3.13.5

O Dart segue o versionamento semântico (semantic versioning, ou "semver"): três números separados por pontos, MAIOR.MENOR.CORREÇÃO.

ParteNo exemploMuda quando…
Maior (major)3Há mudanças que quebram código antigo. Raro: o Dart 3 saiu em 2023.
Menor (minor)13Entram recursos novos. Mais ou menos a cada três meses.
Correção (patch)5Só conserto de defeitos e de segurança. A cada poucas semanas.

Então 3.13.5 é "o Dart 3, revisão 13, quinta correção". Um programa escrito para o 3.10 roda no 3.13; um escrito para o 3.13 pode usar coisas que o 3.10 não conhece.

Os canais

  • stable ("estável"): a que você instala e usa. Este guia usa a estável.
  • beta: a próxima versão, para quem quer testar antes. Pode ter defeitos.
  • main (ou dev): o código do dia, para quem trabalha no próprio Dart.

O ritmo

Pelas datas do CHANGELOG, as versões menores recentes saíram em fevereiro, maio, agosto e novembro de cada ano (3.7.0 em 12/02/2025, 3.8.0 em 20/05/2025, 3.9.0 em 13/08/2025, 3.10.0 em 12/11/2025, 3.11.0 em 11/02/2026, 3.12.0 em 20/05/2026, 3.13.0 em 12/08/2026), com correções no meio. O Flutter acompanha: cada versão do Flutter traz uma versão do Dart dentro.

Missão: o número abaixo é difícil de ler. Use o separador de dígitos do Dart 3.6: escreva 1_000_000. Os _ só ajudam quem lê; a saída não muda.

void main() {
  final populacao = 1000000;
  print('Moradores: $populacao');
}

void main() {
  final populacao = 1_000_000;
  print('Moradores: $populacao');
}

4. A versão da linguagem: quem escolhe é o projeto

Aqui está uma ideia importante: o SDK instalado é o 3.13.5, mas o seu código pode estar sendo lido como Dart 3.9, ou 3.5. Cada pacote diz para qual versão da linguagem foi escrito, e o Dart respeita. Assim, um pacote antigo continua funcionando do jeito que o autor escreveu, mesmo num SDK novo.

No projeto: o environment do pubspec.yaml

name: loja
environment:
  sdk: ^3.9.0
environment:
"Ambiente": o que o projeto precisa para rodar.
sdk: ^3.9.0
"Funciona com o SDK 3.9.0 ou mais novo, até antes do 4.0.0". O ^ (acento circunflexo) quer dizer "compatível com": >=3.9.0 <4.0.0. O número mais baixo (3.9) é a versão da linguagem que vale para o código do projeto.

A Ana usou nesse projeto um recurso do Dart 3.10, o atalho com ponto (.medio em vez de Tamanho.medio):

enum Tamanho { pequeno, medio, grande }

void main() {
  Tamanho cafe = .medio;
  print('Café $cafe');
}

$ dart pub get
Resolving dependencies...
Downloading packages...
Got dependencies!
$ dart run bin/loja.dart; echo "codigo: $?"
bin/loja.dart:4:18: Error: This requires the experimental 'dot-shorthands' language feature to be enabled.
Try passing the '--enable-experiment=dot-shorthands' command line option.
  Tamanho cafe = .medio;
                 ^
codigo: 254

O SDK 3.13 conhece o atalho, mas o projeto disse "sou Dart 3.9", e no 3.9 ele não existia. A mensagem diz "isto exige que o recurso experimental dot-shorthands esteja ligado", e sugere a opção --enable-experiment. Não siga essa sugestão: o recurso não é mais experimental; ele só é novo demais para a versão que o projeto pediu. O conserto certo é subir a versão no pubspec.yaml e rodar dart pub get de novo:

$ sed -i 's/\^3.9.0/^3.10.0/' pubspec.yaml
$ cat pubspec.yaml
name: loja
environment:
  sdk: ^3.10.0
$ dart pub get
Resolving dependencies...
Downloading packages...
Got dependencies!
$ dart run bin/loja.dart; echo "codigo: $?"
Café Tamanho.medio
codigo: 0

(O sed trocou o texto dentro do arquivo; você pode simplesmente editar o pubspec.yaml no editor.) O dart pub get anota a versão da linguagem num arquivo interno, o .dart_tool/package_config.json:

$ grep -B2 -A3 '"name": "loja"' .dart_tool/package_config.json
  "packages": [
    {
      "name": "loja",
      "rootUri": "../",
      "packageUri": "lib/",
      "languageVersion": "3.10"

"languageVersion": "3.10": é aqui que o dart run consulta a versão. Por isso, depois de mudar o sdk:, rode sempre dart pub get.

E fora de um projeto?

Um arquivo solto, sem pubspec.yaml por perto, é lido na versão do próprio SDK (aqui, 3.13). Por isso o mesmo .medio funcionou direto num arquivo solto na pasta versoes da Ana. É também o caso do editor do guia.

Num arquivo só: o comentário // @dart=

Um arquivo pode pedir uma versão mais antiga que a do projeto, com um comentário especial na primeira linha:

// @dart=3.5
void main() {
  final populacao = 1_000_000;
  print('Moradores: $populacao');
}

$ dart run antigo.dart; echo "codigo: $?"
antigo.dart:3:21: Error: This requires the experimental 'digit-separators' language feature to be enabled.
Try passing the '--enable-experiment=digit-separators' command line option.
  final populacao = 1_000_000;
                    ^^^^^^^^^
codigo: 254

Sem o comentário, o mesmo programa roda e mostra Moradores: 1000000. Com // @dart=3.5, o arquivo é lido como Dart 3.5, que ainda não tinha o separador de dígitos (ele chegou no 3.6). É raro precisar disso; serve para migrar um projeto grande aos poucos.

Quando dá errado

"This requires the experimental '…' language feature"

Você viu duas vezes acima: dot-shorthands e digit-separators. Quase sempre quer dizer que o recurso existe no seu SDK, mas o projeto (ou o arquivo) pediu uma versão de linguagem anterior a ele. Como consertar: confira na tabela das versões 3.x quando o recurso chegou, suba o sdk: do pubspec.yaml e rode dart pub get. Não use --enable-experiment para recursos que já são estáveis.

Pedir uma versão que o SDK ainda não tem 
// @dart=3.14
void main() {
  print('oi');
}

$ dart run novo.dart; echo "codigo: $?"
novo.dart:1:1: Error: The specified language version 3.14 is too high. The highest supported language version is 3.13.
// @dart=3.14
^^^^^^^^^^^^^
codigo: 254

"A versão de linguagem 3.14 é alta demais. A mais alta suportada é a 3.13." O SDK não conhece o futuro. O mesmo vale para um pubspec.yaml com sdk: ^3.14.0:

$ dart pub get; echo "codigo: $?"
Resolving dependencies...
The current Dart SDK version is 3.13.5.

Because loja requires SDK version ^3.14.0, version solving failed.
codigo: 1

"A versão atual do SDK é 3.13.5. Como loja exige o SDK ^3.14.0, a resolução de versões falhou." Acontece quando você baixa um projeto feito num Dart mais novo que o seu. Como consertar: atualize o SDK (veja Instalar o Dart) ou baixe o número pedido.

O tutorial antigo que "não funciona"

Um tutorial de 2019 pode ter String nome = null;, import 'dart:html'; ou new em todo canto. O primeiro não compila no Dart 3, porque o null safety virou obrigatório:

$ dart run nulo.dart; echo "codigo: $?"
nulo.dart:2:17: Error: A value of type 'Null' can't be assigned to a variable of type 'String'.
  String nome = null;
                ^
codigo: 254

("Um valor do tipo Null não pode ser guardado numa variável do tipo String"; o conserto é String? nome, veja Tipos Anuláveis.) O segundo está obsoleto (veja Dart na Web); o terceiro funciona, mas está fora de estilo. Sempre olhe a data e a versão de um tutorial antes de copiar.

Missão final: o recurso do Dart 3.10

Missão: o editor lê o código como a versão do próprio SDK, então os atalhos com ponto (Dart 3.10) funcionam. Troque Tamanho.medio pelo atalho do tamanho grande: .grande.

enum Tamanho { pequeno, medio, grande }

void main() {
  Tamanho cafe = Tamanho.medio;
  print('Café $cafe');
}

enum Tamanho { pequeno, medio, grande }

void main() {
  Tamanho cafe = .grande;
  print('Café $cafe');
}

Resumo

  • dart --version mostra a versão do SDK, o canal (stable), a data e a plataforma; no programa, Platform.version.
  • MAIOR.MENOR.CORREÇÃO: a maior quebra código antigo (raro), a menor traz recursos (a cada ~3 meses), a correção só conserta.
  • Marcos: 1.0 (2013), 2.0 (2018), null safety no 2.12 (2021), Dart 3.0 (2023) com null safety obrigatório, records e patterns; depois, um recurso novo a cada poucas versões (3.6 separador de dígitos, 3.10 atalhos com ponto, 3.13 construtores primários).
  • A versão da linguagem do projeto é a mínima do sdk: no pubspec.yaml; mudou, rode dart pub get. Um arquivo pode pedir uma mais antiga com // @dart=X.Y.
  • This requires the experimental '…' language feature costuma querer dizer "versão de linguagem baixa demais", não "recurso experimental".
