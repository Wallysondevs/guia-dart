Dart Mapas (Map)

Numa lista, você encontra um valor pela posição: compras[0]. Mas, na padaria, ninguém pergunta "quanto custa o item número 0?"; pergunta "quanto custa o pão?". Para achar um valor por um nome (ou qualquer outra etiqueta), o Dart tem o mapa, o tipo Map: uma coleção de pares chave → valor. Em outras linguagens ele se chama dicionário.

Você vai aprender
  • Como criar um mapa com {chave: valor} e o tipo dele: Map<String, double>.
  • Como ler um valor pela chave, e por que o resultado pode ser null.
  • Como lidar com esse null: ??, containsKey, if (x != null) e o !.
  • Como acrescentar, trocar e remover pares.
  • keys, values, length, mapa vazio, chaves que são números e listas dentro de mapas.
  • Os erros reais: a conta com double?, o ! numa chave que não existe, o valor de tipo errado, a chave repetida e o mapa const.

Todos os programas desta aula rodaram no Dart 3.13.5 da máquina da Ana (usuária ana, computador notebook), com dart run arquivo.dart.

A ideia: o cardápio na parede

Na parede da padaria tem uma tabela:

Produto (chave)Preço (valor)
pãoR$ 0,75
leiteR$ 5,49
caféR$ 18,90

Você procura pelo nome do produto (a chave) e encontra o preço (o valor). Cada produto aparece uma vez só na tabela; preços podem se repetir. E se você pergunta por um produto que não está lá ("tem bolo?"), a resposta é "não tem". É exatamente assim que um Map funciona.

1. Criando um mapa e lendo valores

void main() {
  final precos = {
    'pão': 0.75,
    'leite': 5.49,
    'café': 18.90,
  };
  print(precos);
  print(precos['leite']);
  print(precos['bolo']);
  print(precos.length);
  print(precos.runtimeType);
}

$ dart run precos.dart
{pão: 0.75, leite: 5.49, café: 18.9}
5.49

_Map<String, double>
{ 'pão': 0.75, … }
Um mapa literal: pares chave: valor entre chaves, separados por vírgula. Antes dos dois-pontos, a chave; depois, o valor. Um par por linha e a vírgula no fim deixam fácil de ler (é como o dart format deixa).
precos['leite'] → 5.49
Lê o valor pela chave, com colchetes, como numa lista, mas com a chave no lugar da posição.
precos['bolo'] → null
A chave não existe: o mapa devolve null ("nada"; veja Null Safety). Não dá erro, diferente da lista com uma posição que não existe.
precos.length → 3
Quantos pares o mapa tem.
_Map<String, double>
O tipo: Map<String, double>, "mapa de chaves String para valores double". (O _ é o nome da classe interna do Dart; para você, é um Map.) O primeiro tipo entre < > é o das chaves; o segundo, o dos valores.

2. Acrescentar, trocar e remover

void main() {
  final estoque = {'pão': 30, 'leite': 12};
  estoque['leite'] = 10;
  estoque['bolo'] = 4;
  print(estoque);
  estoque.remove('pão');
  print(estoque);
  print(estoque.containsKey('pão'));
  print(estoque.containsKey('bolo'));
  print(estoque.containsValue(10));
}

$ dart run mudar.dart
{pão: 30, leite: 10, bolo: 4}
{leite: 10, bolo: 4}
false
true
true
estoque['leite'] = 10;
A chave 'leite' já existia: o valor é trocado (de 12 para 10).
estoque['bolo'] = 4;
A chave 'bolo' não existia: o par é acrescentado. É a mesma escrita para as duas coisas: "a partir de agora, a chave X vale Y".
estoque.remove('pão')
Tira o par inteiro (chave e valor), pela chave.
containsKey('pão') → false
"Contém a chave?" Depois do remove, não.
containsValue(10) → true
"Contém o valor?" Existe, mas é bem menos usado (e mais lento: precisa olhar todos os valores).

Repare que um mapa nunca tem duas chaves iguais: gravar numa chave que existe troca o valor. Os valores, sim, podem se repetir.

3. O null de quando a chave não existe

Como precos['bolo'] pode dar null, o Dart considera que toda leitura com colchetes é do tipo double? ("um double ou null"; veja Tipos Anuláveis), mesmo que você saiba que a chave existe. Para fazer contas, você precisa dizer o que fazer se vier null. Há três jeitos:

void main() {
  final precos = {'pão': 0.75, 'leite': 5.49};
  final produto = 'bolo';
  final preco = precos[produto] ?? 0.0;
  print('$produto: R\$ $preco');
  if (precos.containsKey('pão')) {
    final total = precos['pão']! * 10;
    print('10 pães: R\$ ${total.toStringAsFixed(2)}');
  }
  final leite = precos['leite'];
  if (leite != null) {
    print('2 leites: R\$ ${(leite * 2).toStringAsFixed(2)}');
  }
}

$ dart run nulo.dart
bolo: R$ 0.0
10 pães: R$ 7.50
2 leites: R$ 10.98
precos[produto] ?? 0.0
"O preço, ou, se vier null, 0.0". O ?? dá um valor padrão (veja ?. , ?? e ??=). O resultado é um double comum.
precos['pão']! * 10
O ! diz ao Dart: "eu garanto que não é null". Aqui é seguro, porque o containsKey conferiu antes. Se a garantia for falsa, o programa para (veja Quando dá errado).
final leite = precos['leite']; if (leite != null)
Guarda numa variável e testa. Dentro do if, o Dart sabe que leite não é null e deixa fazer a conta. É o jeito mais seguro.

Missão: este programa não compila (leia o erro). Use ?? 0.0 para que um produto que não está no mapa valha 0.0.

4. Chaves, valores, mapa vazio e outros tipos de chave

void main() {
  final notas = {'Ana': 9.5, 'Bia': 7.0, 'Caio': 8.0};
  print(notas.keys);
  print(notas.values);
  print(notas.isEmpty);
  final vazio = <String, int>{};
  print(vazio);
  print(vazio.isEmpty);
  final dias = {1: 'domingo', 2: 'segunda', 7: 'sábado'};
  print(dias[7]);
}

$ dart run chavesvalores.dart
(Ana, Bia, Caio)
(9.5, 7.0, 8.0)
false
{}
true
sábado
  • keys (as chaves) e values (os valores) aparecem com parênteses: são Iterables, sequências que dá para percorrer (veja map, where, reduce e Outros). A ordem é a de inserção.
  • O mapa vazio se cria com os dois tipos antes das chaves: <String, int>{}. (Sozinho, {} também é um mapa, mas de dynamic: sem conferência de tipos. Veja Conjuntos.)
  • A chave não precisa ser texto: {1: 'domingo'} é um Map<int, String>, e dias[7] procura a chave 7 (não a posição 7).

Percorrer um mapa par por par tem uma aula própria: Percorrendo Mapas.

5. Listas dentro de mapas

O valor pode ser qualquer coisa, inclusive uma lista. A escola guarda os alunos de cada turma:

void main() {
  final turmas = {
    '1º A': ['Ana', 'Bia'],
    '1º B': ['Caio'],
  };
  turmas['1º B']!.add('Davi');
  print(turmas);
  print(turmas['1º A']![1]);
  final aluno = {
    'nome': 'Ana',
    'idade': 15,
  };
  print(aluno.runtimeType);
}

$ dart run lista_em_mapa.dart
{1º A: [Ana, Bia], 1º B: [Caio, Davi]}
Bia
_Map<String, Object>

turmas['1º B'] é a lista da turma B (ou null, se a turma não existisse); o ! garante que existe, e o .add mexe na lista. turmas['1º A']![1] é a posição 1 da lista da turma A.

O último mapa mistura texto e número nos valores, e o Dart escolheu Object para eles. Funciona, mas toda leitura vira um Object? que precisa de conversão. Para "uma ficha com campos fixos" (nome, idade), o Dart tem coisas melhores: Records e Classes.

Formas diferentes: lista, conjunto ou mapa?

SituaçãoQual usar
Valores em ordem, achados pela posiçãoList: ['pão', 'leite']
Valores sem repetição, a pergunta é "tem?"Set: {'pão', 'leite'}
Achar um valor por uma etiqueta (produto → preço, aluno → nota, número → dia)Map: {'pão': 0.75}
Contar quantas vezes cada coisa apareceMap<String, int> (exemplo em Percorrendo Mapas)
Uma ficha com campos fixos e tipos diferentesRecord ou classe, não Map<String, Object>

E para ler um valor que pode faltar:

EscritaQuando usar
mapa[chave] ?? padraoExiste um valor padrão que faz sentido (0, texto vazio…)
final v = mapa[chave]; if (v != null) { … }Fazer algo só se a chave existir
mapa[chave]!Só quando você tem certeza (acabou de conferir com containsKey, ou acabou de gravar)

Quando dá errado

Conta direto com o valor do mapa 
void main() {
  final precos = {'pão': 0.75, 'leite': 5.49};
  final total = precos['pão'] * 10;
  print(total);
}

$ dart run err_nulo.dart
err_nulo.dart:3:31: Error: Operator '*' cannot be called on 'double?' because it is potentially null.
  final total = precos['pão'] * 10;
                              ^
Operator '*' cannot be called on 'double?'
"O operador * não pode ser usado num double?…"
because it is potentially null.
"…porque ele pode ser null." Você sabe que tem pão no mapa, mas o Dart não confere o conteúdo: para ele, qualquer leitura com colchetes pode faltar.

O erro é de compilação (nada roda, código 254): o null safety evitando uma conta com "nada". Como consertar: (precos['pão'] ?? 0) * 10, ou um dos jeitos da seção 3.

O ! numa chave que não existe 
void main() {
  final precos = {'pão': 0.75, 'leite': 5.49};
  final total = precos['Pão']! * 10;
  print(total);
}

$ dart run err_exclamacao.dart
Unhandled exception:
Null check operator used on a null value
#0      main (file:///home/ana/err_exclamacao.dart:3:30)
#1      _delayEntrypointInvocation.<anonymous closure> (dart:isolate-patch/isolate_patch.dart:313:19)
#2      _RawReceivePort._handleMessage (dart:isolate-patch/isolate_patch.dart:192:12)

"O operador de checagem de nulo (o !) foi usado num valor nulo." Compilou, porque o ! prometeu que não seria null; mas a chave é 'Pão', com P maiúsculo, e o mapa só tem 'pão'. As chaves diferenciam maiúsculas de minúsculas. A coluna 30 da linha 3 é o !. Como consertar: escreva a chave certa e, se ela vem de fora (digitada pela pessoa), não use !: use ?? ou if (v != null).

Valor do tipo errado 
void main() {
  final estoque = {'pão': 30, 'leite': 12};
  estoque['bolo'] = 'quatro';
}

$ dart run err_tipo.dart
err_tipo.dart:3:21: Error: A value of type 'String' can't be assigned to a variable of type 'int'.
  estoque['bolo'] = 'quatro';
                    ^

"Um valor do tipo String não pode ser atribuído a uma variável do tipo int." O mapa é Map<String, int>: todos os valores são inteiros. Como consertar: estoque['bolo'] = 4;.

A mesma chave duas vezes (sem erro nenhum) 
void main() {
  final precos = {
    'pão': 0.75,
    'leite': 5.49,
    'pão': 0.80,
  };
  print(precos);
}

$ dart run err_repetida.dart
{pão: 0.8, leite: 5.49}

O dart run não reclama: o segundo 'pão' simplesmente substitui o primeiro, e o mapa fica com 2 pares, não 3. Num mapa grande, isso esconde um engano de digitação. Quem pega é o dart analyze, o "revisor" do Dart (veja Análise e Formatação):

$ dart analyze err_repetida.dart
Analyzing err_repetida.dart...

warning - err_repetida.dart:5:5 - Two keys in a map literal shouldn't be equal. Change or remove the duplicate key. - equal_keys_in_map

1 issue found.

"Aviso, linha 5, coluna 5: duas chaves num mapa literal não deveriam ser iguais. Mude ou remova a chave repetida." O equal_keys_in_map do fim é o nome da regra. Como consertar: deixe uma só.

Mudar um mapa const 
void main() {
  const dias = {1: 'domingo', 2: 'segunda'};

  final precos = {'pão': 0.75, 'leite': 5.49, 'manteiga': 3.25};
  final pedido = ['pão', 'pão', 'leite', 'manteiga', 'bolo', 'pão', 'pão'];

  for (final item in pedido) {
    total = total + (precos[item] ?? 0);
  }
  print('Total: R\$ ${total.toStringAsFixed(2)}');
}

Resumo

  • Um Map guarda pares chave → valor: {'pão': 0.75}, do tipo Map<String, double>.
  • mapa[chave] lê; mapa[chave] = valor acrescenta ou troca; remove(chave) tira.
  • Chave que não existe dá null, não erro. Por isso a leitura é do tipo double?: use ??, if (v != null) ou, com certeza absoluta, !.
  • Cada chave aparece uma vez só; gravar numa chave existente troca o valor.
  • keys e values são Iterables (parênteses no print). Mapa vazio: <String, int>{}.
