Dart Null Safety

Este é o assunto que mais confunde quem está começando no Dart, e também um dos que mais protegem o seu programa. A ideia cabe numa frase: no Dart, uma variável só pode ficar "vazia" se você disser, no tipo, que ela pode. Nesta aula você vai ver o que é esse "vazio" (o null), que estrago ele fazia, e como o Dart pega o problema antes de o programa rodar, com as mensagens de erro reais que você vai encontrar.

Você vai aprender
  • O que é o null e por que ele é perigoso.
  • O erro que o null causa quando ninguém confere: The getter 'length' was called on null.
  • O que é null safety ("segurança contra o nulo"): tipos que não aceitam null (String) e tipos que aceitam (String?).
  • Como conferir com != null antes de usar.
  • De onde vem o null no dia a dia: tryParse, mapas, o teclado.
  • As cinco mensagens de erro de compilação mais comuns, explicadas linha por linha.

Todos os programas desta aula rodaram no Dart 3.13.5 da máquina da Ana (usuária ana, computador notebook), com dart run arquivo.dart.

A ideia: a gaveta vazia

Pense numa variável como uma gaveta com etiqueta. A gaveta nome guarda um texto; a gaveta idade, um número. Agora imagine que alguém abre a gaveta nome para ler o nome da cliente e… ela está vazia. Não tem um texto em branco lá dentro: não tem nada. Esse "nada" se chama null (em inglês, "nulo").

O problema não é a gaveta vazia em si. É não saber que ela podia estar vazia. Quem abre a gaveta esperando um texto e tenta contar as letras do nada… quebra o programa. Por décadas, esse foi um dos erros mais comuns da programação: o inventor do null, Tony Hoare, chamou a própria invenção de "o erro de um bilhão de dólares".

A solução do Dart é simples: a etiqueta da gaveta diz se ela pode ficar vazia.

Etiqueta (tipo)Lê-sePode ficar vazia (null)?
String"um texto"Nunca. Sempre tem um texto dentro.
String?"um texto ou nada"Pode. E o Dart obriga você a conferir antes de usar.

O mesmo vale para todos os tipos: int e int?, double e double?, bool e bool?.

1. O problema: o null sem conferência

Primeiro, veja o estrago que o null faz quando ninguém confere. Para isso, a Ana usou dynamic, o tipo que desliga a conferência do Dart (antes do null safety, todo tipo do Dart aceitava null e quebrava assim, sem aviso):

void main() {
  dynamic apelido = null;
  print('Tamanho do apelido: ${apelido.length}');
}

2. A solução: o Dart recusa o null antes de rodar

Com tipos de verdade, o Dart confere tudo antes de executar a primeira linha. Tente guardar null numa variável String:

void main() {
  print('Antes');
  String nome = null;
  print(nome);
}

nulo.dart:3:17: Error: A value of type 'Null' can't be assigned to a variable of type 'String'.

Isso é o null safety: o erro que antes quebrava o programa na mão do cliente agora aparece para você, no seu computador, antes de tudo. Ele existe desde o Dart 2.12 e, a partir do Dart 3.0, é obrigatório: não há como desligar.

3. Quando o "nada" é um valor válido: String?

Às vezes a gaveta vazia faz sentido: nem toda cliente tem apelido. Aí você põe um ? no fim do tipo:

void main() {
  String nome = 'Ana';
  String? apelido = null;
  print(nome);
  print(apelido);
  apelido = 'Aninha';
  print(apelido);
}

$ dart run anulavel.dart
Ana
null
Aninha

String? se lê "String ou nada" e se chama tipo anulável (nullable). A gaveta apelido começou vazia (o print mostra a palavra null) e depois recebeu um texto. Mas o Dart cobra um preço pela liberdade. Tente usar o texto direto:

void main() {
  String? apelido = null;
  print(apelido.length);
}

$ dart run chamar.dart

4. Conferir antes de usar: != null

O jeito mais simples de usar um String? é perguntar se ele tem algo dentro. Depois do if (apelido != null), o Dart sabe que ali dentro a gaveta está cheia, e libera o uso:

void main() {
  String? apelido = null;
  if (apelido != null) {
    print('Tamanho: ${apelido.length}');
  } else {
    print('Sem apelido');
  }
  apelido = 'Aninha';
  if (apelido != null) {
    print('Tamanho: ${apelido.length}');
  }
}

$ dart run checar.dart
Sem apelido
Tamanho: 6

O != quer dizer "diferente de". Dentro do bloco do if, apelido passa a ser tratado como String (sem ?): é a mesma promoção de tipo que você viu com o is em dynamic e Object. O Dart acompanha o caminho do programa para saber, em cada linha, se a variável pode ou não ser null.

Missão: este programa não compila (String? pode ser null). Use um if (apelido != null) para mostrar o apelido em maiúsculas quando ele existir e Sem apelido quando não existir.

void main() {
  String? apelido = null;
  print(apelido.toUpperCase());
}

void main() {
  String? apelido = null;
  if (apelido != null) {
    print(apelido.toUpperCase());
  } else {
    print('Sem apelido');
  }
}

5. De onde vem o null

Você quase nunca escreve null à mão. Ele chega de funções que podem não ter resposta:

void main() {
  var precos = {'pão': 1, 'bolo': 25};
  print(int.tryParse('abc'));
  print(precos['torta']);
  print(precos['bolo']);
}

$ dart run fontes.dart
null
null
25
De ondeDevolvePor que pode vir null
int.tryParse(texto)int?O texto pode não ser um número (Conversão)
mapa[chave]o tipo do valor, com ?A chave pode não existir: não há 'torta' nos preços (Mapas)
stdin.readLineSync()String?A entrada pode acabar sem nenhuma linha (Lendo o Teclado)
bool.tryParse(texto)bool?O texto pode não ser true/false (Booleanos)

Em todos esses casos, o tipo do resultado tem o ?, e o Dart vai cobrar que você trate o "nada". É isso que as próximas aulas ensinam.

Quando dá errado: as mensagens do null safety

Todas estas são de compilação: o Dart recusa o programa inteiro (código 254), e nada roda. Vale a pena aprender a reconhecer cada uma.

1. null numa variável que não aceita

Seção 2: A value of type 'Null' can't be assigned to a variable of type 'String'. Como consertar: se o "nada" faz sentido, String? nome = null;; se não faz, dê um valor de verdade: String nome = 'Ana';.

2. Variável criada sem valor e usada 
void main() {
  String nome;
  print(nome);
}

$ dart run semvalor.dart
semvalor.dart:3:9: Error: Non-nullable variable 'nome' must be assigned before it can be used.
  print(nome);
        ^^^^

"A variável não anulável nome precisa receber um valor antes de ser usada." Non-nullable = "não anulável", isto é, sem ?. Criar String nome; sem valor é permitido; usar antes de dar um valor, não, porque ela estaria vazia. Como consertar: String nome = 'Ana';, ou dê o valor antes do print.

3. Usar um String? como se fosse String

Seção 3: Property 'length' cannot be accessed on 'String?' because it is potentially null. Com um método, a mensagem é parecida: Method 'toUpperCase' cannot be called on 'String?' because it is potentially null. (você vê na missão da seção 4). Como consertar: if (x != null) antes, ou os operadores de ?. , ?? e ??=.

4. Passar null para uma função que espera String 
void saudar(String nome) {
  print('Olá, $nome!');
}

void main() {
  saudar('Ana');
  saudar(null);
}

$ dart run funcao.dart
funcao.dart:7:10: Error: The argument type 'Null' can't be assigned to the parameter type 'String'.
  saudar(null);
         ^

"O tipo do argumento, Null, não pode ser atribuído ao tipo do parâmetro, String." O parâmetro é a gaveta que a função tem (String nome); o argumento é o que você mandou (null). Repare que nem o saudar('Ana'), que estava certo, rodou (funções em Funções). Como consertar: mande um texto, ou mude o parâmetro para String? nome e trate o null dentro da função.

5. Guardar um int? num int 
void main() {
  var precos = {'pão': 1, 'bolo': 25};
  int preco = precos['torta'];
  print(preco);
}

$ dart run mapa.dart
mapa.dart:3:21: Error: A value of type 'int?' can't be assigned to a variable of type 'int'.
  int preco = precos['torta'];
                    ^

"Um valor do tipo int? não pode ser atribuído a uma variável do tipo int." A busca no mapa pode não achar a chave, então o resultado é int?. A mesma mensagem aparece com int idade = int.tryParse(texto);. Como consertar: dê um valor para o caso do "nada": int preco = precos['torta'] ?? 0; (veja ?. , ?? e ??=).

6. Campo de classe sem valor 
class Cliente {
  String nome;
}

void main() {
  var c = Cliente();
  print(c.nome);
}

$ dart run classe.dart
classe.dart:2:10: Error: Field 'nome' should be initialized because its type 'String' doesn't allow null.
  String nome;
         ^^^^

"O campo nome deveria receber um valor inicial, porque o tipo dele, String, não permite null." Você ainda vai ver classes em Classes; por ora, guarde a mensagem: doesn't allow null ("não permite null"). Como consertar: um valor inicial (String nome = '';), um construtor que exige o nome (Construtores), String? nome; ou late String nome; (late).

Missão final: três gavetas

Missão: o programa tem dois erros de null safety. (1) nome nunca fica vazio: dê a ele o valor 'Ana' em vez de null. (2) apelido pode ficar vazio: mude o tipo para String?. A saída deve ser Cliente: Ana e Apelido: nenhum.

void main() {
  String nome = null;
  String apelido = null;
  print('Cliente: $nome');
  if (apelido != null) {
    print('Apelido: $apelido');
  } else {
    print('Apelido: nenhum');
  }
}

void main() {
  String nome = 'Ana';
  String? apelido = null;
  print('Cliente: $nome');
  if (apelido != null) {
    print('Apelido: $apelido');
  } else {

  }
}

Resumo

  • null é o "nada": a gaveta vazia. Usá-lo sem saber quebrava programas no meio da execução (The getter 'length' was called on null).
  • Com null safety (obrigatório no Dart 3), um tipo sem ? nunca é null; um tipo com ? (String?) pode ser.
  • O Dart confere antes de rodar: null em String, variável sem valor, String? usado direto e int? em int são erros de compilação.
  • if (x != null) libera o uso dentro do bloco (promoção de tipo).
  • tryParse, mapas e o teclado devolvem tipos com ?: trate o "nada".
