Dart e Flutter

Muita gente chega ao Dart por causa do Flutter: o kit do Google para criar aplicativos de celular, computador e web com um código só. O Flutter é escrito em Dart, e um app Flutter é um programa Dart. Esta aula é uma visão geral: o que é o Flutter, como o Dart que você aprendeu aparece nele, e o caminho para começar. Não há Flutter no laboratório da Ana, então o código de Flutter desta página é ilustrativo (tirado da documentação oficial, docs.flutter.dev); o que roda de verdade é um "Flutter de mentira" em Dart puro, para você sentir a ideia.

Você vai aprender
  • O que é o Flutter e como ele se relaciona com o Dart.
  • O que é um widget e a árvore de widgets.
  • A diferença entre StatelessWidget e StatefulWidget, e o papel do setState.
  • O que é o hot reload e por que o Dart tem dois jeitos de compilar.
  • Quais aulas deste guia você mais vai usar no Flutter.

A ideia: blocos de montar

Pense numa tela de app como um brinquedo de blocos de montar. Um bloco é um texto; outro é um botão; outro é uma "caixa" que centraliza o que estiver dentro; outro empilha blocos um embaixo do outro. Você monta a tela encaixando blocos dentro de blocos. No Flutter, cada bloco se chama widget (em inglês, "componente", "coisinha"), e tudo é widget: o texto, o botão, o espaço entre eles, a tela inteira.

Os blocos encaixados formam uma árvore: a tela é a raiz; dentro dela, uma coluna; dentro da coluna, um título e um botão; dentro do botão, um texto.

void main() {

import 'package:flutter/material.dart';
Traz a biblioteca de widgets do Flutter no estilo Material (o visual do Google). É um import de pacote, como os da aula Pacotes do pub.dev.
void main()
O mesmo main de todo programa Dart: o app começa aqui.
runApp(…)
"Rode o app": pega o widget passado e o põe como raiz da árvore, ocupando a tela toda.
const Center(child: …)
Um widget que centraliza o filho. child: ("filho") é um parâmetro nomeado. O const diz que esse pedaço da tela nunca muda, e o Flutter pode reaproveitá-lo.
Text('Hello, world!', …)
Um widget de texto. O texto vem como parâmetro posicional; textDirection (direção: ltr, da esquerda para a direita) e style (estilo: cor azul) vêm nomeados.
as vírgulas no fim
Repare na vírgula depois de cada último parâmetro. Com ela, o dart format põe um parâmetro por linha, e a árvore fica com o formato de escada que você vê.

3. Um "Flutter de mentira" em Dart puro

Para ver a ideia da árvore funcionando, a Ana escreveu, em Dart puro, umas classes com os mesmos nomes de parâmetro do Flutter. Em vez de pintar uma tela, cada widget sabe se desenhar como texto:

// Um "Flutter de mentira", só para ver a ideia da árvore de widgets.
abstract class Widget {
  const Widget();
  String desenhar();
}

class Texto extends Widget {
  final String texto;
  const Texto(this.texto);

  @override
  String desenhar() => texto;
}

class Centro extends Widget {
  final Widget child;
  const Centro({required this.child});

  @override
  String desenhar() => '[ centro: ${child.desenhar()} ]';
}

class Coluna extends Widget {
  final List<Widget> children;
  const Coluna({required this.children});

  @override
  String desenhar() => children.map((w) => w.desenhar()).join('\n');
}

void runApp(Widget app) {
  print(app.desenhar());
}

void main() {
  runApp(
    const Coluna(
      children: [
        Texto('Padaria da Ana'),
        Centro(child: Texto('Pão francês: R\$ 0.75')),
      ],
    ),
  );
}

$ dart run arvore.dart
Padaria da Ana
[ centro: Pão francês: R$ 0.75 ]

Tudo ali é Dart que você já viu: uma classe abstrata (Widget), classes filhas com extends e @override, construtores const, parâmetros nomeados com required, uma lista de widgets (children, "filhos") e funções de seta (=>). O Flutter de verdade é isso em escala gigante: centenas de widgets prontos, e o "desenhar" pinta pixels na tela.

4. Widgets que mudam: StatefulWidget e setState

Os widgets do Flutter se dividem em dois tipos:

  • StatelessWidget ("sem estado"): só mostra o que recebeu do pai, guardado em campos final. Um título, um ícone.
  • StatefulWidget ("com estado"): tem um objeto State que lembra informações entre um desenho e outro. Um contador, um campo de texto, uma lista de tarefas.

Todo widget tem um método build ("construir"), que diz como ele é agora. Quando o dado muda, o widget chama setState ("defina o estado"): isso avisa o Flutter "mudou algo aqui", e o Flutter roda o build de novo para atualizar a tela. Este é o contador da documentação do Flutter (ilustrativo; os comentários em inglês foram tirados):

import 'package:flutter/material.dart';

class Counter extends StatefulWidget {
  const Counter({super.key});

  @override
  State<Counter> createState() => _CounterState();
}

class _CounterState extends State<Counter> {
  int _counter = 0;

  void _increment() {
    setState(() {
      _counter++;
    });
  }

  @override
  Widget build(BuildContext context) {
    return Row(
      mainAxisAlignment: MainAxisAlignment.center,
      children: <Widget>[
        ElevatedButton(onPressed: _increment, child: const Text('Increment')),
        const SizedBox(width: 16),
        Text('Count: $_counter'),
      ],
    );
  }
}

void main() {
  runApp(
    const MaterialApp(
      home: Scaffold(body: Center(child: Counter())),
    ),
  );
}
class Counter extends StatefulWidget
O widget "contador", do tipo com estado. Ele só cria o seu State em createState().
_CounterState
Onde mora o dado (_counter). O _ no começo do nome quer dizer privado: só este arquivo enxerga (veja Privacidade).
setState(() { _counter++; })
Recebe uma função anônima que muda o dado. Depois de rodá-la, o Flutter agenda um novo build.
onPressed: _increment
"Ao apertar": passa a função _increment (sem parênteses) para o botão chamar depois. É uma função usada como valor, um callback.
Text('Count: $_counter')
A interpolação de sempre: cada build mostra o valor atual.

O mesmo mecanismo, em Dart puro

// Um "setState de mentira": muda o dado e redesenha a tela.
class TelaContador {
  int _cliques = 0;

  void setState(void Function() mudanca) {
    mudanca();
    build();
  }

  void build() {
    print('Tela: Cliques: $_cliques');
  }

  void apertarBotao() {
    setState(() {
      _cliques++;
    });
  }
}

void main() {
  final tela = TelaContador();
  tela.build();
  tela.apertarBotao();
  tela.apertarBotao();
}

$ dart run contador.dart
Tela: Cliques: 0
Tela: Cliques: 1
Tela: Cliques: 2

O primeiro build desenha a tela com 0; cada aperto muda o dado dentro do setState, e o setState redesenha. No Flutter de verdade o redesenho não é imediato (fica agendado para o próximo quadro da tela), mas a ideia é a mesma.

5. Hot reload e os dois jeitos de compilar

Enquanto você programa um app, o comando flutter run deixa o app aberto no celular (ou no emulador). Você muda o código, salva, e em menos de um segundo a tela muda, sem perder o estado: o contador continua no número em que estava. Isso é o hot reload ("recarga a quente").

Ele é possível porque o Dart sabe compilar de dois jeitos (veja Compilando):

  • JIT (just-in-time, na hora) durante o desenvolvimento: o Dart consegue trocar pedaços do programa enquanto ele roda.
  • AOT (ahead-of-time, antes) para publicar: flutter build gera código de máquina, que abre rápido no celular de quem baixou.
Comando (ilustrativo)O que faz
flutter create meu_appCria um projeto de app (como o dart create).
flutter runRoda o app no aparelho ou emulador, com hot reload (tecla r).
flutter build apk / flutter build webGera o app final para Android / para a web.
flutter pub add pacoteO mesmo pub do Dart, dentro do Flutter.
flutter analyzeO mesmo analisador do dart analyze, com as regras do flutter_lints.

Quando dá errado

Mudou o dado e esqueceu o setState

É o erro mais comum de quem começa no Flutter: o número muda por dentro, mas a tela não. O Flutter não dá mensagem nenhuma; ele simplesmente não sabe que precisa redesenhar. A documentação avisa: "se você esquecer de chamar setState ao mudar o estado de um widget, o framework não saberá que ele mudou e talvez não chame o build()". No nosso Flutter de mentira:

class TelaContador {
  int _cliques = 0;

  void build() {
    print('Tela: Cliques: $_cliques');
  }

  void apertarBotao() {
    _cliques++;
  }
}

void main() {
  final tela = TelaContador();
  tela.build();
  tela.apertarBotao();
  tela.apertarBotao();
  print('(por dentro, _cliques vale ${tela._cliques})');
}

$ dart run esqueceu.dart
Tela: Cliques: 0
(por dentro, _cliques vale 2)

A "tela" ficou parada no 0, embora o dado valha 2. Como consertar: faça a mudança dentro do setState(() { … }).

Como você viu na seção 2, o dart run não conhece o pacote flutter (Couldn't resolve the package 'flutter') e termina com o código 254. Apps Flutter rodam com flutter run, de dentro da pasta do projeto.

Missão final: o botão de menos

Missão: a Ana pôs um botão "menos" no contador, mas a tela não atualiza quando ele é apertado. Conserte o apertarMenos do jeito do Flutter, para a saída terminar em Tela: Cliques: 1.

class TelaContador {
  int _cliques = 0;

  void setState(void Function() mudanca) {
    mudanca();
    build();
  }

  void build() {
    print('Tela: Cliques: $_cliques');
  }

  void apertarMais() {
    setState(() {
      _cliques++;
    });
  }

  void apertarMenos() {
    _cliques--;
  }
}

void main() {
  final tela = TelaContador();
  tela.build();
  tela.apertarMais();
  tela.apertarMais();
  tela.apertarMenos();
}

Resumo

  • O Flutter é um kit do Google, escrito em Dart, para fazer apps com tela (Android, iOS, web, Windows, macOS, Linux) com um código só. Instala-se à parte e traz o próprio Dart.
  • Tudo é widget, e os widgets se encaixam numa árvore (child:, children:); runApp põe a raiz na tela.
  • StatelessWidget só mostra; StatefulWidget lembra dados num State. Mude os dados dentro do setState para a tela se redesenhar com o build.
  • Hot reload usa a compilação JIT; o app final usa AOT (flutter build).
  • Classes, construtores const, parâmetros nomeados, funções anônimas, listas, null safety e async são o Dart que você mais vai usar no Flutter.
