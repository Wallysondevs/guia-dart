Dart assert

Quem escreve um programa faz várias suposições: "a porcentagem de desconto sempre vai de 0 a 100", "o estoque nunca fica negativo", "o cliente sempre paga pelo menos o preço". O assert (em inglês, "afirmar, garantir") escreve essas suposições no próprio código: se uma delas for falsa, o programa para e avisa onde. Ele tem uma particularidade que pega muita gente de surpresa: com o dart run normal, o assert não faz nada. Ele só vale quando você liga a opção --enable-asserts.

Você vai aprender
  • Como escrever assert(condição) e assert(condição, 'mensagem').
  • A diferença real entre dart run (o assert é ignorado) e dart run --enable-asserts (ele confere).
  • Como ler a mensagem Failed assertion: line 2 pos 10: ….
  • Como usar o assert no construtor de uma classe.
  • Quando usar assert e quando usar throw.

Todos os programas desta aula rodaram no Dart SDK 3.13.5 da máquina da Ana (usuária ana, computador notebook), uma vez com dart run arquivo.dart e outra com dart run --enable-asserts arquivo.dart, para você ver a diferença.

A ideia: a conferência do caixa no treinamento

Na primeira semana de trabalho na padaria, a gerente fica ao lado da Ana conferindo cada troco: "o troco nunca pode ser negativo; se for, alguma coisa está errada". Depois do treinamento, a gerente vai embora e a Ana trabalha sozinha: as conferências não acontecem mais, e o atendimento fica mais rápido.

O assert é essa gerente:

  • Enquanto você desenvolve e testa o programa, liga as conferências (--enable-asserts): qualquer suposição falsa para o programa na hora, apontando a linha.
  • Quando o programa está pronto, roda sem elas: o assert some, e não gasta nem um instante.

Por isso o assert serve para pegar enganos de quem programa, não para validar o que a pessoa digita (para isso existe o throw; veja Formas diferentes).

1. O primeiro assert

double aplicarDesconto(double preco, double porcentagem) {
  assert(porcentagem >= 0 && porcentagem <= 100);
  return preco - preco * porcentagem / 100;
}

void main() {
  print(aplicarDesconto(50, 10));
  print(aplicarDesconto(50, 150));
  print('Fim');
}
assert( … );
A conferência. Entre os parênteses vai uma condição (algo que dá true ou false, como no if): a suposição que tem de ser verdadeira.
porcentagem >= 0 && porcentagem <= 100
"A porcentagem está entre 0 e 100". Um desconto de 150% faria o preço ficar negativo: não faz sentido.
aplicarDesconto(50, 150)
Um engano de propósito: quem chamou a função passou 150.

Rodando do jeito normal: o assert é ignorado

Fim
$ echo $?

O desconto de 150% passou sem nenhum aviso, e o preço virou -25.0. O programa terminou "bem" (código 0). Com o dart run simples, a linha do assert é pulada inteira.

A posição da opção importa

Escrita depois do nome do arquivo, a opção não liga nada: ela vira um argumento para o seu programa (veja Argumentos da Linha de Comando). Com a versão do programa que tem mensagem (seção 2):

$ dart run desconto2.dart --enable-asserts
45.0
-25.0

O desconto de 150% passou de novo. O certo é dart run --enable-asserts desconto2.dart. Também funciona sem o run: dart --enable-asserts desconto2.dart.

2. Uma mensagem para o assert

O assert aceita um segundo valor, separado por vírgula: a mensagem que aparece quando a conferência falha. Ela pode ter interpolação, para mostrar o valor que veio:

double aplicarDesconto(double preco, double porcentagem) {
  assert(porcentagem >= 0 && porcentagem <= 100,
      'porcentagem tem de ser de 0 a 100, veio $porcentagem');
  return preco - preco * porcentagem / 100;
}

void main() {
  print(aplicarDesconto(50, 10));
  print(aplicarDesconto(50, 150));
}

3. assert no construtor

Um lugar clássico para o assert é o construtor de uma classe: ele confere os valores antes de o objeto existir. Vai na lista de inicialização, depois dos dois-pontos (veja Construtores):

class Produto {
  final String nome;
  final int estoque;

  Produto(this.nome, this.estoque)
      : assert(nome.isNotEmpty, 'nome vazio'),
        assert(estoque >= 0, 'estoque negativo: $estoque');
}

void main() {
  final p = Produto('pão', 30);
  print('${p.nome}: ${p.estoque}');
  final q = Produto('bolo', -2);
  print('${q.nome}: ${q.estoque}');
}

$ dart run ponto.dart
pão: 30
bolo: -2
$ dart run --enable-asserts ponto.dart
pão: 30
Unhandled exception:
'file:///home/ana/ponto.dart': Failed assertion: line 7 pos 16: 'estoque >= 0': estoque negativo: -2
#0      _AssertionError._doThrowNew (dart:core-patch/errors_patch.dart:67:4)
#1      _AssertionError._throwNew (dart:core-patch/errors_patch.dart:49:5)
#2      new Produto (file:///home/ana/ponto.dart:7:16)
#3      main (file:///home/ana/ponto.dart:13:13)
#4      _delayEntrypointInvocation.<anonymous closure> (dart:isolate-patch/isolate_patch.dart:313:19)

De novo os dois mundos: sem a opção, nasceu um bolo com estoque -2; com a opção, o construtor (new Produto, no stack trace) recusou na linha 7, e o #3 main (…:13:13) mostra quem tentou criar o bolo errado. Vários assert separados por vírgula são conferidos em ordem.

4. Mais dois detalhes

O assert lança um AssertionError

void main() {
  try {
    assert(1 + 1 == 3, 'a conta está errada');
    print('passou');
  } on AssertionError catch (e) {
    print('Tipo: ${e.runtimeType}');
    print('Mensagem: ${e.message}');
  }
}

$ dart run pega.dart
passou
$ dart run --enable-asserts pega.dart
Tipo: _AssertionError
Mensagem: a conta está errada

Dá para pegar com on AssertionError, mas quase nunca se faz isso: é um Error, sinal de engano no código, e o certo é consertar o código (veja a dica sobre Exception e Error em Exceções). E repare na primeira execução: sem a opção, até 1 + 1 == 3 "passou".

O que está dentro do assert nem roda

var contador = 0;

bool contar() {
  contador++;
  return true;
}

void main() {
  assert(contar());
  print('contador = $contador');
}

$ dart run lado.dart
contador = 0
$ dart run --enable-asserts lado.dart
contador = 1

Sem a opção, a função contar() nem foi chamada. Por isso, nunca coloque dentro de um assert algo que o programa precisa que aconteça (somar, salvar, ler): só conferências.

Formas diferentes de fazer a mesma coisa

A conferência do troco pode ser escrita com assert ou com throw (veja throw):

int calcularTroco(int pago, int preco) {
  assert(pago >= preco, 'pagou $pago, mas custa $preco');
  return pago - preco;
}

void main() {
  print('Troco: ${calcularTroco(20, 12)}');
  print('Troco: ${calcularTroco(10, 12)}');
}

$ dart run troco.dart
Troco: 8
Troco: -2
$ dart run --enable-asserts troco.dart
Troco: 8
Unhandled exception:
'file:///home/ana/troco.dart': Failed assertion: line 2 pos 10: 'pago >= preco': pagou 10, mas custa 12
#0      _AssertionError._doThrowNew (dart:core-patch/errors_patch.dart:67:4)
#1      _AssertionError._throwNew (dart:core-patch/errors_patch.dart:49:5)
#2      calcularTroco (file:///home/ana/troco.dart:2:10)
#3      main (file:///home/ana/troco.dart:8:19)
#4      _delayEntrypointInvocation.<anonymous closure> (dart:isolate-patch/isolate_patch.dart:313:19)
#5      _RawReceivePort._handleMessage (dart:isolate-patch/isolate_patch.dart:192:12)

Com if (pago < preco) throw ArgumentError('…'); no lugar do assert, a recusa aconteceria sempre, com ou sem a opção. Qual escolher?

SituaçãoQual usar
Uma suposição do seu código, que só falha se você errou (a função interna que nunca deveria receber 150%)assert: confere enquanto você desenvolve, some no programa pronto
Um valor que vem de fora: o que a pessoa digitou, um arquivo, a internetthrow (ou int.tryParse e if): tem de conferir sempre
Uma função que outras pessoas vão usar (uma biblioteca)throw ArgumentError: quem chama vê a recusa mesmo sem --enable-asserts
Conferir os valores ao criar um objeto, durante o desenvolvimentoassert na lista de inicialização do construtor

Quando dá errado

O assert "não funciona"

O erro mais comum nem tem mensagem: você escreve o assert, passa um valor errado de propósito, e nada acontece. É o que você viu na seção 1: com dart run arquivo.dart, os assert são ignorados. Como consertar: rode com dart run --enable-asserts arquivo.dart (a opção antes do nome do arquivo).

Esqueceu os parênteses 
void main() {
  final nota = 11;
  assert nota <= 10;
  print(nota);
}

$ dart run a1.dart
a1.dart:3:10: Error: Expected '(' before this.
  assert nota <= 10;
         ^^^^
a1.dart:3:3: Error: Expected ';' after this.
  assert nota <= 10;
  ^^^^^^

"Era esperado ( antes disto", apontando o nota. A segunda mensagem é consequência da primeira. Diferente do assert falso, este é um erro de compilação: aparece com ou sem --enable-asserts, e nada roda. Como consertar: assert(nota <= 10);.

A condição não é bool 
void main() {
  final nome = 'Ana';
  assert(nome, 'nome vazio');
  print(nome);
}

$ dart run a2.dart
a2.dart:3:10: Error: A value of type 'String' can't be assigned to a variable of type 'bool'.
  assert(nome, 'nome vazio');
         ^

"Um valor do tipo String não pode ser usado onde se espera bool". O primeiro valor do assert tem de ser true ou false; um texto não serve (o Dart não tem "texto vazio é falso", como outras linguagens). Como consertar: escreva a pergunta inteira: assert(nome.isNotEmpty, 'nome vazio');.

Missão final: o troco errado

Missão: a cliente pagou 15 reais por uma compra de 12, mas alguém digitou 10 no código, e o troco saiu negativo. Rodando com --enable-asserts, o assert pararia o programa na hora; sem a opção, o -2 passa calado. Conserte o engano na chamada (não apague o assert) até aparecer Troco: 3.

int calcularTroco(int pago, int preco) {
  assert(pago >= preco, 'pagou $pago, mas custa $preco');
  return pago - preco;
}

void main() {
  print('Troco: ${calcularTroco(20, 12)}');
  print('Troco: ${calcularTroco(10, 12)}');
}

int calcularTroco(int pago, int preco) {
  assert(pago >= preco, 'pagou $pago, mas custa $preco');
  return pago - preco;
}

void main() {
  print('Troco: ${calcularTroco(20, 12)}');
  print('Troco: ${calcularTroco(15, 12)}');
}

Resumo

  • assert(condição, 'mensagem') escreve uma suposição no código; se ela for falsa, lança AssertionError com Failed assertion: line L pos C: 'condição': mensagem.
  • Com dart run arquivo.dart, os assert são ignorados, e nem a condição roda. Só valem com dart run --enable-asserts arquivo.dart (a opção antes do arquivo).
  • Use assert para enganos de programação, enquanto desenvolve; use throw para o que vem de fora e tem de ser conferido sempre.
  • No construtor, o assert vai na lista de inicialização, depois dos dois-pontos.
  • Nunca ponha dentro do assert algo que o programa precisa que aconteça.
