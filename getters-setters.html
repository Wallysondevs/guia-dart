Dart get e set

Um item do carrinho tem preço e quantidade. E o total do item? Dá para guardar num campo, mas aí, se a quantidade mudar, alguém precisa lembrar de atualizar o total. O Dart oferece algo melhor: um getter (de get, "pegar"), que parece um campo para quem usa (item.total), mas é calculado na hora, toda vez. E o seu par, o setter (de set, "definir"), parece uma atribuição comum (t.celsius = 25), mas roda código: por exemplo, para recusar um valor impossível.

Você vai aprender
  • Como escrever um getter: double get total => preco * quantidade; e como usá-lo (sem parênteses).
  • Getters com corpo e getters que usam outros getters.
  • Como escrever um setter que confere o valor antes de guardar.
  • Que todo campo já vem com um getter e um setter "invisíveis", e o que isso explica nas mensagens de erro.
  • Quando usar getter e quando usar método.
  • Os erros reais, incluindo o setter que chama a si mesmo para sempre.

Todos os programas desta aula rodaram no Dart 3.13.5 da máquina da Ana (usuária ana, computador notebook), com dart run arquivo.dart.

A ideia: o visor da balança e o porteiro

Na balança da padaria, o visor mostra o preço a pagar. Ninguém digita esse número: a balança calcula na hora, peso vezes preço do quilo. Põe mais pão, o visor muda sozinho. Isso é um getter: você "lê" um valor que, por trás, é uma conta.

Na portaria do prédio da Ana, quem chega não entra direto: o porteiro confere antes. Se estiver tudo certo, deixa entrar; se não, barra. Isso é um setter: você "guarda" um valor, e por trás um código decide se aceita.

1. O primeiro getter

class ItemDoCarrinho {
  final String nome;
  final double preco;
  final int quantidade;

  ItemDoCarrinho(this.nome, this.preco, this.quantidade);

  double get total => preco * quantidade;
}

void main() {
  final cafe = ItemDoCarrinho('café', 18.9, 3);
  print('${cafe.nome}: ${cafe.quantidade} x ${cafe.preco}');
  print('Total: ${cafe.total.toStringAsFixed(2)}');
}
double
O tipo do valor que o getter devolve.
get
A palavra que faz disto um getter.
total
O nome, como o de um campo. Sem parênteses: getter não recebe parâmetros.
=> preco * quantidade;
A conta, numa linha só, com a seta (veja Funções de Uma Linha). Ela roda toda vez que alguém lê total.
cafe.total
Para quem usa, é igual a ler um campo: sem parênteses.
$ dart run getter.dart
café: 3 x 18.9
Total: 56.70

O valor se recalcula sozinho

Como o getter faz a conta na hora, ele acompanha as mudanças dos campos. A meta do cofrinho é R$ 100:

class Cofrinho {
  double saldo = 0;
  double get faltaParaMeta => 100 - saldo;
}

void main() {
  final c = Cofrinho();
  print('Falta: ${c.faltaParaMeta}');
  c.saldo = 30;
  print('Falta: ${c.faltaParaMeta}');
  c.saldo = 75.5;
  print('Falta: ${c.faltaParaMeta}');
}

$ dart run atualiza.dart
Falta: 100.0
Falta: 70.0
Falta: 24.5

Ninguém atualizou faltaParaMeta: ela não está guardada em lugar nenhum. Se fosse um campo comum, alguém teria de lembrar de mudá-la a cada depósito, e um dia esqueceria.

Getter com corpo, e getters que usam getters

Quando a conta não cabe numa linha, o getter pode ter um corpo com { } e return, como uma função:

class Aluno {
  final String nome;
  final List<double> notas;

  Aluno(this.nome, this.notas);

  double get media {
    var soma = 0.0;
    for (final n in notas) {
      soma += n;
    }
    return soma / notas.length;
  }

  bool get aprovado => media >= 7;

  String get situacao => aprovado ? 'aprovado' : 'recuperação';
}

void main() {
  final bia = Aluno('Bia', [8.0, 6.5, 9.0]);
  final caio = Aluno('Caio', [5.0, 6.0, 7.5]);
  for (final a in [bia, caio]) {
    print('${a.nome}: média ${a.media.toStringAsFixed(1)}, ${a.situacao}');
  }
}

$ dart run getters.dart
Bia: média 7.8, aprovado
Caio: média 6.2, recuperação

situacao usa aprovado, que usa media, que usa notas. Cada um é pequeno e tem um nome que diz o que é. Getters do tipo bool costumam ter nome de pergunta ou de adjetivo (aprovado, vazio, estaPago).

2. O setter: conferir antes de guardar

Um termômetro não pode marcar menos de −273,15 °C (o "zero absoluto", a temperatura mais fria que existe). Com um campo comum, qualquer um poderia escrever t.celsius = -300. Com um setter, a classe confere:

class Termometro {
  double _celsius = 0;

  double get celsius => _celsius;

  set celsius(double valor) {
    if (valor < -273.15) {
      throw ArgumentError('abaixo do zero absoluto: $valor');
    }
    _celsius = valor;
  }

  double get fahrenheit => _celsius * 9 / 5 + 32;

  set fahrenheit(double valor) {
    celsius = (valor - 32) * 5 / 9;
  }
}

void main() {
  final t = Termometro();
  t.celsius = 25;
  print('${t.celsius} °C = ${t.fahrenheit} °F');
  t.fahrenheit = 212;
  print('${t.celsius} °C = ${t.fahrenheit} °F');
  t.celsius = -300;
  print('não chega aqui');
}
double _celsius = 0;
O campo que guarda o valor de verdade. O _ no começo do nome o deixa privado: fora deste arquivo, ninguém mexe nele direto, só pelo getter e pelo setter (os detalhes estão na próxima aula, Privacidade).
double get celsius => _celsius;
O getter só devolve o campo.
set celsius(double valor) { … }
O setter: a palavra set, o nome e exatamente um parâmetro, o valor que está chegando. Não se escreve tipo de retorno.
if (valor < -273.15) { throw … }
O porteiro: valor impossível é recusado com uma exceção (veja Lançando Exceções).
_celsius = valor;
Valor aceito: vai para o campo.
set fahrenheit(…) { celsius = …; }
Um setter pode usar outro: este converte e passa pelo setter celsius, que confere.
t.celsius = 25;
Para quem usa, é uma atribuição comum. Por trás, roda o setter.

3. Todo campo já tem getter e setter

Agora dá para entender umas mensagens das aulas anteriores. Quando você escreve um campo comum, como double saldo = 0;, o Dart cria sozinho, sem você ver:

  • um getter saldo, usado em c.saldo;
  • um setter saldo=, usado em c.saldo = 30.

Um campo final só ganha o getter. Por isso tentar mudá-lo dá The setter 'preco' isn't defined (veja Construtores). E um getter escrito por você, sem setter, também é só de leitura.

A boa notícia: quem usa a classe não vê diferença entre um campo e um getter. Você pode começar com um campo comum e, mais tarde, trocá-lo por getter e setter (para conferir valores), sem mudar uma linha do código que usa a classe.

Não escreva getter e setter "de enfeite"

Em algumas linguagens, é costume escrever getNome() e setNome() para todo campo. No Dart, não: o estilo oficial pede um campo comum quando o getter e o setter só leriam e gravariam o valor. Escreva get/set só quando houver algo a calcular ou a conferir.

Getter ou método?

Um getter e um método sem parâmetros fazem quase a mesma coisa. Compare:

class ItemDoCarrinho {
  final double preco;
  final int quantidade;
  ItemDoCarrinho(this.preco, this.quantidade);

  double get total => preco * quantidade;
  double totalComDesconto(double porcento) => total * (1 - porcento / 100);
}

void main() {
  final item = ItemDoCarrinho(20, 3);
  print(item.total);
  print(item.totalComDesconto(10));
}

$ dart run metodo.dart
60.0
54.0
SituaçãoQual usar
Uma característica do objeto, calculada dos campos, rápida e sem efeitos (total, média, idade, está vazio?)Getter: item.total
Precisa de parâmetrosMétodo: item.totalComDesconto(10) (getter não recebe parâmetros)
Uma ação, que muda algo ou demora (vender, salvar, imprimir, baixar)Método: conta.depositar(50)
Guardar um valor, mas conferir antesSetter (com um campo privado por trás)
Só guardar e ler, sem conta e sem conferênciaCampo comum

Missão final: a nota que não passa de 10

Missão: complete a classe Nota com o setter set valor(double v): se v for menor que 0 ou maior que 10, lance ArgumentError('nota inválida'); se não, guarde em _valor. O main guarda 8.5 (deve mostrar Nota: 8.5) e depois 15 (deve parar com o erro).

class Nota {
  double _valor = 0;

  double get valor => _valor;

  // escreva o setter valor aqui
}

void main() {
  final n = Nota();
  n.valor = 8.5;
  print('Nota: ${n.valor}');
  n.valor = 15;
  print('Nota: ${n.valor}');
}

class Nota {
  double _valor = 0;

  double get valor => _valor;

  set valor(double v) {
    if (v < 0 || v > 10) {
      throw ArgumentError('nota inválida');
    }
    _valor = v;
  }
}

void main() {
  final n = Nota();
  n.valor = 8.5;
  print('Nota: ${n.valor}');
  n.valor = 15;
  print('Nota: ${n.valor}');
}

Resumo

  • Um getter (tipo get nome => …;) parece um campo, mas é calculado toda vez que é lido. Usa-se sem parênteses.
  • Um setter (set nome(tipo v) { … }) parece uma atribuição, mas roda código: ótimo para conferir valores. Tem exatamente um parâmetro.
  • O valor de verdade fica num campo privado (_nome); dentro do setter, guarde nele, nunca em nome, ou o setter chama a si mesmo até o Stack Overflow.
  • Todo campo já tem getter e setter automáticos; final e getter sem setter são só de leitura.
  • Característica calculada: getter. Com parâmetros ou ação: método. Só guardar: campo comum.
  • Próxima aula: Privacidade (_), o que o sublinhado no começo do nome realmente faz.
