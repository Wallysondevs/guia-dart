Dart throw

Na aula Exceções, quem lançava as exceções era o próprio Dart: o int.parse com um texto que não é número, a lista sem a posição pedida. Agora é a sua vez. Com o throw (em inglês, "lançar, arremessar") a sua função avisa: "não dá para fazer o que você me pediu". Quem chamou a função decide o que fazer com o aviso, com o try/catch que você já conhece.

Você vai aprender
  • Por que uma função deve lançar uma exceção em vez de só mostrar uma mensagem.
  • Como escrever throw Exception('…'), throw ArgumentError('…') e throw StateError('…'), e qual escolher.
  • Como o throw interrompe a função na hora, e como quem chamou pega o aviso com on.
  • Como usar o throw no meio de uma expressão: ?? (throw …).
  • Como pegar, anotar e repassar a mesma exceção com rethrow.

Todos os programas desta aula rodaram no Dart SDK 3.13.5 da máquina da Ana (usuária ana, computador notebook), com dart run arquivo.dart.

A ideia: o caixa eletrônico que recusa o saque

Você pede R$ 500 no caixa eletrônico e só tem R$ 70 na conta. O caixa não entrega R$ 70 fingindo que está tudo bem, nem trava a máquina: ele recusa e diz o motivo, "Saldo insuficiente". O que fazer com a recusa é com você: pedir menos, ir embora, ligar para o banco.

Uma função sua deve agir igual. Uma função sacar(valor) não sabe se está num programa de terminal, num aplicativo de celular ou num site; ela não deveria decidir sozinha o que mostrar na tela. Ela só deve recusar o pedido impossível, com um motivo claro. Isso é lançar uma exceção:

  • throw interrompe a função na hora: as linhas seguintes dela não rodam.
  • A exceção "sobe" para quem chamou a função. Se lá tiver um try/catch, ele a pega. Se não tiver, ela continua subindo até o main, e o programa termina com Unhandled exception:.

1. O primeiro throw

var saldo = 100;

void sacar(int valor) {
  if (valor <= 0) {
    throw ArgumentError('O valor tem de ser maior que zero: $valor');
  }
  if (valor > saldo) {
    throw Exception('Saldo insuficiente: pediu $valor, tem $saldo');
  }
  saldo -= valor;
  print('Saque de $valor. Saldo: $saldo');
}

void main() {
  sacar(30);
  sacar(500);
  print('Fim');
}
if (valor > saldo)
A função confere se o pedido é possível antes de mexer no saldo.
throw
"Lance". A palavra-chave que dispara a exceção. Depois dela vem o objeto que vai ser lançado.
Exception('Saldo insuficiente: …')
Cria uma exceção comum, com a mensagem entre parênteses. Exception é o tipo mais simples de exceção do Dart. Os parênteses são obrigatórios: eles criam o objeto (veja Quando dá errado).
ArgumentError('…')
Outro tipo, para quando o argumento (o valor que veio entre parênteses na chamada) não presta: um saque de valor zero ou negativo.
saldo -= valor;
Só chega aqui quem passou pelos dois testes. Se um throw rodou, a função parou antes.

Quem chama, decide

Agora o main faz vários pedidos e trata cada recusa. A função sacar não mudou nada:

void main() {
  for (final pedido in [30, 500, -5, 70]) {
    try {
      sacar(pedido);
    } on ArgumentError catch (e) {
      print('Pedido recusado: ${e.message}');
    } on Exception catch (e) {
      print('Não deu: $e');
    }
  }
  print('Saldo final: $saldo');
}

$ dart run sacar2.dart
Saque de 30. Saldo: 70
Não deu: Exception: Saldo insuficiente: pediu 500, tem 70
Pedido recusado: O valor tem de ser maior que zero: -5
Saque de 70. Saldo: 0
Saldo final: 0

(O saldo e a função sacar são os mesmos de sacar.dart; no arquivo, eles vêm antes do main.) O -5 caiu no on ArgumentError e o 500 caiu no on Exception: cada tipo de recusa recebeu o tratamento certo. Nenhum pedido ruim mexeu no saldo, porque o throw parou a função antes do saldo -= valor.

Missão: a função registrarNota aceita qualquer número, até 15. Faça ela lançar um ArgumentError quando a nota for menor que 0 ou maior que 10 (if (nota < 0 || nota > 10) { throw ArgumentError('…'); }). O main já está pronto para pegar e mostrar Nota inválida.

void registrarNota(int nota) {
  print('Nota registrada: $nota');
}

void main() {
  for (final nota in [8, 15]) {
    try {
      registrarNota(nota);
    } on ArgumentError catch (e) {
      print('Nota inválida: ${e.message}');
    }
  }
}

void registrarNota(int nota) {
  if (nota < 0 || nota > 10) {
    throw ArgumentError('a nota tem de ser de 0 a 10, veio $nota');
  }

No lab, a solução mostrou Nota registrada: 8 e Nota inválida: a nota tem de ser de 0 a 10, veio 15.

2. Qual tipo lançar?

O Dart já vem com vários tipos prontos. A Ana lançou e pegou um de cada num programa de teste; o $e (a mensagem) e o e.runtimeType (o tipo) de cada um saíram assim:

O que foi lançadoTipoO que o print('$e') mostrouUse quando…
throw Exception('caixa fechado')_ExceptionException: caixa fechadoUm problema esperado, sem tipo melhor
throw FormatException('CPF com letras', 'abc.123')FormatExceptionFormatException: CPF com letras e, na linha de baixo, abc.123Um texto fora do formato (o segundo valor é o texto que veio)
throw ArgumentError.value(-3, 'quantidade', 'não pode ser negativa')ArgumentErrorInvalid argument (quantidade): não pode ser negativa: -3O argumento recebido não presta
throw RangeError.range(15, 0, 10, 'nota')RangeErrorRangeError (nota): Invalid value: Not in inclusive range 0..10: 15Um número fora da faixa permitida
throw StateError('o pedido já foi entregue')StateErrorBad state: o pedido já foi entregueO pedido até é válido, mas não agora (o estado das coisas não deixa)
throw UnimplementedError('ainda não fiz o desconto')UnimplementedErrorUnimplementedError: ainda não fiz o descontoUma parte do programa que você ainda não escreveu
throw 'um texto qualquer'Stringum texto qualquerNunca: funciona, mas ninguém consegue pegar com um on que faça sentido
  • O tipo de Exception('…') aparece como _Exception, com sublinhado: é a versão "por dentro" do Dart. Para pegar, escreva on Exception mesmo.
  • ArgumentError.value e RangeError.range são construtores nomeados (veja Construtores Nomeados): jeitos prontos de montar uma mensagem completa, com o nome e o valor.
  • Lembre da regra da aula anterior: …Exception é problema que vem de fora e merece tratamento; …Error é sinal de engano de quem chamou a função. Na aula Exceções Próprias, você cria os seus próprios tipos, como SaldoInsuficienteException.

3. throw no meio de uma expressão

O throw também funciona no lugar de um valor. Isso combina com o ?? ("se for nulo, use o outro"): "converta; se não der, lance":

int lerQuantidade(String texto) =>
    int.tryParse(texto) ?? (throw FormatException('Quantidade inválida', texto));

void main() {
  print(lerQuantidade('3'));
  print(lerQuantidade('três'));
}

$ dart run expr.dart
3

três

#2      _delayEntrypointInvocation.<anonymous closure> (dart:isolate-patch/isolate_patch.dart:313:19)

O int.tryParse('3') deu 3, então o ?? nem olhou para o lado direito. O int.tryParse('três') deu null, então o ?? usou o lado direito, e o lado direito era um throw. Os parênteses em volta do throw são necessários. A função é de uma linha só (=>; veja Funções de Uma Linha).

4. rethrow: anotar e passar adiante

Às vezes você quer saber que a exceção passou por ali (para anotar num registro), mas não é você quem deve tratá-la. O rethrow ("lance de novo") só existe dentro de um catch/on: ele lança a mesma exceção de novo, para cima, com o stack trace original:

int converter(String texto) {
  try {
    return int.parse(texto);
  } on FormatException {
    print('[registro] falhou ao converter "$texto"');
    rethrow;
  }
}

void main() {
  try {
    print(converter('8'));
    print(converter('oito'));
  } on FormatException catch (e) {
    print('No main: ${e.message} -> ${e.source}');
  }
}

$ dart run rethrow.dart
8
[registro] falhou ao converter "oito"
No main: Invalid radix-10 number -> oito

A exceção passou por dois lugares: o on do converter anotou o registro e a repassou; o on do main a pegou de vez. O e.source de uma FormatException é o texto que não deu para converter.

Formas diferentes de fazer a mesma coisa

Uma função que recebe um pedido impossível pode reagir de três jeitos:

JeitoExemploQuando faz sentido
Lançar uma exceçãothrow StateError('Estoque insuficiente')O pedido é impossível e quem chamou precisa saber. É o padrão.
Devolver nullint? buscar(…) devolve null se não achar"Não achei" é um resultado normal, não um problema (como o int.tryParse)
Devolver true/falsebool sacar(…)Só importa se deu certo ou não, sem motivo
Só dar print do problemaprint('Saldo insuficiente'); return;Evite: quem chamou acha que deu certo, e a mensagem vai para a tela mesmo onde não há tela

Quando dá errado

Criou a exceção, mas esqueceu o throw 
void sacar(int valor) {
  if (valor <= 0) {
    Exception('Valor inválido: $valor');
  }
  print('Saque de $valor');
}

void main() {
  sacar(-5);
}

$ dart run r2.dart
Saque de -5

Nenhuma mensagem de erro, e esse é o problema: Exception('…') sem o throw só cria o objeto e o joga fora. O saque de -5 passou. Como consertar: throw Exception('Valor inválido: $valor');.

Esqueceu os parênteses: lançou o tipo, não uma exceção 
void main() {
  throw Exception;
}

Parece que funcionou, mas repare: não tem o Exception: com mensagem. Sem parênteses, Exception é o nome do tipo, e foi esse nome que foi lançado, não uma exceção. Um on Exception não pega isso. Como consertar: throw Exception('o motivo');.

rethrow fora de um catch 
void sacar(int valor) {
  if (valor <= 0) {
    rethrow;
  }
  print('Saque de $valor');
}

void main() {
  sacar(-5);
}

$ dart run r1.dart
r1.dart:3:5: Error: 'rethrow' can only be used in catch clauses.
    rethrow;
    ^^^^^^^

"O rethrow só pode ser usado dentro de um catch". Ele lança de novo uma exceção que foi pega; aqui não havia nenhuma. Como consertar: para uma exceção nova, use throw ArgumentError('…').

Lançar um valor que pode ser nulo 
void main() {
  String? nome;
  throw nome;
}

$ dart run r3.dart
r3.dart:3:9: Error: Can't throw a value of 'String?' since it is neither dynamic nor non-nullable.
  throw nome;
        ^

"Não dá para lançar um valor do tipo String?, porque ele não é dynamic nem não-anulável". O throw precisa de um objeto de verdade, nunca null (veja Tipos Anuláveis). Como consertar: lance uma exceção: throw StateError('nome vazio').

Uma função que nem sempre devolve um valor 
int dobro(int n) {
  if (n < 0) {
    throw ArgumentError('negativo');
  }
}

void main() {
  print(dobro(2));
}

$ dart run r5.dart
r5.dart:1:5: Error: A non-null value must be returned since the return type 'int' doesn't allow null.
int dobro(int n) {
    ^

"Um valor não nulo tem de ser devolvido, porque o tipo de retorno int não aceita null". O throw cuidou do caminho ruim, mas o caminho bom ficou sem return. Como consertar: acrescente return n * 2; depois do if.

Missão final: o estoque que não fica negativo

Missão: o estoque da lojinha começa com 10. Hoje o pedido de 8 deixa o estoque negativo. Na função retirar, antes de mexer no estoque, lance um StateError('Estoque insuficiente: tem $estoque') quando qtd for maior que o estoque. O main já pega o StateError. No fim deve aparecer Sobrou: 2.

var estoque = 10;

void retirar(int qtd) {
  // escreva o throw aqui
  estoque -= qtd;
  print('Retirou $qtd. Sobrou: $estoque');
}

void main() {
  for (final pedido in [5, 8, 3]) {
    try {
      retirar(pedido);
    } on StateError catch (e) {
      print('Pedido de $pedido recusado: ${e.message}');
    }
  }
}

var estoque = 10;

void retirar(int qtd) {
  if (qtd > estoque) {
    throw StateError('Estoque insuficiente: tem $estoque');
  }
  estoque -= qtd;
  print('Retirou $qtd. Sobrou: $estoque');
}

void main() {
  for (final pedido in [5, 8, 3]) {
    try {
      retirar(pedido);
    } on StateError catch (e) {
      print('Pedido de $pedido recusado: ${e.message}');
    }
  }
}

No lab, a solução mostrou:

$ dart run estoque.dart
Retirou 5. Sobrou: 5
Pedido de 8 recusado: Estoque insuficiente: tem 5
Retirou 3. Sobrou: 2

Resumo

  • throw objeto lança uma exceção: a função para na hora e a exceção sobe até alguém pegá-la (ou até o programa terminar com código 255).
  • Use o tipo que descreve o problema: ArgumentError (argumento ruim), RangeError (fora da faixa), StateError (não dá agora), FormatException (texto fora do formato), Exception (o resto).
  • Sempre com parênteses e mensagem: throw Exception('motivo'). Não lance textos soltos nem null.
  • A função recusa; quem chama decide o que fazer, com try e on.
  • throw também é expressão: valor ?? (throw …).
  • rethrow, só dentro de um catch, repassa a mesma exceção para cima.
