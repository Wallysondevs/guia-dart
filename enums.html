Dart Enums

O açaí da lojinha vem em três tamanhos: pequeno, médio e grande. Não existe "médio e meio", nem "gigante". Se o programa guardasse o tamanho num texto ('medio'), nada impediria alguém de digitar 'médio', 'Medio' ou 'mdeio', e o erro só apareceria quando o cliente fosse cobrado errado. Para uma lista fechada de opções, o Dart tem o enum (de enumeration, "enumeração", "lista numerada").

Você vai aprender
  • Como declarar um enum e usar os seus valores: Tamanho.medio.
  • O que são name, index, values e byName.
  • Como o switch confere se você tratou todas as opções.
  • Como fazer um enum melhorado: cada opção com os seus dados (mililitros, preço), construtor const, getters e métodos.
  • Os erros reais: switch incompleto, opção que não existe, campo que não é final, tentar criar um enum, e o byName com nome errado.

Todos os programas desta aula rodaram no Dart 3.13.5 da máquina da Ana (usuária ana, computador notebook), com dart run arquivo.dart.

A ideia: o cardápio com botões

Pense na maquininha de pedidos do açaí. Em vez de um campo onde o cliente escreve o tamanho, ela tem três botões: P, M e G. O cliente não consegue pedir um tamanho que não existe, porque não há botão para ele. E quem programou a maquininha sabe exatamente quais casos tratar: três, nem mais, nem menos.

O enum é esse conjunto de botões: um tipo novo cujos valores possíveis são só os que você listou.

1. O primeiro enum

enum Tamanho { pequeno, medio, grande }

void main() {
  final pedido = Tamanho.medio;
  print(pedido);
  print(pedido.name);
  print(pedido.index);
  print(pedido == Tamanho.medio);
  print(pedido == Tamanho.grande);
}
enum Tamanho { … }
Cria o tipo Tamanho. Como classes, enums têm nome em UpperCamelCase e ficam fora do main.
pequeno, medio, grande
Os valores possíveis, separados por vírgula, em lowerCamelCase e sem acento (são nomes de código, como variáveis).
Tamanho.medio
Um valor do enum: o nome do tipo, um ponto, o nome da opção. A variável pedido é do tipo Tamanho.
pedido.name
O nome da opção, como texto: 'medio'.
pedido.index
A posição na lista, começando do 0: pequeno é 0, medio é 1, grande é 2.
pedido == Tamanho.medio
Valores de enum se comparam com ==.
$ dart run tamanho.dart
Tamanho.medio
medio
1
true
false

Repare na diferença entre a primeira e a segunda linha: print(pedido) mostra Tamanho.medio (o tipo junto); pedido.name mostra só medio. Para mostrar ao cliente, use o name (ou um texto próprio, como na seção 4).

2. Todas as opções: values e byName

enum Tamanho { pequeno, medio, grande }

void main() {
  print(Tamanho.values);
  print('Temos ${Tamanho.values.length} tamanhos:');
  for (final t in Tamanho.values) {
    print('${t.index} - ${t.name}');
  }
  final digitado = 'grande';
  final escolhido = Tamanho.values.byName(digitado);
  print('Você escolheu: $escolhido');
}

$ dart run values.dart
[Tamanho.pequeno, Tamanho.medio, Tamanho.grande]
Temos 3 tamanhos:
0 - pequeno
1 - medio
2 - grande
Você escolheu: Tamanho.grande
Tamanho.values
Uma lista com todas as opções, na ordem em que foram declaradas. Serve para montar um menu, percorrer com for-in, contar com .length.
Tamanho.values.byName('grande')
O caminho de volta: do texto para a opção. Útil quando o tamanho vem do teclado ou de um arquivo. Se o texto não for o nome de nenhuma opção, dá exceção (veja Quando dá errado).

3. Enum e switch: o Dart confere se faltou algum caso

O melhor amigo do enum é o switch (veja switch e Expressões switch). Como o Dart conhece todas as opções, ele confere se você tratou cada uma:

enum Tamanho { pequeno, medio, grande }

double preco(Tamanho t) {
  return switch (t) {
    Tamanho.pequeno => 5.0,
    Tamanho.medio => 7.0,
    Tamanho.grande => 9.5,
  };
}

void main() {
  for (final t in Tamanho.values) {
    print('Açaí ${t.name}: R\$ ${preco(t).toStringAsFixed(2)}');
  }
}

$ dart run switch_enum.dart
Açaí pequeno: R$ 5.00
Açaí medio: R$ 7.00
Açaí grande: R$ 9.50

Não há default nem _ no fim, e não precisa: os três casos cobrem tudo. Se um dia a Ana acrescentar gigante ao enum, este switch para de compilar e aponta exatamente o que falta (a mensagem está em Quando dá errado). Por isso, com enums, evite o _: ele engoliria a opção nova sem avisar.

Experimente: acrescente gigante ao enum ({ pequeno, medio, grande, gigante }) e rode. Leia o erro e acrescente o caso que falta no switch, com preço 12.0.

4. Enums melhorados: cada opção com os seus dados Dart 2.17

Na seção 3, o preço de cada tamanho morava num switch, longe do enum. Se a Ana quisesse também os mililitros, seria outro switch. Desde o Dart 2.17, um enum pode ter campos, construtor, getters e métodos, como uma classe. Os dados de cada opção ficam junto dela:

enum Tamanho {
  pequeno(300, 5.0),
  medio(500, 7.0),
  grande(700, 9.5);

  const Tamanho(this.ml, this.preco);

  final int ml;
  final double preco;

  String get rotulo => '${name.toUpperCase()} ($ml ml)';

  double precoPorLitro() => preco / ml * 1000;
}

void main() {
  for (final t in Tamanho.values) {
    print('${t.rotulo}: R\$ ${t.preco.toStringAsFixed(2)}'
        ' - R\$ ${t.precoPorLitro().toStringAsFixed(2)} o litro');
  }
  print(Tamanho.grande.ml);
}
pequeno(300, 5.0),
Cada opção agora tem parênteses com os seus dados, que vão para o construtor: 300 ml e R$ 5,00.
grande(700, 9.5);
Depois da última opção vem ponto e vírgula, não vírgula: é ele que separa a lista de opções do resto (construtor, campos, métodos).
const Tamanho(this.ml, this.preco);
O construtor. Ele é const porque as opções de um enum são constantes, criadas uma vez só (veja final e const). Ninguém chama esse construtor de fora: só as opções lá de cima.
final int ml; final double preco;
Os campos. Têm de ser final: o médio tem 500 ml para sempre.
String get rotulo
Um getter (veja get e set) que usa o name de cada opção.
double precoPorLitro()
Um método, como os de uma classe.
$ dart run melhorado.dart
PEQUENO (300 ml): R$ 5.00 - R$ 16.67 o litro
MEDIO (500 ml): R$ 7.00 - R$ 14.00 o litro
GRANDE (700 ml): R$ 9.50 - R$ 13.57 o litro
700

Agora o preço, os mililitros e o rótulo de cada tamanho estão num lugar só. Para mudar o preço do médio, a Ana mexe numa linha. E a conta mostrou uma coisa que ela suspeitava: o grande sai mais barato por litro.

Outro exemplo: as etapas de um pedido

enum StatusPedido {
  recebido('Recebemos o seu pedido'),
  preparando('Estamos preparando'),
  saiu('Saiu para entrega'),
  entregue('Entregue. Bom apetite!');

  const StatusPedido(this.mensagem);

  final String mensagem;

  bool get terminou => this == StatusPedido.entregue;
}

void main() {
  var status = StatusPedido.recebido;
  print('${status.name}: ${status.mensagem}');
  status = StatusPedido.saiu;
  print('${status.name}: ${status.mensagem}');
  print('Terminou? ${status.terminou}');
  print('Terminou? ${StatusPedido.entregue.terminou}');
}

$ dart run status.dart
recebido: Recebemos o seu pedido
saiu: Saiu para entrega
Terminou? false
Terminou? true

A variável status é var e pode mudar de etapa; o que não muda são as etapas em si e as suas mensagens. Dentro do enum, this é a opção atual: this == StatusPedido.entregue pergunta "eu sou a etapa entregue?".

Quando dá errado

O switch esqueceu uma opção

double preco(Tamanho t) {
  return switch (t) {
    Tamanho.pequeno => 5.0,
    Tamanho.medio => 7.0,
  };
}

void main() {
  print(preco(Tamanho.medio));
}

 - 'Tamanho' is from 'erro_naoexaustivo.dart'.
Try adding a wildcard pattern or cases that match 'Tamanho.grande'.
  return switch (t) {
                 ^

Linha por linha:

  • erro_naoexaustivo.dart:4:18: Error: erro de compilação (código 254) na linha 4, coluna 18, onde está o t do switch.
  • "O tipo Tamanho não é coberto por completo pelos casos do switch, porque eles não pegam Tamanho.grande." Exhaustive = "exaustivo", "que esgota todas as possibilidades". O Dart diz até qual opção faltou.
  • - 'Tamanho' is from …: de que arquivo vem o tipo.
  • "Acrescente um padrão curinga (o _) ou casos que peguem Tamanho.grande." Prefira a segunda sugestão.

Repare que o programa nem precisava do grande (o main só pede o médio), e mesmo assim o Dart recusou. É de propósito: o erro aparece antes de algum cliente pedir um açaí grande. Como consertar: Tamanho.grande => 9.5,.

"Membro não encontrado: gigante." É a maquininha sem o botão: o pedido impossível nem chega a ser feito. Com texto ('gigante'), o programa teria rodado. Como consertar: use uma das opções que existem, ou acrescente gigante ao enum (e aos switch, que o Dart vai apontar).

Campo de enum que não é final 
enum Tamanho {
  pequeno(300),
  medio(500),
  grande(700);

  const Tamanho(this.ml);

  int ml;
}

void main() {
  Tamanho.medio.ml = 550;
  print(Tamanho.medio.ml);
}

$ dart run erro_var.dart
erro_var.dart:6:9: Error: Enum constructors are constant so all fields must be final.
  const Tamanho(this.ml);
        ^
erro_var.dart:8:7: Context: Field isn't final, but constructor is 'const'.
  int ml;
      ^

"Construtores de enum são constantes, então todos os campos têm de ser final." E o Context: aponta o culpado: "o campo não é final, mas o construtor é const". A Ana queria aumentar o médio para 550 ml no meio do programa, mas as opções de um enum não mudam. Como consertar: final int ml;, e mude o valor na declaração: medio(550).

Tentou criar um valor novo do enum 
enum Tamanho { pequeno, medio, grande }

void main() {
  final t = Tamanho();
  print(t);
}

$ dart run erro_criar.dart

"Enums não podem ser instanciados." Os únicos valores são os da lista; não dá para fabricar outro. Como consertar: final t = Tamanho.pequeno;.

Os textos vêm de fora (um arquivo de pedidos), então o compilador não tem como conferir. Os dois primeiros deram certo; o terceiro, "gg", não:

Missão final: as coberturas do açaí

Missão: o main usa c.preco, mas o enum ainda não tem preço, e o programa não compila. Transforme Cobertura num enum melhorado: granola custa 1.5, leite Ninho 3.0 e morango 2.5. (Lembre: o ; depois da última opção, o construtor const e o campo final.)

enum Cobertura { granola, leiteNinho, morango }

void main() {
  for (final c in Cobertura.values) {
    print('${c.name}: R\$ ${c.preco.toStringAsFixed(2)}');
  }
}

enum Cobertura {
  granola(1.5),
  leiteNinho(3.0),
  morango(2.5);

  const Cobertura(this.preco);

  final double preco;
}

void main() {
  for (final c in Cobertura.values) {
    print('${c.name}: R\$ ${c.preco.toStringAsFixed(2)}');
  }
}

No lab, o código inicial parou com Error: The getter 'preco' isn't defined for the type 'Cobertura'., e a solução mostrou granola: R$ 1.50, leiteNinho: R$ 3.00 e morango: R$ 2.50.

Resumo

  • enum cria um tipo com uma lista fechada de valores: Tamanho.pequeno, Tamanho.medio, Tamanho.grande. Erros de digitação viram erros de compilação.
  • Cada valor tem name (o texto) e index (a posição, a partir de 0); Tamanho.values lista todos; values.byName('medio') faz o caminho de volta e dá exceção com nome errado.
  • Num switch sem _, o Dart exige um caso para cada opção e diz qual faltou.
  • Enum melhorado (Dart 2.17+): opções com dados entre parênteses, ; depois da última, construtor const, campos final, getters e métodos.
  • Enums não são instanciados (Tamanho() é erro) e os seus campos não mudam.
